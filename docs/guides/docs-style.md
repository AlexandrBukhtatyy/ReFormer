# Как писать документацию ReFormer

Правила для всех, кто правит документацию, людей и агентов. Цель — чтобы страницу понял человек,
который видит библиотеку впервые, и чтобы её можно было перевести на английский, не переписывая.

## Где что лежит

| Слой               | Каталог                       | Для кого                              | Что там                                  |
| ------------------ | ----------------------------- | ------------------------------------- | ---------------------------------------- |
| Факты API, рецепты | `packages/*/docs/llms/`       | ИИ-ассистенты через MCP, авторы доков | точные сигнатуры, рецепты, частые ошибки |
| Руководство        | `projects/reformer-doc/docs/` | люди                                  | зачем → пример → детали                  |
| Вход в пакет       | `packages/*/README.md`        | npm и GitHub                          | что это, установка, один пример, ссылки  |

**Факт меняется сначала в `docs/llms`**, потом на сайте и в README. Сайт не переписывает сигнатуры:
он объясняет и ссылается на справочник API.

**Копий страниц в `projects/reformer-doc/i18n/ru/` быть не должно.** Русский — локаль по
умолчанию, и Docusaurus читает её страницы из `i18n/ru/…/current/`, если каталог есть. Копия там
молча перекрывает `docs/`: правка в `docs/` не появляется на сайте. В `i18n/ru/` лежат только
переводы темы (`code.json`, `docusaurus-theme-classic/*.json`).

## Шаблон страницы-руководства

1. **Что это** — одна-две фразы без терминов, которых нет в [глоссарии](../../projects/reformer-doc/docs/reference/glossary.md).
2. **Когда нужно** — задача читателя, а не устройство библиотеки.
3. **Минимальный пример** — живой (`<LiveExample>`) или короткий листинг, который работает как есть.
4. **Детали** — варианты, параметры, таблицы.
5. **Подводные камни** — частые ошибки и как их узнать.
6. **См. также** — 2–4 ссылки.

## Шаблон страницы компонента (UI Kit, CDK)

1. Назначение и когда брать его, а не соседний компонент.
2. Анатомия: из каких частей состоит и что настраивается.
3. `<ComponentDoc config={…} />` — варианты, примеры, вкладка API.
4. Доступность: клавиатура, `aria-*`, что берёт на себя компонент.
5. Локализация: какие строки рисует сам и как их заменить.
6. См. также.

## Язык

- Короткие предложения. Одна мысль — одно предложение.
- Термин при первом упоминании на странице — ссылкой на глоссарий.
- Сначала как сделать, потом почему. Разбор «почему не иначе» — только если он снимает частую
  ошибку.
- **Не писать в руководствах «Удалены: … (→ …)», «Прежний контракт», «раньше было».** История
  изменений — на странице «Переход с прежних API» и в CHANGELOG. Руководство описывает то, что есть.
- Внутренние подробности реализации («под капотом», имена внутренних функций) — не в руководство.
  Если без них нельзя — отдельный раздел в конце страницы.

Слова, которые путают читателя, и чем их заменять:

| Не писать                          | Писать                                                                      |
| ---------------------------------- | --------------------------------------------------------------------------- |
| ручка                              | сигнал поля (`model.$.email`)                                               |
| сборка (без пояснения)             | сборка формы (`FormBundle`) — со ссылкой на глоссарий при первом упоминании |
| сабпат                             | вход пакета (`@reformer/core/validation`)                                   |
| M1 (вне введения)                  | модель, схема, правила и поведение                                          |
| диалект, поверхность, дверь записи | назвать конкретную вещь                                                     |

## Инфографика

**Mermaid** — по умолчанию. Блок ` ```mermaid ` прямо в тексте страницы: правится как код и
переводится вместе со страницей. Годится для потоков (`flowchart`), последовательностей
(`sequenceDiagram`) и состояний (`stateDiagram-v2`). Не больше ~10 узлов: больше — делить на две
схемы. Подписи — по-русски, имена API в узлах — как есть.

**Нарисованная SVG** — только для «карт», где важна раскладка, а не порядок: карта пакетов,
анатомия сборки формы, раскладка интерфейса билдера.

- Компонент в `projects/reformer-doc/src/components/diagrams/` на примитивах `Diagram`, `Box`,
  `Arrow` (см. `PackageMap.tsx`), регистрация в `src/theme/MDXComponents.tsx`.
- Цвета — только переменные темы (`--ifm-*`) в `diagram.module.css`: схема должна быть верной в
  светлой и тёмной теме без второго варианта.
- Все подписи — через `translate({ id: 'diagram.<схема>.<ключ>', message })`.
- Страница со схемой-компонентом — `.mdx` (в `.md` JSX не работает).

## Живые примеры

- Файл примера — `projects/reformer-doc/src/components/demo/live/<раздел>/<пример>.tsx`,
  default-экспорт компонента.
- Только публичные импорты пакетов (`@reformer/core`, `@reformer/ui-kit`…), как у пользователя.
- Без сети: вместо запроса к серверу — `Promise` с задержкой и комментарий об этом.
- На странице (`.mdx`) пример импортируется дважды — как компонент и как исходник:

  ```mdx
  import ContactForm from '@site/src/components/demo/live/getting-started/contact-form';
  import contactFormSource from '@site/src/components/demo/live/getting-started/contact-form.tsx?raw';

  <LiveExample component={ContactForm} source={contactFormSource} />
  ```

  Вкладка «Код» показывает тот же файл, что работает в превью, поэтому код и демо не расходятся.

- Классы Tailwind в примерах работают: каталог `live/` сканируется (`src/css/reformer-demo.css`).

## Перевод

- Русские страницы — в `docs/`, английские — в `i18n/en/docusaurus-plugin-content-docs/current/`
  по тому же пути.
- Строки компонентов сайта — только через `translate()` с id (`demo.*`, `diagram.*`), переводы — в
  `i18n/en/code.json`. Новую строку интерфейса сразу добавлять и туда.
- Тексты внутри живых примеров — часть кода. Английской странице, если понадобится, — свой файл
  примера рядом (`contact-form.en.tsx`).
- **Ссылка на страницу, у которой уже есть английский перевод, — только в форме `/docs/...`**
  (`[MCP](/docs/mcp/overview)`), не путём к файлу (`../mcp/overview.md`). В английской сборке
  непереведённая страница берётся из `docs/`, а переведённая — из `i18n/en/…`, и файловая ссылка
  между ними не резолвится: русская сборка проходит, английская падает.
- Подписи категорий сайдбара переводит `npm run write-translations -w reformer-doc -- --locale en`
  (файл `i18n/en/docusaurus-plugin-content-docs/current.json`). Одинаковым подписям в разных
  категориях нужен свой `key` (см. категории справочника API в `sidebars.ts`).

## Проверка

```bash
# пакеты, которые сайт импортирует по exports (→ dist/)
npm run build -w @reformer/core && npm run build -w @reformer/cdk \
  && npm run build -w @reformer/renderer-react && npm run build -w @reformer/renderer-json \
  && npm run build -w @reformer/ui-kit
npm run build -w reformer-doc   # битая ссылка, якорь или MDX роняют сборку
```

После правки `docs/llms` — `npm run generate:llms -w <пакет>` и тесты `@reformer/mcp`; перед
переименованием файлов `docs/llms` — `npm run mcp:evaluate`: имена файлов и заголовки участвуют в
поиске `find_recipe`.
