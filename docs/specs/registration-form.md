## Пользовательская история

**Как новый пользователь**, я хочу зарегистрироваться, **чтобы** получить доступ к сервису.

### Сценарий использования

1. Пользователь открывает форму регистрации (по прямой ссылке — пустую, по ссылке-приглашению —
   с предзаполненными email и полным именем).
2. Заполняет учётную запись, профиль, вводит символы с картинки капчи, принимает условия.
3. Нажимает «Зарегистрироваться». Если есть ошибки — видит их под полями и исправляет.
4. Получает подтверждение об успешной регистрации.

### Критерии приемки

- ✅ Ошибки не показываются, пока пользователь не нажал «Зарегистрироваться»
- ✅ После первой попытки отправки ошибки обновляются при каждом изменении поля
- ✅ Занятость имени пользователя и email проверяется на сервере
- ✅ Капча проверяется на сервере; картинку можно обновить
- ✅ «Очистить» возвращает форму к исходному состоянию и скрывает ошибки
- ✅ После успешной отправки показывается подтверждение

### Капча

Виджет из трёх частей: картинка с кодом, кнопка «Обновить», поле ввода.

- Код — 6 символов из алфавита без похожих знаков (`ABCDEFGHJKLMNPQRSTUVWXYZ23456789`).
- Картинка рисуется на `<canvas>`: символы со смещением и поворотом, шумовые линии и точки.
- Код выдаёт сервер (`GET /api/v1/captcha`), он же хранит действующий код в сессии. Клиент получает
  только данные для отрисовки, ответа не знает.
- «Обновить» запрашивает новый код и очищает поле ввода.
- Проверка — `POST /api/v1/captcha/verify` с введённым ответом; сервер сверяет с кодом из сессии
  без учёта регистра. Код не расходуется проверкой, расходуется регистрацией.

## 🔄 Сценарии формы

### Инициализация формы

- Без параметров — пустая форма, капча загружена.
- С параметром `invite` — запрос `GET /api/v1/auth/registration-prefill?invite=<код>`; ответ
  (`email`, `fullName`) подставляется в поля и становится исходным состоянием для «Очистить».

### Поведение при изменении полей

- До первой попытки отправки ошибки не показываются.
- После первой попытки отправки любое изменение поля перепроверяет его правила, включая асинхронные.
- Изменение пароля перепроверяет подтверждение пароля.
- Асинхронные проверки занятости выполняются после паузы ввода 300 мс; повторная проверка того же
  значения берёт ответ из кэша.

### Отправка

1. «Зарегистрироваться» проверяет все поля, дожидаясь асинхронных проверок.
2. Есть ошибки — показываются под полями, запрос не отправляется.
3. Ошибок нет — `POST /api/v1/auth/register`; успех — блок подтверждения «Регистрация успешна».

### Очистка

«Очистить» возвращает исходные значения (пустые или из приглашения), скрывает ошибки и возвращает
форму в состояние «до первой попытки отправки». Капча не обновляется.

### Сценарии ошибок

| Ситуация                | Поведение                                                                 |
| ----------------------- | ------------------------------------------------------------------------- |
| Имя или email заняты    | Ошибка под полем, отправка блокируется                                    |
| Неверная капча          | Ошибка под полем капчи, код не меняется                                   |
| Сбой проверки занятости | Проверка считается пройденной, окончательно решает сервер при регистрации |

## 🔗 API интеграция

| Метод | Endpoint                                  | Назначение                                                                            |
| ----- | ----------------------------------------- | ------------------------------------------------------------------------------------- |
| GET   | /api/v1/auth/check-username?username=     | `{ available: boolean }`                                                              |
| GET   | /api/v1/auth/check-email?email=           | `{ available: boolean }`                                                              |
| GET   | /api/v1/auth/registration-prefill?invite= | `{ email, fullName }`                                                                 |
| GET   | /api/v1/captcha                           | `{ challengeId, glyphs }` — данные для отрисовки                                      |
| POST  | /api/v1/captcha/verify                    | `{ answer }` → `{ valid: boolean }`                                                   |
| POST  | /api/v1/auth/register                     | `{ username, email, password, fullName, phone, captcha, acceptTerms }` → `{ userId }` |

Занятые значения для проверки: имена `johndoe`, `janedoe`, `admin`; email `john@example.com`,
`admin@example.com`.
