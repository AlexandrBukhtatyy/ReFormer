# Аудит `@reformer/mcp` и его веб-версии — ноябрь 2026

> Аудит 2026-11-11. План исправлений — [docs/plans/mcp-audit-one-path.md](../plans/mcp-audit-one-path.md),
> задачи — эпик `ReFormer-11oe` в bd (фазы `11oe.1`–`11oe.8`, удаление legacy — `11oe.9`).

## Итог

Сервер «работает криво» не из-за одного бага. Причин четыре, и все системные:

1. **Три несовместимых пути создания формы.**
   - Инструкции сервера требуют писать `form.intent.json` и звать `form_build`.
   - Главный промпт `start-here` о `form_build` не знает. Он ведёт по пути «спека → `plan_form` →
     `generate_form`», где агент пишет файлы сам, а для текстового описания — в промпт
     `create-form` с ручным кодом и несуществующим API.
   - Агент выбирает путь случайно, и итог зависит от выбора.
2. **Части intent теряются молча.** Так происходит и в `form_build`, и в `build_form` ассистента.
   Сборка отвечает ✓, а условный пересчёт стал безусловным, подписи и подсказки пропали, обработчик
   отправки исчез.
3. **Сервер зависит от окружения.**
   - Ни один из шести библиотечных пакетов не отдаёт `./package.json`.
   - Вне монорепо справка пуста, а проверка импортов объявляет несуществующим код, который
     напечатал сам генератор.
   - Из-за этого испорчены и замеры: ночная матрица Ollama 2026-11-04 недействительна целиком.
4. **MCP собран в браузер четырежды, отдельно и без сверки версий.**
   - У ассистента и сервера две грамматики intent и два прохода нормализации.
   - Словари ошибок разные.
   - Воркер называет инструменты, которых у него нет.

Решения по исправлению приняты (раздел «Решения»), исполнение — по фазам плана.

## Что проверялось и как

- **Код.** Три независимых обхода:
  - stdio-сервер: инструменты, конвейер `form_build`, окружение, тесты;
  - веб-канал: сборка воркера, плагины ассистента, `build_form`;
  - замеры: стенды `eval/`, записи прогонов, прошлые планы.
- **Живые вызовы** собранного сервера (`packages/reformer-mcp/dist`, 2026-11-09) из Claude Code: `form_build`
  (грамматика), `plan_form`, `generate_form`, `find_recipe`, `choose_api`, `get_context`,
  `validate_form` (`code`, `bundle`).
- **Замеры.** Опубликованные батчи `eval/runs/2026/`, неопубликованные `.tmp/mcp-runs/`, база
  калибровки `eval/baselines/`.

### Как воспроизвести (`R`)

Все вызовы — к серверу из `.mcp.json` (`node packages/reformer-mcp/dist/index.js`).

- **A1:** `form_build{dir:"<несуществующий каталог>"}` возвращает грамматику со словами «ты пишешь
  только этот файл, остальные файлы модуля записывает form_build». На тот же intent
  `generate_form` отвечает «Сервер на диск не пишет: создайте их сами». Промпт `start-here` ведёт на
  `plan_form → generate_form`.
- **A3:** `plan_form{description:"Форма записи к ветеринару: кличка питомца (обязательно), вид
животного (select)…", target:"renderer-react"}` → «Unknown form», «Разобрано: полей 0».
- **A9:**
  - `get_context{task:"многошаговая форма заявки: 3 шага, на втором массив контактов, на третьем
итог с вычисляемым полем; валидация по шагам"}` → `Use compute`, без `FormWizard` и `flow`
    в решении.
  - `choose_api{requirement:"поле «уточните вид» видно и обязательно только когда вид животного =
другое"}` → только `validateWhen`.
- **B2:** `validate_form{kind:"bundle", intent:{…, "fields":{"email":{…}}}, schema:{…}}` → ошибка
  JSON-RPC `items.filter is not a function`.
- **B7:** `validate_form{kind:"code"}` на коде с `required({ message: '…' })`,
  `model.items.reduce(…)` и `bundle.form.submit()` → «✅ ошибок нет, предупреждений 1» (только RF010
  про `message`).
- **C1:**

  ```sh
  cd packages/reformer-mcp && node --input-type=module -e \
    "import.meta.resolve('@reformer/core/package.json')"
  ```

  → `ERR_PACKAGE_PATH_NOT_EXPORTED`, так же у cdk, ui-kit, renderer-react, renderer-json и
  form-registry.

## Решения

Приняты пользователем 2026-11-11:

- **Терминал — только `form_build`.**
  - `generate_form` уходит из списка инструментов. Уточнено в тот же день: удаляется совсем,
    вместе с псевдонимами `validate_json_schema` и `check_behaviors`, а у воркера остаются только
    справочные инструменты (`11oe.9`).
  - `plan_form` — только «спека → черновик `form.intent.json`».
  - Промпты переписываются вокруг intent.
  - Мажорная версия `@reformer/mcp` 7.0.
- **Ассистент — один язык intent с MCP.**
  - Грамматика профиля `document`, разбор и судья из MCP.
  - `build_form` только переносит intent в документ.
  - Неподдержанное получает явный отказ.
- **Воркер — справочный канал.**
  - Тексты под профиль.
  - Корпус собирается один раз, есть сверка версий.
- **Тексты для модели — английские.** Тексты форм — на языке пользователя.
- **Приёмка:**
  - Claude Code в терминале;
  - локальные модели ~27B и 4–8B в терминале и в ассистенте.

Что база **не** видит, и почему она зелёная при находках выше:

- **Метрика «потери intent» калибровки сверяет только известные ключи.** Незнакомые ключи (B1)
  отбрасываются до неё, поэтому 0 потерь при реальных потерях.
- **Стенды идут из монорепо со свежими `dist`.** Ветка «пакет не найден» (C1, B3) не
  проверяется.
- **Сценарии без модели не проверяют выбор пути.** Агента, которому даны три пути (A1), нет в
  контуре. Это проверяют только матрицы с моделью: Claude Code и Ollama, их запускает
  пользователь.
- **Калибровка запускается с `npm_config_cache` во временном каталоге.** Иначе Inspector не
  ставится: песочница агента не пускает в `~/.npm/_cacache`.
