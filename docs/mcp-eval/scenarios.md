# Сценарии `@reformer/mcp`: получится ли у агента рабочая форма

> Замер 2026-11-02. Стенд — [packages/reformer-mcp/eval/scenarios/](../../packages/reformer-mcp/eval/scenarios/),
> верификатор — [eval/verify/](../../packages/reformer-mcp/eval/verify/). Записи прогонов —
> [runs/](../../packages/reformer-mcp/eval/runs/README.md). Задачи — эпик `ReFormer-qo9b` в bd.

## Зачем

[`mcp:evaluate`](README.md) меряет, отдаёт ли сервер нужное знание. [`mcp:calibrate`](calibration.md)
проходит путь «спека → intent → бандл» по заранее известному маршруту, без модели. Ни один из них не
отвечает на главный вопрос: **что получится, если настоящий агент получит задание и этот сервер**.
Ручной iter-цикл отвечал на него только для одной спеки и запускался раз в несколько месяцев.

## Как устроено

```
задание → агент ↔ MCP-сервер → form/ → верификатор: статика → без браузера → браузер → запись прогона
```

| Часть       | Что делает                                                                                                                                                         |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Лестница    | 16 сценариев: одна фраза (L1), правила (L2), поведение (L3), массив и мастер (L4), спецификация (L5). Из них 5 — holdout, запускаются отдельным флагом             |
| Агенты      | `replay` (эталон, без модели, для CI), `ollama` (свой цикл вызовов), `claude-code` (`claude -p` с единственным MCP-сервером)                                       |
| Подходы     | `bare`, `start-here`, `prompt-create-form`, `no-generate`. Текст задания у всех агентов подхода один. A/B сборок — `--server <другой dist>`                        |
| Контракт    | Поля, шаги, массивы и пробы: что ввести и что должно получиться. Эталонное решение доказывает, что контракт выполним                                               |
| Верификатор | Точка входа, стек по импортам, `tsc`, `validate_form`; форма без браузера и пробы; браузер: роли, подписи и порядок в снимке доступности, axe. Скриншот — артефакт |
| Запись      | Один формат для всех стендов: вердикт, проверки, метрики, токены, отпечатки сборки, поверхности и знания                                                           |

Рабочий каталог агента — вне репозитория, чтобы он не видел исходники пакетов: иначе замерялся бы не
сервер. У Claude Code изоляция проверяется по факту: каталог, инструменты и серверы — по событию
`system/init`, адреса — по вызовам инструментов. Нарушение делает прогон `invalid`, а не проваленным.

## Команды

```bash
npm run mcp:verify -- --golden [--browser]     # эталоны проходят контракты
npm run mcp:verify -- --negative               # сломанные формы падают на своей проверке
npm run mcp:verify -- --reverify <батч>[,<батч>]  # новая оценка сохранённых форм без модели
npm run mcp:scenarios -- --matrix smoke        # весь путь без модели, годится для CI
npm run mcp:scenarios -- --agent claude-code --model sonnet --scenario 'L1-*,L3-*' --repeats 3 \
  --max-usd-batch 5 --browser --publish
npm run mcp:scenarios -- --agent ollama --model qwen3.8:27b-32k --scenario L1-feedback
npm run mcp:compare -- <A> <B> [--gate]
npm run mcp:report
npm run mcp:mutate                             # умеют ли приборы краснеть
```

Без модели всё это идёт в `.github/workflows/mcp-quality.yml` (ночью, вручную и при пуше в main).
Прогоны с моделью в CI не идут: они тратят лимит и не детерминированы.

### `form_build`: тот же замер после смены пути

Агент правит только `form.intent.json`, сервер сам компилирует, проверяет типы и пишет файлы
([план и история замеров](../plans/mcp-misty-graham.md)). База — старый сервер, финал — подход `bare` без
подсказок в задании. Все плечи оценены одним прибором (`mcp:verify --reverify`), браузерные проверки — из
своих прогонов. Цена, вывод и ходы — медиана за прогон; у holdout — сумма за 10 прогонов.

| Набор                       |   N | Прошло: база → финал | Цена          | Вывод, токены    | Ходов    |
| --------------------------- | --: | -------------------- | ------------- | ---------------- | -------- |
| L5-credit, renderer-react   | 3/5 | 1/3 → 5/5            | $1.27 → $0.41 | 38.3 → 19.2 тыс. | 60 → 11  |
| L4-contacts-array           | 3/5 | 3/3 → 5/5            | $0.14 → $0.04 | 4.0 → 1.1 тыс.   | 16 → 4   |
| core: L1-login, L3, L5-loan |   9 | 5/9 → 9/9            | $0.11 → $0.09 | 3.6 → 2.4 тыс.   | 13 → 14  |
| Holdout, агрегат            |  10 | 4/10 → 9/10          | $3.21 → $1.35 | 108 → 63 тыс.    | 220 → 60 |

**Чего эти цифры не доказывают.** Значимость по самому прохождению на настроечных сценариях слабая:
интервалы при N=3–5 широкие. Сильнее всего разница в цене и ходах. Одна модель и один клиент. Holdout
частично загрязнён, запускался четырежды, поэтому служит контролем, а не оценкой.

**Что найдено по дороге:**

- Единственный провал holdout: агент записал исходник и закончил работу, не вызвав сборку, поэтому
  результат пуст. Причина общая, не связанная с заданием: в грамматику добавлено условие завершения.
  Повторный holdout 2026-11-04 (батч `1035`, сервер с правками ReFormer-j356.5–j356.7, b464, j356.6):
  10/10, но $1.75 против $1.35 и 96 ходов против 60. Выхода без сборки не было. Ходы добавили три
  причины: на core агент придумывает `bundle.form.submit()`/`validate()` (2 из 2, в `10be` — 1 из 2);
  предупреждение о `submitLabel` у корневого `Box` дало лишнюю сборку в L1; в L5 — потерянные тексты
  ошибок, как и раньше, и одна итерация от `string | null` у необязательного текста.
  **Цена и ходы `1035` с `10be` несопоставимы.** Снимок сервера для `--server` был скопирован без
  соседних пакетов, и справки по `@reformer/core` у него не было (ReFormer-qo9b.34). Сборку это не
  задело: типы проверялись по пакетам репозитория. Но оба прогона L2 на core искали API отправки и
  получали «not found», а полный сервер отвечает `bundle.submit`. Первая причина поэтому хотя бы
  отчасти — артефакт стенда.
- Контракт не видел подмены стека: в одной из серий агент заменил `core` на `renderer-react` в 7 прогонах
  из 9 при зелёном вердикте. Теперь это гейт `static.stack`.
- Контракт не проверял межполевые правила спеки. Новые пробы показали, что правило из таблицы
  зависимостей реализовано в 2 формах из 8; пример в грамматике и напоминание в ответе подняли это до
  5 из 5.
- L3-order-total на core: `total` доступен для ввода, вычисляемое поле не заблокировано в разметке
  (негейтовая проба, 3 из 3 финальных прогонов). Разметку на core пишет агент, сборка этого не проверяет.
  Причина — `componentProps.disabled`: обёртка поля затирает его состоянием узла. С 2026-11-04 цель
  `compute` получает ключ узла `disabled` от генератора (ReFormer-j356.6); сохранённый прогон L3,
  пересобранный новым сервером, рисует `total` заблокированным.

### Локальные модели: qwen3.8:27b-32k и gemma4:26b

Базового замера нет, в `runs/` ничего не опубликовано: это проверка адаптера, а не оценка. Первый батч
(4 прогона, 0 пройдено, ни одного записанного файла) снят как недействительный. Его испортил стенд:
предел `fetch` в 5 минут рвал связь, а бюджет в 10 минут мал для модели, у которой шаг занимает минуты.

После правки — один прогон L1-feedback, подход `start-here` (`.tmp/mcp-runs/20261102T173729Z-439a`):
25 минут, 23 шага, 27 вызовов MCP, 286 тыс. входных токенов, ❌ по таймауту, счёт 0.2. Модель дошла до
`plan_form` и `generate_form` и записала файлы, но форма не компилируется: импортирован несуществующий
`FormBehavior`, в `model.ts` нет `createFormModel`.

**Причину этот прогон не разделяет.** Стенд усёк старые ответы инструментов 135 раз (контекст 32k), и
под усечение мог попасть сам бандл `generate_form`: модель могла потерять готовый код и писать по
памяти. Прежде чем судить, надо проверить запись файлов при неусечённом ответе генератора и снять
замер с повторами.

**Ночная матрица 2026-11-04 недействительна целиком.** Батч `20261103T234434Z-f7d3`: `nightly-ollama`,
6 сценариев, 2 модели, 3 повтора, около 15 часов. Итог 2/32 и 4 недействительных прогона, но о сервере
и моделях эти цифры ничего не говорят. Сработали два дефекта стенда:

1. Снимок сервера (`.tmp/baseline/mcp-20261104`) скопирован без соседних пакетов. Индексы
   `@reformer/core` и `cdk` CLI-сервер находит только путём монорепо от своего `dist`, поэтому справки
   по ним на снимке нет (ReFormer-qo9b.34).
2. Адаптер Ollama, в отличие от claude-code, не передавал серверу `REFORMER_TYPECHECK_ROOT`. Без
   проверки типов `form_build` проверяет только импорты по индексу (ReFormer-qo9b.35, исправлено).

Вместе они дали отказ «`createModel` не существует ни в одном @reformer/\* пакете» на `model.ts`,
который сервер напечатал сам. Так случилось в 26 из 27 прогонов, где модель записала intent; в 27-м
сборка отказала раньше, на текстах ошибок. После отказов модели писали модуль руками и выдумывали
API: `defineFormBehavior`, `useFormBundle` не из того пакета. Оба зачётных прогона написаны руками,
без единой успешной сборки.

**Что видно на исправном сервере.** Первый `form.intent.json` каждого прогона, взятый из транскрипта
и собранный в чистом каталоге тем же снимком с `REFORMER_TYPECHECK_ROOT`:

| Исход первого intent                                               | Прогонов |
| ------------------------------------------------------------------ | -------: |
| Собирается сразу                                                   |  8 из 27 |
| Отказ «тексты ошибок потеряны»: один `message` на несколько правил | 13 из 27 |
| Кросс-проверка C4: правило на `contacts.name` вместо `each`        |  2 из 27 |
| Ошибки типов: `reduce` у `ModelArray`, лишнее поле строки          |  2 из 27 |
| Intent не разбирается как JSON                                     |  1 из 27 |
| Intent не записан вовсе (8 прогонов qwen, 1 gemma)                 |  9 из 36 |

Главный реальный барьер — тексты ошибок. Обе модели группируют валидаторы поля под общим текстом:
`[required, email]` с «Укажите корректный email», `[min(0), max(50)]` со «Скидка от 0 до 50%»
(ReFormer-j356.10). Sonnet после такого отказа исправляется. Восстанавливаются ли локальные модели,
матрица показать не могла: исправленный intent упёрся бы в тот же ложный отказ.

Ещё два наблюдения:

- **4 недействительных прогона.** Все qwen, ответ Ollama 500 «no user query found in messages». В трёх
  последний ответ — ресурс `reformer://guide` на 70 тыс. символов при контексте 32k: Ollama
  отбрасывает начало переписки вместе с заданием (ReFormer-qo9b.36).
- **qwen чаще не доходит до intent.** 8 из 18 прогонов без записанного intent, усечений 66–436 за
  прогон, 12 выходов по пределу шагов. gemma записала intent в 17 из 18 и ни разу не упёрлась в предел.

Перезамер — после ReFormer-qo9b.34: на полном снимке и с исправленным адаптером.

## Что замер уже нашёл

**В сервере:**

- **`ReFormer-qo9b.28`, P1.** `generate_form` с компонентом `DatePicker` на всех трёх таргетах печатает
  импорт из корня `@reformer/ui-kit`, а компонент есть только в подпути `@reformer/ui-kit/date-picker`.
  Форма с таким полем не компилируется — 2 из 10 прогонов. Калибровка этого не видела: в кредитном
  эталоне полей `DatePicker` нет вовсе.
- **`ReFormer-qo9b.29`.** `choose_api` не отвечает на «минимум один, максимум пять строк». В ядре нет
  валидаторов длины массива, ограничение — проп `maxItems` у `FieldArray`, и агенты угадывают.
- **`ReFormer-qo9b.30`.** В двух прогонах L5-credit из трёх агент считает `ModelArray` обычным массивом
  (`.reduce`, `.get`). Компилятор это ловит, но агент до компилятора не доходит: запускать ему нечем.
- **Канон раскладки не доходит.** В 7 прогонах из 10 нет файлов, которые манифест велит создать самому
  (`RF012`). `validate_form kind=layout` вызван один раз из 10, а `kind=code` — только в двух прогонах,
  обошедших генератор.
- **Агенты обходят генератор.** В 2 прогонах из 10 (L3-order-total, L4-wizard-3steps) агент не дошёл до
  `generate_form` и написал форму сам: неканонично, поэтому пробы не запустились. Почему — ещё не
  разбиралось: двух прогонов для вывода мало.

**В самих приборах** — потому верификатор и проверяется эталонами, негативными фикстурами и мутантами:

- контракт кредитной заявки требовал то, чего нет в спеке: честный прогон был красным;
- файл `form.schema.tsx` не загружался, и форма собиралась без схемы: честная форма была красной;
- пропущенная браузерная проверка считалась упавшим гейтом;
- проба требовала короткое сообщение, а агент вправе потребовать минимальную длину;
- проба `at-most-five` проверяла только добавление строки: снята, чтобы не врать о покрытии;
- мутант нашёл настоящую дыру: потеря алиаса `wizard` с фильтром `package` не была видна ни одному тесту.

## Чего замер не говорит

- **Один прогон, одна модель, один подход.** Разброс между прогонами виден уже здесь.
- **Контракт проверяет заявленное**, а не качество целиком: подписи и порядок — да, удобство — нет.
- **Оценка стоимости условна:** запуск по подписке, `total_cost_usd` — расчётная цена.
- **Форма на `core` без схемы** проверяется только с канонической раскладкой: без `model.ts` пробы не
  запускаются, и прогон считается проваленным. Это решение стенда: сервер требует канон, и агент, не
  дошедший до него, — дефект пути, а не только агента.
- **Holdout не полностью независимый.** Задания L1–L4 написал агент, знающий сервер, а страховая заявка
  частично загрязнена: [holdout/README.md](../../packages/reformer-mcp/eval/scenarios/holdout/README.md).
