# Ассистент билдера: режим файлов против структурного режима

> Эпик ReFormer-lhvk, план — [docs/plans/tender-toasting-rocket.md](../plans/tender-toasting-rocket.md).
> Стенд — [integration/assistant-ab-eval.test.ts](../../projects/reformer-builder-playground/.ui_builder/plugins/reformer/integration/assistant-ab-eval.test.ts),
> формы прогонов — страница `/debug/builder-ab` витрины
> ([pages/debug/builder-ab](../../projects/react-playground/src/pages/debug/builder-ab/index.tsx)).

## Зачем замер

Ассистент получил второй режим работы. В **структурном** модель называет намерение
инструментами редактора (`insert_node`, `set_node_prop`, `set_form_rules`…), а формат документа
знает редактор. В режиме **файлов** модель сама правит файлы модуля формы (`read_file`, `edit_file`,
`write_file`): схему, файлы шагов, код валидации и поведения. Целость формы держит гейт записи —
запись, ломающая форму, отвергается и не пишется.

Режим файлов проще по устройству и дешевле по постоянной части запроса: поверхность инструментов
2862 символа против 10165, системный промпт 3634 против 4175. Но этот путь уже отклоняли
([chatgpt-cheeky-cloud.md](../plans/chatgpt-cheeky-cloud.md)): с файлами на модель снова ложатся
`$model`, `$component` и сборка составных компонентов. Замер должен ответить, окупается ли
упрощение, а не предположить это.

## Критерии — записаны ДО прогона

- **Облачная модель** (Claude или GPT): полнота полей в режиме файлов не ниже структурного при
  входных токенах на ход не больше чем на 30 % выше.
- **Локальная модель** (Ollama): в режиме файлов **ноль сломанных итоговых форм** — гейт обязан
  удержать форму целой, даже если задача не доделана.
- Сценарий правил: в режиме файлов правила должны оказаться в коде модуля (его исполняет превью) и
  проходить проверку API `@reformer/*` без ошибок.

Если режим файлов проходит критерии, структурный снимается отдельной задачей (ReFormer-57zo).

## Методика

Сценарии:

- **spec** — форма кредитной заявки с нуля по спецификации (`.tmp/builder-spec-run/spec-slice.md`,
  задание дословно из прошлого замера): шесть шагов мастера и поля из таблиц. Мера — сколько из
  82 ключей колонки «Ключ в форме» нашлось среди путей `$model(...)` итоговой формы.
- **rules** — на шаблоне `reformer-multi-step-form`: «Сделай поле „Город“ обязательным. Поле
  „Должность“ показывай только тогда, когда город заполнен». Мера — попала ли каждая просьба в
  форму: у структурного — в правила хода, у файлового — в `validation/*.ts` и `behavior/index.ts`.
  В первом прогоне структурный режим начинал с пустого набора правил; со второго оба режима
  начинают с правил затравки шаблона — тех, из которых напечатаны его файлы.
- Детерминированный эталон «мастер 3×4» — в обычных тестах (`file-loop.test.ts`): режим файлов
  собирает его за два вызова.

Для каждого прогона пишется JSON в `.tmp/ab-eval*/`: время, `TurnStats` (шаги, токены), вызовы по
именам, отказы по кодам, валидность итоговой формы строгой проверкой, число шагов и полей.

Со второго прогона итог каждого хода ещё и **печатается модулем формы** — кодогеном билдера, той
же доставкой, что «Сгенерировать»: производные файлы по итоговой схеме, авторские — как их оставила
модель (или из правил, если файл всё ещё несёт маркер кодогена). Модули лежат в
`projects/react-playground/src/pages/debug/builder-ab/<сценарий>-<режим>/` вместе с `meta.json`, и
страница `/debug/builder-ab` показывает каждую форму рядом со счётом прогона.

## Результаты — локальная модель, первый прогон, 2026-10-20

`qwen3.8:27b` через Ollama, канал `openai-compatible`, окно контекста 32768 (вариант модели
`qwen3.8:27b-32k`: с окном по умолчанию 262144 в видеопамять 16 ГБ помещалось 8 из 33,6 ГБ, и шаги
упирались в таймаут заголовков; с окном 32K — 11,7 из 19,2 ГБ). По одному прогону на режим и
сценарий. Сырые отчёты — `.tmp/ab-eval-32k/`.

### rules — правила на готовой форме

| режим      | время | шагов | вход, токенов | вызовы                                         | «Город» обязателен | «Должность» по условию | форма   |
| ---------- | ----- | ----- | ------------- | ---------------------------------------------- | ------------------ | ---------------------- | ------- |
| structured | 130 с | 2     | 9 501         | `set_node_prop`, `set_render_rules`            | ✗                  | ✓ (в памяти моста)     | валидна |
| files      | 201 с | 7     | 43 033        | `read_file` ×5, `ask_reformer`, `edit_file` ×3 | ✓                  | ✓ (в коде модуля)      | валидна |

Режим файлов выполнил обе просьбы тремя правками трёх файлов — ровно так, как форму написал бы
человек:

```ts
// validation/kontakty.ts
validate(model.$.city, [required()]);
// behavior/index.ts
hideWhen(schema.node('position'), () => !model.city);
```

и узлу «Должность» в файле шага добавлен `"selector": "position"`. Новых находок проверки API
`@reformer/*` в коде нет (единственная — в шаблоне до хода, и она ложная, см. ниже).

Структурный режим поставил обязательность СВОЙСТВОМ (`set_node_prop` → `required: true`), а не
правилом валидации — то самое ложное «готово», ради которого заводился `set_form_rules`
([builder-rules.md](builder-rules.md)). Видимость он задал правилом, но правило живёт в памяти моста
и до кода модуля, который исполняет превью, не доходит.

Цена — вход вчетверо с половиной больше: из девяти вызовов пять — чтения файлов перед правкой.

### spec — форма кредитной заявки с нуля

| режим      | время | шагов | вход, токенов (из кэша) | записей | шагов мастера | полей (ключей из 82) | конец хода |
| ---------- | ----- | ----- | ----------------------- | ------- | ------------- | -------------------- | ---------- |
| structured | 492 с | 9     | 149 134 (131 326)       | 3       | 6             | 0                    | `abort`    |
| files      | 626 с | 8     | 116 824 (100 856)       | 0       | 0             | 0                    | `abort`    |

Сценарий на этой машине режимы **не различает**: оба хода оборвались одинаково (`stop.reason:
'abort'`) ещё на разведке — структурный успел вставить шесть шагов мастера, файловый не записал
ничего. По всей видимости, это сторож тишины потока (60 с в `providers/ai-sdk.ts`): при частичной
выгрузке модели на CPU шаг с ~16 тыс. токенов контекста молчит дольше минуты. Августовский замер
кончился тем же «aborted, без причины» — вероятно, по той же причине (ReFormer-6zxe).

## Результаты — локальная модель, второй прогон, 2026-10-20

Та же модель и то же окно, по одному прогону на режим и сценарий. Что изменилось с первого:

- ReFormer-6zxe: обрыв по сторожу тишины виден в отчёте как `timeout`, а не безымянный `abort`;
  у локального канала сторож — 5 минут вместо минуты;
- оба режима сценария `rules` начинают с правил шаблона;
- итог каждого хода напечатан модулем формы и открыт в браузере (`/debug/builder-ab`).

Сырые отчёты — `.tmp/ab-eval-pages/`.

### rules

| режим      | время | шагов | вход, токенов | вызовы                                                | «Город» обязателен | «Должность» по условию | форма   |
| ---------- | ----- | ----- | ------------- | ----------------------------------------------------- | ------------------ | ---------------------- | ------- |
| structured | 467 с | 2     | 9 915         | `set_node_prop`, `set_form_rules`, `set_render_rules` | ✓                  | ✓                      | валидна |
| files      | 190 с | 5     | 29 203        | `read_file` ×6, `ask_reformer`, `edit_file` ×3        | ✓                  | ✓                      | валидна |

На этот раз обе просьбы выполнили оба режима, и по коду модуля результаты совпадают:
`validate(model.$.city, [required()])` в `validation/kontakty.ts` и `hideWhen` на узел «Должность»
по `!model.city` в `behavior/index.ts`. Структурный дал узлу селектор `dolzhnost` (`set_node_prop`),
файловый — `position`, и правило ссылается на тот селектор, что стоит в схеме. Обязательность
структурный на этот раз поставил правилом (`set_form_rules`), а не свойством.

Обе формы проверены в браузере: на шаге «Контакты» «Далее» без города показывает «Обязательное
поле» под «Городом», «Должности» нет; после выбора города она появляется. Скриншоты —
`projects/react-playground-e2e/screenshots/builder-ab/`.

Цена режима файлов — втрое больше входа (в первом прогоне — вчетверо с половиной); по времени
теперь быстрее он: 190 с против 467 с. Время структурного режима — два шага с долгим рассуждением,
а не число вызовов.

### spec

| режим      | время   | шагов | вход, токенов (из кэша) | записей | шагов мастера | полей (ключей из 82) | конец хода                    |
| ---------- | ------- | ----- | ----------------------- | ------- | ------------- | -------------------- | ----------------------------- |
| structured | 3 115 с | 11    | 185 855 (167 181)       | 3       | 6             | 0                    | `error`: пустой ответ на шаге |
| files      | 901 с   | 8     | 121 128 (104 147)       | 0       | 0             | 0                    | `error`: `timeout` (сторож)   |

Сторож в одну минуту больше не обрывает разведку: оба хода дошли до работы с формой. Но полей нет
ни у одного:

- **structured** за 52 минуты вставил шесть пустых шагов мастера (один `insert_node` отвергнут
  гейтом, `SCHEMA_INVALID`) и закончил очередной шаг пустым ответом — без текста и без вызова. Форма
  открывается визардом из шести шагов без полей.
- **files** после семи вопросов `ask_reformer` начал запись — и его оборвал сторож. Журнал Ollama
  показывает, что модель всё это время работала: последний запрос шёл 9 мин 40 с и сгенерировал
  около 3 тысяч токенов (5 токенов в секунду). OpenAI-совместимый эндпоинт Ollama отдаёт аргументы
  вызова инструмента одним куском, когда вызов дописан, поэтому длинная запись файла для потока —
  тишина. Пять минут сторожа на этом не хватает (ReFormer-lhvk.5). Форма осталась исходной, пустой.

Сценарий `spec` на этой машине по-прежнему **не различает режимы**: для формы на 82 поля пять
токенов в секунду — это час генерации только на тексты файлов шагов. Различить его может облачная
модель.

### Третий прогон: только spec

После второго прогона у локального канала убран сторож тишины (ReFormer-lhvk.5). Первый повтор
оборвался на той же записи и на той же отметке: дело оказалось не только в стороже. `fetch` в Node,
через который идёт стенд, сам рвёт ответ после 5 минут без байтов (`bodyTimeout` undici,
`UND_ERR_BODY_TIMEOUT`, проверено отдельной пробой). В браузере, где работает билдер, такого предела
нет, поэтому стенд для живых прогонов ставит `fetch` без таймаутов.

Следующий повтор дошёл до записи. Режим файлов дважды написал форму целиком одним `write_file`,
каждая запись генерировалась около 24 минут, и обе гейт отверг (`SCHEMA_INVALID`) — форма осталась
целой. Обе отвергнутые записи по ~7 тыс. токенов остались в контексте, и следующий запрос весил
32 517 токенов при окне 32 768 (ReFormer-lhvk.6). Прогон остановлен вручную через ~80 минут: он
занимал единственный слот Ollama, и ассистент в песочнице ждал в очереди. Структурный режим в этом
прогоне не запускался.

## Попутные находки

- Проверка кода из MCP (`validateCode`) даёт ложные находки на коде, который печатает сам кодоген:
  RF002 на `import { ru } from '@reformer/ui-kit/locale/ru'` и RF005 на правила поведения внутри
  `behaviorRules`, переданной в `defineFormBehavior`. Гейт отвергает только НОВЫЕ ошибки, поэтому
  на правке существующих файлов это не мешало, но модель получает ложный совет «перенесите вызов»
  (ReFormer-kbs4).
- Обёртка `scripts/run-vitest.mjs` непригодна для живых замеров: минуту тишины она считает
  зависанием, а «убитый» ею на Windows vitest продолжает работать и занимает модель
  (ReFormer-23l1, исправлено). Замер запускается `npx vitest run` напрямую.
- Печать модуля по шаблону без правил его затравки стирает правила самого шаблона: файлы
  `validation/*.ts` и `behavior/index.ts` несут маркер кодогена и перепечатываются из правил, а
  `rulesOf` в билдере ни к кому не проброшен (`codegen/src/workspace.ts`). В стенде это закрыто
  правилами затравки; в самом билдере «Сгенерировать» после хода структурного режима ведёт себя так
  же — известная неполнота кодогена.
- Кодоген печатает пустой `behaviorRules(_scope)`, и стандартный конфиг `typescript-eslint` (шаблон
  Vite, витрина) считает это ошибкой (ReFormer-q6ek). Модули стенда поэтому исключены из линта
  витрины; `tsc` их проверяет.
- Dev-сервер Vite на Windows пропускает удаление и пересоздание каталога и продолжает отдавать
  прежние модули. Стенд поэтому переписывает файлы прогона на месте, а не пересоздаёт каталог.
- Живая проверка в песочнице нашла дефект платформы: правка ассистента в режиме файлов доходила до
  рабочей копии, но не до дерева и буфера открытой формы. Одновременные `Workspace.open` одного
  файла (вкладка открывается несколькими вызовами подряд) заводили разные буферы; модель редактора
  смотрела в первый, запись попадала в последний. Исправлено, покрыто юнит- и e2e-тестом
  (ReFormer-fswg). Структурный режим этого не видел: он правит через ручку модели.
- Сообщение об отказе гейта лента показывает человеку по-английски — тем же текстом, что модели
  (ReFormer-lhvk.7).

## По критериям

- **Локальная модель — ноль сломанных форм в режиме файлов:** выполнен, 4 из 4 за два прогона (на
  `spec` — тривиально: записей не было).
- **Правила в коде модуля без ошибок API:** выполнен в обоих прогонах; единственная находка
  проверки — ложная, в коде шаблона до хода (ReFormer-kbs4).
- **Облачная модель:** не измерялась — ключа в окружении нет.

Вывод пока частичный. На задаче правил режим файлов выполнил обе просьбы оба раза, структурный — со
второго; файловый дороже по входу в 3–4,5 раза. Сценарий `spec` на локальной модели не различает
режимы: в первом прогоне мешал сторож в одну минуту (ReFormer-6zxe, исправлено), во втором —
буферизация вызовов инструментов в Ollama (ReFormer-lhvk.5, исправлено), в третьем — скорость
модели и окно, забитое отвергнутыми записями (ReFormer-lhvk.6). Решение о снятии
структурного режима (ReFormer-57zo) — после прогона на облачной модели.
