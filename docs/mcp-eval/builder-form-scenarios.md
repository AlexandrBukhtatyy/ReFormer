## Зачем

Документ сценариев отмечает, что ассистент может **по коду**: есть ли инструменты и сохраняется ли
результат. e2e с подменённой моделью (`tests/assistant/form-scenarios.spec.ts`) проверяет, что
обвязка выдерживает сценарий, когда вызовы правильные. Ни то, ни другое не отвечает на вопрос,
**позовёт ли их правильно сама модель**, услышав просьбу человека. Это и меряется здесь.

## Как мерялось

- **Ход целиком, как в билдере.** `createAgentBridge` с настоящими реестрами инструментов,
  затравкой, второй попыткой и файлом правил. Рабочая область — двойник (`testing.ts`), шаблоны и
  генерация кода — двойники возможностей: интерфейс замер не задевает.
- **Запрос — словами пользователя**, по-русски, без подсказок об инструментах.
- **Три стартовые формы:** формы нет вовсе (1.1), пустая форма, анкета клиента из 11 полей
  (имя, почта, телефон, пароль, тип клиента, ИНН, цена, количество, сумма, самовывоз, адрес
  доставки) с правилом «почта обязательна».
- **Критерий — по результату, а не по вызовам:** что легло в форму и в файл правил. Например, 7.4
  засчитан, если у `inn` есть `required` с условием `when`; 5.3 — если есть мастер из двух шагов
  и почта во втором. Неудачные вызовы по пути не делают сценарий проваленным, но считаются.
- **Вопросы модели** (`ask_user`) получают первый вариант ответа автоматически.
- Предел хода — 24 шага; по одному прогону на сценарий.

Запуск: `EVAL_MODEL=qwen3.8:27b-32k npx vitest run assistant-scenarios-eval.test.ts` из
`.ui_builder/plugins/reformer/integration` проекта-образца; `EVAL_ONLY=7.1,8.1` — выборочно. JSON прогона ложится в `.tmp/eval/`.

## Что нашёл замер

**1. Текст ошибки у обычного правила — лишний шаг почти в каждом ходе с правилами.** В трёх из
четырёх сценариев с правилами (1.1, 7.1, 7.4) модель первой попыткой ставит `message` к
`required` («Укажите телефон»). `set_form_rules` принимает текст только у `cross`/`async` и
отказывал словами «needs code — the code the async check returns». Эта формулировка уводила
модель в справку (`ask_reformer`) ещё одним шагом. Отказ переписан: он называет починку прямо —
«для cross и async; у стандартных проверок свой текст — убери message». Перемер тех же трёх
сценариев:

| №   | Вызовы до                                           | Вызовы после                         | Время, с  |
| --- | --------------------------------------------------- | ------------------------------------ | --------- |
| 1.1 | … `set_form_rules✗ → ask_reformer → set_form_rules` | … `set_form_rules✗ → set_form_rules` | 188 → 140 |
| 7.1 | `set_form_rules✗ → ask_reformer → set_form_rules`   | `set_form_rules✗ → set_form_rules`   | 99 → 58   |
| 7.4 | `get_form_node → set_form_rules✗ → set_form_rules`  | то же                                | 74 → 65   |

Первая попытка всё равно отказывает: модель хочет свой текст ошибки. Это возможность, а не
формулировка, — сценарий 7.9 («тексты ошибок»), в структурном режиме ❌; задача ReFormer-74zy.

Исправлено (ReFormer-74zy): `message` у обычного правила принимается. Правило получает свой код
по соглашению ядра (`<поле>.<правило>`), код дописывается в вызов валидатора
(`required({ code: 'phone.required' })`), а генерация кладёт текст под ним в словарь формы.
Перемер тех же сценариев — **ни одного отказа**: 1.1 — 7 вызовов, 156 с; 7.1 — 2 вызова, 64 с;
7.4 — 3 вызова, 66 с.

**2. Перенос полей по одному — самый дорогой ход.** В сценарии 5.3 надо разложить 11 полей по
двум шагам. `move_node` переносит один узел, а адреса соседей после каждого переноса сдвигаются.
Модель то перечитывает карту, то бьёт по старому адресу: 38 вызовов, 17 отказов «No node at … —
the form changed» за 8 минут. Во втором прогоне — 24 вызова и 3 отказа: разброс большой, порядок
один.

Исправлено (ReFormer-ggpp): `move_node` переносит пачку узлов (`refs`), адреса — по форме до
правки, пересчитывает их ядро. Перемер 5.3: **10 вызовов, два `move_node` без отказов, 197 с**
вместо 24–38 вызовов и 368–489 с. Первый перемер дал ещё один отказ: модель передала `expect` с
пачкой, потому что промпт велел «для move_node передавай expect». Промпт уточнён — `expect` только
у одного узла.

**3. Вопрос о форме читает каждый узел.** На «какие поля обязательны» модель вызвала
`get_form_node` 11 раз, по разу на поле, хотя правила («validate email: required») уже есть в
затравке хода. Ответ верный, но ход вдвое дороже нужного.

Исправлено (ReFormer-y7y0). Рассуждение модели назвало причину прямо: «The form map doesn't show
the "required" prop directly. I need to check each node». Карта помечала `required` только по
свойству узла, а что поле без пометки необязательно, нигде сказано не было. Теперь карта
помечает обязательность и по правилам — `required` или `required (conditional)` для правила с
условием, — а её заголовок говорит, что пометка есть у всех обязательных полей. Перемер 17.1:
**ни одного вызова, 32 с** вместо 11 вызовов и 122–140 с. Контроль на 1.3, 4.1, 7.4, 8.4 —
без регрессий.

**4. Харнесс.** Первый прогон 22.1 упал по таймауту не из-за ассистента. Карточка вопроса
появлялась в ленте раньше, чем мост заводил ожидание ответа, и синхронный автоответ харнесса
уходил в пустоту. Человек так быстро не отвечает; харнесс теперь отвечает отложенно.

### Пустые ответы gemma: причина и правка (ReFormer-qsm8.11, 2026-10-27)

Пустой ответ gemma — не обрыв: модель выводит токены (`completion_tokens` > 0), а до ассистента не
доходит ни текста, ни вызова. Сырой текст выброшенного вызова Ollama пишет в свой журнал
(`%LOCALAPPDATA%\Ollama\server.log`, строка `gemma4 tool call parsing failed … content=…`). Разбор у
Ollama такой: строки `<|"|>…<|"|>` подменяются заглушками, кавычки ставятся ключам из букв, цифр и
подчёркивания, результат идёт в `json.Unmarshal`. Не вышло — восстановление (одиночные кавычки,
незакрытая строка, недостающая `}` в конце); не вышло и оно — вызов выбрасывается молча.

Причин в журнале две:

- **Ключ объекта не из букв и цифр.** gemma пишет ключи без кавычек, и ключ с `/`, `.`, `-`, `$`
  остаётся без кавычек. Так терялись `set_node_prop` со словарём `edits` (ключ — адрес узла) и
  особый ключ `$disabled`: сценарии 4.1, 7.1 и 20.2 не проходили ни в одном прогоне, а в 7.1 из
  двух параллельных вызовов молча пропадал один. **Исправлено:** `edits` — список `{ ref, props }`,
  особые ключи — `_disabled` и `_newRow`; тест реестра держит перечень словарей в аргументах.
- **Лишняя закрывающая скобка на глубокой вставке.** Визард → шаг → поле одним `insert_node` модель
  записывает верно, кроме одной лишней `]` в конце или в середине. Ключи она пишет по алфавиту
  (`children` раньше `component` и `props`), но дело не в порядке: с вложенным списком, названным
  `subnodes`, ошибка та же. Восстановление Ollama лишнюю скобку не убирает. **Не исправлено:** на
  нашей стороне это лечится только плоской вставкой (родитель — ссылкой, а не вложением), см.
  ReFormer-qsm8.12; 5.4 у gemma поэтому по-прежнему проваливается. _Позже исправлено не плоской
  вставкой, а правилом промпта — визард в два уровня, см. ниже._

### Форма хода — не только активная вкладка (ReFormer-vypu, 2026-10-28)

Ход больше не требует вкладки формы: форму берёт закрепление в «Правит: …», вкладка формы или
файл её модуля, а без них — попытка выбора с `create_form`, `choose_form` и `ask_user`. Замер
получил три сценария строк 21.3–21.4 документа сценариев. В двойнике рабочей области формы
проекта ищет тот же обход, что у плагина:

- **21.3** — анкета клиента, активна вкладка `validation/form.ts`, «Сделай телефон обязательным».
  До правки такой ход уходил в попытку создания (по коду моста; живой моделью это не мерялось).
- **21.4** — вкладок нет, в проекте две пустые формы, «Добавь в форму поле телефона». Ожидается
  `choose_form`; карточку выбора замер отвечает первым вариантом, телефон должен лечь в эту форму.
- **21.4b** — те же две формы, «Сделай новую форму обратной связи…». Ожидается `create_form` без
  карточки выбора.

## Чего замер не говорит

- **Одна модель, один язык, один прогон.** Облачных каналов и английских формулировок в замере
  нет — это оси вариаций документа сценариев, следующий прогон. Разброс между прогонами виден уже
  на 5.3 (38 и 24 вызова), так что число вызовов — порядок, а не точное значение.
- **Режим файлов не мерялся** — только структурный.
- **Качество формы проверяется критерием сценария**, а не человеком: «секция из четырёх полей с
  выбором даты» засчитана без оценки подписей и порядка.
