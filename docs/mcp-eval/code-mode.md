## Что проверяли

Гипотеза: слабая модель собирает форму лучше, если сервер отдаёт не набор инструментов, а один
инструмент `run_script` с API сервера в песочнице (метод
[Code Mode от Cloudflare](https://blog.cloudflare.com/code-mode/)).

|                     | Было — `bare`                       | Стало — `code-mode`                                                                        |
| ------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------ |
| Инструменты сервера | 10 инструментов из `tools/list`     | один `run_script { code }`                                                                 |
| Описание API        | JSON Schema каждого инструмента     | TS-объявление `declare const reformer: {…}` из тех же схем, описания дословно              |
| Инструкции сервера  | `SERVER_INSTRUCTIONS`, 486 символов | `CODE_MODE_INSTRUCTIONS`, 830 символов, с готовыми строками вызова                         |
| Исполнение          | вызов инструмента                   | скрипт в QuickJS-wasm: нет сети, файлов, `require`, таймеров; лимиты памяти, CPU и времени |
| Включение           | —                                   | `REFORMER_SURFACE=code`                                                                    |

Задание у обоих подходов одно и то же. Агент — `ollama`, модель `qwen3.5:4b`, по одному прогону на
сценарий, 11 сценариев лестницы без holdout, L5-credit только на `core`. Матрица —
[code-mode-weak.json](../../packages/reformer-mcp/eval/scenarios/matrices/code-mode-weak.json).

## Что произошло на самом деле

- **Было:** модель редко доходит до основного пути «intent → `form_build`». Она ходит по справочным
  инструментам (`search_docs`, `get_context`, `choose_api`) и `validate_form`, а модуль пишет руками.
  Три прогона из 11 — без единого вызова MCP. Два из них — пустой ответ на первом шаге: модель
  молча закончила работу.
- **Стало:** каждый прогон работает через `run_script` и почти всегда начинает со сборки или
  черновика `planForm`. Чаще всего — цикл «правка intent → `formBuild` → ошибка → правка».
- **Сцепления нет.** Из 73 скриптов ни один не вызвал больше одной функции: слабая модель пишет
  `console.log(await reformer.formBuild({ dir: "form" }))` и всё. Выигрыш даёт не композиция
  вызовов в коде, а единственный инструмент с конкретными строками вызова в инструкции. Это
  смешанный фактор: инструкции `code-mode` конкретнее, и замер их вклад не отделяет.

Ошибки скриптов, 46 из 73:

| Причина                                                                 | Скриптов |
| ----------------------------------------------------------------------- | -------: |
| `formBuild` отверг intent или сборку — обычный цикл исправления         |       32 |
| `TypeError: not a function` — имя в snake_case (`reformer.search_docs`) |        6 |
| `run_script` с пустыми аргументами `{}`                                 |        4 |
| `planForm` с неверным путём спеки                                       |        3 |
| `validateForm` без `target`                                             |        1 |

## Проигрыши

- **L5-registration (0.82 → 0).** Модель выбросила черновик `planForm` и писала intent с нуля:
  ошибок сборки стало меньше (12 → 1 → 5 ошибок типов), но каждая перезапись — 1.3–2 тыс. токенов
  по 4–5 минут на шаг, и 50-минутный лимит кончился до сборки. В `bare` модель собрала черновик
  почти без правок.
- **L1-login (0.50 → 0.33).** Оба прогона без успешной сборки, разница в пробах написанного руками
  модуля.

## Оговорки

- N=1. Разброс qwen3.5:4b велик: в контрольном батче `20261112T163051Z-ad08` (bare ×3) L1-feedback
  набрал 0.8, 0.33 и pass, а здесь — 0.
- Абсолютное качество низкое у обоих подходов: проверку типов (`static.tsc`) не прошли почти все
  прогоны, полностью прошёл 1 из 22.
- Первый прогон L5-credit сорвал сон Mac на батарее (23:50–04:06): у `code-mode` за 2 часа было
  2 шага. Пара перезапущена под `caffeinate`, в таблице — перезапуск. В сорванной попытке `bare`
  до сна набрал 0.33; с ним средний счёт «было» — 0.317.
- Прогоны шли на батарее: генерация около 6 токенов в секунду, длинные сценарии упираются в лимит
  времени.
- `surfaceDigest` в записи снимается без окружения и у обоих подходов показывает классическую
  поверхность; `process.validatedAfterLastWrite` не видит сборок внутри `run_script`. Обе метрики
  из сравнения исключены.

## Как пересобрать отчёт

Таблицы отчёта собираются по снимку в git. Сырьё для этого не нужно, команда работает и после
клона:

```bash
npm run mcp:approaches -- packages/reformer-mcp/eval/runs/approaches/code-mode-weak.json
npm run mcp:approaches -- packages/reformer-mcp/eval/runs/approaches/code-mode-weak.json --sequence
```

`--sequence` добавляет цепочки вызовов MCP по прогонам: на них держится вывод «сцепления нет».

Снимок [code-mode-weak.json](../../packages/reformer-mcp/eval/runs/approaches/code-mode-weak.json)
собран по сырью трёх батчей. Если поменялся сам подсчёт, снимок пересобирается там, где сырьё
осталось (`.tmp/mcp-runs/`, `.tmp/dev-logs/`):

```bash
npm run mcp:approaches -- 20261112T180626Z-8315 20261113T010642Z-594a 20261113T031241Z-45c6 \
  --save packages/reformer-mcp/eval/runs/approaches/code-mode-weak.json
```

Если в батче нет `records.jsonl`, запись собирается из `verify.json`, журнала модели и строки итога
в логе. Когда одна ячейка есть в нескольких батчах, берётся прогон из последнего по порядку
аргументов: так перезапуск L5-credit заменяет сорванный. Таблицу причин ошибок скриптов и разбор
проигрышей скрипт не печатает: их берут из журналов прогонов (`npm run mcp:log -- <батч>`), а
журналы есть только в сырье.
