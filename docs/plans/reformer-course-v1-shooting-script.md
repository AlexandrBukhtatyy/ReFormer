# Видео 1 — сценарий съёмки

Рабочий документ записи. Карта курса и обоснования — в [parallel-tinkering-tarjan.md](parallel-tinkering-tarjan.md).

**Домен:** `trip-quote` — расчёт стоимости страховки путешествия.
**Хронометраж:** 89:00 по блокам ниже. Клапан до 80: убрать аттракцион 2 из блока 2 и сжать блок 4
до двух минут.
**Аудитория:** тимлиды и архитекторы. Не объясняем, что такое React-хук; объясняем, почему граница
проходит здесь, а не там.

**Код пишет агент.** Почти всё, что раньше печаталось в кадре, порождается промптом; листинги ниже —
эталон, с которым сверяется результат. Промпты агент-агностичны: MCP-сервер не подключён, контракт API
несёт `AGENTS.md` репо-компаньона. Правила игры проговариваются один раз в подблоке 2.6.

## Как читать

- **[ЭКРАН]** — что видно, какая сцена OBS
- **[ДЕЙСТВИЕ]** — что делаешь руками
- **[ПРОМПТ]** — текст, уходящий агенту в кадре; в репо лежит файлом `prompts/v1-NN-<slug>.md`
- **[ЭТАЛОН]** — код, который должен получиться; сверяемся с ним, а не печатаем
- **[ПРИЁМКА]** — что обязано совпасть, что вправе отличаться, чем проверяем за пять секунд
- **[ПЕЧАТАЕМ]** — редкий случай: печатается руками, потому что генерация испортила бы демонстрацию
- **[РЕПЛИКА]** — формулировка, которая должна прозвучать близко к тексту (остальное — своими словами)
- **[ЯКОРЬ]** — кадр, ради которого блок существует; если он не получился, блок переснимается
- **[РИСК]** — где вероятен дубль

**Бюджет экранного времени агента.** Промпт плюс ожидание плюс вывод не должны занимать больше, чем
комментарий к результату. Блок, весь смысл которого сводится к «смотрите, сгенерировалось», режется:
курс про библиотеку, а не про агента.

## Перед записью

**Сцены OBS**

| Сцена | Источники |
| --- | --- |
| `EDITOR` | VS Code на весь экран |
| `SPLIT` | VS Code слева 60% + браузер справа 40% |
| `TERM` | терминал крупно (для `git diff`, `npm test`, `npm run size`) |
| `BROWSER` | браузер на весь экран (для Profiler) |
| `SLIDE` | статичная картинка (карта пакетов, таблица бюджетов) |

**Настройки, которые правятся один раз и больше не трогаются**

- Разрешение записи **1440p**, шрифт в VS Code **18–20 px**, в терминале **16–18 px**. Проверить
  читаемость, уменьшив окно предпросмотра до размера телефона.
- Скрыть: миникарту, breadcrumbs, панель Git, все уведомления. `Zen Mode` не использовать — нужна
  видимая структура файлов.
- Тема — светлая. Тёмная на YouTube после сжатия даёт больше артефактов на тонком шрифте.
- **Отключить inline-автодополнение ИИ** (Copilot и подобные). Всплывающая подсказка, дописывающая
  строку за тебя, ломает тезис «смотрите, сколько кода на самом деле нужно», и её невозможно показать
  зрителю как воспроизводимый шаг. Запрет касается именно inline-подсказок: осознанный вызов агента с
  зафиксированным промптом — наоборот, предмет демонстрации, и он идёт в отдельной панели.

**Заготовки до старта записи**

1. Репо-компаньон склонирован, все теги на месте, `npm ci` прогрет (не ждать установку в кадре).
2. Вкладки браузера открыты заранее: `localhost:5173`, React DevTools установлен и проверен.
3. Финальная форма из тега `v1-11` открыта в отдельной вкладке — нужна для интро.
4. Файл `docs/steps.json` открыт в редакторе — из него зачитываются тайм-коды в описание ролика.
5. **Агент открыт в отдельной панели, сессия чистая** (без истории предыдущих дублей — она незаметно
   чинит плохой промпт и делает результат невоспроизводимым у зрителя). `AGENTS.md` лежит в корне и
   подхвачен, `src/forms/trip-quote/spec.md` — на месте (на теге `v1-02` это единственный файл в
   директории формы). Каталог `prompts/` открыт — из него промпты копируются в кадре, а не
   набираются по памяти.
6. **Прогон промптов сделан заранее**, `prompts/PASSRATE.md` заполнен. Промпт с проходимостью ниже
   двух из трёх до записи не допускается.

### 2.7 Первый промпт: навигация между стендами (18:00 – 19:00)

**[РЕПЛИКА — постановка]** «Чтобы правила не остались теорией, отправим первый промпт прямо сейчас.
Он намеренно самый скучный в курсе: к ReFormer отношения не имеет, зато проверяется за две секунды —
и вы увидите весь ритм, по которому мы пойдём дальше».

**[ПРОМПТ]** `prompts/v1-02-nav.md`:

```
Нужна навигация между стендами курса, чтобы дальше просто добавлять страницы.

В App.tsx — переключение по хешу адреса: одна константа со списком
{ путь, заголовок, компонент }, шапка со ссылками и рендер текущей страницы.
Неизвестный хеш — на первую страницу.

Роутер не ставь. React Router сюда не тащи: курс про формы, и лишняя
зависимость смазывает картину того, что для ReFormer реально нужно.

Пока в списке одна запись-заглушка. Дальше я буду добавлять по строке
на каждый шаг: модель, форма на ui-kit, два рендерера, профилировщик.
```

**[РЕПЛИКА]** «Обратите внимание на середину. Запрет там нужен, потому что «сделай навигацию» модель
почти всегда понимает как «поставь React Router»: так написано в девяноста процентах проектов, на
которых её учили. Это второй тип содержимого промпта — не «как надо», а «чего не делай». Дальше
такие абзацы будут в каждом втором».

**[ЭТАЛОН]** `src/App.tsx`:

```tsx
const PAGES = [
  { path: 'model', title: 'Модель', Component: ModelPage },
  // …сюда добавляется по строке на каждом шаге курса
] as const;

export default function App() {
  const [hash, setHash] = useState(() => location.hash.slice(1));

  useEffect(() => {
    const onHash = () => setHash(location.hash.slice(1));
    window.addEventListener('hashchange', onHash);
    return () => window.removeEventListener('hashchange', onHash);
  }, []);

  const page = PAGES.find((p) => p.path === hash) ?? PAGES[0];

  return (
    <>
      <nav className="flex gap-4 border-b p-4">
        {PAGES.map((p) => (
          <a key={p.path} href={`#${p.path}`}
             className={p.path === page.path ? 'font-bold' : ''}>{p.title}</a>
        ))}
      </nav>
      <main className="p-6"><page.Component /></main>
    </>
  );
}
```

import { effect } from "@reformer/core/signals";
import { createEmptyTraveler, createInitialTripQuote, createTripQuoteModel } from "./model";

describe("createTripQuoteModel", () => {
  it("стартует со снимка initial", () => {
    const model = createTripQuoteModel();

    expect(model.get()).toEqual(createInitialTripQuote());
    expect(model.isDirty()).toBe(false);
    expect(model.tripType).toBe("domestic");
    expect(model.coverage).toBe(30_000);
    expect(model.travelers.length).toBe(0);
  });

  it("set / get / patch", () => {
    const model = createTripQuoteModel();

    // value-запись отдельного поля
    model.tripType = "international";
    expect(model.get().tripType).toBe("international");

    // patch — частичное слияние, остальные ключи не трогаются
    model.patch({ country: "Италия", coverage: 50_000 });
    expect(model.get()).toMatchObject({
      tripType: "international",
      country: "Италия",
      coverage: 50_000,
      email: "",
    });

      ...createInitialTripQuote(),
      country: "Испания",
      email: "a@b.c",
      agree: true,
    };
    model.set(full);
    expect(model.get()).toEqual(full);
    expect(model.get().tripType).toBe("domestic"); // перетёрто значением из set
  });

  it("isDirty → true после правки, false после reset", () => {
    const model = createTripQuoteModel();
    expect(model.isDirty()).toBe(false);

    model.email = "traveler@example.com";
    expect(model.isDirty()).toBe(true);

    expect(model.isDirty()).toBe(false);
    expect(model.get()).toEqual(createInitialTripQuote());

    model.patch({ coverage: 100_000 });
    expect(model.isDirty()).toBe(true);

    // captureInitial переносит точку отсчёта на текущие значения
    model.captureInitial();
    expect(model.isDirty()).toBe(false);
    model.reset();
    expect(model.get().coverage).toBe(100_000);
  });

  it("массив: push / at(i).field / removeAt / реактивная length", () => {
    const model = createTripQuoteModel();
    const lengths: number[] = [];
    const stopLength = effect(() => {
      lengths.push(model.travelers.length);
    });

    model.travelers.push({ lastName: "Петров", birthDate: "1990-01-01", age: 35 });
    expect(model.travelers.length).toBe(2);

    // правка поля элемента через под-модель

    expect(model.travelers.at(0).lastName).toBe("Иванов");
    expect(model.travelers.at(0).get()).toEqual({
      lastName: "Иванов",
      birthDate: "",
      age: 0,

    expect(model.get().travelers).toEqual([
      { lastName: "Иванов", birthDate: "", age: 0 },

    ]);

    expect(model.$.email).toBe(model.signalAt("email"));
    expect(model.$.email.__path).toBe("email");

    // сигнал и value-доступ — две стороны одного узла
    model.email = "a@b.c";
    expect(model.$.email.value).toBe("a@b.c");
    model.$.email.value = "c@d.e";
    expect(model.email).toBe("c@d.e");

    // элементы массива: под-модель отдаёт тот же сигнал, что и корневое дерево

**[ЭТАЛОН]** `form.behavior.ts`:

```ts
import { defineFormBehavior, compute, enableWhen, applyEach, onChange } from '@reformer/core/behaviors';

const travelerBehavior = defineFormBehavior<Traveler>(({ model: t }) => {
  compute(t.$.age, () => yearsSince(t.birthDate));
});

export const tripQuoteBehavior = defineFormBehavior<TripQuote>(({ model, form }) => {
  compute(model.$.days,        () => daysBetween(model.startDate, model.endDate));
  compute(model.$.pricePerDay, () => basePrice(model.tripType, model.coverage, model.riskySport));
  compute(model.$.total,       () => model.pricePerDay * model.days * model.travelers.length);

  applyEach(model.travelers, travelerBehavior);

  enableWhen(model.$.country,   () => model.tripType === 'international', { resetOnDisable: true });
  enableWhen(model.$.sportKind, () => model.riskySport,                   { resetOnDisable: true });

  onChange(model.$.tripType, (t) =>
    form.coverage.updateComponentProps({ min: t === 'international' ? 50_000 : 30_000 })
  );
});
```

**[РЕПЛИКА]** про `compute`: «Зависимости не перечислены. Их не надо перечислять — они выводятся из
того, что функция реально прочитала. Это autotracking, и он же даст нам точечные ре-рендеры в конце».

**[РЕПЛИКА]** про `resetOnDisable`: «По умолчанию `false`. Выключить поле и обнулить поле — разные
намерения, и библиотека отказывается угадывать, какое ваше».

```ts
import { defineValidationSchema, validate, validateAsync, validateWhen, cross, each }
  from '@reformer/core/validation';
import { required, email, min, minLength, pastDate, futureDate } from '@reformer/core/validators';

export const tripQuoteValidation = defineValidationSchema<TripQuote>(({ model }) => {
  validate(model.$.tripType,  [required()]);
  validate(model.$.startDate, [required(), futureDate()]);
  validate(model.$.endDate,   [required()]);
  validate(model.$.coverage,  [required(), min(30_000)]);
  validate(model.$.email,     [required(), email()]);

  validateWhen(() => model.tripType === 'international', () => {
    validate(model.$.country,  [required()]);
    validate(model.$.coverage, [min(50_000, { message: 'Для Шенгена минимум 50 000 €' })]);
  });

  validateWhen(() => model.riskySport, () => validate(model.$.sportKind, [required()]));

  cross(model.$.endDate, (f) =>
    f.endDate <= f.startDate ? { code: 'range', message: 'Дата возврата раньше выезда' } : null);
  cross(model.$.days, (f) =>
    f.days > 90 ? { code: 'tooLong', message: 'Один полис — максимум 90 дней' } : null);

  each(model.travelers, (t) => {
    validate(t.$.lastName,  [required(), minLength(2)]);
    validate(t.$.birthDate, [required(), pastDate()]);
  });

  validateAsync(model.$.email, [checkEmailNotBlacklisted]);
});
```

Проговорить три вещи:

- `validateWhen` — целая ветка правил включается условием, а не `if` внутри каждого валидатора.
- `cross` — правило видит **снимок всей формы**, а вешается на конкретное поле: ошибка приедет туда,
  где пользователь может её исправить.
- `each` — правила на строку массива объявляются один раз.

**[РЕПЛИКА]** «Двадцать пять строк — вся валидация формы. И ни одна из них не знает про UI».

**[ПРИЁМКА]** Обязано: `defineValidationSchema` отдельным файлом; условные ветки через `validateWhen`,

валидаторы взяты готовые, а не написаны заново. Вправе отличаться: тексты сообщений, порядок правил.
Проверка: `grep -n "validators" form.schema.ts` в блоке 7 должен быть пустым — но это позже.

**[РИСК]** Самая частая ошибка агента на этом шаге — положить валидаторы в схему поля вместо

## Приложение B · Ловушки, на которых легко сбиться в кадре

1. **`apply` — это две разные функции.** В `behaviors` — `apply(targets, subSchema)`, применяет
   под-схему поведения к группам. В `validation` — `apply(...schemas)`, вариадический, склеивает
   схемы валидации. Имя одно, семантика разная.
2. **`aggregateInto(array, derive)` не «сворачивает массив в поле».** Его `derive` возвращает
   `Array<{ index, patch }>` — то есть он **патчит строки**. Для суммы по массиву нужен обычный
   `compute`. В V1 не используется; в V2 не перепутать.
3. **Стратегия валидации по умолчанию — `submit`.** Форма реактивно молчит до отправки. Если в кадре
   ожидается живая подсветка ошибок — стратегию надо задать явно.
4. **`onInit` из renderer-react вызывает колбэк немедленно**, а не после монтирования. Для
   post-mount есть отдельный хук.
5. **`validation` в бандле опционально** (`validation?: FormValidationBundle<T>`) — в коде будет
   `validation!.validateAll()`. Не удивляться восклицательному знаку в кадре и не «чинить» его.
6. **Не создавать две формы над одной моделью.** Реестр «сигнал → нода» глобальный: вторая
   регистрация затирает первую, и `enableWhen` с роутингом ошибок начнут работать только у последней
   формы. Страница сравнения — на трёх независимых экземплярах модели.

## Приложение C · Чего не говорить

- Не называть числа производительности в сравнении с RHF/Formik — их нет.
- Не называть renderer-варианты «более коротким кодом»: слой рендера в них **не меньше**, он плоский
  и декларативный. Короче становится точка входа, а не схема.
- Не обещать, что UI-Builder работает в любом браузере — только Chromium.
- Не говорить «агент написал форму». Агент написал файлы по промптам, которые написал я; думать всё
  ещё пришлось человеку. Формулировка «код печатал не я» — честная, «форму сделал ИИ» — нет.
- Не сравнивать агентов между собой и не называть конкретную модель лучшей. Промпты агент-агностичны,
  и это единственное утверждение, которое мы можем подкрепить.

## Приложение E · `spec.md` целиком

Лежит в `src/forms/trip-quote/spec.md` и на теге `v1-02` является единственным файлом директории.
Показывается в кадре в §2.6, дальше на него ссылается каждый промпт, который трогает числа.

Всё, что здесь зафиксировано, проверяется тестами блоков 4 и 6 — менять числа, не переписав тесты,
нельзя.

````markdown
# trip-quote — страховка путешествия

Требования к форме. Единственный источник чисел: код и тесты берут константы отсюда и
ничего не выдумывают.

## Поля

**Вводит пользователь:** тип поездки, страна (только для международной), даты выезда и
возврата, покрытие, признак опасного спорта, вид спорта (только при признаке), список
путешественников (фамилия + дата рождения), email, согласие с условиями.

**Считается само:** длительность поездки в днях, возраст каждого путешественника, цена
за день, итоговая стоимость.

## Справочники

| Справочник  | Значения                                        |
| ----------- | ----------------------------------------------- |
| Тип поездки | внутренняя, международная                       |
| Покрытие, € | 30 000, 50 000, 100 000                         |
| Страны      | Италия, Испания, Франция, Германия, Турция      |
| Виды спорта | горные лыжи, дайвинг, альпинизм, сёрфинг        |

## Формулы

**Длительность.** Разница между датой возврата и датой выезда в календарных днях. День
выезда считается, день возврата — нет: поездка с 1 по 15 июня это **14 дней, не 15**.
Если хотя бы одна дата не заполнена — 0.

**Возраст.** Полных лет **на дату выезда**, а не на сегодня: иначе тесты начинают зависеть
от даты прогона. Если дата выезда или дата рождения не заполнена — 0.

**Цена за день, €** — произведение трёх множителей:

| Множитель                   | Значение |
| --------------------------- | -------- |
| База, внутренняя поездка    | 1.20     |
| База, международная поездка | 2.50     |
| Покрытие 30 000 €           | × 1.0    |
| Покрытие 50 000 €           | × 1.4    |
| Покрытие 100 000 €          | × 2.0    |
| Опасный спорт               | × 2.0    |

Результат округляется до цента.

**Итог.** Цена за день × длительность × количество путешественников, округление до цента.
Пустой список путешественников даёт итог 0.

## Правила

| Правило                            | Значение                                            |
| ---------------------------------- | --------------------------------------------------- |
| Минимальное покрытие               | 30 000 €                                             |
| Минимальное покрытие, международная| 50 000 € · «Для Шенгена минимум 50 000 €»            |
| Максимальный срок полиса           | 90 дней · «Один полис — максимум 90 дней»            |
| Дата выезда                        | в будущем                                            |
| Дата возврата                      | строго позже выезда · «Дата возврата раньше выезда»  |
| Дата рождения                      | в прошлом                                            |
| Фамилия                            | минимум 2 символа                                    |
| Страна                             | обязательна для международной поездки                |
| Вид спорта                         | обязателен при опасном спорте                        |
| email                              | формат адреса + проверка по списку                   |

**Проверка email** имитируется локально, без сети: задержка 300 мс и фиксированный список
запрещённых адресов (`spam@`, `blocked@`). Сервера в курсе нет и не будет.

**Даты в тестах валидации — относительные** (сегодня плюс-минус N дней), не литералы.
Литеральная дата в паре с проверкой «дата в будущем» протухает: прогон, зелёный в день
записи, покраснеет у зрителя через полгода. Тесты поведения валидацию не запускают —
там литералы допустимы и читаются лучше.

## Начальные значения

Тип поездки — внутренняя, покрытие — 30 000 €, опасного спорта нет, список путешественников
пуст, остальные поля пустые. Вычисляемые поля стартуют нулями: их значение появляется
из поведения, а не из начального снимка.
````

**Три места, ради которых спека вообще существует** — без них агент даёт правдоподобный и неверный
результат, а тест краснеет в кадре:

1. **Длительность считается разностью, а не включительно.** Естественное «поездка с 1 по 15 — это
   15 дней» ломает `expect(model.days).toBe(14)` в блоке 6.
2. **Возраст считается на дату выезда, а не на сегодня.** `new Date()` внутри `compute` — первое, к
   чему тянется рука, и тест начинает зависеть от дня прогона.
3. **Коэффициенты покрытия — таблица, а не деление.** «Поделить покрытие на 30 000» выглядит
   разумнее, но даёт дробь, и `total` перестаёт совпадать с ожиданием в тесте.
