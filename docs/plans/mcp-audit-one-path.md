# План: аудит и выправление MCP-сервера и его веб-версии — формы любой сложности в терминале и в ассистенте билдера

## Context

**Запрос.** Пользователь видит «неразбериху»: MCP-сервер `@reformer/mcp` и его веб-версия (Web Worker
в билдере) «работают криво». Нужен качественный аудит и максимально корректная работа. Цель —
создавать формы любой сложности: простая → валидация → поведение → массивы и визард → форма по
спеке. Два канала: агент в терминале и ИИ-ассистент ui-builder.

**Как проводился аудит:**
- три независимых обхода кода: stdio-сервер, веб-канал вместе с ассистентом, состояние замеров и
  прошлых планов;
- живые вызовы собранного сервера — `form_build` (грамматика), `plan_form`, `generate_form`,
  `find_recipe`, `choose_api`, `get_context`, `validate_form`.

**Корень проблемы — не один баг, а четыре системных:**
1. **Агенту даны три несовместимых пути создать форму.** Описания инструментов, промпты и справка
   указывают на разные пути.
2. **Части intent теряются молча.** Так происходит и в `form_build`, и в `build_form` ассистента:
   сборка отвечает ✓, но часть формы пропала.
3. **Сервер зависит от окружения.** Пакеты `@reformer/*` не отдают `./package.json`, поэтому вне
   монорепо справка пуста, а проверка импортов ложно бракует собственный код генератора. Из-за
   этого испорчены и замеры: ночной прогон Ollama 2026-11-04 признан недействительным целиком.
4. **В браузере три отдельно собранные копии MCP.** У них две грамматики intent, два прохода
   нормализации, разные словари ошибок и нет сверки версий.

**Решения пользователя (зафиксированы):**
- **Терминал — только `form_build`.**
  - `generate_form` уходит из списка инструментов и остаётся внутренним. **Изменено 2026-11-11:**
    по решению пользователя удалён сразу в 7.0 вместе с псевдонимами `validate_json_schema` и
    `check_behaviors` (ReFormer-11oe.9); генератор живёт внутри `form_build`.
  - `plan_form` делает только «спека → черновик `form.intent.json`».
  - Промпты переписываются вокруг intent.
  - Это мажорная версия `@reformer/mcp` 7.0.
- **Ассистент — один язык intent.**
  - Грамматику для профиля `builder`, разбор и кросс-проверку даёт MCP.
  - `build_form` только переносит intent в документ.
  - Всё, что документ не держит, получает явный отказ с подсказкой.
- **Воркер — справочный канал.**
  - `plan_form` и `generate_form` из профиля воркера убраны (сделано в 7.0, ReFormer-11oe.9).
  - Тексты инструментов зависят от профиля.
  - Корпус собирается один раз, у копий есть сверка версий.
- **Модели приёмки:**
  - Claude Code в терминале;
  - локальная модель в терминале (адаптер Ollama стенда `mcp:scenarios`);
  - локальная модель в ассистенте (openai-compatible).

  Облачные модели в ассистенте в приёмку не входят. Локальные — двух классов: ~27B
  (qwen3.8:27b, gemma4:26b) с порогом на L1–L4 и малые 4–8B (qwen3.5:4b) с порогом на L1–L3;
  остальные уровни у локальных моделей — отчётом.
- **Язык текстов для модели — английский.** Это грамматика intent, описания инструментов и
  диагностика `form_build`/`build_form`. Тексты форм (подписи, сообщения) остаются на языке
  пользователя. Справочные рецепты `docs/llms` остаются русскими — это решение их не касается.
  Человеку интерфейс ассистента показывает свой локализованный текст (lhvk.7).

## Принципы

- **Один путь.**
  - Форму создаёт только intent → `form_build` в терминале и intent → `build_form` в ассистенте.
  - Язык intent, грамматика, разбор (`readIntent`) и судья (`judgeIntent`) — одни на оба канала.
  - Каналы отличаются только профилем: `module` — модуль на диске, `document` — документ билдера.
- **Без молчаливых потерь.**
  - Каждый ключ intent либо потреблён, либо поднят на место с заметкой, либо назван в проблеме
    с подсказкой.
  - ✓ значит, что собрана вся форма.
- **Ошибка окружения ≠ ошибка intent.** Нет пакета, индекса или компилятора — это отдельный
  диагноз со своей починкой. Он никогда не превращается в «правь intent» или RF002 на код
  генератора.
- **Тексты под профиль.** Ни один текст не называет инструмент, которого в этом канале нет.
- **Потолки размера.** Размер грамматики, guide и ответов держат тесты: малые локальные модели
  — полноправные потребители.
- **«Работает» решает замер.** Одна лестница L1–L5 и один верификатор на оба канала.

### Фаза 1. Окружение

- **Поиск пакетов.** Новый `M/src/platform/cli/package-locator.ts`, функция
  `locatePackage(pkg, bases)`.
  - Базы: каталог формы, cwd, `REFORMER_TYPECHECK_ROOT`, место самого сервера.
  - Сначала подъём по `node_modules/<pkg>/package.json` через fs, в обход exports. Затем
    `import.meta.resolve` и подъём до `package.json` с тем же `name`.
  - Монорепо — через `workspaces` корня, без зашитого пути.
  - На него переходят `docs-source.ts`, `index-source.ts` (битый JSON → следующий кандидат),
    `recipe-source.ts`, `symbols-parser.ts`.
  - `ui-kit-catalog.ts` и `ui-kit-props.ts` берут один корень, свойства сверяются по `propsSchema`
    каталога (zjqy).
- **`./package.json` в exports шести библиотечных пакетов** — отдельными коммитами
  `fix(<pkg>)`. Locator на это не опирается.
- **Видимость сбоев.**
  - Проглоченные `catch` собираются в список `KnowledgeProblem`.
  - Новый ресурс `reformer://status` в обоих профилях: найденные пакеты и версии, индексы,
    доступность проверки типов, buildId.
- **Кэш знания** (`cli/knowledge.ts:36`, `generate/catalogs.ts:33`) — с ключом по mtime артефактов,
  без перезапуска сервера.
- **Проверка типов** (`cli/form-workspace.ts`).
  - Корень — проект каталога формы, а не cwd сервера.
  - tsconfig проекта читается через `ts.parseJsonConfigFileContent`.
  - Оверлей в памяти через CompilerHost.
  - Резолв проверяется у всех импортируемых `@reformer/*`.
  - Один `Program` на серию вызовов (`oldProgram`).
- **Детектор проекта.** Корень с `workspaces` проектом не считается.
- **Стенд.**
  - Fingerprint записи читает `reformer://status`.
  - `scenarios/run.mjs` не стартует батч, если сервер не видит core/cdk/ui-kit (qo9b.34).
- **Тесты.**
  - Фикстуры пакетов с exports только на `import`.
  - «Нет индексов» → ошибка окружения без RF002 на код генератора (j356.9).
  - gf9a: `vitest.config.ts` с построчным репортером и один компилятор на файл.
  - Страж в `test-preconditions.test.ts` ловит тернарий `describe.skip`.
- **Приёмка.**
  - Из проекта вне репо и из снимка сервера `reformer://status` показывает все шесть пакетов.
  - `npm test -w @reformer/mcp` проходит в лимит сторожа.
  - Под `REFORMER_TEST_STRICT=1` нет пропусков.

### Фаза 2. Один путь в CLI — `@reformer/mcp` 7.0

- **Инструменты профиля node** (`M/src/core/server/tool-catalog.ts`): `get_context`, `choose_api`,
