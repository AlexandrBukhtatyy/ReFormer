# План видеокурса по ReFormer

## Context

Нужно записать серию видео, показывающую ReFormer «от нуля до продакшена»: от `npm create vite` до
использования UI-Builder в готовом проекте. Исходный набросок — 14 пунктов в одном ролике.

Разведка по монорепо показала три вещи, которые меняют структуру:

1. **14 пунктов — это 2–2.5 часа.** В один ролик не влезает даже при плотной подаче.
2. **Два пункта — самостоятельные продукты, а не шаги пути.** `@reformer/form-registry` — это
   микрофронты (`register()` в одном бандле → `<FormOutlet id="…"/>` в другом), а не «реестр
   компонентов»; UI-Builder — офлайн-SPA на `npx reformer-builder` c DnD, live-исполнением твоих
   `.ts`, BYOK-AI-агентом на 13 инструментов и codegen из 12 файлов. Каждый тянет на свой ролик.
3. **Пункт «замеры производительности» нечем подкрепить.** Микробенчмарков и сравнений с
   RHF/Formik в репо нет — есть только e2e-конвейер метрик и `.size-limit.json` (бюджеты, не
   замеры). Обещание «замерим производительность» придётся либо не выполнить, либо выдумать цифры.

**Решения, принятые с пользователем:** 2 больших видео по 60–90 мин + 3 ролика-спутника;
аудитория — тимлиды и архитекторы; код показывается через репозиторий-компаньон с git-тегами;
**код не печатается в кадре, а порождается промптами** — агент-агностичными, без MCP, живьём с
монтажной склейкой (раздел «Промпты как артефакт репо»).

**Итог:** курс из 5 роликов и публичный репо `reformer-course` с 21 аннотированным тегом на одной
линейной ветке, где `git checkout <tag> && npm ci && npm run dev` работает в любой точке.

## Что изменилось относительно исходного наброска

| Пункт наброска | Что с ним стало | Почему |
| --- | --- | --- |
| Инициализация + установка зависимостей | Слиты в один блок, скучная часть — в тег `v1-02` | Tailwind v4 + tsconfig вживую = 8 минут мёртвого эфира |
| Первая модель / демонстрация / тесты | Без изменений, это ядро видео 1 | — |
| Первая форма на чистом TS + тестирование без UI | **Усилено до центрального аргумента видео** | Главный довод для тимлида: бизнес-правила формы тестируются в node без jsdom |
| React + ui-kit → renderer → renderer-json | Без изменений, но доказательство переносится **в структуру репо и в diff** | `git diff --stat v1-07 v1-08` — сильнее любых слов |
| Установка и демонстрация form-registry | **Вынесено в спутник S2** | Микрофронты — другая постановка задачи (два бандла, host+remote, права, фиче-флаги) |
| Демонстрация в браузере + замеры производительности | **Переформулировано:** точечность обновлений через React DevTools Profiler + собственный `size-limit` | Бенчмарков нет; механизм показать честнее, чем цифры |
| Демонстрация UI-Builder | **Вынесено в спутник S1** | 25–30 мин собственного материала |
| Итог: архитектура и пакеты | **Раздвоено:** карта на 3 минуты в начале + разбор в конце | Без карты в начале зритель не понимает, зачем core ставится отдельно от ui-kit |
| — | **Добавлен спутник S3 про MCP-сервер** | Решение пользователя; естественно ложится рядом с UI-Builder как «AI-этаж» |

**Не путать два разных «реестра».** `defineRegistry` из `@reformer/renderer-json` — реестр
компонентов для JSON-схемы, показывается в видео 1 шаг 9. `@reformer/form-registry` — реестр
**форм** для микрофронтов, спутник S2. На видео это надо развести явно, иначе путаница гарантирована.

это работает, но это цена, и в финале V1 она проговаривается вслух. S3 отвечает ровно на возникший у
зрителя вопрос: как эту цену не платить. V1 ставит задачу, S3 её закрывает.

### Блок 2 — три аттракциона (ломается руками, не промптом)

Это три самых частых провала установки; каждый экономит зрителю час.

1. **`moduleResolution` (~40 с).** Поставить `node10` → `import { required } from '@reformer/core/validators/required'` даёт TS2307, при этом `npm run dev` работает. Мораль: пакеты ESM-only с subpath-exports; рантайм молчит, ломается только типизация.
2. **`layer(theme)` (~30 с).** `@import '@reformer/ui-kit/styles' layer(theme);` → сломанная тёмная тема (`@custom-variant` не работает). Импорт обязан быть голым.
3. **Забытый `@source` (~60 с).** Убрать `@source '../node_modules/@reformer/ui-kit/dist'` → компоненты без стилей. Tailwind v4 сканирует исходники и в `node_modules` по умолчанию не смотрит.

### Блок 5 — почему форма без React вообще возможна

Проверено по коду: `schema?: FormSchemaNode` опциональна
([create-form.ts:43](packages/reformer/src/form/create-form.ts#L43), ветка
[:230](packages/reformer/src/form/create-form.ts#L230)), узел признаётся полем по
`node.value instanceof Signal`, а `component?: ElementType` несёт доккомментарий «Опционален:
core-часть работает без UI» ([schema-node.ts:73-76](packages/reformer/src/form/types/schema-node.ts#L73-L76)).
Эталон — [web-scenarios.test.ts](packages/reformer/tests/behaviors/web-scenarios.test.ts), где
`createForm<F>({ model, behavior })` вызывается без схемы 14 раз подряд.

Поэтому `headless.ts` — это `createCoreForm({ model, behavior, validation })` **без схемы вообще**.
Никаких `() => null`-заглушек: заглушка была бы React-компонентом и формально сломала бы тезис.

Отступление на 20 секунд стоит проговорить: если нужна материализация top-level массива в
`ModelArrayNode`, минимальный узел без `component` тип разрешает — но в `headless.ts` его не тащим.

### Блок 10 — что показываем вместо бенчмарков

Сначала механизм (30 с, открыть на экране): `useSignalSubscription` подписывается через
`useSyncExternalStore` на сигналы конкретной ноды; `FormField` обёрнут в `React.memo` по ссылке
`control` ([form-field.tsx:138](packages/reformer-ui-kit/src/components/form-field/form-field.tsx#L138));
`useFormBundle` — ленивый `useState`, а не `useMemo`, поэтому React не вправе потерять форму.

Затем стенд `/profiler?rows=50` (150 полей в массиве + 12 верхнеуровневых):

- **A.** Highlight updates ON, печать в `travelers[7].lastName` → мигает одна рамка.
- **B.** Печать в `startDate` → мигают ровно `startDate`, `days`, `pricePerDay`, `total`.
  Реплика: *набор ре-рендеров равен транзитивному замыканию `compute`-графа, и я не написал ни
  одного `useMemo`.*
- **C.** Контрольная группа `/profiler-usestate`: те же 150 инпутов в одном `useState` → коммитятся все.
- **D.** `RenderCounter` — счётчик рендеров прямо на странице, чтобы аргумент пережил видеокодек.

**Обязательная оговорка на камеру:** это сравнение механизмов, а не бенчмарк против RHF. React
Hook Form решает ту же задачу через uncontrolled inputs и соседей тоже не ре-рендерит. Разница в
том, что здесь свойство бесплатно распространяется на **вычисляемые** поля и условную доступность —
туда, где в RHF появляются `watch()` и ручные подписки.

Плюс `npm run size` на собственных точках входа курса — реальные, воспроизводимые зрителем числа
«сколько стоит перейти с ui-kit на renderer-json». Бюджеты библиотеки (`.size-limit.json`, 27
записей) идут слайдом: ядро 21 kB, рендерер 10 kB, `state` 2 kB, 27 валидаторов 5 kB, 12 операторов
behaviors 5 kB; 11 тяжёлых библиотек вынесены за barrel и стоят 0 до импорта своего subpath.
Формулировать как **бюджеты в CI**, а не как замеры.

## Спутники

**S1 · UI-Builder (25–30 мин).** `npx reformer-builder` — офлайн-SPA, **только Chromium** (File
System Access API). Сюжет: открыть папку курса → билдер сам находит `renderer.schema.json` из тега
`v1-09` → собрать поле мышкой → три режима превью (wire / runtime / code) → live-режим, исполняющий
реальные `.ts` формы → AI-агент правит форму («поставь имя и фамилию в одну строку»), причём модель
**не пишет JSON**, а вызывает 13 типизированных инструментов редактора → round-trip сохранение с
diff и детектом внешних правок → HMR в dev-сервере курса. Финал — codegen 12 файлов.
Требуется свой API-ключ (BYOK) — сказать явно.

**S2 · form-registry (20–25 мин).** Два бандла: remote регистрирует `FormEntry`, host монтирует
`<FormOutlet id="credit-application" />`, ничего не зная о форме. Права, фиче-флаги, загрузка JSON-схем
по сети с кэшем, preflight схемы против модели, guard от двойной загрузки ядра. Эталон —
[complex-multy-step-form-registry/](projects/react-playground/src/pages/examples/complex-multy-step-form-registry/),
где страница ужимается до 29 строк.

**S3 · MCP-сервер (15–20 мин).** `claude mcp add --transport stdio reformer -- npx @reformer/mcp`.
8 инструментов, 11 промптов, 81 рецепт в `docs/llms/`. Сюжет: агент без MCP выдумывает API → тот же
запрос с MCP: `find_recipe` → `get_symbol_docs` → пишет форму → `check_behaviors` ловит цикл →
`validate_json_schema` ловит опечатку `$component(Selct)`. Тезис общий с S1: **давать инструменты
вместо свободного текста**.

## Промпты как артефакт репо

**Решение, принятое с пользователем:** код в V1 и V2 не печатается в кадре, а порождается промптами.
Листинги в сценариях остаются как эталон, рядом появляются `[ПРОМПТ]` и `[ПРИЁМКА]`. Домен —
декорация; демонстрируется библиотека.

Почему это усиливает курс, а не разбавляет его:

- **Якорь блока 8 становится доказательством.** `git diff --stat v1-07 v1-08` доказывал «я аккуратно
  не трогал `model.ts`». Промпт «перенеси слой рендера, бизнес-логику не трогай» **не перечисляет**
  файлов — значит, диффом проверяется архитектура, а не человеческая аккуратность. Ровно тот же приём
  в блоке 9.
- **Порядок блоков V1 совпадает с каноническим workflow библиотеки** — модель → схема → сборка →
  валидация → поведение → массивы → рендер,
  [05-m1-workflow.md](packages/reformer-mcp/docs/llms/05-m1-workflow.md) §1–7. Слои разделены так, что
  каждый генерируется и проверяется отдельно; это и есть содержание курса.
- **Самое ценное в промптах — предупреждения о ловушках**, а не описания задач: `aggregateInto` не для
  сумм, `resetOnDisable` не угадывается, устаревший ответ надо выбрасывать. Список этих ловушек уже
  есть в сценариях; промпты — тот же список, повёрнутый к агенту.

**Агент-агностик, без MCP.** Промпты не вызывают `find_recipe`/`get_symbol_docs` и работают в любом
агенте, читающем контекст-файл. Единственное исключение — ручной прогон `check_behaviors` (V1 §5.1,
V2 §3.1): это инструмент проверки, а не канал генерации, и он помечен оговоркой в обоих сценариях.
Побочный эффект решения: V1 становится завязкой S3, а не его пересказом — цену ручного `AGENTS.md`
зритель видит своими глазами, а S3 показывает, как её не платить.

**Три файла в репо-компаньоне:**

| Файл | Содержание |
| --- | --- |
| `AGENTS.md` | Инвариант контракта: стек и версии, импорты только из subpath'ов, разделение слоёв (валидаторов в схеме нет), `useFormBundle` вместо `useMemo`, `value: model.$.field`, layout каталогов, соглашение `testId`, несуществующие формы API |
| `src/forms/<форма>/spec.md` | ТЗ формы: состав полей, числа и формулы. `trip-quote` — цена, коэффициенты, порог 50 000 €, лимит 90 дней; `auto-loan` — аннуитет, ставка, пороги. **Лежит в директории формы, а не в корне** — модуль носит свои требования с собой, и агенту достаточно сказать «в этой папке». На теге `v1-02` это единственный файл в директории |
| `prompts/v{1,2}-NN-<slug>.md` | Задача блока, 6–15 строк — чтобы читалось в кадре на 18–20 px |

`spec.md` закрывает главный риск живой съёмки: тесты проверяют точные числа (`model.days === 14`,
`loanAmount === 1_500_000`), и если формулу придумывает модель, `npm test` краснеет в кадре. Порядок
внутри тега — **сначала реализация, потом тесты**: обратный заставил бы агента подгонять реализацию
под собственные выдуманные числа.

**Ловушки для промптов не выдумываются с нуля** — они уже описаны в планах монорепо, и их надо оттуда
забирать. Пример: инспектор живого JSON из блока 3 разобран в
[scalable-knitting-lantern.md](scalable-knitting-lantern.md) вместе с тем, почему `model.get()` в
`getSnapshot` даёт бесконечный ре-рендер и зачем гасится первый синхронный вызов подписчика. Промпт
`v1-03-inspector.md` пересказывает ровно эти два абзаца — без них агент пишет правдоподобный
компонент, который вешает вкладку.

**Съёмка живьём, с монтажной склейкой.** Ожидание вырезается, результат — тот, что реально приехал.
Процедура вместо надежды:

1. Каждый промпт прогоняется до записи ≥3 раз в чистой сессии, результат — в `prompts/PASSRATE.md`.
   Ниже 2 из 3 к съёмке не допускается. Чинится уточнением в `AGENTS.md`, а не удлинением промпта:
   длинный промпт нечитаем в кадре.
2. Протокол отклонения решается за пять секунд по `[ПРИЁМКА]`: косметика — принять вслух; нарушение
   контракта — одна уточняющая реплика агенту в кадре (это ценный материал); второй промах — склейка
   и `git checkout <tag> -- <path>` с проговариванием.
3. Оговорка про недетерминизм произносится один раз, прямо: теги гарантируют воспроизводимость шага,
   промпт — эквивалентный результат, а не идентичный.

**`docs/steps.json` получает поле `prompt`** — путь к файлу промпта. Из него, как и раньше,
генерируется таблица в README (теперь с колонкой «промпт») и матрица `tags.yml`.

**Порядок работ меняется на обратный: репетиция → съёмка → фиксация тегов.** Репо собирается по
промптам заранее — это одновременно источник эталонов и замер проходимости. Но тег ставится по факту
записи: если в кадре приехал эквивалентный, а не идентичный код, тег переставляется `git tag -f`,
иначе `git checkout` даёт зрителю не то, что он видел на экране.

## Репозиторий-компаньон

### Решение: один Vite-проект, не монорепо

Курс — про установку **из npm**; монорепо тянет workspace-линки, то есть ровно ту специфику, от
которой надо увести. Один `package.json` → один lock → `npm ci` детерминирован на любом теге.

Три варианта рендера — **три тонких слайса внутри одного модуля формы**, лежащих уровнем ниже
общего ядра. Дерево само становится доказательством тезиса:

```
AGENTS.md          ← контракт API для агента, читается перед каждым промптом
prompts/           ← v1-02-nav.md … v2-08-files-prefill.md · PASSRATE.md
docs/steps.json    ← тег · видео · тайм-код · заголовок · путь к промпту

src/forms/trip-quote/
├── spec.md                                                 ← ТЗ формы, лежит с ней
├── types.ts  model.ts  form.behavior.ts  validation.ts     ← ОБЩЕЕ ЯДРО
├── data-sources.ts  api.ts  headless.ts                       не меняется после v1-06
├── __tests__/  model · behavior · validation · headless
│                render-count(tsx) · reuse · parity
└── targets/                                                 ← СМЕННЫЙ СЛОЙ
    ├── core-ui-kit/     form.schema.ts · create-form.ts · index.tsx
    ├── renderer-react/  renderer.schema.tsx · renderer.behavior.ts · index.tsx
    └── renderer-json/   renderer.schema.json · registry.ts · renderer.behavior.ts · index.tsx
```

`form.schema.ts` лежит **внутри** `targets/core-ui-kit/`, а не в корне модуля — так велит reuse-map
из [06-form-directory-layout.md](packages/reformer-mcp/docs/llms/06-form-directory-layout.md) §6.
Побочный выигрыш: схема тащит за собой React-компоненты, а тесты ядра ими не пользуются, поэтому
headless-тесты остаются headless и после шага 7.

Приём не выдуман для курса: в монорепо `complex-multy-step-form-renderer/` и `-renderer-json/`
**физически импортируют** `model.ts` / `behavior.ts` / `validation.ts` из `complex-multy-step-form/`.
Курс воспроизводит документированный layout, и это стоит сказать вслух.

### Теги

`v<видео>-<NN>-<slug>`, дефисы, не слэши: тег `v1/01` создаёт директорию `refs/tags/v1/`, после чего
тег `v1` создать невозможно. Все теги аннотированные — `git tag -n9` печатает весь план курса одной
командой. Одна линейная ветка `main`: GitHub compare-URL
(`/compare/v1-04-model-tests...v1-05-headless-form`) — самый ценный артефакт в описании ролика, и он
требует линейности. При переснятии теги **двигаются** (`git tag -f`), в README — `git fetch --tags --force`;
суффиксы `-take2` сломали бы ссылки в уже выпущенных роликах.

Тот же `git tag -f` закрывает расхождение живой генерации с эталоном: тег фиксируется **после**
записи, по тому коду, который зритель видел на экране. Репетиционная сборка даёт эталон и замер
проходимости, но последнее слово — за кадром.

12 тегов V1 (`v1-00-start` … `v1-11-architecture`) + 9 тегов V2 (`v2-01-scaffold` … `v2-09-wrapup`).

### Две гвардии переиспользования

- `reuse.test.ts` — структурная: ни один файл в `targets/**` не содержит `createModel(` /
  `defineFormBehavior(` / `defineValidationSchema(`. *«Переиспользование — не обещание в README, а
  падающий тест».*
- `parity.test.ts` — поведенческая: три фабрики форм, один набор ожиданий, один прогон. Финальный
  кадр V1.

### CI

`docs/steps.json` — единственный источник правды (тег, видео, тайм-код, заголовок, путь к промпту).
Из него генерируется таблица в README — с колонкой «промпт», чтобы зритель повторял шаг дословно, —
и матрица `.github/workflows/tags.yml`, которая на каждом теге гоняет
`npm ci && npx tsc -b && npm run build && npm test --if-present`. Это единственная гарантия, что
обещание «встань в любую точку» не сломается через полгода. Проходимость промптов CI не проверяет и
проверять не может: это замер, а не тест, и он живёт в `prompts/PASSRATE.md`.

### Что из монорепо зрителю НЕ нужно

`resolve.dedupe` (нужен только при workspace-линке), `include` соседнего пакета в `tsconfig.app.json`,
`@radix-ui/*` и `@preact/signals-core` в прямых зависимостях (`effect` берётся из
`@reformer/core/signals` — этот subpath существует именно ради одной копии `Signal`), msw/express/swagger
плейграунда, alias `@`, `tw-animate-css`. Реальный setup consumer'а — три строки в `vite.config.ts`,
три строки в `index.css` и проверка `moduleResolution` в `tsconfig.app.json`.

**Версии пинить `--save-exact`.** Версии в `package.json` монорепо (6.0.0) отстают от npm — их ведёт
semantic-release. Без пина тег `v1-02` перестанет собираться через полгода.

## Ловушки записи

1. **Не делать демо «одна модель — три рендерера на одной странице».** Реестр «сигнал → нода» в
   [signal-node-registry.ts](packages/reformer/src/form/signal-node-registry.ts) — глобальный
   `WeakMap`; второй `createForm` над той же моделью затрёт первый, и `enableWhen` с роутингом
   ошибок начнут работать только у последней формы. Страница `/compare` собирается на **трёх
   независимых экземплярах модели**.
2. **Не обещать бенчмарки.** Формулировка — «сравнение механизмов» и «бюджеты в CI».
3. **UI-Builder показывать только в Chromium** и предупредить про это в первые 30 секунд S1.
4. **Развести два «реестра»** (`defineRegistry` vs `form-registry`) явной репликой.
5. **Недетерминизм генерации — назвать вслух один раз, в V1 §2.6.** Аудитория архитекторов спросит
   сама, и лучше ответить до вопроса: теги воспроизводят шаг дословно, промпт даёт эквивалентный
   результат, а не идентичный. Замалчивание стоит дороже оговорки.
6. **Не превращать курс в рекламу агента.** Бюджет: промпт плюс ожидание плюс вывод не длиннее, чем
   комментарий к результату. Блок, у которого весь смысл «смотрите, сгенерировалось», режется. И не
   говорить «форму сделал ИИ»: форму спроектировал человек, агент напечатал файлы.
7. **Не сравнивать агентов и не называть модель.** Единственное подкреплённое утверждение —
   «промпты агент-агностичны»; всё остальное устареет быстрее ролика.

## Побочный продукт: что записать в беады после съёмки

Съёмка обнажит расхождения документации с кодом — их стоит завести задачами, а не чинить по ходу:

- В доках нет страницы «Тестирование форм», хотя это главный аргумент V1.
- `@reformer/form-registry` отсутствует в таблице корневого README, в `release-and-publishing.md` и в
  `KNOWN_PACKAGES` MCP-сервера — то есть MCP про него ничего не расскажет.
- `@reformer/builder` не в таблице README, хотя публикуется.
- README билдера описывает старую модель применения правок агента (до коммита `5eb99f55`).
- README MCP перечисляет 4 инструмента из 8.
- README ui-kit называет `@reformer/renderer-react` peer-зависимостью — в `package.json` его нет.
- В playground нет примера «чистая TS-форма без UI» — курс его создаёт, стоит перенести в примеры.
- **`05-m1-workflow.md` противоречит сам себе про стабилизацию модели.** §1 велит «Stabilise the
  instance in `useMemo`», а §3 и §7 того же файла требуют `useFormBundle` и прямо объясняют, почему
  `useMemo` здесь неверен (React вправе выбросить кэш вместе с введёнными данными). Агент, читающий
  доки сверху вниз, споткнётся об это первым — и это единственный пункт списка, который стоит
  починить **до** съёмки, потому что промпты курса опираются на доки.
