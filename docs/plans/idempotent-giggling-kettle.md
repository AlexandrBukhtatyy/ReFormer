# Промпты в сценариях курса — код генерируется агентом в кадре

## Context

Сценарии курса ([V1](reformer-course-v1-shooting-script.md), [V2](reformer-course-v2-shooting-script.md))
предполагают, что код печатается вживую: 16 блоков `[ПЕЧАТАЕМ]` в V1 и 21 в V2. Это 20+ минут
экранного времени на механическую печать при том, что содержание курса — не код, а **границы между
слоями**: почему модель ничего не знает про React, почему валидация — отдельная схема, почему замена
рендерера не трогает бизнес-логику.

Решение: код в сценариях остаётся как **эталон**, но рядом появляется **промпт**, который этот код
порождает. Домен (страховка путешествия / автокредит) — декорация; демонстрируется библиотека.

Что это даёт помимо экономии времени:

1. **Якорь блока 8 становится доказательством, а не обещанием.** Сейчас `git diff --stat v1-07 v1-08`
   доказывает «я аккуратно не трогал `model.ts`». Если миграцию делает агент по промпту «перенеси слой
   рендера», человеческая аккуратность уходит из уравнения: агент либо может отделить слой, либо нет.
   Граница либо есть в архитектуре, либо её нет.
2. **Порядок блоков V1 совпадает с каноническим workflow библиотеки** — модель → схема → сборка →
   валидация → поведение → массивы → рендер, ровно
   [05-m1-workflow.md](packages/reformer-mcp/docs/llms/05-m1-workflow.md) §1–7. Это не совпадение, и
   это стоит проговорить: слои разделены так, что каждый генерируется и проверяется отдельно.
3. **Репо-компаньона ещё нет** (`docs/steps.json` не существует, тегов нет). Значит промпты
   валидируются самой сборкой репо: каждый тег — эталонный вывод своего промпта, а сборка становится
   генеральной репетицией съёмки. Делать это надо сейчас, до сборки, а не после.

**Решения, принятые с пользователем:** полный текст промпта inline в блоке; агент-агностик, **без
MCP**; генерация живьём с монтажной склейкой; охват — V1 + V2 + карта курса.

Выбор «без MCP» снимает конфликт с S3: V1 показывает, что для надёжной генерации приходится руками
писать файл с контрактом API, а S3 отвечает — «можно не писать, подключи сервер». V1 становится
завязкой спутника, а не его пересказом.

## Формат в сценарии

В «Как читать» добавляются три маркера, `[ПЕЧАТАЕМ]` **сохраняется** для ручных кусков:

- **[ПРОМПТ]** — текст, уходящий агенту; в репо лежит файлом `prompts/v1-NN-<slug>.md`
- **[ЭТАЛОН]** — код, который должен получиться (существующие листинги переименовываются из `[ПЕЧАТАЕМ]`, **сам код не меняется**)
- **[ПРИЁМКА]** — что обязано совпасть / что вправе отличаться / чем проверяем за 5 секунд

Пример готового блока (V1 §3.2, показывает целевой вид правки):

> ### 3.2 Модель (18:00 – 19:20)
>
> **[ПРОМПТ]** `prompts/v1-03-model.md`
>
> ```
> Напиши src/forms/trip-quote/model.ts.
> Фабрика createTripQuoteModel() на createModel<TripQuote> из @reformer/core.
> Плюс две фабрики начальных значений: createInitialTripQuote() и createEmptyTraveler().
> Вычисляемые поля (days, age, pricePerDay, total) инициализируй нулями — их посчитает behavior.
> Начальные значения домена — в spec.md.
> ```
>
> **[ЭТАЛОН]** `model.ts` — _(листинг из текущего сценария, без изменений)_
>
> **[ПРИЁМКА]** обязано: фабрика, а не синглтон; ноль импортов React; вычисляемые поля присутствуют в
> initial. Вправе отличаться: имена локальных хелперов, порядок ключей. Проверка: `npx tsc --noEmit`.

**Бюджет экранного времени агента.** Промпт + ожидание + вывод не должны занимать больше, чем
комментарий к результату. Если весь смысл блока сводится к «смотрите, сгенерировалось» — блок режется.
Курс про библиотеку, не про агента.

## Двухуровневая структура промпта

Без MCP источник правды приходится нести самим. Чтобы промпт в кадре читался на 18–20 px и не
превращался в стену текста, контракт выносится из промптов в два файла репо-компаньона:

| Файл | Содержание | Читается агентом |
| --- | --- | --- |
| `AGENTS.md` | Инвариант: стек и версии, импорты только из subpath'ов, разделение слоёв (валидаторов в схеме нет), `useFormBundle` вместо `useMemo`, `value: model.$.field`, layout каталогов, соглашение `testId`, запрещённые формы API | автоматически (или вставляется один раз в начале сессии) |
| `src/forms/<форма>/spec.md` | ТЗ формы — состав полей, числа, формулы: базовая цена, коэффициенты, лимит 90 дней, порог 50 000 € (V1); аннуитет, ставка по году и сроку, пороги (V2). Лежит **в директории формы**, а не в корне: модуль носит требования с собой, и агенту достаточно сказать «в этой папке» | по ссылке из промпта |
| `prompts/v1-NN-*.md` | Собственно задача блока: 6–15 строк | отправляется в кадре |

`spec.md` закрывает главный риск живой съёмки: тесты блоков V1-04, V1-06 и V2-3.3 проверяют точные
числа (`model.days === 14`, `loanAmount === 1_500_000`). Если агент придумывает формулу цены сам,
`npm test` краснеет в кадре. Порядок промптов внутри тега — **сначала реализация, потом тесты** (обратный
порядок заставил бы агента подгонять реализацию под собственные выдуманные числа).

`AGENTS.md` — сам по себе учебный материал: «контекст-файл это часть архитектуры проекта», и он же
готовит реплику-мостик в S3.

## Что генерим, что печатаем руками

Принцип: **всё, что является демонстрацией, а не кодом, — руками.**

**V1 — 12 промптов, примерно один на тег:**

| Промпт | Порождает | Блок |
| --- | --- | --- |
| `v1-03-model` | `types.ts` + `model.ts` | 3.1–3.2 |
| `v1-04-tests` | `__tests__/model.test.ts` | 4 |
| `v1-05-behavior` | `form.behavior.ts` | 5.1 |
| `v1-05-validation` | `validation.ts` | 5.2 |
| `v1-06-tests` | `behavior.test.ts`, `validation.test.ts`, `headless.test.ts` | 6 |
| `v1-07-schema` | `form.schema.ts` + `create-form.ts` | 7.1–7.2 |
| `v1-07-page` | `index.tsx` | 7.3–7.4 |
| `v1-08-renderer` | миграция на renderer-react | 8 |
| `v1-09-json` | миграция на renderer-json + `registry.ts` | 9.1 |
| `v1-10-profiler` | стенды `/profiler`, `/profiler-usestate`, `render-count.test.tsx` | 10 |
| `v1-11-guards` | `reuse.test.ts` + `parity.test.ts` | 11.1 |

Руками остаются: три аттракциона блока 2 (агент будет их **чинить**, а не ломать), `headless.ts` из
§5.3 (шесть строк и эмоциональный пик курса — «схему я не передаю вообще»), `grep -rn "react"`, все
`git diff --stat`, прогоны Profiler, вставка роутов.

**V2 — 8 промптов, по одному на тег `v2-01` … `v2-08`** (финальный `v2-09-wrapup` ничего не порождает:
там только прогон тестов и чеклист). Руками: прогон `check_behaviors` в §3.1, все браузерные демо,
прогоны `npm test`.

### Промпты блоков 8 и 9 — отдельный случай

**Чем короче промпт, тем сильнее кадр.** Целевой текст блока 8 — две строки:

```
Перенеси слой рендера этой формы на @reformer/renderer-react.
Бизнес-логику не трогай.
```

Перечислять в промпте, какие файлы не трогать, **нельзя** — тогда `git diff --stat` доказывает
послушность агента, а не наличие границы. Если на репетиции pass rate окажется ниже 2 из 3, в промпт
добавляется ровно одна оговорка со списком файлов, и на камере проговаривается, что она добавлена и
почему. Обе формулировки честны, но первая сильнее.

### Единственная точка MCP в курсе

`check_behaviors` в V1 §5.1 и V2 §3.1 остаётся. Это **инструмент проверки**, а не канал генерации, так
что тезис «промпты работают в любом агенте» он не ломает. В сценарий добавляется одна реплика: «это
единственное место в курсе, где я беру инструмент из MCP-сервера ReFormer — как он устроен, отдельное
видео».

## Протокол живой съёмки

Съёмка живьём — сознательный выбор в пользу убедительности, поэтому риск дубля закрывается процедурой,
а не надеждой.

1. **Репетиция до записи.** Каждый промпт прогоняется ≥3 раза в чистой сессии, результат пишется в
   `prompts/PASSRATE.md`. Ниже 2 из 3 — промпт ужесточается, и правило переезжает в `AGENTS.md`, а не
   в текст промпта (иначе промпт перестаёт читаться в кадре).
2. **Теги фиксируются по факту съёмки.** Это инверсия текущего плана: сначала репо собирается по
   промптам (репетиция даёт эталон и pass rate), затем идёт запись, и если живой вывод отличается по
   существу — тег переставляется `git tag -f` на фактический. Иначе зритель делает `git checkout` и
   видит не то, что было на экране. Карта курса `git tag -f` уже разрешает.
3. **Протокол отклонения — в кадре, решение за 5 секунд по `[ПРИЁМКА]`:**
   - косметика (имена, порядок полей, комментарии) → принимаем вслух и идём дальше;
   - нарушение контракта (валидатор в схеме, импорт из корня пакета, React в headless-файле) → одна
     уточняющая реплика агенту **в кадре**; это ценный материал, а не провал съёмки;
   - второй промах → склейка, `git checkout <tag> -- <path>`, вслух сказать, что подставлен эталон.
4. **Оговорка про недетерминизм — один раз, прямо.** Аудитория — архитекторы, они спросят сами.
   Формулировка: «теги гарантируют, что вы встанете в любую точку курса. Промпт гарантирует
   эквивалентный результат, не идентичный».

Новый подблок **2.6 «Правила игры с агентом» (90 секунд)** ставится перед первым промптом, то есть в
конце блока 2: зритель только что посмотрел установку и сейчас впервые увидит генерацию. В блоке 0
добавляется одна фраза про то, что код пишет агент, а промпты лежат в репо.

## Правки по файлам

### 1. [reformer-course-v1-shooting-script.md](reformer-course-v1-shooting-script.md)

- «Как читать» += три маркера; в «Перед записью» переписать пункт про Copilot: запрет остаётся на
  **inline-автодополнение** (прячет объём кода, шумит в кадре), осознанный вызов агента с
  зафиксированным промптом разрешён и является предметом демонстрации. Без этой правки сценарий
  противоречит сам себе.
- «Заготовки до старта записи» += агент открыт в отдельной панели, `AGENTS.md` подхвачен, сессия чистая.
- Блок 0 += фраза про промпты. Новый подблок 2.6 «Правила игры с агентом».
- 11 блоков `[ПЕЧАТАЕМ]` → `[ПРОМПТ]` + `[ЭТАЛОН]` + `[ПРИЁМКА]` по таблице выше. **Листинги кода не
  меняются ни на строку** — меняется только маркер над ними и появляются два соседних блока.
- Блок 5.1 += реплика про единственную точку MCP. Блок 11.3 += реплика-мостик: «контракт API я нёс
  руками в `AGENTS.md`; можно не нести — про это отдельное видео».
- Приложение D · Промпты: сводная таблица «тег → файл промпта → что порождает → чем проверяется».
- Хронометраж пересобирается сквозняком: ожидаемо 94 → 86–88 мин (минус печать, плюс 2.6 и чтение
  промптов). Клапан «сжать блок 4 и убрать аттракцион 2» больше не нужен — отметить это.

### 2. [reformer-course-v2-shooting-script.md](reformer-course-v2-shooting-script.md)

То же самое, 9 промптов вместо 21 `[ПЕЧАТАЕМ]`. Отличия:

- Легенда наследуется от V1 ссылкой, дублировать не нужно.
- «Правила игры» не повторяются — одна фраза «формат тот же, что в V1».
- Блок 3.1 (`check_behaviors`) остаётся ручным и получает ту же оговорку про MCP.
- Пачки однотипного кода (§3.2 «остальные пять `compute` одной пачкой», §5 группы) — самый выигрышный
  случай генерации: промпт на пачку короче, чем перечисление, и реплика «механика та же» звучит
  честнее, когда пачка приезжает одним запросом.
- Хронометраж: 88 → 80–84 мин.

### 3. [parallel-tinkering-tarjan.md](parallel-tinkering-tarjan.md) — карта курса

- Новый раздел «Промпты как артефакт репо»: `AGENTS.md`, `spec.md`, `prompts/`, поле `prompt` в
  `docs/steps.json`, колонка в генерируемой таблице README.
- Раздел про репо-компаньон: дерево `src/forms/trip-quote/` += `prompts/` и два контекст-файла;
  порядок работ «репетиция → съёмка → фиксация тегов».
- Обоснование порядка публикации V1 → S3 переписать: сейчас там «S3 короткий», станет «V1 показывает
  цену ручного контракта, S3 показывает, как его не писать».
- «Ловушки записи» += недетерминизм генерации и протокол отклонения.
- «Что записать в беады» += найденное расхождение: в
  [05-m1-workflow.md](packages/reformer-mcp/docs/llms/05-m1-workflow.md) §1 сказано «Stabilise the
  instance in `useMemo`», что противоречит §3 и §7 того же файла, требующим `useFormBundle`. Это ровно
  та ловушка, на которой споткнётся агент, читающий доки, — чинить в доках, а не в курсе.
- «Verification» += критерий «каждый промпт даёт годный результат ≥2 из 3 прогонов».

### Чего этот план НЕ трогает

`reformer-course-satellites-shooting-scripts.md` — S3 выигрывает от выбранного варианта без правок
(V1 стал его завязкой), S1 уже про AI-агента билдера, S2 к теме не относится. Отдельная сессия, если
захочется усилить связку явными ссылками.

## Verification

Проверяется не «код работает» (кода здесь нет), а «сценарий снимаем и внутренне непротиворечив»:

1. **Ни одного осиротевшего маркера.** `grep -c "ПЕЧАТАЕМ" docs/plans/reformer-course-v*.md` — остаются
   только заявленные ручные куски (V1: аттракционы + `headless.ts`; V2: ноль). Каждый `[ПРОМПТ]`
   сопровождается `[ЭТАЛОН]` и `[ПРИЁМКА]` — проверяется глазами по разделам.
2. **Листинги не пострадали.** `git diff` по сценариям не должен показывать изменений **внутри**
   блоков ```` ``` ````-кода: правка добавляет текст вокруг них. Единственное исключение — если правка
   тайм-кодов задела строку заголовка блока.
3. **Тайм-коды сходятся.** Границы блоков идут без разрывов и нахлёстов, сумма совпадает с
   заявленным хронометражом в шапке (V1 ~86–88, V2 ~80–84).
4. **Промпты самодостаточны без MCP.** Каждый `[ПРОМПТ]` читается как задача для агента, который
   ничего не знает про ReFormer сверх `AGENTS.md`: нет ссылок на `find_recipe`, `get_symbol_docs`,
   `reformer://` ресурсы. Исключение — два ручных прогона `check_behaviors`, помеченных явно.
5. **Числа домена не выдуманы в кадре.** Каждый промпт, порождающий формулу или тест с константой,
   ссылается на `spec.md`; для V1 это `days`, `pricePerDay`, `total`, порог 50 000 €, лимит 90 дней,
   для V2 — аннуитет и ставка.
6. **Взаимная согласованность трёх документов.** Карта курса, V1 и V2 описывают одну и ту же схему
   артефактов (`AGENTS.md` / `spec.md` / `prompts/` / `steps.json`) одними и теми же именами.
7. **Фактическая проверка — на репетиции репо-компаньона.** Промпты прогоняются вживую, pass rate
   пишется в `prompts/PASSRATE.md`; всё ниже 2 из 3 возвращается в правку сценария. Это выходит за
   рамки этого плана, но является настоящим приёмочным критерием.
