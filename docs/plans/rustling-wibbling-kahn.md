# Ассистент билдера: правки «не туда», вопросы модели, размышление, e2e-каталог

## Context

Пользователь просит четыре вещи по ИИ-ассистенту билдера
(`projects/reformer-builder-playground/.ui_builder/plugins/reformer/ai/src`, далее — `ai/`):

1. **Баг:** первый запрос отрабатывает, последующие «пишут не туда». Уточнено: оба режима правки,
   **разные формы**, переключение **во время работы ассистента**, **локальная** OpenAI-совместимая
   модель, симптом — «форма не меняется» (ассистент отчитался, а в форме пусто). Главные подозреваемые —
   D1 и D2 ниже; подтверждаем воспроизведением.
2. **Фича:** уточняющие вопросы модели, как `AskUserQuestion` в Claude Code: модель останавливается,
   задаёт **до 4 вопросов за вызов**, у каждого 2–4 варианта (можно мультивыбор и свой ответ),
   **ответ продолжает тот же ход**.
3. **Баг:** развёрнутое размышление отображается криво.
4. **Тесты:** сначала каталог всех сценариев ассистента, затем тесты — уровень **E2E (Playwright)**.
   Unit-регрессии к исправленным багам допустимы как часть исправлений.

**Решение по порядку:** соседняя сессия (`reformer-d0`) сейчас правит те же файлы ассистента по плану
`docs/plans/cozy-crunching-cray.md` (инструменты/ресурсы плагинов). Реализацию начинаем **после того,
как её работа закоммичена**; наши правки в общих файлах — аддитивные.

## Что установлено при исследовании

**Баг 1 — подтверждённые в коде механизмы.** Переключение посреди хода указывает на D1+D2 (структурный
режим) и на «ход дописывает форму A, пока на экране B, а вкладку A заменила временная» (режим
файлов); D3/D4 — следующий ход по B с историей про A. Остальные — сопутствующие дефекты того же сценария.

| # | Режим | Механизм | Где |
|---|---|---|---|
| D1 | структ. | Вторая попытка хода заново берёт **активную** вкладку: правки уходят в форму, открытую сейчас, а снимок/отмена остаются у первой | `ai/session/bridge.ts:768` |
| D2 | структ. | Цель открыта **временной вкладкой**; одиночный клик по форме B заменяет её (`projects/reformer-builder/src/shell/platform/ui/state/tabs.ts:129-135`) → «форма закрыта» или (с D1) правки в B. Правки структурного хода копятся до конца попытки, а локальная модель медленная — окно большое | `bridge.ts` `resolveTarget`/`land`, `ai/session/apply.ts:104` |
| D3 | файлы | Путь из прошлого хода (формы A) трактуется относительно модуля B: `form.schema.json` в вложенном модуле или `forms/contact/...` создаёт **лишний файл**, `write_file` отвечает «Created», форма B не меняется | `ai/files/scope.ts:38-51`, `ai/tools/files/write-file.ts:42-63` |
| D4 | оба | Модели не говорят, какая форма активна и что она сменилась; история — вся сессия; затравка пустой формы пропускается целиком | `ai/loop/loop.ts:182-196`, `bridge.ts:744-747, 842-845` |
| D5 | структ. | Все правки упали (NOT_FOUND по адресам из формы A), модель пишет «готово» — предупреждения нет (`silentTurnNote` только при пустом тексте) | `bridge.ts:667-695` |
| D6 | оба | Набор `pending` прошлого хода переживает `startTurn`, превью кликабельно во время следующего хода; потом молча теряется | `ai/session/session.ts:279-321`, `ai/ui/ChatPanel.tsx:129-144` |
| D7 | оба | «Новый разговор» чистит только ленту; отмена хода может откатить форму прошлого разговора | `ai/ui/ChatActions.tsx:69-71`, `ai/plugin.ts:287-294` |
| D8 | оба | Смена режима и «Подключить» во время хода делает `session.reset()` посреди хода | `ai/ui/ProviderSettings.tsx:146-157`, `ChatPanel.tsx:97-99` |
| D9 | структ. | Нет `documents.flush` перед чтением буфера (в режиме файлов есть, `ai/workspace.ts:111-117`) | `bridge.ts:506-521` |
| D10 | оба | После «Остановить» показывается ложное «ассистент ничего не сделал» | `bridge.ts:693-695, 917-918` |

Попутно: в `forms/ai-test/aas` корень мастера ссылается на `steps/*`, которых нет на диске — шаги,
созданные в режиме файлов, — отдельные ресурсы и не сохраняются Ctrl+S корня (сценарий F10).

**Баг 3 — причины:** в `ai/ui/MessageList.tsx:51-75` предел высоты стоит на флекс-обёртке с
`height:auto`, процентная высота вьюпорта Radix не разрешается → текст выше 160px вылезает поверх
следующих реплик; обёртка вьюпорта Radix `display:table` + `break-words` → длинные токены расширяют
блок и всю ленту (обрезка справа); `scrollIntoView` на каждый чанк дёргает ленту; блоки рассуждения
склеиваются без разделителя (`session.ts` `appendReasoning`, `ai/providers/ai-sdk.ts:371` обрабатывает
только `reasoning-delta`). Кит-`MessageScroller` как замена не годится: зависит от утилит, которых нет
в CSS кита/билдера.

**Фича 2 — ограничение:** у облачных каналов сторож тишины — `timeout.chunkMs` SDK (60 с,
`ai-sdk.ts:99, 350-352`); в `ai@7.0.127` таймер тикает и во время выполнения инструмента (сбрасывается
только на выходных чанках, гасится после результатов шага). Ожидание ответа пользователя внутри хода
оборвётся → нужен **свой приостанавливаемый сторож**. У локального канала сторожа нет
(`ai/providers/byok.ts:134-149`).

Ещё две находки, влияющие на тесты: SDK по умолчанию пишет каждую ошибку потока в `console.error`
(e2e-фикстура `pageErrors` валит тест) → передать `onError: () => {}`; у локального провайдера
обрезанный вызов всё равно закрывается, поэтому вторую попытку в e2e вызывает ответ «только
рассуждение + `finish_reason: 'length'`» (`stop.emptyFinish`).

## Риски

- Свой сторож расходится с семантикой SDK — страхуют unit-тесты; локальный канал не затронут.
