## Context

Билдер заявлен как **technology-agnostic и ui-kit-agnostic** (брейншторм §2.1–2.2, спека MVP §4: «ядро не знает React, конкретные компоненты, ui-kit»). Половина тезиса выполнена: киты сменные — есть контракт дескриптора, реестр, символьный гейт совместимости, три подключённых кита включая стороннюю дизайн-систему.

Вторая половина не выполнена. `@reformer/renderer-json` импортируют 70 не-тестовых файлов, живое превью прибито к React-рендереру, кодоген имеет один таргет без абстракции эмиттера, а панели, меню, хоткеи, виджеты инспектора и реестр китов — литеральные массивы в модулях. RFC-0001 §1.6 фиксирует итог честно: расширяемы данными шесть точек (`--catalog`, `--config`), «плагинов в смысле исполняемый сторонний код нет вообще», а `buildRegistry()` и `codegen/emit-*.ts` — «только форк».

**Что нужно.** Два независимых свойства:

1. **Переопределение основных компонентов** — заменяемыми должны стать модель документа («конструктор схемы») и рендерер превью. `JsonFormSchema` становится одной из реализаций, а не встроенным допущением.
2. **Установка расширений** — сторонний код, добавляющий панели, команды, виджеты инспектора, codegen-таргеты, киты. Канал доставки — папка проекта пользователя через File System Access API.

**Порядок, зафиксированный решением:** сначала швы (хардкод → реестры и порты, регистрации остаются внутренними), плагинная машинерия — последним этапом поверх готовых швов. Это снимает главный риск: плагинный API, спроектированный до того, как известны реальные точки крепления, зафиксирует не те границы.

**Ключевое ограничение, определяющее механику доставки.** Билдер публикуется как готовый бандл (`@reformer/builder`: `bin/` + prebuilt `dist/`, ноль runtime-зависимостей) и одновременно деплоится статикой на GitHub Pages, где Node нет. У потребителя нет сборочного шага, поэтому «плагин = npm-пакет, который резолвит бандлер приложения» невозможен. Зато в билдере уже есть всё для исполнения чужого кода из папки проекта: `io/fs-access` читает файлы, `preview-runtime/live/transpile.ts` компилирует TS/TSX в CJS, `preview-runtime/live/link.ts` исполняет его с подставным `require`, а `preview-runtime/live/module-registry.ts` отдаёт единственные инстансы `react` и `@reformer/*`. Плагины переиспользуют этот конвейер целиком — launcher править не нужно, hosted-режим не ломается.

## Механика (единая для всего плана)

Ничего не изобретаем: в репозитории уже сложился четырёхслойный паттерн, повторённый в каждом пакете.

```
① МАНИФЕСТ (данные)   JSON Schema, владелец = потребитель, поставщик генерирует под неё
                      component-catalog.schema.json · runtime-config.schema.json
                                    ↓
② РЕЕСТР (сборка)     фабрика + builder-callback + композиция last-wins
                      defineRegistry(reg => …) · composeRegistries(...) · createFormRegistry()
                                    ↓
③ СОСТОЯНИЕ (жизнь)   модульный синглтон getXxx/setXxx/resetXxx + возврат unregister
                      getActiveDescriptor() · getActiveNamespace() · getRuntimeConfig()
                                    ↓
④ ДОСТАВКА (потребл.) React-контекст, НО всегда с прямым каналом-дублёром
```

Сквозные правила, обязательные здесь:

- **слияние поверх дефолтов, а не замена** — инвариант «неявный кит» ([kits/descriptor.ts:5-13](../../projects/reformer-builder/src/kits/descriptor.ts#L5-L13), закреплён `descriptor.test.ts` + `catalog-equivalence.test.ts`);
- **совместимость проверяется символами, а не semver** — [kits/compat.ts:51](../../projects/reformer-builder/src/kits/compat.ts#L51) `loadKitNamespace` со структурированным отказом;
- **отсутствие → дефолты, невалидное → видимый экран** — [config/load.ts:68-107](../../projects/reformer-builder/src/config/load.ts#L68-L107) + `config/BootError.tsx`;
- **изоляция отказа** — error boundary на каждый компонент ([preview-runtime/isolate-component.tsx](../../projects/reformer-builder/src/preview-runtime/isolate-component.tsx)), fallback-протокол [config/boot.ts:44](../../projects/reformer-builder/src/config/boot.ts#L44);
- **код только через `import()`, никогда по сети** — P4 «No remote code» (RFC-0001 §3.2);
- **`resetXxx()` — обязательный член каждого синглтона**;
- **правило R7 против свалки** (deep-sun §7): в контракт идёт только то, что реально различается между двумя носителями; нет примера двух реализаций с разными ответами — поле не входит.

Базовый реестр берём с [packages/reformer-form-registry/src/registry.ts](../../packages/reformer-form-registry/src/registry.ts) — там уже решены ключ `${id}@${version}`, `owner` для namespacing, `ConflictPolicy = 'throw' | 'replace' | 'keep'`, идемпотентный `unregister`, не снимающий чужую запись (`:119-129`), `subscribe` и `diagnostics[]` вместо молчания.

| --- | --- | --- | --- |

| Э2 — виджеты инспектора | свой редактор пропа без форка | 2 | да |
| Э3 — codegen-таргеты | второй таргет возможен; закрывает долг `s0j.11` | 2 | да |

| **Э5 — `PreviewRendererPort`** | подмена рендерера, задел под iframe | 10 | да |

| Э7 — плагины из папки проекта | сторонний код добавляет вклады | 5–7 | да |

**Порядок Э4 → Э5 обязателен, и это исправление.** Первая редакция плана ставила рендерер первым — по коду выходит наоборот: `PreviewInput.doc` и `Hit.path` типизируются через типы документ-модели, `annotateSchema` — через её обход дерева, а второй адаптер рендерера (схематичный canvas) существует только поверх `slotsOf`/`axisOf`. Сделав рендерер первым, его пришлось бы переписывать дважды.

Э0–Э3 полезны и без плагинов: закрывают существующие долги. Э4 — самый дорогой и единственный, чей результат не виден снаружи.

### Э0 — инфраструктура вкладов

Новый слой `src/ext/`, лист графа зависимостей (как `config/types.ts`).

- `src/ext/registry.ts` — `createExtRegistry<T>({ key, onConflict })` → `{ register, registerAll, list, get, subscribe, diagnostics }`; `register` возвращает `unregister`.
- `src/ext/types.ts` — типы вкладов.

Две детали, без которых React сломается:

1. **`list()` обязан возвращать кэшированный снапшот.** Реестры читаются через `useSyncExternalStore`, новая ссылка на каждый вызов = бесконечный цикл рендера (React error #185). В form-registry это уже решено и прокомментировано ([registry.ts:67-79](../../packages/reformer-form-registry/src/registry.ts#L67-L79)).
2. **Политика конфликта различается по смыслу вклада.** Панели и команды — `'throw'` (молчаливая перезапись хуже явного отказа). Виджеты инспектора и компоненты превью — last-wins, как `composeRegistries`: более специфичная реализация должна побеждать. Выбор фиксируется на каждом реестре явно.

### Э1 — панели, вкладки, команды

- `LEFT_PANELS`/`RIGHT_PANELS` ([app/EditorLayout.tsx:56-112](../../projects/reformer-builder/src/app/EditorLayout.tsx#L56-L112)) → `panelRegistry`; регистрации в `app/panels.builtin.ts`. `LeftPanelKind`/`RightPanelKind` из union'ов → `string` с константами.
- `BottomTab` → `bottomTabRegistry`. Здесь вылезает приём, повторяющийся на каждом открытии union'а: он служит ключом исчерпывающих карт — `const SECTION: Record<BottomTab, MockSection | null>` ([canvas/BottomPanel.tsx:36-41](../../projects/reformer-builder/src/canvas/BottomPanel.tsx#L36-L41)). Правило: **то, что было ключом `Record`, переезжает полем записи реестра**, а не остаётся отдельной картой.
- **Реестр команд.** Операция сегодня размазана по трём местам: `editorActions`, JSX меню ([app/AppMenuBar.tsx:64-249](../../projects/reformer-builder/src/app/AppMenuBar.tsx#L64-L249)) и `if`-цепочка хоткеев ([app/EditorLayout.tsx:301-486](../../projects/reformer-builder/src/app/EditorLayout.tsx#L301-L486)). Разъезд виден в коде: пункт меню несёт предикат доступности, действие **и подпись клавиши** (`<MenubarShortcut>{formatShortcut('Mod+D')}</MenubarShortcut>`) — а сама клавиша обрабатывается в другом файле.

  Запись `{ id, title, run, enabled?, keybinding? }`; формат `keybinding` уже существует — платформенно-нейтральная запись из [lib/shortcuts.ts](../../projects/reformer-builder/src/lib/shortcuts.ts) (`'Mod+Shift+Z'`, парсер `shortcutKeys`, форматтер `formatShortcut`). Не хватает одной функции `matchShortcut(spec, event)`. Хоткеи, которые командами не являются (стрелки по canvas, F6, аккорд `⌘K V`), остаются обработчиком — это ввод, а не операции.

### Э2 — виджеты инспектора

`InspectorWidget` ([catalog/types.ts:120](../../projects/reformer-builder/src/catalog/types.ts#L120)) — закрытый union; назначение виджета — хардкод по ключу пропа ([catalog/widgets.ts:31-40](../../projects/reformer-builder/src/catalog/widgets.ts#L31-L40)); диспетчер ([panels/Inspector.tsx:276-344](../../projects/reformer-builder/src/panels/Inspector.tsx#L276-L344)) неоднороден: три `if` с выносом в компоненты и четыре ветки прямо в JSX.

`inspectorWidgetRegistry`: `{ id, Component }` с уже существующим набором пропсов `{ node, path, prop, classNames }`. Четыре inline-ветки выносятся такими же записями — это и есть проверка, что реестр покрывает реальные случаи. Тонкости, которые нельзя потерять (каждая отмечена комментарием в коде): пустой ввод удаляет ключ, а не пишет `""`; `min`/`max`/`step` берутся из props-схемы; сброс `enum` едет отдельным значением `UNSET_OPTION`, потому что Radix запрещает `SelectItem` с пустым `value`.

### Э3 — codegen-таргеты

### Э7 — плагины из папки проекта

Только после Э0–Э6, когда точки крепления существуют и обкатаны внутренними регистрациями.

- **Манифест** `.reformer/plugins/<slug>/plugin.json` по новой builder-owned JSON Schema — по образцу `component-catalog.schema.json` и `runtime-config.schema.json` (draft-07, `$id: https://reformer.dev/schemas/…`, `additionalProperties: false`, поле `$schema` для IDE). Поля: `id`, `apiVersion`, `displayName`, `entry`, `contributes` (какие реестры трогает — объявляется заранее, чтобы отказ был виден до исполнения кода), `requires`.
- **Обнаружение и чтение** — новый `io/plugin-repo.ts`, зеркало работающего [io/template-repo.ts](../../projects/reformer-builder/src/io/template-repo.ts): `listSubdirectories(root, pluginsDir())` → `<slug>/plugin.json` + `entry`, чтение через `fs-ops`, каталог настраивается по образцу `project.templatesDir`. Проектные шаблоны уже так живут и шарятся через git. Границу каталога стережёт существующий `isInsideDir` ([io/fs-ops.ts:169](../../projects/reformer-builder/src/io/fs-ops.ts#L169)).
- **Исполнение** — существующий конвейер live-схем: `transpileTs` → `evalCjsModule` с `require` из `module-registry`, расширенного одной записью `@reformer/builder/plugin-api`. Плагин физически не может принести свой React или `@reformer/core` — это уже enforced таблицей `STATIC_MODULES`.
- **Подтверждение пользователя** — по образцу `canvas/LiveSchemasControl.tsx` (`executionApproved`). Принцип P3 «deny by default».
- **Изоляция отказа и версий** — упавший в `activate` помечается `failed`, ядро живёт; `apiVersion` вне диапазона — не активируется с внятным сообщением; конфликт имён — диагностика, а не молчаливая перезапись.
- **Что плагин получает.** Контракт из RFC-0001 §8.1 (`Plugin { manifest, activate(ctx), deactivate? }`), но `PluginContext` наполняется сущностями SPA: реестры вкладов из Э0–Э3, `editorActions.apply(fn)` как единственный канал мутации (он держит историю и коалесинг), `getCatalog()`/`getActiveDescriptor()` на чтение, `logger` с id плагина. Регистрации возвращают `unregister` — это и есть `deactivate` по умолчанию. Пакетные правки идут через `applyChangeSet`/`isStale` ([agent/apply.ts:44](../../projects/reformer-builder/src/agent/apply.ts#L44)) — механизм ассистента доступен как есть.
- **Момент активации.** Порты и вклады нужны до импорта `App`, а папка проекта на первом запуске выбирается уже внутри приложения. Следствие: при повторном открытии handle восстанавливается из IndexedDB и плагины поднимаются на бутстрапе; при первом выборе — `location.reload()` после подтверждения. Та же модель, что у смены кита ([kits/selection.ts:9-12](../../projects/reformer-builder/src/kits/selection.ts#L9-L12)).

## Порты ядра

### Измеренная связность

`@reformer/renderer-json` импортируют **70 не-тестовых файлов**, но связность резко неоднородна, и это определяет стоимость:

- **52 файла — только `import type`.** Чинятся переименованием типа.
- **18 файлов — поведенческая связка** (value-импорт `isFieldNode`/`isArrayNode`/`isContainerNode`/`parseOperator`) плюс сам слой `model/`. Переписыванию подлежат именно они.

Отдельные измерения, задающие объём волны 0:

- `['root']` — **18 вхождений**, 11 боевых (`model/query.ts:71`, `model/mutate.ts:224`, `store/reducers.ts` ×5, `preview-runtime/annotate-schema.ts:105`, `canvas/SchematicCanvas.tsx:308`, `agent/core/outline.ts:55`), плюс три проверки `path.length === 1 && path[0] === 'root'`;
- построение адреса ребёнка `slot.single ? slot.path : [...slot.path, entry.index]` — **7 копий**;
- «слот для вставки внутрь» (`find(s => !s.single)` + ветка «создать `children`») — **4 копии**;
- «каталожное имя узла» — **3 независимые реализации** с **разными фолбэками**: `'Input'` (`Inspector.tsx:78`), `'Node'` (`node-display.ts:16`), `undefined` (`node-ref.ts:64`);
- читателей Tailwind-`className` — **три независимых**: `node-kind.ts:261`, `mutate.ts:550/565`, `agent/core/layout.ts:44`.

**`model/paths.ts` формат-агностичен уже сейчас** — `getAt`/`updateAt`/`removeAt`/`toPointer`/`fromPointer`/`pathEquals`/`isPrefix` работают над произвольным JSON-деревом. Это снимает самый тяжёлый вопрос: идентичность узла (сегодня = путь) менять не придётся.

### `DocumentModelPort`

**Типизация — фантомный бренд, а не generic через потребителей.** Generic `<TDoc, TNode>`, протянутый через 70 файлов, отравляет сигнатуры; `unknown` без бренда снимает типобезопасность; `declare module` в репозитории не используется (0 случаев) и появляться не должен.

```ts
// src/doc/types.ts — лист графа, только import type
declare const BRAND: unique symbol;
export type Doc  = object & { readonly [BRAND]?: 'doc' };
export type Node = object & { readonly [BRAND]?: 'node' };
```

Пересечение с `object` обязательно: `JsonFormSchema` — интерфейс, и присваивание типу, у которого все свойства опциональны, режется weak type detection. `Doc` и `Node` при этом взаимно неприсваиваемы — ядро физически не спутает документ с узлом. Номинальность односторонняя (адаптер не защищён), но адаптер один и покрыт тестами. Сам порт generic на своей стороне: адаптер объявляет `DocumentModel<JsonFormSchema & Doc, JsonNode & Node>` и внутри типизирован полностью.

**`NodePath` остаётся примитивным массивом — абстрагируется не он, а каждая его интерпретация.** Три причины: путь обязан переживать сериализацию (`HistorySnapshot`, IndexedDB, CSS-класс, `postMessage`); адрес `/root/children/0` — часть контракта с LLM (`agent/core/node-ref.ts:42`, дайджест `outline.ts:71`); и главное — путь несёт **три разных смысла**, и format-specific именно они:

| Сегодня | Становится | Почему |
| --- | --- | --- |
| `isPrefix(a, b)` как «предок» (`resolve-drop.ts:89,116`, `mutate.ts:255,465`) | `port.contains(doc, a, b)` | при id-адресации префикс пути ≠ вложенность |
| `Number(targetPath.at(-1))` как индекс (`resolve-drop.ts:66-69`) | `port.siblingsOf(doc, path) → { slotPath, ordinal, … }` | у id-модели последний сегмент — `'n7'`, а не позиция |
| `parentNodePath` (режет хвосты `children`/`steps`/`item.$template`/`wrapper`) | `port.parentPath(doc, path)` | список хвостов — словарь одного формата |
| `['root']` × 11 | `port.rootPath()` | |
| `toPointer`/`fromPointer` + `refToPath` | `port.serializer.toAddress/fromAddress` | одна точка нормализации индексов; асимметрия, задокументированная в `node-ref.ts:11-15`, исчезает |
| `io/error-path.ts lineOfPath` | `port.serializer.lineOf(doc, path)` | строка зависит от формы печати |

`isPrefix`/`pathEquals` остаются в `paths.ts` там, где смысл действительно «префикс массива» (сравнение выделений). Стор не меняется: `selectionPath`/`anchorPath`/`hoverPath` остаются путями, `HistorySnapshot` — `{ doc, selectionPath }`, механика «выделение следует за узлом» через `Edit.path` сохраняется 1:1.

**`NodeKind` остаётся закрытым union из трёх — и это тоже исправление.** Первая редакция предлагала открыть его в `string`. R7-проверка проваливается в обе стороны: нет модели форм, которой мало трёх видов («держит значение» / «повторяет шаблон» / «держит детей»), и нет осмысленной `default:`-ветки (что рисует канвас для неизвестного вида? что отвечает инспектор?). Открытие дало бы шесть недостижимых веток навсегда. Кандидат на четвёртый вид — **текст** (сегодня `JsonTextChild` живёт внутри `children` и потому не узел); модель, где текст — узел, потребует ломающего изменения порта. Заплатить один раз честно лучше.

**`ChildSlotKind` открывается в `string`.** `'children'|'steps'|'template'|'wrapper'` — словарь конкретно `renderer-json`. Но литерал слота нигде не нужен как таковой: за ним всегда стоит одно из четырёх структурных свойств, и они и идут в контракт — `single`, `axis`, `canPlace`, «слот по умолчанию» (`insertionSlot`). Открытие union — не потеря типобезопасности, а перенос её на настоящий предикат. `kind` остаётся строкой для диагностики и React-key.

**`orientationOf` и групповые классы — модель, параметризованная диалектом стилей кита.** Четыре метода порта — `axisOf`, `withAxis`, `makeGroup`, `isGroup` — реализуются адаптером через сменный диалект: `tailwindDialect` для `kit.styles.mode === 'tokens'`, `opaqueDialect` для `standalone`. R7 здесь выполнен фактом, а не гипотезой: у `@reformer/kit-hexa-ui` в каталоге `styles.mode: "standalone"` и `classNames` отсутствует — то есть `orientationOf` **уже сегодня** отвечает `'vertical'` на любой HexaUI-контейнер, а `flipDirection`/`wrapInRow` пишут в HexaUI-документ Tailwind-классы. Поэтому `Axis` = `'vertical' | 'horizontal' | 'unknown'`, и на `'unknown'` геометрия зон (`dnd/compute-zone.ts`) перестаёт предлагать перпендикулярные зоны вместо того, чтобы врать. Прецедент шва уже есть — `agent/core/layout.ts:1-8` («модель оперирует смыслом, конкретные токены знает редактор»); три независимых читателя `className` схлопываются в один.

**Что в порт не идёт** (R7): `switchVariant` (его аргумент — знание каталога), `migrateTextNodes` (миграция одного формата — внутрь `normalize`), `emptySchema` с тремя JSON-специфичными опциями, мок-синтез (`mock-synth.ts` — знание о формах, а не о формате), `assign-selectors`/`emit-*` (это таргет кодогена, Э3).

**Порядок работ — четыре волны.**

*Волна 0 — дедупликация швов до введения абстракции (7 коммитов, 2 дня).* Правило: абстракция поверх трёх копий одного правила консервирует три копии. Предвычисленный `ChildEntry.path` вместо 7 копий; `insertionSlot()` вместо 4; один `componentOf` вместо 3 (с явной фиксацией разницы фолбэков); `ROOT_PATH`/`isRootPath`; четыре независимых ручных обхода дерева (`synth-model`, `mock-synth`, `annotate-schema`, `codegen/collect`) → общий `walkNodes`/`mapNodes` — они сегодня по-разному трактуют `wrapper`/`template`.

*Волна 1 — контракт и адаптер-фасад (3 коммита, 2 дня).* `src/doc/types.ts` + `src/doc/port.ts` (только типы, лист графа); адаптер, целиком делегирующий в сегодняшние `model/*`, без единого нового правила; `getDocumentModel/setDocumentModel/resetDocumentModel`.

Два снапшота нулевой дельты, по образцу `kits/catalog-equivalence.test.ts:42-57`:
- `src/doc/topology.test.ts` — по каждому узлу каждой встроенной формы строка `toAddress|kind|component|binding|label|leaf|axis|slots(...)|insertionSlot`. Ловит любое изменение топологии во всех волнах;
- `src/doc/roundtrip.test.ts` — `print(parse(print(x))) === print(x)` на тех же фикстурах.

*Волна 2 — перевод потребителей (14 коммитов, 6 дней),* от листьев графа к корню, 1–3 файла на коммит: `dnd/*` → `agent/core/*` → `io/*` → `store/reducers.ts` (самый большой, сеть безопасности — его 551-строчный тест) → `canvas/*` → `panels/*` → `preview-runtime/*` → `codegen/*`. Гейт: eslint `no-restricted-imports` на `@reformer/renderer-json` вне адаптеров, вводится **сразу** с allow-списком из 70 файлов, который каждый коммит сокращает — список-долг, а не флаг, иначе зона либо блокирует работу, либо не включается никогда.

*Волна 3 — вычистка (3 коммита, 2 дня):* диалект стилей, `makeGroup` вместо шести литералов `'$html(div)'`, переезд `src/model/**` → `src/doc/adapters/reformer-json/**` с мостом-реэкспортом на один релиз.

**Критерий готовности — вторая реализация `wire` (2 дня).** Плоская модель, живущая только в тестах: `{ tree: { uid, t, dir?, bind?, props?, kids? } }`. Каждое отличие целится в конкретное предположение JSON-модели:

| Отличие | Ломает | Что упадёт, если порт — фикция |
| --- | --- | --- |
| корень по адресу `['tree']` | литерал `['root']` | всё, начиная с открытия документа |
| **адрес ребёнка `['tree','kids','n7']`, не индекс** | `Number(path.at(-1))` как позиция | вставка, реордер, дубликат |
| единственный слот `kids` | закрытый `ChildSlotKind` | `Inspector:406`, `move-node:58`, `SchematicCanvas:252`, `query:230` |
| ось в поле `dir` | `orientationOf` по `className` | drag-раскладка «всё вертикально» |
| привязка без `$model(...)` | `parseOperator` | превью и кодоген не видят полей |
| `grp` вместо `$html(div)` | `isDivContainer`/`isFlexWrapper` | group/ungroup, авто-unwrap, переворот |
| текста-детей нет | `JsonTextChild` | `capabilities.textContent === false` ⇒ инспектор прячет секцию |

Acceptance — `describe.each` по обеим моделям, сценарии вынимаются из существующих тестов и переформулируются в терминах порта: навигация выделения, дроп, блочные операции, write-инструменты агента, round-trip. Тесты в билдере гоняются в `environment: 'node'` и только `.ts` — доказательство обязано быть React-free.

Механические гейты (иначе «абстракция» проверяется ревью, а не CI): `wire` реализует интерфейс целиком, без `throw new Error('not supported')` вне объявленных `capabilities`; тест-счётчик «каждый метод порта вызван acceptance-набором на обеих моделях»; запрет строковых литералов `'children'`/`'steps'`/`'$template'`/`'$model('`/`'$component('` вне адаптеров.

### `PreviewRendererPort`

Сегодня `canvas/RuntimePreview.tsx` — 382 строки с шестью слитыми обязанностями: сборка бандла, монтирование, хит-тест, подсветка, DnD, DEV-сторож. Порт разделяет **фабрику** (`PreviewRendererPort`) и **смонтированный экземпляр** (`PreviewSurface`). Именно из-за того, что они слиты в одном React-компоненте, хит-тест сегодня берёт `Element`: у компонента есть `hostRef` — «зачем абстракция».

**Хит-тест обязан быть push, а не pull — это второе исправление первой редакции.** Она предлагала `hitTest(point): Promise<HitInfo>`. Над `<iframe>` события мыши в родителе **вообще не возникают**, поэтому хит-тест обязан инициироваться изнутри поверхности: `subscribePointer(cb)`. In-realm адаптер реализует его теми же слушателями, что сейчас (`RuntimePreview:210-238`) — код переезжает, а не растёт.

**Самое тонкое место — `preventDefault()` в `dragover`.** Его нельзя вызвать после `await`: событие уже обработано. Решение: родитель зовёт `preventDefault()` безусловно, пока идёт drag (это уже нынешнее условие `RuntimePreview.tsx:264`), а индикатор рисует из push-события кадром позже. Это надо зафиксировать в доке порта, иначе первый же адаптер сделает `hitTest(point): Promise` и дроп перестанет срабатывать.

Контракт держит iframe тогда и только тогда, когда соблюдены четыре условия:

1. **всё, что пересекает границу, сериализуемо** — `Doc`, мок, `kitId`, `NodePath`, `Rect`, события формы, снимок модели. Никаких `ComponentRegistry`/`FormModel`/`Element`/`ComponentType`. Следствие: `PreviewBundle` ([build-preview.ts:34-38](../../projects/reformer-builder/src/preview-runtime/build-preview.ts#L34-L38)) исчезает из публичной поверхности и становится внутренностью in-realm адаптера;
2. **хит-тест push-овый**;
3. **DnD — отдельная способность с push-контрактом** (`setDragActive` + `subscribeDrag` + `subscribeDrop`): HTML5 drag не пересекает границу окна как один жест, `dragstart` возникает в iframe и модульного синглтона родителя (`dnd/drag-state.ts`) не видит. Геометрия зон (`dnd/compute-zone.ts`) остаётся общей чистой функцией — её зовёт адаптер в своём realm; `commitDrop` остаётся в родителе;
4. **состояние формы наружу — снимок и поток событий**, а не `FormModel`: и сигналы, и form-node'ы realm-локальны. `LogEntry` ([canvas/form-event-log.ts:32-39](../../projects/reformer-builder/src/canvas/form-event-log.ts#L32-L39)) уже сериализуем — его надо только перенести за порт.

Адресация помогает: «узел ⇄ DOM» уже строковая — класс-токен `rbnode-root__children__0` ([preview-runtime/node-token.ts](../../projects/reformer-builder/src/preview-runtime/node-token.ts)), через `postMessage` проходит как есть. DOM протекает наружу ровно в трёх местах: `HitResult.element` используется **единственный раз** (`getBoundingClientRect()` в `canvas/preview-dnd.ts:42`), `elementForPath` — дважды в `RuntimePreview.tsx`.

**Отдельного `HitTestPort` не будет.** У хит-теста нет носителя, независимого от рендерера: он всегда «спроси у того, кто нарисовал». Правильная декомпозиция — способности внутри одного порта (`hitTest`/`highlight`/`dragSource`/`interactive`/`code`), как у кита, где `previewPolicy` и `adapters.*` — поля дескриптора, а не отдельные порты.

**Live-путь — способность рендерера, а не отдельный порт. Это третье исправление.** Первая редакция выносила его отдельно. Разрез проходит по физическому ограничению: `preview-runtime/live/module-registry.ts:18-52` статически импортирует инстансы `react`, `@preact/signals-core`, `@reformer/core` того бандла, в котором живёт, и отдаёт их коду формы через подставной `require`. Значит `evalCjsModule` обязан исполняться в realm рендерера, и «исполнение кода формы» как самостоятельный порт означало бы возможность подменить его, не подменяя рендерер, — такого носителя нет. Снаружи остаются `readFormSources` (читает вкладки и диск), подтверждение пользователя (это политика) и `transpileTs` (чистая функция).

**Кит живёт над рендерером, но его превью-срез идёт входом.** Это уточнение: первая редакция говорила «кит принадлежит рендереру» — слишком грубо. Разделение проходит так: `palette.*`, `styles.classNames`, `classGroupPolicy`, `codegen.*`, `leafComponents` нужны каталогу, инспектору и кодогену даже когда превью выключено — они **над** портом; `infra.*`, `adapters.*`, `previewPolicy`, `styles.{mode,href}` — **вход** рендерера. В `PreviewInput` идёт `kitId: string`, а не namespace: in-realm адаптер резолвит через `getActiveNamespace()`, iframe-адаптер грузит кит у себя. Смена кита продолжает идти через `location.reload()`.

**Критерий готовности — две дополнительные реализации.**

- **`wire-canvas`: сегодняшний `SchematicCanvas`, переписанный как адаптер.** Он уже рисует тот же документ другими механизмами — хит-тест через React-контекст и попадание в `NodeView` (`:197-208`), подсветка через `className` на узле, индикатор дропа абсолютным `div` внутри узла. Его `capabilities` честно закрывают две способности (`interactive: false`, `code: false`), и ядро обязано это пережить: в режиме `wire` не должны предлагаться ни тумблер «Схемы формы», ни `runtimeMode`, ни нижние вкладки «Модель»/«Registry»/«Форма» — сегодня они предлагаются всегда. Побочно снимается дублирование DnD-обвязки, написанной дважды.
- **Headless-поверхность в node-тестах**: документ раскладывается в карту `path → Rect` детерминированной раскладкой, `subscribePointer` кормится синтетическими точками. Проверяет то, чего не проверит ни одна реальная: что контур **адрес → прямоугольник → зона → мутация** замкнут без DOM. Гейт — запрет `document.`/`HTMLElement`/`getBoundingClientRect`/`.closest(`/`querySelector` вне адаптеров.

## Бутстрап: где всё это включается

Окно регистрации одно и уже существует — [main.tsx](../../projects/reformer-builder/src/main.tsx) вызывает `bootRuntime()` **до** динамического `import('./App.tsx')`, потому что граф `store`/`catalog` инициализируется на импорте модулей.

```
bootRuntime()
 1. await loadRuntimeBundle()          — данные (config + catalog), как сегодня
 2. registerBuiltinContributions()     — панели, команды, виджеты, codegen-таргеты
 3. registerBuiltinPorts()
 4. setDocumentModel(select(config))   — ДО каталога и ДО кита
 5. await activateKit()                — как сегодня
 6. setPreviewRenderer(select(config))
 7. [Э7] await loadProjectPlugins()    — только при наличии handle в IDB И согласия
 8. ранние эффекты (document.title)
```

Инварианты порядка и почему:

- **(4) до (5).** `activateKit` ведёт к `buildCatalog()`, а каждая запись каталога несёт `makeNode(): JsonNode` — **фабрику узлов документа** ([catalog/types.ts:61](../../projects/reformer-builder/src/catalog/types.ts#L61)). Если модель ещё не выбрана, каталог замемоизируется с фабриками чужой модели.
- **(2) до (7).** Плагин должен уметь перекрыть встроенный вклад, а не наоборот; порядок регистрации задаёт победителя.
- **(7) до `import('./App.tsx')`.** Единственное окно.

**Горячей смены не будет** — и это уже принятая проектом политика, а не упрощение. `getCatalog()` захвачен React-мемо (`PalettePanel`, `Inspector`, `QuickAddDialog`), `knownComponents()` — мемо реестра превью, `knownComponentNames()` — мемо монако-диагностики, плюс три `useMemo` в `CanvasArea.tsx:46-54`. Механика та же, что у китов ([kits/selection.ts:9-12](../../projects/reformer-builder/src/kits/selection.ts#L9-L12)): выбор в `localStorage`, страница перезагружается. Три ключа (`active-kit`, `document-model`, `preview-renderer`) и один `reload()` на все.

Единственное мемо без reset — `catalog/index.ts:44`; `resetCatalog()` добавляется **только ради тестов**, наравне с существующими `resetKnownComponents`/`resetKnownNames`/`resetClassNamesCache`. Побочный эффект `setActiveDescriptor()` внутри `buildCatalog()` ([catalog/catalog.ts:26](../../projects/reformer-builder/src/catalog/catalog.ts#L26)) стоит развязать при первом касании файла.

**Черновики при смене модели документа.** `reload()` здесь опаснее, чем при смене кита: документы в `io/draft-store` сохранены в формате старой модели. Правило: `port.accept(value) === null` ⇒ вкладка открывается как `kind: 'code'` (Monaco, без канваса и инспектора). Это уже существующий вид вкладки, нового механизма не нужно.

## Открытые вопросы

1. **Команда ≠ инструмент агента.** Свести их в один реестр заманчиво — контракт `AgentTool` уже машиночитаем. Но поверхность инструментов ограничена храповиком `TOOL_SURFACE_BUDGET = 7700`: она уходит в запрос модели на каждом шаге. Значит «эта команда видна ассистенту» — отдельное поле записи, по умолчанию выключенное.
2. **Доступ плагина к файлам проекта.** Сейчас `io/*` пишет только схемы и шаблоны. На Э7 запись не давать; если понадобится — через явную capability в манифесте.
3. **Реестр правил структурного линта.** `io/structure-lint.ts` — одна функция с зашитыми правилами; пользы мало, пока правил единицы. Вернуться вместе с RFC-0003 (контракт `Diagnostic` + пул воркеров).
4. **Выбор документ-модели при открытии файла.** У `JsonFormSchema` есть `$schema`, и брейншторм Q28 предлагал резолвить по нему применимый каталог (не реализовано). Тот же механизм естественно выбирает и модель — проектировать вместе с Э4, не раньше.

## Верификация

Сквозной критерий — **нулевая дельта поведения**: каждый этап переносит существующую логику за новую границу и доказывает, что билдер ведёт себя как раньше. Образец есть — `kits/descriptor.test.ts` и `kits/catalog-equivalence.test.ts` закрепляют инвариант «неявный кит» ровно так.

1. **Юниты реестра**: каждая политика конфликта, идемпотентность `unregister`, «не снять чужую запись», уведомление подписчиков, накопление диагностик.
2. **Снапшоты эквивалентности**: `doc/topology.test.ts` и `doc/roundtrip.test.ts` (Э4), состав панелей/команд/клавиш и файлов кодогена (Э1, Э3). Расширить существующий `preview-runtime/registry-drift.test.ts`.
3. **Acceptance по всем реализациям** — `describe.each` для двух документ-моделей и трёх поверхностей превью.
4. **Механические гейты вместо ревью**: eslint-зона на `@reformer/renderer-json` (со списком-долгом), запрет DOM вне адаптеров превью, запрет операторных литералов вне адаптеров документа, тест-счётчик покрытия методов порта.
5. **Node-тесты остаются node-тестами.** `model/`, `agent/core/`, `dnd/` React-free и гоняются в `environment: 'node'`; порт не имеет права затащить туда React.
6. **`npm test --workspace @reformer/builder`** + `tsc --noEmit -p projects/reformer-builder/tsconfig.app.json`.
7. **Сборка и раскладка чанков**: `npm run build --workspace @reformer/builder`; бюджет главного чанка завести в `.size-limit.json` до начала работ.
8. **Оба канала дистрибуции живы**: `npx reformer-builder` из собранного пакета и hosted-сборка с `BUILDER_BASE`.
9. **Ручной сценарий Э7**: демо-плагин в `.reformer/plugins/` с панелью и командой; ошибка в `activate` не роняет билдер, несовпадение `apiVersion` даёт внятное сообщение, отказ от подтверждения оставляет билдер работоспособным.
10. **E2E** — у билдера нет своего playwright-проекта (`ReFormer-549`). На Э1–Э3 хватает снапшотов; поднять до Э7, иначе плагинную активацию нечем проверить сквозным сценарием.
