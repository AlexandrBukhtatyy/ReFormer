# План: генерация форм через MCP — исходник `form.intent.json` и компиляция на диск

## Context

Цели: высокое качество, мало ошибок, низкая цена в токенах. Гипотеза пользователя: MCP сейчас работает
как поисковик по справке, а должен выдавать готовые части форм и редактировать их.

**На практике гипотеза верна, но компилятор уже есть.** `generate_form` — настоящий детерминированный
компилятор с кросс-проверками, однако на больших спеках форму из него не собрал ни один агент:

- в 6 из 6 свободных запусков форма написана вручную по документации;
- в 4 из них `generate_form` вызван поздно (вызов №44–94), как образец;
- в единственном сохранённом транскрипте (`clean-test`) 81 из 105 вызовов MCP — `find_recipe` и
  `get_symbol_docs`, это 82% токенов MCP;
- цена формы кредита — 180–240 тыс. токенов на таргет и с iter-15 не снижается.

**Вероятная причина — перепечатка.** Сервер возвращает файлы текстом, и агент печатает их заново через
Write (оценка для формы кредита, не замер):

| Путь | Агент пишет | Агент читает |
|---|---|---|
| Вручную | ~30 тыс. | документация |
| `generate_form` сейчас | ~20 тыс. intent + ~30 тыс. перепечатка = **~50 тыс.** | ~30 тыс. |
| Компиляция на диск | ~20 тыс., после уплотнения ~10 тыс. | < 1 тыс. |

Выходит, что готовый путь дороже ручного, и избегать его рационально. Один прогон это косвенно
подтверждает: на крошечной форме L1 sonnet прошёл `plan_form → generate_form → Write×8` и уложился в
$0.10 (`.tmp/mcp-runs/20261102T164722Z-a5b3`).

Данных мало: после исправлений генератора от 10-27 есть один свободный запуск на большой спеке и один
на L1. Поэтому решение сначала проверяется экспериментом (фаза 0).

## Решение

**Один новый инструмент — `form_build(dir)`.** Агент пишет и правит `form.intent.json` своими Write/Edit,
сервер компилирует, проверяет, сам записывает производные файлы и возвращает только диагностику.

```
Агент: Write form/form.intent.json          ← часть формы: шаг, группа, правила
Агент: form_build({ dir: "form" })
Сервер: ✗ validation[12]: нет поля loanTerm  ← файлы не тронуты
Агент: Edit form/form.intent.json            ← правка одной записи
Агент: form_build({ dir: "form" })
Сервер: ✓ записано 3 файла, 5 без изменений  ← без содержимого файлов
```

Так выполняется и замысел пользователя: части формы — это записи intent, правка — это Edit записи.

Отвергнутые варианты:

- **API операций `form_edit(ops[])`** — вторая грамматика поверх FormIntent. В билдере похожий набор
  занял около дюжины инструментов, а выигрыша нет: первая сборка стоит столько же, малая правка почти
  столько же (оценка). Возвращаемся к нему только по триггеру из фазы 0.
- **Выдача готовых частей текстом** — не убирает перепечатку и ничего не даёт для правок.
- **Разбор TS обратно в intent** — `typescript` намеренно не входит в обязательные зависимости, а `expr`
  и правила в intent — непрозрачные строки. Чужие и написанные вручную формы остаются на пути
  «документация + `validate_form`».

Прежние доводы против записи на диск (`generate-form.ts:10-14`) снимаются так:

- от модели приходит только `dir`, имена файлов задаёт бандл;
- `dir` проходит realpath и обязан лежать внутри корня проекта;
- разрешение остаётся на уровне вызова инструмента клиента;
- компиляция остаётся чистой, диск живёт за портом.

Браузерный профиль и ассистент конструктора не меняются: там остаётся `generate_form`.

## Порядок работы (решение пользователя, 2026-11-02)

1. **Ждём** окончания работы над тестированием MCP в параллельной сессии (эпик ReFormer-qo9b). До этого
   план не выполняется.
2. **Базовый замер** на завершённом тестировании, до любых правок сервера. Записи прогонов и копия
   сборки `dist` сохраняются: без копии её нельзя будет передать в `--server`. Команда, согласованная
   с сессией `reformer-e9` (худший случай ~$29):

   ```bash
   npm run mcp:scenarios -- --agent claude-code --model sonnet \
     --scenario "L5-credit,L4-contacts-array" --target renderer-react \
     --repeats 3 --concurrency 2 --max-usd-batch 30 --browser --publish
   ```

   - Старт только после сообщения `reformer-e9` о завершении: стенд пока не закоммичен и меняется.
   - `--max-usd-batch` обязателен: потолок по умолчанию $5, а L5-credit может стоить до $8 за прогон.
   - Два батча с `--browser` одновременно не запускать: браузерная стадия удаляет чужие слоты в
     `pages/debug/mcp-scenarios`.
   - Claude на этих двух сценариях ещё не запускался, живой прогон был только на L1-feedback.
3. **Выполнение плана**, начиная с фазы 0.
4. **Сверка с базовым замером** через `mcp:compare`. Сравнение честное, только если сценарии, контракты,
   верификатор и модель те же. Если они изменились, базовый замер прогоняется заново на старой сборке.

| Сценарий | Прошло | Счёт (медиана, разброс) | Цена | Вывод, токены | Кэш-чтение | Ходов | Время |
|---|---|---|---|---|---|---|---|
| L5-credit | **1/3** | 0.444 (0.375–1) | **$1.27** | 38.3 тыс. | 1.99 млн | 60 | 277 с |
| L4-contacts-array | 3/3 | 0.917 | $0.14 | 4.0 тыс. | 154 тыс. | 16 | 71 с |

Что это меняет в плане:

- **Причина подтвердилась, но не полностью.** На L4 агент идёт `generate_form → Write×5`. На L5
  `generate_form` вызван в 2 из 3 прогонов, и только на пробном intent (ответ 7–9 тыс. символов вместо
  ~116 тыс.); затем форма написана вручную. Полный intent не передал никто.
- **Главная статья расхода — повторное чтение контекста.** 1.4–2.1 млн токенов кэш-чтения за 43–60 ходов.
  В контекст попадает 125–139 тыс. символов ответов MCP: `plan_form` 52 тыс., `find_recipe` 39–48 тыс.
  Рычаг цены — меньше ходов и справки, а не только меньше вывода.
- **Угроза для подхода.** Агент пишет 42–53 тыс. символов кода, а эталонный intent занимает 70 тыс.,
  потому что подробнее (192 правила). Значит, без уплотнения выигрыша по выводу может не быть, и
  уплотнение, возможно, надо переносить из фазы 3 раньше. Решит прогон фазы 0.
- **Главный рычаг качества — компиляция.** Ни в одном прогоне L5 форма не компилировалась: шелла у агента
  нет, а `validate_form` проверяет имена файлов и импорты. Два провала из трёх — выдуманный API (`reduce`
  и `get` у `ModelArray`). `expr` в intent остаётся строкой TS, так что эта ошибка возможна и в новом пути:
  нужен пример вычисления по массиву в грамматике и `tsc` внутри сборки. В рабочем каталоге сценария
  `@reformer/*` не резолвится, поэтому `tsc` в прототипе требует отдельного решения.
- **Третий прогон формы прошёл.** Сначала он был красным из-за ошибки контракта: тот требовал поле
  `documents` и точные ставки из эталона, которых нет в спеке. Контракт исправлен, сохранённые формы
  перепроверены без повторного запуска модели (`source.provenance: "reverified"`). Сравнивать нужно с
  записью, а не с журналом прогона.

**Уточнение критериев.** Базовая линия по гейтам — всего 1/3, это слишком грубо, поэтому для L5-credit
сравниваем медиану итогового счёта и список упавших проверок. Пороги: цена ≤ $0.89, счёт ≥ 0.444. Автор
стенда считает, что для решений нужно N=5; при N=3 и разбросе 0.375–1 разница по счёту значима только при
сильном эффекте, поэтому спорный результат добирается до N=5 в обоих плечах. Контракт и верификатор
замораживаются до конца A/B: при их изменении оба плеча перепроверяются заново.
