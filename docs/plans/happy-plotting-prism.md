# Кодогенерация через шаблонизатор (Eta)

## Context

В билдере v2 два плагина печатают код, и оба печатают его **захардкоженным текстом**:

- **`plugins/codegen`** — 12 функций `(EmitContext) => string` в `src/lib/codegen/emit/`. Каждая
  возвращает один большой template literal. Чтобы изменить хоть строку в выводе, нужно править
  исходник билдера или написать плагин.
- **`plugins/templates`** — «шаблон» это снимок файлов плюс замена **ровно одной** строки (имени
  формы) в четырёх написаниях: `__FormName__ / __formName__ / __form-name__ / __form_name__`.
  Ни условий, ни циклов, ни второй переменной.

Доказательство, что второй механизм не выражает первый, лежит в самом коде: встроенные шаблоны
(`stores/builtin.ts`) **печатает кодоген** и потом токенизирует результат — плейсхолдеры не смогли
бы выразить ни резолв кита, ни шим визарда, ни правила.

Итог для пользователя билдера: чтобы поменять то, что уезжает в проект, надо писать плагин.
Это и есть барьер, который снимаем.

**Результат:** текст файлов описывается шаблонами на Eta; встроенные шаблоны лежат `.eta`-файлами
в репозитории; пользователь кладёт свои в `.ui_builder/codegen/`, переопределяет любую встроенную
цель и получает ошибки с номером строки. Шаблоны форм получают тот же движок.

**Решения, принятые пользователем:** движок — **Eta 4**; охват — **кодоген + шаблоны форм**;
**prettier не подключаем** (пробелы контролируем вручную средствами Eta).

---

## Несущее правило

> Шаблон умеет **цикл**, **ветвление по флагу** и **подстановку строки**.
> Шаблон **не принимает решений**. Любое решение — какой символ, какой импорт, какая заглушка,
> какая причина, какой вид правила — принимается в TypeScript и попадает в шаблон **данными**.

Это делает разрез объективным, а не вкусовым, и объясняет, почему `emitRegistry` и
`emitRenderBehavior` не «переписываются в шаблон», а **расщепляются** на презентер + шаблон.

Разрез уже наполовину сделан: `prepare()` (`src/lib/codegen/context.ts`) выполняет весь обход
схемы, резолв селекторов, синтез мока и вывод имён **до** любого эмиттера. Эмиттеры читают
переваренные данные. Слой данных и слой текста уже разделены — текст просто живёт в TS.

## Архитектура

### 1. Движок — один настроенный экземпляр

**`src/lib/codegen/render.ts`** (новый):

```ts
import { Eta } from 'eta/core'; // ← НЕ 'eta': корневой вход тянет node:fs / node:path
```

Конфигурация фиксируется явно, а не наследуется:

| Опция | Значение | Почему |
| --- | --- | --- |
| `autoEscape` | **`false`** | По умолчанию `true` — превратил бы `&&` в `&amp;&amp;`, а `<div>` в `&lt;div&gt;`. Мы печатаем код, не HTML. **Самая важная строка миграции**; закрепить тестом. |
| `useWith` | `false` | `with` — ошибка в strict-режиме; `it.` явнее. |
| `varName` | `'it'` | |
| `tags` | `['<%', '%>']` | `<%` невозможен в валидном TS/TSX. |
| `autoTrim` | `[false, 'nl']` | Снимает перевод строки после закрывающего тега — иначе `<% for … { %>` оставляет пустую строку в выводе. |
| `rmWhitespace` | `false` | Съел бы отступы. |

Экспорт: `renderTemplate(source, view, { name })`, `registerPartial(name, source)`.
Включения работают без файловой системы: на `eta/core` поля `readFile`/`resolvePath` равны `null`,
поэтому `include("snippet", it)` идёт прямо во внутренний стор, заполняемый `loadTemplate`.

### 2. Слой представления — один вид на прогон

**`src/lib/codegen/view/index.ts`** (новый): `buildView(ctx: EmitContext): CodegenView`,
`withViewFiles(view, refs)` — зеркало существующего `withFiles`.

**Один `CodegenView`, а не двенадцать частных форм.** Довод уже записан в шапке
`context.ts` про сам `EmitContext` («один объект, а не пять параметров… добавление поля не меняет
ни одной сигнатуры»), и к виду он применим сильнее: вид — это **публичная поверхность для
пользовательских шаблонов**. Двенадцать частных форм = двенадцать страниц документации и
пользователь, который не может написать *новую* цель, потому что для неё формы нет.

Опциональный `view?(ctx): object` у цели остаётся лазейкой для чужих целей, подмешивается в
`it.local`. Встроенные им не пользуются.

Два презентера (стадия 5) забирают всю логику из тяжёлых эмиттеров:

- **`view/registry.ts`** → `RegistryView { importSpecifier, kitLabel, fieldWrapper, kitSymbols[],
  components: {name, symbol|null, placeholder, reason?}[], dataSourceNames[], hasPlaceholder,
  wizard | null }`. Забирает `resolveComponent`-цикл, нормализацию заглушек, дедуп и сортировку
  символов, порядок трёх классов источников. Четыре ad-hoc фрагмента импорта
  (`${reactImport}${kitImport}…`, каждый — `''` либо строка с `\n`) становятся **видимыми
  условными строками шаблона**, где им и место.
- **`view/render-rules.ts`** → `RenderBehaviorView`. Забирает `propKey`, `propsLiteral` и
  `renderRuleLine`, **с одной правкой**: последний возвращает `readonly string[]` без отступа.
  Захардкоженные `'    '` / `'      '` уходят из TS; отступ ставит хелпер `indent(lines, n)`.
  Разбор `$expr(…)` против JSON остаётся в TS — шаблон честно не отличит строку от выражения.

Хелперы (`indent`, `json`, `q`) передаются **на виде**, а не через `functionHeader`: так они
типизированы и видны в инспекторе `it`.

### 3. Контракт цели — принимает и код, и шаблон

**`src/plugins/codegen/contract.ts`**:

```ts
export interface CodegenTarget {
  readonly id: string;
  readonly path: string;
  readonly titleKey?: string;
  readonly title?: string;                        // NEW: у пользовательского файла нет словаря
  readonly cls: FileClass;
  readonly regenerable?: boolean;
  applies?(ctx: EmitContext): boolean;
  emit?(ctx: EmitContext): string;                // было обязательным — расширение, не слом
  readonly template?: string;                     // NEW: исходник Eta
  readonly view?: (ctx: EmitContext) => object;   // NEW: подмешивается в it.local
  readonly origin?: 'builtin' | 'user' | 'plugin';// NEW: для панели
}
```

Совместимость полная: id точки (`codegen.target`), ключ `id`, порядок кратный десяти и семантика
`applies` не меняются. Чужая цель с одним `emit` продолжает работать без правок.

Инвариант «ровно одно тело» проверяется там же, где уже проверяются три других, — в
`selectTargets` ([generate.ts:75-122](../../projects/reformer-builder-v2/src/plugins/codegen/generate.ts#L75)),
двумя новыми `CodegenProblem.reason`: `'no-body'`, `'both-bodies'` (плюс `'template-invalid'` на
стадии 6). Каждому нужен ключ в `locales/{en,ru}.json` — панель рендерит
`t('problem.${reason}')` ([ExportPanel.tsx:189](../../projects/reformer-builder-v2/src/plugins/codegen/ui/ExportPanel.tsx#L189)).

`emitWizard` сейчас **бросает** при неприменении. Бросок исчезнет вместе с файлом, и это лучше:
`wizardShimOf` остаётся `applies`-предикатом, а `it.wizard === null` даст `TypeError`, который Eta
обернёт в `RuntimeErr` с именем шаблона и окном ±3 строки, и он попадёт в тот же `problems` через
существующий `catch` в `generateModule`. Ни один тест бросок не проверяет.

### 4. Где лежит текст встроенных шаблонов — `?raw`

```
src/lib/codegen/templates/
  api.eta  model.eta  index-tsx.eta  readme.eta  data-sources.eta
  types.eta  validation.eta  form-behavior.eta  wizard.eta
  registry.eta  render-behavior.eta
  _snippet.eta          ← партиал; emit/snippet.ts остаётся (второй потребитель — run.ts)
```

```ts
import registryTemplate from './templates/registry.eta?raw';
```

Почему так, а не инлайн-строки и не генерируемый TS-модуль:

1. **`.eta`-файл на диске — и есть история авторства.** Главное, что даёт фича, — «скопируй
   встроенный шаблон и правь». Для этого встроенный обязан быть файлом.
2. `String.raw` **не умеет держать обратную кавычку**, а вывод `index.tsx` содержит блок
   ` ```ts ` внутри JSDoc. Инлайн воспроизвёл бы ровно ту проблему экранирования, ради которой
   всё затевается.
3. Типизация бесплатна: `tsconfig.app.json` уже содержит `"types": ["vite/client"]`, который
   объявляет `module '*?raw'`.
4. Размер нейтрален: Vite инлайнит `?raw` в тот же чанк, где эти байты уже лежали литералами.

**Риск, который снимает стадия 0:** `?raw` в node-прогоне vitest — `vitest.config.ts` не
подключает ни одного плагина. Должно работать (`?raw` — ядро Vite), но проверить до, а не после.

## Пользовательские шаблоны

### Цели кодогена — `<project>/.ui_builder/codegen/`

Сосед `plugins/` и `templates/`, не потомок: те — снимки для «новая форма по шаблону», смешение
сделало бы список неоднозначным.

Один файл на цель, JSON-front-matter:

```
---
{ "id": "user.registry", "overrides": "codegen.registry", "path": "registry.ts",
  "cls": "derived", "order": 40, "title": "Реестр компонентов (наш)" }
---
// registry.ts — привязка $component/$dataSource к реализациям.
<% if (it.registry.hasPlaceholder) { -%>
import type { ReactNode } from 'react';
<% } -%>
import { <%= it.registry.kitSymbols.join(', ') %> } from '<%= it.registry.importSpecifier %>';
```

- **`---`, JSON, а не YAML** (парсера в репозитории нет) и **не Eta-комментарий**: `<%#` у Eta не
  зарегистрирован как префикс, он разберётся как *exec* с телом `# …` — синтаксическая ошибка JS.
  Срез до второго `---\n` тривиально тестируется и держит заголовок вне грамматики движка.
- Разбор **терпимый на чтении, строгий в отчёте**: в отличие от `parseManifest`, который молча
  возвращает `{}`, битый заголовок обязан дать `'template-invalid'` в панели.
- **`title`, не `titleKey`** — у пользовательского файла нет словаря. Приоритет в панели:
  `title` → `t(titleKey)` → `path` (последнее уже документировано в контракте).
- **`applies` — строка-выражение**, необязательная: `"applies": "it.wizard !== null"`,
  компилируется один раз через `new Function('it', 'return (…)')`. Прецедент исполнения кода
  тотален — `host/modules/linker.ts` так работает, CSP в репозитории нет вовсе.

**Переопределение — явным полем `overrides`, и это вынужденно, а не по вкусу:**
`ExtensionRegistry.contribute` **бросает** на повторный явный `id`
([extension-point.ts:205](../../projects/reformer-builder-v2/src/host/primitives/extension-point.ts#L205)),
так что «просто тот же id» недоступен. Явное поле и лучше: панель скажет
*«registry.ts — из `.ui_builder/codegen/registry.eta`, переопределяет `codegen.registry`»*, а
забытый `overrides` не молчит — обе цели претендуют на `registry.ts`, и срабатывает существующая
проблема `'duplicate-path'` с именем победителя.

Фильтр — шесть строк в существующем ленивом аксессоре `targets()`
([plugin.ts:253](../../projects/reformer-builder-v2/src/plugins/codegen/plugin.ts#L253)):

```ts
const targets = () => {
  const all = ctx.extensions.get(point).map((c) => c.value);
  const overridden = new Set(all.flatMap((t) => (t.overrides ? [t.overrides] : [])));
  return all.filter((t) => !overridden.has(t.id));
};
```

**Обнаружение и перечитывание.** Порт `CodegenHost` уже имеет `list?`, `readText`, `resolve`,
`exists`; не хватает корня — добавляем `projectRoot?(): ResourceId | null` по тому же идиому
«названной неполноты», что `rulesOf?`. Watcher невозможен (File System Access не умеет следить),
поэтому — при открытии проекта и по команде `codegen.refresh-targets`, зеркало
`plugins/templates/refresh.ts` + кнопка в шапке дока. Вклады кладутся сменяемой группой: перед
новым набором прежний снимается, поэтому refresh идемпотентен.

**Доверие:** соблюдаем `source.capabilities.executesCode`, как
[loader.ts:343](../../projects/reformer-builder-v2/src/host/plugin/loader.ts#L343). Пофайлового
включения **нет**: шаблон исполняется только по явному нажатию «Сгенерировать», а пофайловый
опт-ин вернул бы ровно то трение, которое снимаем.

**Что видит человек при отладке** — четыре вещи, и последние две решают всё:

1. Ошибки разбора → `'template-invalid'` в списке проблем панели. Сообщение Eta уже несёт
   `at line N col M` и строку с кареткой — **панели нужен `whitespace-pre-wrap`**, иначе
   `<Alert>` схлопнет многострочный текст.
2. Ошибки исполнения → существующий путь `'threw'` с окном ±3 строки от `RuntimeErr`.
3. **Инспектор `it`** — сворачиваемое дерево JSON в `ExportPanel`, из уже хранимого
   `GeneratedModule.context`. Первый вопрос автора шаблона — «что лежит в `it`?», и ответом не
   может быть «читай исходники».
4. **Команда `codegen.eject-template`** — выбрать встроенную цель, записать её `.eta` в
   `.ui_builder/codegen/` с уже заполненным front-matter (`id: "user.<name>"`,
   `overrides: "<id>"`, path/cls/order скопированы) и открыть. Это разница между фичей, которой
   пользуются, и фичей, о которой читают. **В стадии 6, не в «потом».**

### Шаблоны форм — тот же движок

`plugins/templates` **вправе** импортировать `@/lib/codegen` (ESLint запрещает только `@/host`,
`@/plugins/*`, `@/app` — и тесты плагина уже это делают), а `TemplatesHost` уже отдаёт `kit()` и
`catalog()`. Значит вид строится прямо в плагине, без нового порта.

- `TemplateManifest` и `TemplateFile` получают `engine?: 'eta'`.
- Когда `engine` задан, `materializeFiles` **рендерит** путь и содержимое вместо подстановки
  токенов. Токены и Eta не смешиваются — одна модель на шаблон.
- **`FormTemplateView`** = варианты имени (`pascal/camel/kebab/snake`, уже есть `nameVariants`)
  + сведения о шаблоне + **полный `CodegenView`, когда шаблон несёт схему формы**. Схему находит
  уже существующий `formSchemaFileOf(files)` — он и сейчас решает, какой файл открыть после
  генерации. Это и есть настоящий мост: пользовательский шаблон формы получает циклы по полям и
  ветвление по наличию визарда, а не одну строку имени.
- Снимок каталога (`createTemplateFromDirectory`) по-прежнему производит **токенные** шаблоны без
  `engine` — регрессии нет, и для произвольных файлов проекта (css, `vite.config.ts`) подстановка
  честнее шаблона.
- Новый класс отказа: шаблон может бросить. Возвращается существующим `OperationResult`
  (`error.template-failed` + сообщение Eta), путь для него в панели уже есть.

**`stores/builtin.ts` и `ModulePrinter` не трогаем.** Инвариант «встроенный шаблон ЕСТЬ вывод
кодогена по затравочной схеме» — это то, что убило 900 строк дублирования v1, и он ортогонален
тому, *как* кодоген печатает текст. `boot.ts:546` продолжает передавать `BUILTIN_TARGETS`
**буквально**, а не эффективный `targets()`: иначе «Простая форма» значила бы разное в каждом
чекауте. Добавить это комментарием там же.

**`FormTemplate` не получает «генеративного» вида** — отклонено: `files` потребляется чекбокс-
пикером, транзитивным каскадом `requires` и `materializeFiles`; второй вид удвоил бы все три,
а генеративное поведение уже существует и называется «Сгенерировать код формы».

## Снятие риска

### Стадия 1 — только защита, ноль изменений поведения

Тесты эмиттеров сегодня — ~25 подстрочных `toContain` без единого golden-файла. Перенос на
шаблоны мог бы **переформатировать все двенадцать файлов и остаться зелёным**. Поэтому первым
ложится снимок, и ничего кроме.

- **`src/lib/codegen/golden.test.ts`** — идёт через `generateModule(BUILTIN_TARGETS, input)`,
  а не по эмиттерам поштучно: так под защиту попадают ещё и отбор по `applies`, раскладка путей,
  список `ctx.files` в README и маркеры.
- **`src/lib/codegen/__golden__/<combo>/<path>.snap`** — шесть комбинаций:

  | комбинация | схема | кит | правила |
  | --- | --- | --- | --- |
  | `plain-builtin` | `plainSchema()` | `builtinKit()` | — |
  | `plain-foreign` | `plainSchema()` | `foreignKit()` | — |
  | `wizard-builtin` | `wizardSchema()` | `builtinKit()` | — |
  | `wizard-foreign` | `wizardSchema()` | `foreignKit()` | — |
  | `plain-rules` | `plainSchema()` | `builtinKit()` | validation + behavior + render ← путь через `@reformer/mcp` |
  | `wizard-no-adapter` | `wizardSchema()` | `foreignKit()` без адаптеров | — ← путь заглушки с причиной |

- **`src/lib/codegen/__fixtures__/kit.ts`** — **дополнить** (`noWizardKit()`, `seededRules()`),
  не переписывать: `foreignKit()` намеренно не содержит `Checkbox`, и это несущая деталь.

**Ловушка первых десяти минут:** `tsconfig.app.json` содержит `"include": ["src"]`, а ESLint
матчит `**/*.{ts,tsx}`. Golden-файл с именем `index.tsx` под `src/` был бы **проверен tsc и
линтером как исходник проекта** — и `tsc -b` упал бы сразу. Отсюда суффикс **`.snap`** у каждого
golden (`index.tsx.snap`, `registry.ts.snap`): его не claim-ит ни tsc, ни ESLint, ни
`include: ['src/**/*.test.ts']` — **править конфиги не нужно**, а настоящее имя видно в диффе.

**Маркер срезается перед записью golden.** Иначе любая правка содержимого дополнительно меняет
12 hex — двойной шум без информации, а сам механизм покрыт `marker.test.ts`. Вместо него —
одно утверждение на комбинацию: у всех `derived`/`regenerable` файлов, принимающих маркер,
`originOf(content) === 'generated'`.

**Туда же:** расширить `src/app/builtin-templates.test.ts` дешёвой проверкой, переживающей любое
переформатирование, — после `materializeFiles` с кириллическим именем ни один токен семейства
`__FormName__` не выжил и ни один файл не пуст. Транспиляцию **не** добавлять: она тянет чанк
`typescript` на 3.59 МБ и снесёт бюджет прогона в 7-8 секунд.

**После стадии 5:** утверждение, что ни один сгенерированный файл не содержит `<%` или `%>` —
ловит незакрытый тег, который Eta молча пропускает текстом.

### Маркеры и существующие проекты — влияния нет

FNV-1a считается от финальных байт, поэтому переформатирование сделало бы `originOf` → `'edited'`.
Но маркер **гейтит только `regenerable`-файлы**, а их ровно три: `renderer.behavior.ts`,
`form.behavior.ts`, `validation.ts`. Наш единственный намеренный сдвиг байт — отступ в `model.ts`,
который **`derived`** и перезаписывается безусловно. Следовательно:

- Гейт каждой стадии — **пустой дифф golden**. Расхождение либо баг переноса (чинить), либо
  намеренная правка (принять **в том же коммите**, чтобы она была атрибутируема одному файлу).
- Версионировать маркер (`@reformer-generated v2 <hash>`) **не нужно**: это навсегда меняло бы
  контракт на диске ради перехода, который никого не задевает.

### Форматирование

**Prettier не подключаем** (решение пользователя). `CodegenHost.format` остаётся названной
неполнотой, как сейчас. Пробелы контролируются средствами Eta (`-%>`, `_%>`, `autoTrim`).
Баг `emitModel` — `JSON.stringify(mock.model, null, 2)` с нулевой колонки внутри тела функции —
чинится в `model.eta` хелпером `indent()` на стадии 3, с видимым однофайловым диффом golden.

## Что вышло иначе, чем планировалось

Записано по факту исполнения; план выше оставлен как есть.

**Golden-тест лежит в `plugins/codegen/`, а не в `lib/codegen/`.** ESLint запрещает
`src/lib/**` импортировать `@/plugins/*` (`denyFromLib`), а тест обязан идти через
`generateModule` — он живёт в плагине. Снимки, соответственно, в
`src/plugins/codegen/__golden__/`.

**Комбинаций семь, а не шесть.** Первые шесть давали ПУСТОЙ `data-sources.ts`: в `plainSchema`
и `wizardSchema` нет ни одного `$dataSource`, то есть ни циклы, ни строка импорта
`SelectOption`, ни склейка блоков не проверялись вовсе. Добавлена `rich-builtin` на
`sampleSchema()` — источник-список, подпись элемента массива и скаляр сразу, плюс массив
с шаблоном элемента. Обнаружено при переносе цели, закрыто ДО переноса.

**`autoTrim: [false, false]` вместо умолчания Eta `[false, 'nl']`.** Умолчание снимает перевод
строки за КАЖДЫМ закрывающим тегом, а не только за управляющим: обычная подстановка в конце
строки (`# <%= it.names.title %>`) молча склеивала заголовок со следующим абзацем, причём
в шаблоне перенос стоял на месте. Обрезка теперь только явная — `-%>` на управляющих строках.
Для генерации кода без форматтера и для шаблонов, которые пишет человек со стороны, буквальная
передача важнее экономии символов.

**Сниппет регистрации стал партиалом.** `_snippet.eta` регистрируется в сторе включений при
загрузке `templates/index.ts`, README зовёт его через `include`, а `emit/snippet.ts` рендерит
по имени для панели. Один текст на двоих вместо копии.

**`STEP_NAME` уехал в `WizardShim.stepName`.** Шим объявляет экспорт этим именем, а `registry.ts`
его регистрирует; литерал в шаблоне позволил бы им разъехаться молча.

**Два намеренных изменения байт**, оба приняты отдельно и видны в диффе снимков:

1. Отступ `JSON.stringify` в `model.ts` (файл `derived` → перезаписывается безусловно →
   для существующих проектов невидимо).
2. Список подписей элементов массива в README теперь отсортирован, как и в `data-sources.ts`
   (раньше README брал порядок обхода Set — он менялся от перестановки узлов в схеме).

**Одно расхождение без покрытия:** в вырожденном случае «в схеме нет ни одного компонента вне
шима» прежний `registry.ts` печатал лишнюю пустую строку, шаблон — нет. Снимками не покрыто:
такая схема в фикстурах недостижима.

**Выгрузка шаблона идёт от файла в панели, а не из диалога выбора.** `PromptService` умеет
только строку и подтверждение — списка у него нет. Кнопка стоит в строке файла отчёта и зовёт
ту же команду, что палитра.

**Цели перечитываются ещё и по смене кита.** Только `activate` было недостаточно: проект
в этот момент может быть не открыт, и список остался бы пустым до ручного «перечитать».
Своего события «проект открыт» порт не отдаёт; смена кита — тот же признак, по которому
перечитывает себя панель шаблонов форм.

**Prettier не подключён** — по решению пользователя. `CodegenHost.format` остаётся названной
неполнотой.
