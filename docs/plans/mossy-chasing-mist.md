# Первая попытка `git commit` должна проходить с первого раза

## Context

Коммиты регулярно падают с первой попытки и требуют повторного захода. В последний раз —
`subject may not be empty` + `type may not be empty` на полностью валидном по смыслу сообщении.
Диагностика показала, что причин несколько и они складываются: одна на стороне агента (синтаксис
шелла), одна на стороне неочевидных правил валидации, одна — расхождение конфигов с документацией.

### Причина 1. Два шелла с несовместимым синтаксисом многострочных строк

В сессии доступны **оба** инструмента: Bash (Git Bash, POSIX sh — многострочность через heredoc
`<<'EOF'`) и PowerShell (here-string `@'…'@`). Синтаксисы взаимно невалидны. В прошлый раз в Bash
ушёл PowerShell-овский `@'`, он стал первой строкой сообщения — отсюда пустые subject и type.
Проблема структурная: пока сообщение проходит через шелл, любая ошибка квотинга ломает коммит.

### Причина 2. Блокирующих правил больше, чем кажется

[commitlint.config.js](../../commitlint.config.js) + `@commitlint/config-conventional`. Уровень 2 =
**блокирует коммит**:

| Правило | Ловушка |
|---|---|
| `body-max-line-length: 100` | русский абзац легко длиннее 100 символов — тело надо переносить руками |
| `subject-case: lower-case` (переопределено в проекте) | **любая** заглавная в теме, включая аббревиатуры — `api`, а не `API`; `json`, а не `JSON` |
| `subject-full-stop` | точка в конце темы |
| `header-max-length: 100` | заголовок вместе с `type(scope): ` |
| `type-enum` / `type-case` / `subject-empty` / `type-empty` | базовые |

Уровень 1 (только предупреждение, коммит проходит): `scope-enum`, `body-leading-blank`,
`footer-leading-blank`.

### Причина 3. Конфиги расходятся с реальностью и с документацией

- `beads` использован в **22 коммитах** истории, но его нет в `scope-enum` → предупреждение каждый раз.
- [CONTRIBUTING.md](../../CONTRIBUTING.md) учит писать `core`, `cdk`, `ui-kit`, `renderer-react`,
  `renderer-json`, `mcp`, `repo`. **Ни один** из этих package-scope не входит в фактический enum
  (там `reformer`, `reformer-cdk`, `reformer-ui-kit`, …). Кто следует документации — получает
  предупреждение.
- CONTRIBUTING утверждает: «для feat/fix scope **обязателен** — `semantic-release-monorepo`
  использует его, чтобы определить какому пакету принадлежит change». Это **фактически неверно**:
  пакет определяется по **путям изменённых файлов**
  ([only-package-commits.js:35-58](../../node_modules/semantic-release-monorepo/src/only-package-commits.js#L35-L58)),
  scope влияет только на группировку в release notes. Из-за этого неверного утверждения scope
  подбирают «чтобы не сломать релиз», хотя релиз от него не зависит.

### Причина 4 (не провал, но источник сюрпризов)

`pre-commit` → `lint-staged` прогоняет `eslint --fix` и `prettier --write` по проиндексированным
файлам и **применяет правки в коммит**. Коммит проходит, но содержимое отличается от того, что было
проверено тестами до него — после коммита нужен повторный прогон.

**Цель:** первая попытка `git commit` успешна by construction — сообщение не проходит через
квотинг шелла, а все правила проверены до коммита.

## Решение

### 1. Процедура коммита (главное)

Три шага, ни одного многострочного текста в шелле:

1. **Написать сообщение в файл инструментом Write** (не через `echo`/heredoc/here-string), в
   scratchpad-директорию сессии: `<scratchpad>/commit-msg.txt`.
2. **Прогнать валидацию до коммита:** `npx --no commitlint < <файл>` — проверено, ловит все правила
   (длина строк, case, точка, scope) примерно за секунду и ничего не меняет на диске. Есть ошибки —
   править файл и повторять, пока не станет чисто.
3. **Коммитить файлом:** `git commit -F <файл>`.

`git commit -m` остаётся допустимым только для однострочного ASCII-безопасного сообщения без
кавычек и переносов.

После коммита, если `lint-staged` сообщил «Applying modifications from tasks» — перепроверить
затронутый пакет (тесты + `tsc`), потому что в коммит попал автоформатированный код.

### 2. `commitlint.config.js` — добавить реально используемые scope

В `scope-enum` дописать `beads` (22 коммита истории; `.beads/**` не входит ни в один пакет, релиз не
триггерит) и `repo` (обещан в CONTRIBUTING; для корневых конфигов, хуков, tooling). Остальные
«хвосты» из истории (`renderer-json`, `ui-kit`, `core`, `stackblitz`) — сокращения канонических имён,
их добавлять не нужно; правильный ответ на них даёт исправленная таблица в CONTRIBUTING.

Уровень правила оставить `1` (предупреждение) — enum не должен блокировать коммит.

### 3. `CONTRIBUTING.md` — привести раздел Commit Messages в соответствие с фактами

- Таблицу scope заменить фактическим содержимым `scope-enum` (плюс `beads`, `repo` из п. 2).
- Убрать неверное утверждение про `semantic-release-monorepo` и scope; заменить корректным:
  принадлежность пакету определяется путями изменённых файлов, а scope нужен для читаемости и
  группировки в release notes.
- Добавить короткий блок «что блокирует коммит» — таблица из «Причины 2», иначе про `lower-case` и
  лимит в 100 символов узнают только методом проб.

### 4. `CLAUDE.md` — новая секция сразу после «Git commits — strict authorization» (строка 139)

Существующая секция отвечает на вопрос «**можно ли** коммитить». Новая отвечает на «**как**»:
процедура из п. 1, список блокирующих правил, явный запрет на PowerShell here-string в Bash-инструменте
и наоборот. Секция про авторизацию не меняется — она ортогональна.

### 5. Память — чтобы правило пережило сессию

Новый файл `feedback_commit_message_via_file.md` (тип `feedback`, с **Why** и **How to apply**) в
`C:\Users\user\.claude\projects\d--Work-ReFormer\memory\` + строка-указатель в `MEMORY.md`. Смысл:
CLAUDE.md может быть не прочитан целиком к моменту коммита, а память всплывает по релевантности.

## Вне scope

- **Slash-команда `/commit`** и **PreToolUse hook** — рассмотрены, не берём: первая требует помнить
  о вызове, второй хрупок (надо парсить произвольную `git commit` с `-m`/`-F`/`--amend` и рискует
  ложными срабатываниями). Процедура + dry-run закрывают те же случаи без новых движущихся частей.
- Ослабление `subject-case` или `body-max-line-length` — политика проекта не меняется.
- `AGENTS.md` (разошёлся с CLAUDE.md, 181 против 201 строки) — синхронизация это отдельная задача.

## Верификация

```bash
# 1. Негативный тест — dry-run обязан поймать все три блокирующие ошибки
printf 'feat(beads): Тест Сообщения.\n\n<строка длиннее 100 символов>\n' | npx --no commitlint
#    ожидаем: body-max-line-length, subject-case, subject-full-stop; exit 1

# 2. Позитивный тест — после правки enum warning про scope исчезает
printf 'chore(beads): sync issues jsonl\n' | npx --no commitlint
#    ожидаем: 0 problems, 0 warnings; exit 0

# 3. Тот же прогон для repo и для канонических package-scope
printf 'chore(repo): tighten commit workflow\n' | npx --no commitlint

# 4. Сверка документации с конфигом: каждый scope из таблицы CONTRIBUTING
#    должен присутствовать в scope-enum (проверить глазами, списки короткие)
```

Финальная проверка — сам коммит этих изменений делается по новой процедуре (Write → `commitlint` →
`git commit -F`) и обязан пройти с первой попытки без ошибок и предупреждений.
