Три коротких ролика вне основной линии. Карта курса — в [parallel-tinkering-tarjan.md](parallel-tinkering-tarjan.md),
легенда обозначений — как в [V1](reformer-course-v1-shooting-script.md).

| S3 · MCP-сервер | 18 мин | после V1 |

# S3 · MCP-сервер: агент, который не выдумывает API (18 мин)

**Тезис:** давать инструменты вместо свободного текста.

## Блок 1 · Проблема (0:00 – 4:00)

**[ЭКРАН]** `SPLIT` — чистый проект + агент без MCP.

**[ДЕЙСТВИЕ]** Попросить агента: «сделай форму на ReFormer с зависимым полем». Показать результат
как есть, не подыгрывая.

**[РЕПЛИКА]** «Три ошибки, и все три типичные. Импорт из корня вместо subpath — библиотека раздаёт
валидаторы по отдельным путям. Валидаторы прямо в схеме — там их нет, это отдельный слой. И
выдуманный оператор, которого не существует».

**[РЕПЛИКА]** «Это не глупость модели. Это отсутствие источника правды: библиотека свежая, в обучающей
выборке её мало, а угадывать по названиям — ровно то, что модель делать умеет лучше всего».

**[ЯКОРЬ]** Кадр с тремя подсвеченными ошибками — он вернётся в конце для сравнения.

## Блок 2 · Подключение (4:00 – 6:00)

```bash
claude mcp add --transport stdio reformer -- npx @reformer/mcp
```

**[РЕПЛИКА]** «Одна команда. Сервер — обычный npm-пакет с бинарником, работает по stdio. Для Cursor и
любого другого MCP-клиента — четыре строки в JSON-конфиге».

**[ДЕЙСТВИЕ]** Показать, что сервер поднялся и инструменты видны.

## Блок 3 · Восемь инструментов (6:00 – 12:00)

Показывать по назначению, а не списком.

**«Не знаю, как называется» → `search_docs`.** Полнотекстовый поиск по всем секциям всех пакетов.
Запрос словами: «сбросить форму после отправки».

**«Знаю сценарий» → `find_recipe`.** Тема → рецепт. Восемьдесят один рецепт в `docs/llms/`, есть
синонимы: `wizard`, `form-array`, `copy-from`, `json-schema`.

**«Знаю символ» → `get_symbol_docs`.** Полный JSDoc: сигнатура, параметры, все примеры, файл-источник.

**«Что вообще есть» → `list_symbols`.** С фильтром по имени — без фильтра там восемьсот символов.

**Два проверяющих инструмента — самое интересное:**

- **`check_behaviors`** — статический поиск циклов в реактивном графе. Работает по декларации
  (`{ target, reads[] }`), а не по разбору кода, поэтому не разъезжается с реальностью.
- **`validate_json_schema`** — проверка JSON-схемы формы до рендера: структура узлов, синтаксис
  операторов, неизвестные имена компонентов и справочников.

**[РЕПЛИКА]** «Вот это принципиально. Первые четыре инструмента отвечают на вопрос «как правильно» —
их можно заменить хорошей документацией. Последние два отвечают на вопрос «а то, что я написал,
вообще валидно» — и вот их документацией не заменишь».

## Блок 4 · Тот же запрос с MCP (12:00 – 16:00)

**[ДЕЙСТВИЕ]** Повторить запрос из блока 1. В кадре видно цепочку: `find_recipe` → `get_symbol_docs` →
код → `check_behaviors` → `validate_json_schema`.

**[ДЕЙСТВИЕ]** Специально попросить форму с циклической зависимостью → `check_behaviors` ловит цикл.

**[ДЕЙСТВИЕ]** Специально оставить опечатку `$component(Selct)` → `validate_json_schema` ловит.

**[ЯКОРЬ]** Два кадра рядом: результат без MCP и с MCP.

## Блок 5 · Промпты и честные границы (16:00 – 18:00)

**[ДЕЙСТВИЕ]** Показать `/start-here` и `plan-form`. Одиннадцать заготовленных промптов, каждый тянет
только релевантные секции документации, а не всю.

**[РЕПЛИКА]** «Сервер определяет ваш стек сам: смотрит `package.json` вверх по дереву и понимает, стоит
у вас ui-kit или нет, Tailwind третьей версии или четвёртой».

**[РЕПЛИКА — честное ограничение]** «Одна вещь, о которой стоит знать: пакет `@reformer/form-registry`
в списке известных серверу пакетов пока отсутствует — про него он не расскажет. Это баг документации,
и я его завёл».

# S1 · UI-Builder: форма мышкой (28 мин)

**Тезис тот же, что у S3, с другой стороны: модель не пишет JSON — она вызывает операции редактора.**

## Блок 0 · Предупреждение и запуск (0:00 – 3:00)

**[РЕПЛИКА — первые тридцать секунд]** «Сразу важное: билдер работает только в Chromium — Chrome, Edge,
Arc, Brave. Он открывает папку вашего проекта через File System Access API, а его в Firefox и Safari
нет. Если вы на них — дальше будет интересно, но не воспроизводимо».

```bash
npx reformer-builder
```

**[РЕПЛИКА]** «Ничего не устанавливается глобально. Это статический сервер на встроенных модулях Node,
без единой зависимости, который отдаёт локальную страницу. Ваш код никуда не уходит — правки идут
прямо в файлы через браузерный API».

Флаги: `--port`, `--host`, `--no-open`, `--catalog`, `--config`.

## Блок 1 · Открыть проект курса (3:00 – 7:00)

**[ДЕЙСТВИЕ]** «Открыть папку» → выбрать репо-компаньон на теге `v1-09`.

**[РЕПЛИКА]** «Билдер сам нашёл схемы форм. Он не гадает по имени файла: он смотрит, есть ли внутри
JSON узел `root`, и отдельно отмечает те, где стоит маркер `$schema` — у них уверенность выше».

**[ДЕЙСТВИЕ]** Открыть `renderer.schema.json` из тега `v1-09` — ту самую схему из первого видео.

**[ЯКОРЬ]** Момент узнавания: та же форма, что зритель видел в коде, теперь в визуальном редакторе.

## Блок 2 · Три режима (7:00 – 12:00)

**[ДЕЙСТВИЕ]** Переключить `⌘⌥1 / 2 / 3`:

- **Схематичный** — wireframe, видна структура дерева.
- **Живой** — реальный рендер через `@reformer/renderer-json`. Два подрежима: правка (клик выделяет
  узел, интерактив погашен) и тест (форма работает).
- **Код** — Monaco с JSON, редактирование двустороннее.

**[РЕПЛИКА]** «Это не превью-картинка. В живом режиме форма собирается тем же рендерером, что в
приложении».

**[ДЕЙСТВИЕ — самое сильное]** Включить тумблер «Схемы формы» → подтвердить предупреждение.

**[РЕПЛИКА]** «А теперь билдер подхватил ваши настоящие файлы — `model.ts`, `validation.ts`,
`form.behavior.ts` — скомпилировал и выполнил. В превью работают ваши реальные вычисления и ваша
реальная валидация. Предупреждение неслучайно: это исполнение вашего кода в этой вкладке, и
изолировать его нельзя — иначе разъедется единственный экземпляр реактивного рантайма».

**[ДЕЙСТВИЕ]** Показать: ввести даты → пересчитались дни и итог, ровно как в приложении.

## Блок 3 · Собрать поле руками (12:00 – 17:00)

**[ДЕЙСТВИЕ]** Перетащить компонент из палитры. Показать зоны дропа: вдоль оси родителя — до / внутрь /
после; поперёк у края — автоматическая обёртка пары в контейнер.

**[РЕПЛИКА]** «Поперечный дроп создаёт колонку или строку сам. Это то, ради чего обычно лезут в код
править вложенность».

**[ДЕЙСТВИЕ]** Инспектор справа: подписи, обязательность, плейсхолдер.

**[РЕПЛИКА]** «Виджеты в инспекторе не захардкожены — они выведены из схемы пропсов компонента в
каталоге кита. Подключите свой кит — инспектор перестроится сам».

**[ДЕЙСТВИЕ]** Переключить кит (`KitSwitcher`) — та же схема на другой дизайн-системе.

**[ДЕЙСТВИЕ]** Нижняя панель: вкладки JSON / Модель / Registry / Форма.

## Блок 4 · Ассистент (17:00 – 23:00)

**[ДЕЙСТВИЕ]** `⌘⇧K` → настройки → выбрать провайдера, вставить ключ.

**[РЕПЛИКА]** «Ключ ваш и остаётся у вас — в localStorage этой вкладки. Он не уходит на наш сервер,
потому что нашего сервера здесь нет. Anthropic, OpenAI или что угодно OpenAI-совместимое, включая
локальную модель через Ollama — тогда ключ вообще не нужен».

**[ДЕЙСТВИЕ]** Список моделей — кнопкой «Загрузить», а не из захардкоженного перечня.

**[ДЕЙСТВИЕ]** Запросы по возрастанию сложности:

1. «добавь поле email с валидацией»
2. «поставь имя и фамилию в одну строку»
3. «сделай телефон обязательным и добавь маску»

**[РЕПЛИКА — архитектурное ядро ролика]** «Ключевое: модель не пишет JSON. Ей дано тринадцать
типизированных инструментов редактора — вставить узел, поменять свойство, сгруппировать, перенести.
Схему собирает сам билдер, теми же функциями, что палитра и инспектор. Поэтому модель физически не
может выдать сломанную схему: выдуманное имя компонента редактор просто отклонит».

**[РЕПЛИКА]** «Правки применяются сразу — весь ход отменяется одним `Ctrl+Z`. А если вы правили форму
руками, пока модель думала, набор изменений останется ждать вашего решения: применить или отклонить».

**[ДЕЙСТВИЕ]** Показать откат кнопкой «Восстановить» на своей реплике.

**[РЕПЛИКА про безопасность]** «Содержимое формы приходит модели помеченным как данные, не как
инструкции. Если в поле кто-то напишет «игнорируй предыдущие указания», это останется текстом поля».

## Блок 5 · Сохранить и сгенерировать (23:00 – 28:00)

**[ДЕЙСТВИЕ]** `⌘S` → диалог с diff.

**[РЕПЛИКА]** «Перед записью билдер перечитывает файл с диска. Если его изменили снаружи — покажет
конфликт, а не перезапишет молча. Форматирование берётся из вашего же prettier-конфига, поэтому диff
в гите будет только по существу».

**[ДЕЙСТВИЕ]** Переключиться в терминал — dev-сервер курса подхватил изменение через HMR.

**[ЯКОРЬ]** Цикл замкнулся: правка мышкой → файл в репозитории → живое приложение.

**[ДЕЙСТВИЕ]** «Файл → Экспортировать как пример» → двенадцать файлов.

**[РЕПЛИКА]** «Разделение важное: часть файлов производные — при повторной генерации перезаписываются.
Часть — ваши: валидация, поведение, работа с сетью. Они пишутся один раз и больше не трогаются. Ваш
код билдер не затирает».

# S2 · form-registry: формы в микрофронтах (22 мин)

## Блок 1 · Задача (0:00 – 4:00)

**[ЭКРАН]** `SLIDE` — схема: хост и два микрофронта.

**[РЕПЛИКА — постановка]** «Хост-приложение не должно знать, какие формы существуют. Команда,
владеющая кредитным продуктом, выкатывает свою форму независимо; хост только выделяет ей место.
Обычно это решают импортом компонента — и получают связность, ради устранения которой микрофронты и
затевались».

**[РЕПЛИКА — снять путаницу]** «Сразу разведу два похожих имени. В первом видео был `defineRegistry` —
реестр **компонентов** для JSON-схемы. Сейчас речь про `@reformer/form-registry` — реестр **форм**.
Разные пакеты, разные задачи».

## Блок 2 · Регистрация и монтирование (4:00 – 10:00)

**[ПЕЧАТАЕМ]** сторона микрофронта:

```ts
getFormRegistry().register({
  id: 'auto-loan',
  version: '1.2.0',
  owner: 'lending-team',
  schema: … ,          // единственное, что можно тянуть по сети
});
```

**[ПЕЧАТАЕМ]** сторона хоста:

```tsx
<FormOutlet id="auto-loan" />
```

**[РЕПЛИКА]** «Всё. Хост знает идентификатор — и больше ничего. Ни импорта, ни типа, ни версии».

**[ДЕЙСТВИЕ]** Показать три способа монтирования: по идентификатору (`FormOutlet`), по слоту
(`FormSlot`) и по маршруту (`FormRoute`).

**[РЕПЛИКА]** «`FormRoute` получает путь пропом, а не читает из роутера. Это условие работы и в
single-spa, и в Module Federation — реестр не должен знать, какой у вас роутер».

**[РЕПЛИКА про `owner`]** «Поле `owner` — не документация. Когда две команды случайно займут один
идентификатор, вы узнаете, чьи это формы, из сообщения об ошибке, а не из раскопок».

## Блок 3 · Схема по сети (10:00 – 15:00)

**[ДЕЙСТВИЕ]** Схема с CDN, кэш в IndexedDB.

**[РЕПЛИКА]** «Схема — это данные, поэтому её можно обновлять без релиза. Но тогда появляется режим
отказа, которого не было: схема ушла вперёд кода. CDN отдал вторую версию, а микрофронт с поведением
для первой ещё не выкачен».

**[ДЕЙСТВИЕ]** Показать диапазон совместимости в записи и что происходит при несовпадении.

**[ДЕЙСТВИЕ]** Preflight: схема проверяется против модели до монтирования.

**[РЕПЛИКА]** «Схема ссылается на поле, которого в модели нет, — вы узнаете об этом до рендера, а не
через пустой инпут, который молча ничего не сохраняет».

## Блок 4 · Guard (15:00 – 19:00)

**[РЕПЛИКА]** «Теперь самая коварная проблема микрофронтов, и она не про формы».

**[ДЕЙСТВИЕ]** Собрать два бандла, каждый со своей копией `@reformer/core`. Показать симптом: форма
рендерится, но валидация не срабатывает, а условная доступность работает через раз.

**[РЕПЛИКА]** «Две копии ядра — два разных класса сигнала. Проверка «это сигнал?» перестаёт проходить
через границу бандлов, и всё разваливается тихо, без единой ошибки в консоли».

**[ДЕЙСТВИЕ]** Подключить `@reformer/form-registry/guard` → внятное сообщение о двойной загрузке.

**[РЕПЛИКА]** «Полтора килобайта, которые экономят день отладки. Ставьте guard в микрофронтовой сборке
сразу, до того как столкнётесь».

## Блок 5 · Цена и итог (19:00 – 22:00)

**[ЭКРАН]** `SLIDE` — бюджеты (gzip): ядро реестра 3.5 kB, React-слой 2 kB, хранилище 3 kB,
манифест 1 kB, guard 1.5 kB.

**[ДЕЙСТВИЕ]** Открыть пример из монорепо, где страница ужимается до 29 строк.

**[РЕПЛИКА]** «Двадцать девять строк на странице, которая показывает форму в шесть шагов с тремя
массивами. Всё остальное приехало из реестра».

**[РЕПЛИКА — честная оговорка]** «Пакет самый молодой в семействе и пока не описан в общей
документации. Если полезете искать — идите сразу в его README и в рецепты пакета».

## Приложение · Сверенные контракты спутников

```ts
// @reformer/form-registry
getFormRegistry(): FormRegistry
FormEntry<T> = { id, version, owner, schema: DataSource<JsonFormSchema<T>>, … }
// @reformer/form-registry/react
FormOutlet<T>({ id, version, … })      // key по записи+версии: смена записи пересоздаёт форму
FormSlot<T>({ name, … })               // by: 'slot'
FormRoute<T>({ path, … })              // path пропом, не из роутера
// subpaths: '.' | './react' | './storage' | './manifest' | './guard'

// @reformer/mcp — 8 инструментов
get_symbol_docs · find_recipe · search_docs · list_symbols
validate_json_schema · check_behaviors · report_issue · debug (только REFORMER_DEBUG=true)
// 11 промптов: start-here, discover-context, review, plan-form, create-form,
//              add-validation, add-behavior, add-form-array, add-wizard,
//              to-renderer, to-renderer-json
// ресурсы: reformer://guide · reformer://docs/<pkg> · reformer://docs/<pkg>/<slug>

// @reformer/builder — CLI
npx reformer-builder [--port N] [--host H] [--no-open] [--catalog p] [--config p]
// 13 инструментов агента:
//   чтение: get_form_outline, get_form_node, list_components, describe_component, validate_form
//   запись: insert_node, set_node_prop, set_node_model, remove_node,
//           move_node, duplicate_node, group_nodes, set_layout
// адресация — JSON Pointer; write-инструменты батчевые, all-or-nothing
// ключ провайдера — localStorage, канал: anthropic | openai | openai-compatible
```

### Что перепроверить перед записью

1. **S1 — README билдера отстал от кода.** Он описывает старую модель «изменения показываются до
   применения»; в текущей версии правки применяются сразу, откат — кнопкой на реплике. Не зачитывать
   README в кадре.
2. **S3 — `@reformer/form-registry` отсутствует в списке известных MCP пакетов.** Не показывать
   попытку спросить про него — сервер не ответит. Упомянуть как известный баг.
3. **S1 — размер бандла билдера** в README указан устаревший (~8.6 МБ против фактических ~17 МБ).
   Цифру в кадре не называть либо назвать актуальную.
4. **S2 — пакет молодой (0.1.0).** Перед записью прогнать пример из монорепо и убедиться, что API не
   поехал.
