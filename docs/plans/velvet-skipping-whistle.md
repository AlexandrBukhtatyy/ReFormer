# Ассистент: создание формы быстрее и модуль целиком

> Прежняя версия этого файла — план «Правила формы — в коде модуля» (ReFormer-hpjm) — выполнена и
> закоммичена (`404e6dcf`…`79781407`), текст — в истории git.

Сокращения: **RP** = `projects/reformer-builder-playground/.ui_builder/plugins`,
**SDK** = `packages/reformer-builder-plugin-api/src`, **BP** = `projects/reformer-builder/src`.

## Контекст

Пользователь на локальной Ollama (qwen 27B, ~5 ток/с вывода, ~30 с на запрос) просит ассистента
создать форму («форма из трёх шагов по одному полю»). Создание идёт долго, а модуль после хода
неполный: нет страницы, типов, модели, `create.ts`, `flow`, правил, файлов шагов визарда.

Что показали исследования:

- **Запросов к модели 7–9 (140–188 с, сценарий 1.1 замера).**
  - Попытка создания получает полный промпт структурного режима (`RP/reformer/ai/src/stack/index.ts:139`),
    хотя у неё три инструмента. Модель тратит запрос на `list_templates` и зовёт несуществующие
    `list_components` (`AI_NoSuchToolError`).
  - Новая пустая форма уходит без карты (`RP/reformer/ai/src/stack/seed.ts:57`), и продолжение
    всегда начинается с `get_form_outline`.
  - `insert_node` не вкладывает узлы (`RP/reformer/ai/src/tools/insert-node.ts:30`): визард
    строится 3–4 вызовами.
  - Главная доля времени — вывод рассуждения qwen: 650–935 токенов на ход.
- **Модуль неполный.**
  - Пустой шаблон кладёт только `schema/form.schema.json`.
  - Код печатается лишь при первых правилах или по `generate_code`. Дальше ход пишет только
    файлы правил (`RP/reformer/ai/src/stack/rule-code.ts:244`). `flow`, `create.ts`, реестр и
    типы устаревают, а у разбитого визарда новый шаг роняет приложение.
  - Генерация расставляет селекторы и кнопку отправки на своей копии схемы
    (`RP/reformer/core/codegen/selectors.ts:63`), а в ходе запись документа ей запрещена. Поэтому
    `flow` и `submit.ts` ссылаются на селекторы, которых в документе нет: у пустой формы нет кнопки
    отправки.
  - `application/submit.ts` — авторский, не перепечатывается и ломается при переходе простой
    формы в визард.
  - Структурный режим не разносит шаги визарда по файлам.
- **Обвязка.**
  - `list_templates` при каждом вызове заново печатает оба встроенных шаблона полной генерацией
    (`RP/reformer/templates/src/builtin.ts:246`).
  - Генерация за ход идёт до трёх раз: сухой прогон, запись правил, `generate_code`.
  - Превью перекомпилирует модуль на каждую запись файла без задержки
    (`RP/reformer/render/src/compiling/CompilingView.tsx:257`).
  - `loadConfig` читается ~4 раза за ход.
  - Замеров времени по фазам и по запросам нет.

## Решения пользователя

1. После **каждого** хода, изменившего форму, — одна полная генерация модуля. Производные файлы
   перепечатываются, авторские правятся точечно, правленые руками не трогаются.
2. Визард, собранный ассистентом, **разносится по файлам шагов**, как шаблон «Пошаговая форма».
3. Создание — **два хода, но короче**: попытка создания — один запрос, всего ~4 запроса.
4. Рассуждение модели — **замерить** и дать настройку канала, если качество не падает.

## Фазы (каждая проверяется отдельно, коммит — по просьбе)

### Ф0. Замеры — до любых изменений

- **По запросу к модели.** Событие `step_start` в `RP/forms/ai/src/providers/ai-sdk.ts`
  (`'start-step'`); `streamTurn` записывает:
  - длительность и время до первого куска (TTFT);
  - токены входа, выхода и рассуждения (`usageOf` + `outputTokenDetails.reasoningTokens`);
  - прерванный запрос создания тоже считается.
- **По фазам обвязки.** Помощник `traceSpan` в `@reformer/builder-toolkit`
  (`performance.measure('rb:ai.<фаза>')`, префикс как у `trace.ts`). Фазы: config, templates,
  create (с save), open, load, prepare, land, land.codegen, generate.
- **Сводка хода.** Одна строка в консоли на ход вместо строки на попытку
  (`RP/forms/ai/src/session/bridge.ts` `report`). С `?rb-trace` — ещё и таблицы запросов и фаз.
- **Замер на живой модели.** `BridgeDeps.telemetry?(summary)`. Замер
  (`RP/reformer/integration/assistant-scenarios-eval.test.ts`) пишет в JSON запросы, секунды
  модели, TTFT, токены и фазы.
- **Новый сценарий 5.4** «форма из трёх шагов по одному полю». Модуль в замере — настоящая
  генерация (`generatorOver` из `codegen-harness.ts`).
- **Базовый замер** на Ollama пользователя: сценарии 1.1, 1.3, 5.3, 5.4, по 3 прогона.

### Ф1. Обвязка — дёшево и без риска

- **`loadConfig` один раз за ход.** Читается в `send`, а в `sendCreation`, `continueOn`,
  `sendFiles` и `runOnce` передаётся контекстом хода.
- **Шаблоны без печати.**
  - `list()` встроенного хранилища запоминает напечатанное на вид кита и сбрасывает его при смене
    кита (`RP/reformer/templates/src/builtin.ts`).
  - Сводки шаблонов (`templateSummaries`, поиск в `createFormFor`) не печатают модули; печатается
    только выбранный.
- **Превью.** `useFilesVersion` (`RP/reformer/render/src/ui/hooks.ts:109`) получает задержку ~200
  мс; её использует `CompilingView`.
- **Одинаковый текст не пишется** — в двери записи генерации (стек) и в `turn-writes.ts`.
- **Второй `create_form` в продолжении запрещён.** У `Creation` появляется поле `previous`, его
  заполняют из `resume` (сейчас запрет не переживает `continueOn`).

### Ф2. Создание формы — ~4 запроса

- **Свой промпт создания** — `RP/reformer/ai/src/loop/creation-prompt.ts`, ~900 символов, через
  `creationPrompt()`.
  - Одна задача: вызвать `create_form` (имя kebab-case из просьбы) и остановиться — поля, шаги и
    правила добавит продолжение.
  - Без шаблона, если форму описали словами; шаблон — только когда о нём попросили.
  - Не та форма или неоднозначность — `ask_user`.
  - Без имён инструментов структурного режима: тест бюджета и отсутствия имён.
- **Инструменты попытки создания:** `create_form` и `ask_user`. Шаблоны — до ~8 строк
  `"<id>" имя: описание` прямо в затравке (`NO_FORM_SEED`), не в промпте: промпт должен быть
  стабильным. `list_templates` — только если список усечён.
- **Карта пустой формы.** `formSeed` (`seed.ts`) отдаёт корень и для одной записи: «Форма пустая —
  вставляйте в /root». В `prompt.ts` — «ход начинается с карты формы».
- **Вложенный `insert_node`.**
  - У `NodeSpec` появляется `children?: NodeSpec[]` — схема без рекурсивного `$ref`, проверка в
    коде с индексными ошибками.
  - Вставка рекурсивная через `insertSlotOf` (`model/slots.ts`). Переданные `children` визарда
    заменяют шаг по умолчанию «Шаг 1» (`core/catalog/make-node.ts:358`).
  - Пределы: глубина ≤ 3, ≤ ~40 узлов.
  - Промпт: «визард целиком — одним `insert_node`: шаги в children, поля шага — в его children».
- **Подсказка продолжения** (`resumeHint`): «сделайте за как можно меньше вызовов».
- **Бюджеты.** Пересчитать `PROMPT_BUDGET` и `TOOL_SURFACE_BUDGET`
  (`RP/reformer/ai/src/model/types.ts`, точное равенство в
  `RP/reformer/integration/assistant-surface.test.ts`) и завести бюджет поверхности создания.

### Ф3. Полный модуль после каждого хода

- **Генерация — в `land` стека** (`RP/reformer/ai/src/stack/structured.ts`). Только стек может
  подать правила черновика (`stackInput`). Порядок:
  1. Нормализация черновика: `assignSelectors` из `core/codegen/selectors.ts` — чистая и
     идемпотентная. Документ получает те же селекторы и кнопку отправки, что и копия генерации.
     Новая опция `injectSubmit: false` — на случай кита без `Button` или отказа гейта;
     добавленная кнопка — строка в журнале хода.
  2. `applyChangeSet` — гейт и одна запись документа; разбиение — Ф4.
  3. `writeModuleCode` вместо `writeRuleCode` (`rule-code.ts`): одна генерация без `only`, с
     `rulesStackInput(draftRules)`.
- **Когда запускается:** условие — `hasChanges(set)` при наличии файлов и генерации.
  - Исключение — документ со свободным именем без кода: там генерация, как сейчас, только при
    изменении правил, чтобы каталог модуля не заводился на каждую правку.
  - Правленые руками файлы правил по-прежнему дают `broken`.
- **Без сухого прогона.** У созданных ходом файлов `before = null`. `rewind` (и отмена, и
  «Восстановить») при наличии кода у модуля перегенерирует модуль из правил снимка. Тогда правила
  хода не переживают отмену, а производные файлы согласуются с возвращённым документом. Заметка
  отмены о созданных файлах — одной строкой «N файлов в <каталог>».
- **Один прогон на ход.**
  - SDK `FormLandOutcome` (`SDK/assistant/form-stack.ts`) получает необязательное
    `code?: { dir; written; kept }`.
  - Мост пропускает `generateOrdered`, если `land` уже сгенерировал, и пишет одну строку
    `turn.code.updated`.
  - `generate_code` остаётся для хода без правок формы, его описание короче.
- **`application/submit.ts` — перегенерируемый** (маркер):
  - `targets.ts` — `regenerable: true`; заголовок `submit.eta`;
  - роль в `core/codegen/layout.ts` — `regenerable`;
  - старый файл без маркера — заметка `notesOf` (`RP/reformer/codegen/src/stack/disk.ts`), если он
    написан для простой формы, а форма стала визардом;
  - обновить золотые наборы.
- **Режим файлов.** В конце хода `sendFiles` — `generateOrdered` дверью хода, если в журнале
  модуля есть записи. Нормализация селекторов здесь — позже.

### Ф4. Шаги визарда — файлами

- **Операция уже есть:** `splitFormSchema` (`RP/reformer/core/form-model/composite.ts:199`), её
  вызывает `restructure('split')` платформы
  (`BP/shell/platform/workspace/model/model-document.ts:700`).
- **SDK:**
  - `ApplyOptions.restructure?: CompositionRestructure`
    (`SDK/workspace/model/model-document.ts:97`);
  - возможность моделей документов — `1.2.0`.
- **Платформа:** `apply` с `restructure: 'split'` раскладывает документ по файлам одной записью
  истории; части пишутся с пометкой хода.
- **Стек:** `splitWriter(id)` в `RP/reformer/ai/src/stack/workspace.ts` — через ручку
  `DocumentModelsCapability`. Если платформа старая — `handle.restructure('split')` после записи.
- **Когда разбивать:** визард появился в этом ходе
  (`firstWizardStepRefs(base)` пуст, у черновика — нет) и документ ещё не составной. Существующие
  неразбитые визарды не трогаются: их могли собрать в один файл намеренно.
- **Порядок в `land`:** нормализация → гейт → запись через `splitWriter` → генерация. Генерация
  видит составную форму и печатает схемы шагов и импорты `create.ts`.
- **Отмена и «Восстановить»** пишут прежний текст через дверь составной формы; лишние части
  снимаются при сохранении.
- Нет моделей документов — разбиения нет, строка в консоли.

### Ф5. Рассуждение модели — настройка по замеру

- **Настройка канала:** `ProviderSettings.reasoning?: 'default' | 'off' | 'low' | 'medium' |
  'high'` (`RP/forms/ai/src/session/config.ts`). Выбор — в `ui/ProviderSettings.tsx` рядом с
  режимом правки, ru/en.
- **OpenAI-совместимый канал (Ollama):** `providerOptions.<канал>.reasoningEffort` → тело запроса
  `reasoning_effort`, включая `'none'`. Верхнеуровневый `reasoning` AI SDK этот провайдер теряет.
- **OpenAI** — верхнеуровневый `reasoning`. **Anthropic** — только «по умолчанию» и «выкл»:
  рассуждение не сочетается с `temperature: 0`.
- **Проверка, что Ollama её слушает,** — по токенам рассуждения из Ф0. Если нет — запасной путь
  `/no_think` в затравке для qwen.
- **A/B на полном наборе:** `EVAL_REASONING=default|off|low`, по 2 прогона. Рекомендовать `off` или
  `low` для локальных каналов, только если успешных сценариев не меньше чем на 1 и отказов
  инструментов не больше.

## Риски

- Добавленная кнопка отправки и строгий гейт кита — опция `injectSubmit:false`.
- Больше записей за ход — пропуск одинакового текста и задержка превью.
- Ход со второй попыткой генерирует дважды — редкость, принимается.
- Созданные файлы отмена не удаляет — перегенерация в `rewind` и сводная заметка.
- Изменения SDK (`FormLandOutcome.code`, `ApplyOptions.restructure`) аддитивны, у каждого есть
  поведение для старой версии.
- Модель может прислать кривое вложение в `insert_node` — индексные ошибки объясняют, что не так.
- Ollama может не слушать `reasoning_effort` — проверка по токенам и запасной `/no_think`.

## Отложено: модель через MCP (обсудили, в план не входит)

- **Создание по описанию FormIntent.** Модель одним вызовом описывает всю форму, билдер
  компилирует описание компилятором `@reformer/mcp` как библиотекой (`core/generate/form-intent.ts`,
  `schema-emit.ts`) в документ и правила, своя генерация печатает модуль. Сулит создание за 1–2
  запроса. Ограничения:
  - длинный вывод у больших форм;
  - обратное преобразование «документ → описание» с потерями;
  - имена компонентов должны быть из активного кита.
  Вернуться после замеров Ф6.
- **`mcp_call generate_form` плюс режим файлов** — не годится: раскладка MCP плоская и
  расходится с раскладкой билдера, а модель перепечатывает файлы своим выводом.
- **Внешний агент** (Claude Code/Desktop, Cursor) управляет билдером как MCP-сервером —
  отдельный эпик; уже сейчас работает правка файлов на диске с MCP ReFormer.
