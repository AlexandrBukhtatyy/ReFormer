## Как читать

- Ячейка — **медиана по прогонам** (каждый прогон сначала свёрнут: например, медиана задержки по всем клавишам фазы). Меньше — лучше.
- Участник — стек целиком: ReFormer + фреймворк + библиотека компонентов (React + `@reformer/ui-kit`, Vue + Vuetify, Angular + Taiga UI). Разница в числах — о стеке, а не о фреймворке в чистом виде.
- Отметок значимости и «лучшего» в строке нет: отчёт показывает медианы и разброс.
- Документ формы, правила, поведение и fake API у трёх стеков общие (`projects/forms-benchmark/src/cross`); поведение проверено сценариями кросс-e2e на тех же prod-сборках до замеров.
- «Выполнение JS (CDP)» и «JS на клавишу» — счётчик `ScriptDuration` протокола Chrome DevTools. Код в реакциях промисов (`Promise.then`) он не учитывает: 200 мс работы в `Promise.then` дают +0 мс, в `queueMicrotask` и `setTimeout` — +200 мс. Vue перерисовывает в `Promise.then`, поэтому JS у Vue занижен в разы и с другими стеками не сравним; в итог эти строки не вынесены. Задержки ввода и кликов, Total Blocking Time и layout такой ошибки не имеют.
- Числа — сырые миллисекунды этой сессии, без нормировки. Скорость машины в сессии и её дрейф — раздел «Калибровка скорости машины».

## Форма: регистрация с капчей

Одна страница, 8 полей: имя пользователя, email, пароль и повтор, полное имя, телефон с маской, капча и согласие с условиями. Ошибки появляются после первой попытки отправки, дальше валидация живая. Занятость имени и email и ответ капчи проверяет сервер (fake API с задержкой), картинку капчи можно обновить; по ссылке-приглашению форма открывается с email и именем. _Перед замером — перемонтирования прогрева без записи: в первые десятки циклов кучу растит код движка (байт-код, векторы обратной связи, оптимизированный код). «Удержание объектов» — прирост живых объектов страницы между снимками кучи до и после серии, без кода JIT: утечка — когда он больше нуля._

_Перемонтирование — новый корень фреймворка с формой: createRoot у React, createApp у Vue, createComponent у Angular. Библиотека компонентов настраивается один раз на страницу (экземпляр Vuetify, провайдеры Taiga UI). _Перед замером — перемонтирования прогрева без записи: в первые десятки циклов кучу растит код движка (байт-код, векторы обратной связи, оптимизированный код). «Удержание объектов» — прирост живых объектов страницы между снимками кучи до и после серии, без кода JIT: утечка — когда он больше нуля._

## Калибровка скорости машины

В начале и в конце каждого прогона — одна и та же детерминированная JS-нагрузка `form-work-v1` (5 повторов после 2 прогревочных, медиана): объекты полей, строки, regex, мелкие сортировки, spread-копии состояния, JSON. Она идёт на пустой странице той же вкладки под тем же троттлингом CPU, вне окон замера. Её время — мера скорости машины в момент прогона; значение прогона — среднее начала и конца. Таблицы отчёта ею **не нормируются** — она показывает дрейф и нужна для сравнения отчётов разных сессий (`npm run bench:compare`).

Порог сноски — 10 %: собственный шум калибровки на тихой машине — 1–3 %, а типичный разброс временных метрик между прогонами — около 5 % (медиана CV), шум A/A — до 7 % (p90); дрейф вдвое больше этого разброса — уже смена режима машины (частота, тепловой режим, энергоэффективные ядра), и перемешанный порядок итераций не гарантирует, что дрейф лёг на участников поровну. Дрейф внутри прогона попадает в сноску, если порог превышен больше чем в 10 % прогонов: одиночный скачок медиану по итерациям не сдвигает.

## Ограничения

- Троттлинг CPU в Chromium замедляет только main thread: парсинг и компиляция вне основного потока, GC и растеризация не замедляются — стоимость больших бандлов занижена.
- «Клавиша → конец кадра» квантуется частотой кадров; для сравнения точнее «клавиша → конец обработки».
- Одна машина и один браузер; результаты на другом железе отличаются по абсолютным значениям.
- Стеки различаются не только фреймворком: библиотеки компонентов рисуют поля по-своему — разная разметка, стили, всплывающие списки. Цену рендерера ReFormer отдельно от фреймворка и кита эти числа не выделяют.
- Сборщики разные: React и Vue собирает Vite (Rollup), Angular — Angular CLI (esbuild); размер бандла зависит и от этого.
- Счётчик рендеров есть только у React (хук React DevTools) — раздела рендеров у этого отчёта нет.
