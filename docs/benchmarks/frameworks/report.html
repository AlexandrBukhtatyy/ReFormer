Форма: регистрация с капчей

Одна страница, 8 полей: имя пользователя, email, пароль и повтор, полное имя, телефон с маской, капча и согласие с условиями. Ошибки появляются после первой попытки отправки, дальше валидация живая. Занятость имени и email и ответ капчи проверяет сервер (fake API с задержкой), картинку капчи можно обновить; по ссылке-приглашению форма открывается с email и именем. Сценарий: загрузка пустой формы и по приглашению, ввод до и после неудачной отправки, ошибки от сервера и их снятие, капча, согласие, отправка, перемонтирование. Спека — docs/specs/registration-form.md.

CPU 4x: скорость машины в этой сессии менялась больше порога 10 % — разброс калибровки за сессию (p10–p90) 31.8 % > 10 %; от первой итерации к последней −11.5 % (порог ±10 %); в 20 из 30 прогонов (больше 10 % прогонов) скорость от начала к концу прогона изменилась больше чем на 10 % (max 66.1 %). Абсолютные числа менее надёжны, см. «Калибровка скорости машины».

«UI затих» — последнее изменение DOM, а его библиотеки компонентов дают по-разному. @reformer/ui-kit на время серверной проверки показывает под полем индикатор и убирает его по ответу сервера — фаза затихает после ответа. Vuetify на каждой клавише переписывает атрибут value поля — фаза затихает не раньше последней клавиши. Taiga UI пишет значение свойством и по ответу сервера DOM не меняет — фаза затихает, как только снята синхронная ошибка. Перемонтирование — новый корень фреймворка с формой: createRoot у React, createApp у Vue, createComponent у Angular. Библиотека компонентов настраивается один раз на страницу (экземпляр Vuetify, провайдеры Taiga UI). Форма строится после загрузки начальных значений, поэтому «синхронное монтирование» покрывает только оболочку страницы — сравнивайте «монтирование до готовности».

Перед замером — перемонтирования прогрева без записи: в первые десятки циклов кучу растит код движка (байт-код, векторы обратной связи, оптимизированный код). «Удержание объектов» — прирост живых объектов страницы между снимками кучи до и после серии, без кода JIT: утечка — когда он больше нуля.

Форма: кредитная заявка

Визард из 6 шагов: 54 поля и 3 массива строк (имущество, действующие кредиты, созаёмщики). Условные поля по типу кредита и статусу занятости, вычисляемые ставка, взнос и платёж, кросс-правила (стаж, возраст 18–70, платёж не больше 50 % дохода), маски, справочники с сервера (модели авто, города), копирование адреса и email, подтверждение кодом из СМС. Сценарий: загрузка пустой и сохранённой заявки, «Далее» с ошибками, ввод на шагах 1–4 с переходами, смена типа кредита и статуса занятости, массив имущества — включение, добавление строк, ввод, удаление, очистка, код из СМС, отправка с проверкой всех шагов, перемонтирование. «Клик → конец кадра» у Angular здесь завышен способом замера. После клика строки добавляются нажатиями Enter каждые 80 мс. React и Vue перерисовывают форму в обработчике нажатия, и следующее нажатие ждёт его конца. Angular отвечает на нажатие сразу, а перерисовывает в кадре (requestAnimationFrame): нажатия идут подряд, и пока идут ввод и кадры, браузер не берёт обычные задачи. Конец кадра замер отмечает как раз обычной задачей — у первого клика она выполняется только в конце фазы. По Event Timing браузера строка после первого клика отрисована через ~70 мс у React и ~120–130 мс у Vue и Angular (CPU 4x, отдельная проба на тех же сборках).

«UI затих» — последнее изменение DOM, а его библиотеки компонентов дают по-разному. @reformer/ui-kit на время серверной проверки показывает под полем индикатор и убирает его по ответу сервера — фаза затихает после ответа. Taiga UI пишет значение свойством и по ответу сервера DOM не меняет — фаза затихает, как только снята синхронная ошибка. Перемонтирование — новый корень фреймворка с формой: createRoot у React, createApp у Vue, createComponent у Angular. Библиотека компонентов настраивается один раз на страницу (экземпляр Vuetify, провайдеры Taiga UI). Форма строится после загрузки начальных значений, поэтому «синхронное монтирование» покрывает только оболочку страницы — сравнивайте «монтирование до готовности».

Перед замером — перемонтирования прогрева без записи: в первые десятки циклов кучу растит код движка (байт-код, векторы обратной связи, оптимизированный код). «Удержание объектов» — прирост живых объектов страницы между снимками кучи до и после серии, без кода JIT: утечка — когда он больше нуля.
