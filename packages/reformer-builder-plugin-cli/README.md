# @reformer/builder-plugin-cli

`reformer-plugin` — командная строка автора плагина ReFormer Builder: создать плагин из шаблона
и проверить его **теми же правилами, которыми его проверит оболочка**, до того как нести в билдер.

```bash
npx @reformer/builder-plugin-cli create acme-forms --name "Acme Forms"
cd acme-forms && npm install
npx reformer-plugin validate
```

## Команды

### `create <каталог> [--id <id>] [--name <имя>]`

Кладёт в пустой (или несуществующий) каталог готовый плагин:

| Файл                            | Что это                                                                       |
| ------------------------------- | ----------------------------------------------------------------------------- |
| `manifest.json`                 | манифест исходников: `main` → `src/main.ts`, словари объявлены                |
| `src/main.ts`                   | плагин с одной командой, подпись которой берётся из словаря                   |
| `src/main.test.ts`              | `id` кода совпадает с `id` манифеста — иначе оболочка откажет (`id-mismatch`) |
| `locales/ru.json`, `en.json`    | плоские словари «ключ → строка»                                               |
| `package.json`, `tsconfig.json` | `@reformer/builder-plugin-api` в `devDependencies`                            |

Идентификатор по умолчанию — имя каталога. Годится ли он, решает разбор манифеста оболочки,
а не собственное правило CLI. В непустой каталог команда не пишет.

Созданный плагин можно положить в `.ui_builder/plugins/<id>/` проекта как есть: оболочка сама
транспилирует `src/main.ts`.

### `validate [каталог]`

Код выхода `0` — оболочка плагин примет, `1` — нет, и почему именно, напечатано построчно.

- **манифест** — разбором из `@reformer/builder-plugin-api/tooling`, тем же, что у оболочки.
  Отличий у исходников два: имя каталога с `id` не сверяется (репозиторий зовётся как угодно),
  а `version` обязательна и должна быть версией — по ней публикуется пакет;
- **файлы, на которые ссылается манифест**: точка входа существует и это код, таблица стилей
  существует, словари существуют и плоские. Эти отказы собираются все сразу;
- **версия `package.json`** совпадает с версией манифеста. Этого оболочка не проверяет —
  `package.json` она не читает, — а расхождение означает пакет одной версии с плагином другой.

Коды отказов — коды оболочки (`manifest-invalid`, `api-version`, `entry-missing`,
`messages-invalid`…), свой у CLI один: `package-version`.

Пока не проверяется: соответствие `provides` тому, что плагин регистрирует при активации,
и потолок числа файлов. Первое требует исполнить код, второе относится к собранному каталогу —
обе проверки придут вместе с командой `build`.

## Программный вход

```ts
import { createPlugin, validatePlugin } from '@reformer/builder-plugin-cli';

const result = await validatePlugin('./acme-forms');
if (!result.ok) console.log(result.findings);
```
