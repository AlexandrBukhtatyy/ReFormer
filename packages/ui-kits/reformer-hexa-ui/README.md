# @reformer/kit-hexa-ui

Кит ReFormer поверх дизайн-системы Kaspersky HexaUI: поля с адаптерами формы, обёртка и рамка
поля на HexaUI `Field`, провайдер темы, каталог компонентов — и плагин ReFormer Builder, который
ставит этот кит в билдер.

Пакет приватный: он живёт в монорепо как пример кита, внесённого плагином. Билдер о HexaUI не знает
ничего — ни в зависимостях, ни в составе.

## Кит в приложении

```ts
import { FormField, Input, Select, KitProvider } from '@reformer/kit-hexa-ui';
import catalog from '@reformer/kit-hexa-ui/catalog';
```

Вход пакета подключает готовый CSS дизайн-системы (`@kaspersky/hexa-ui/.../styles.css`). Форму
оборачивают в `KitProvider` — это `ConfigProvider` HexaUI с темой, следующей классу `dark` на
`<html>`.

## Кит в билдере — внешним плагином

Плагин — тот же пакет: `manifest.json` (id `kit-hexa-ui`), точка входа `src/builder-plugin.ts`,
стили `src/builder-plugin.css`. Он вносит кит в точку `reformer.kit.source` и требует от оболочки
службу китов `reformer.kit.catalog ^2`.

```bash
npm run plugin:validate -w @reformer/kit-hexa-ui   # пропустит ли оболочка
npm run plugin:build -w @reformer/kit-hexa-ui      # сборка в dist/
npm run plugin:dev -w @reformer/kit-hexa-ui -- --project <каталог проекта>
```

Собранный `dist/` кладётся в проект как `.ui_builder/plugins/kit-hexa-ui/` (или туда пишет
`plugin:dev`). Дальше — включить плагин в списке плагинов и выбрать кит «Kaspersky HexaUI».

Что грузится когда:

- **каталог** — значением при включении плагина: по нему кит виден в выборе;
- **пространство имён** (HexaUI с antd и styled-components, ~4 МБ) — динамическим импортом, когда
  кит выбран и форма рисуется. `src/builder-plugin.ts` его статически не импортирует;
- **стили** — полем `styles` манифеста. Оболочка ставит их с изоляцией `scoped`: каждый селектор —
  под `[data-rb-plugin="kit-hexa-ui"]`, а этот атрибут вешает рамка кита вокруг формы в превью.
  Ресет antd (`html`, `body`, `*`) поэтому действует на форму, а не на билдер.

Сборка (`reformer-plugin build`) проверяет то же, что оболочка: разбор манифеста, «сухую»
активацию и каталог кита — той же проверкой контракта, что у реестра китов.

## Ограничения

- `@kaspersky/hexa-ui` объявляет `react: 16.x || 17.x || 18.x`, билдер работает на React 19.
  Внутри HexaUI живут antd@4 и styled-components@5; отдельные компоненты могут падать. Билдер
  изолирует каждый компонент, поэтому падение даёт плашку, а не крах превью.
- `GlobalStyle` HexaUI и `@kaspersky/hexa-ui-core` кладут CSS-переменные палитры, типографику и
  шрифты прямо в `<head>` — мимо изоляции стилей плагина. Пересечений с токенами билдера у них нет,
  но это глобальный эффект, и он появляется, когда кит впервые рисует форму.
- styled-components вложен в сборку плагина. Повторное включение плагина в той же вкладке
  линкует `main.js` заново, и styled-components предупреждает в консоли о втором экземпляре;
  перезагрузка вкладки его убирает.
- Выпадающий список `Select` HexaUI по умолчанию рисуется в родителе поля — внутри рамки кита,
  со стилями плагина. С `usePortal` он уходит в `document.body`, за пределы скоупа, и остаётся без
  них: портал плагина обязан лежать внутри его контейнера.

## Проверки

```bash
npm run typecheck -w @reformer/kit-hexa-ui
npm test -w @reformer/kit-hexa-ui
```

Тесты — в node и HexaUI не исполняют: идентификатор и версия совпадают с манифестом, вклад в точку
китов, ленивое пространство имён, каталог по контракту SDK, каждый символ каталога есть
в пространстве имён.
