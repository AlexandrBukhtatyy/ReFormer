# Сценарии MCP

Лестница заданий от одной фразы до формы по спецификации. Агент выполняет задание через MCP-сервер,
верификатор судит результат по контракту. Метод и итоги — [docs/mcp-eval/scenarios.md](../../../../docs/mcp-eval/scenarios.md).

```
<id>/
  scenario.json          уровень, таргеты, бюджет, спека, эталон
  prompt.md              задание словами разработчика
  contract.json          что проверить: поля, шаги, массивы, образец значений, пробы
  reference.intent.json  эталон: FormIntent, из которого сервер обязан собрать форму, проходящую контракт
```

`reference` — путь к intent относительно каталога сценария либо `plan_form` (сервер строит intent из
спеки сам). Эталон доказывает, что контракт выполним: `npm run mcp:verify -- --golden`.

## Контракт

- `fields[]` — `id`, `bind` (`path`, `paths` — кандидаты, `label` — регулярка по подписи), `type`, `aria`
  (`role` — через `|`, `name` — регулярка: роль, подпись и порядок сверяются со снимком доступности).
  До L3 имена полей в задании не названы, поэтому привязка мягкая; с L3 названы и привязка — по пути.
- `steps[]`, `arrays[]` — структура.
- `sample` — валидное заполнение, от которого отклоняется каждая проба.
- `probes[]` — `id`, `gate` (провал роняет вердикт), `sample: false` (без образца), `set` (значения;
  `{ push: {…} }` добавляет строку массива, `{ removeAt: n }` удаляет), `expect` (`valid`, `invalid[]`, `noIssues[]`, `errorCode{}`,
  `disabled[]`, `enabled[]`, `values{}`, `positive[]`, `expressions[]`, `arrayLength{}`), `where: "browser"` (`hidden[]`, `visible[]`,
  `readonly[]`: видимость и доступность ввода исполняет только рендерер).

Проба не должна требовать того, чего нет в задании. Например, образец сообщения длиннее, чем обычно
просят: агент вправе добавить минимальную длину. Иначе честная работа окажется красной.
