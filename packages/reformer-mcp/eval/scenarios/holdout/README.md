# Holdout-сценарии

Под них сервер не подгоняется. Раннер берёт их только с `--include-holdout`, а `mcp:compare` и
`mcp:report` показывают их агрегатом. Провалы holdout не становятся задачами на правку сервера: задача
формулируется по похожему настроечному сценарию. Смотреть результат стоит как контрольную проверку
уже выбранного решения, а не как материал для выбора.

**Сейчас каталог пуст.** Прежний holdout (L1-callback, L2-event-signup, L3-refund, L4-expense-report,
L5-insurance) удалён 2026-11-14 вместе со старой лестницей L1–L5 (ReFormer-mhsh). Его задания писал
агент, который знает сервер, поэтому полностью независимым набор не был. Старые записи прогонов
остаются в истории метрик.

Новый holdout пишет человек или сессия, которая не видела сервер. Формат — как у любого сценария
([../README.md](../README.md)): каталог со `scenario.json`, `prompt.md`, `contract.json` и
эталоном. Holdout-сценарий может быть и правкой (`seed`), если его затравка — настроечный сценарий
создания.
