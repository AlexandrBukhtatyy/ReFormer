# Holdout-сценарии

Под них сервер не подгоняется. Раннер берёт их только с `--include-holdout`, а `mcp:compare` и
`mcp:report` показывают агрегатом. Провалы holdout не становятся задачами на правку сервера: задача
формулируется по похожему настроечному сценарию. Смотреть результат стоит как контрольную проверку
уже выбранного решения, а не как материал для выбора.

| Сценарий          | Уровень | Таргет         | Чистота                                                                                       |
| ----------------- | ------- | -------------- | --------------------------------------------------------------------------------------------- |
| L1-callback       | 1       | renderer-json  | `authored`                                                                                    |
| L2-event-signup   | 2       | core           | `authored`                                                                                    |
| L3-refund         | 3       | renderer-react | `authored`                                                                                    |
| L4-expense-report | 4       | renderer-json  | `authored`                                                                                    |
| L5-insurance      | 5       | renderer-react | `partial`: по этой спеке уже правили сервер (ReFormer-j356.4.20), контракт только структурный |

`authored`: задания написал по просьбе пользователя агент, который знает сервер и видел настроечные
сценарии. Правок сервера под них не было, но полностью независимым такой набор не считается. Если
понадобится контроль строже, задания пишет человек или сессия, не видевшая сервер: формат — как у
любого сценария, описан в `../README.md`.
