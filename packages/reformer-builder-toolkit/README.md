# @reformer/builder-toolkit

Нейтральные кирпичи для стеков ReFormer Builder — то, что нужно любому стеку, какой бы формат
схемы и способ отрисовки он ни приносил.

```bash
npm install @reformer/builder-toolkit
```

## Что такое стек

Стек (домен) — набор плагинов билдера, который приносит свой формат схемы формы, свой редактор,
превью, кодоген и валидатор. Стек ReFormer редактирует схемы `@reformer/renderer-json`; другой стек
может принести совсем другой формат. Предметный код стека живёт ядром домена внутри билдера
(`src/plugins/<домен>/core`); оболочка билдера о стеках не знает: она получает вклады плагинов
и службы.

## Что здесь есть

| Имя                                                                                     | Зачем                                                                                              |
| --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `renderTemplate`, `registerPartial`                                                     | Eta, настроенный для печати КОДА: без экранирования, пробелы передаются буквально                  |
| `withMarker`, `isGenerated`, `originOf`, `acceptsMarker`, `MARKER_PREFIX`, `keepOrigin` | маркер `// @reformer-generated <hash>`: по нему доставка решает, можно ли перезаписать             |
| `translit`, `kebab`                                                                     | имена файлов и селекторов из подписей на кириллице                                                 |
| `createToolRegistry` (вход `@reformer/builder-toolkit/registry`), `TOOL_TEXT_BUDGET`    | реестр инструментов модели: проверка аргументов по схеме, отказы с похожими именами, бюджет ответа |
| `measureToolSurface`, `TOOL_NAME_BUDGET`, `TOOL_DESCRIPTION_BUDGET`                     | мера поверхности инструментов, которую ход платит на каждом шаге, и лимиты одного инструмента      |
| `pageOf`, `linesOf`, `snippetOf`, `changedLines`, `joinWithinBudget`, `similarNames`    | текст для модели: страницы файла со строками, ответ по целым строкам в бюджете, подсказки имён     |
| `createFileJournal`, `pathWithin`                                                       | журнал хода режима файлов (его заводит ассистент, пишет стек) и путь от корня модуля               |
| `parseTargetFile`, `formatTargetFile`                                                   | файл цели генерации из проекта: заголовок JSON между `---` и шаблон; читает хозяин, выгружает стек |
| `applyOverrides`, `overrideDrift`                                                       | замены целей: кто печатает и какие замены не действуют; устаревание замены узнаёт стек крючком     |
| `targetsOfStack`                                                                        | цели одного стека: свои, общие и замены его целей (замена наследует стек заменённой)               |

Реестр — отдельным входом `@reformer/builder-toolkit/registry` (его типы есть и в главном): он
грузит ajv отложенным импортом, а сборщик плагина выносит такой импорт в чанк каждому, кто
импортирует модуль с ним, даже если реестр не зовёт никто. Из главного входа печать, маркер и
правило замен берут генерация кода и шаблоны — их сборки чанка ajv не везут.

## Что сюда НЕ попадает

Критерий — не «код не знает про ReFormer», а «код нужен двум стекам» — или общему плагину и
вкладу стека в него (ассистенту и стеку форм в нём): они живут в разных доменах, и делить код им,
кроме контракта, больше негде. Нейтральный модуль, который
нужен одному стеку, остаётся в ядре этого стека: вынести его «на будущее» значит завести
контракт, которым никто не пользуется, и платить за его совместимость при каждой правке.
