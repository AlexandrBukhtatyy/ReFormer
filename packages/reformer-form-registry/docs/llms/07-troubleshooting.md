# Troubleshooting

Симптом → причина → что делать. Большинство отказов реестра **молчаливы**, поэтому список
отсортирован по коварности, а не по частоте.

## Форма не появилась, в DOM пусто, ошибок нет

Запись либо не найдена, либо отсеяна гейтом — снаружи это неотличимо, и намеренно: пустая рамка на
месте недоступной формы сообщала бы о её существовании.

```ts
const reg = getFormRegistry();
console.log(reg.list().map((e) => `${e.owner}/${e.id}@${e.version}`)); // зарегистрирована ли
console.log(reg.resolve({ by: 'id', id: 'checkout' }, ctx)); // проходит ли гейт
console.log(reg.diagnostics); // конфликты id
```

Частые причины: микрофронт ещё не смонтировался; `unregister` вызван раньше времени; в `ctx` не
попало право или флаг из `access`.

## Поля отрисовались голыми — без label, подсказки и места под ошибку

Реестр компонентов дошёл, а производная от него обёртка полей (`$fieldWrapper`) — нет. Признак в
разметке: `<input label="Фамилия">` — атрибут `label` уехал прямо в DOM, потому что его никто не
потребил.

В единой сборке обёртку берёт из реестра формы сама сборка (`registry.resolveSchema`) и кладёт в
бандл — проверьте, что запись `FIELD_WRAPPER` есть в базовом реестре или в расширении записи. На
прежнем пути (`JsonFormRenderer`) обёртку доставал **провайдер**, и реестр, пришедший в обход
провайдера (пропом или в бандле `form`), её терял; починено в `@reformer/renderer-json` — обёртка
берётся из того реестра, который реально используется.

## Валидация «не работает» на конкретном поле

Поля нет в начальных значениях → у него нет сигнала → ни поведение, ни замечания к нему не
привяжутся. Прогон правил разносит замечания через `getNodeForSignal(handle)?.setIssues(...)`, и
опциональная цепочка молча глотает замечание.

Preflight ловит это как `unmaterialized-model-paths` (уровень `warn`). Проверьте
`loaded.preflight.problems` — или включите `preflight: 'error'`.

## Замечания есть, а текста нет — показан код

Правило несёт только код (`required({ code: 'delivery.required' })`), строку по коду даёт словарь.
Если на месте текста виден сам код, словаря формы нет выше по дереву: оберните место монтирования в
`ValidationMessagesProvider messages={…}` из `@reformer/cdk` (словарь — `defineIssueMessages`, это
код, и по сети он не едет).

## Пошаговая валидация молча не срабатывает на одном шаге

Шаг переименовали в документе, а `id` в `flow.steps` записи остался прежним. Идентификатор шага
потока — это **селектор** узла шага, и договорённость держится только на совпадении строк.

Ловится как `unknown-step-selectors`; сообщение перечисляет доступные селекторы. В dev то же
расхождение видят сборка («в `flow.steps` есть шаги, для которых в дереве схемы нет узла») и визард
(«шаги схемы и шаги потока расходятся»).

## `Component "..." not found in registry`

Схема ссылается на имя, которого нет в реестре. Если схема сетевая — почти наверняка она ушла вперёд
кода.

Задайте `compatibleSchema` и включите preflight: вместо одного промаха из конвертера вы получите
полный список плюс проверку версии.

## Форма собралась, но пишет не те поля

CDN отдал чужую схему. Ловится как `schema-identity-mismatch` — сверка `id` записи и `id` схемы.
Без неё отказ полностью молчалив: форма выглядит работающей.

## `enableWhen` перестал работать / вычисляемые поля затираются

Классический признак **двух копий `@reformer/core`** в одном realm. См. `06-guard.md`: подключите
`stampRuntime` в каждом бандле и `reportRuntime` в хосте.

Проверьте заодно, что `observed` не пуст — пустой означает, что guard просто не подключён, а не что
дублей нет.

## `Cannot find module '@reformer/renderer-react'` у потребителя

Типы пакета ссылаются на `RenderBehaviorFn`. Пакет объявлен в `peerDependencies` — установите его
рядом. Внутри монорепозитория проблема не воспроизводится: там работает симлинк.

## Схема не грузится по сети

Смотрите `kind` у `FormFetchError`:

| `kind` | что случилось |
| --- | --- |
| `not-json` | пришёл `text/html` — почти всегда SPA-fallback отдал `index.html` вместо файла |
| `not-a-form-schema` | JSON без `root` — чужой эндпоинт или ответ об ошибке в виде объекта |
| `http-error` | 4xx не ретраится намеренно; 5xx ретраился и исчерпал попытки |
| `network` | сеть недоступна |
| `aborted` | отменено — размонтировали последнего ожидающего |

## Кэш отдаёт устаревшую схему

`maxAgeMs` (дефолт 5 минут) ещё не истёк. Точечно:

```ts
await cache.invalidate(`${owner}/${id}@${version}#schema`);
```

Кэш выбрасываемый — `cache.clear()` безопасен в любой момент.

## Бесконечный цикл рендера, React error #185

`useSyncExternalStore` сравнивает снимок по ссылке. Если ваш код оборачивает `registry.list()` в
`map`/`filter` внутри рендера, каждый вызов даёт новый массив. Сам `list()` ссылку сохраняет, пока
состав реестра не менялся, — не ломайте это трансформацией на месте, мемоизируйте.

## `entry.ts` от билдера не компилируется

Запись прежнего контракта: фабрика `renderBehavior` получает `(form, model, level, options?)` —
третьим параметром идёт собранный уровень формы (`FormLevel`: `submission`, `validate`, `flow`),
а не правила валидации; настройки места — четвёртый параметр. Сгенерированная фабрика вида
`(form, model, options)` подключается переходником:
`value: (form, model, _level, options) => createRenderBehavior(form, model, options)`.

Лучше перевести запись на единый контракт: правила узлов — в `behavior` (фабрика
`(options) => defineFormBehavior(…)` получает настройки места), правила шагов — в `flow`, поле
`renderBehavior` убрать. Настройки места хост передаёт пропом `behaviorOptions` (прежнее имя
`renderBehaviorOptions` работает как синоним).
