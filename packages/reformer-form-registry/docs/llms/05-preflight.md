# Preflight — проверки до сборки формы

Конвертер документа синхронный и бросает на первом же незарегистрированном компоненте. Для схемы,
приехавшей по сети, это самый вероятный отказ — и бросок из конвертера называет один промах, ничего
не говоря ни о версии, ни о том, сколько промахов впереди.

Preflight собирает полную картину до того, как форма начнёт строиться.

```ts
const loaded = await loadForm(entry, baseRegistry, {
  preflight: 'error', // дефолт | 'warn' — только диагностика | 'off'
  onDiagnostic: (d) => telemetry.warn(d.code, d.message),
});
```

Документ проверяется в обоих форматах. В формате 2 обход идёт и по именованным частям (`parts`):
их операторы и селекторы учитываются наравне с корневым деревом, а пути модели внутри части
достраиваются от группы, к которой она подключена.

## Шесть проверок

| проверка | код | что ловит |
| --- | --- | --- |
| `compatibleSchema` ↔ версия схемы | `schema-version-drift` | схема ушла вперёд кода: CDN отдал v2, поведение осталось v1 |
| `id` записи ↔ `id` схемы | `schema-identity-mismatch` | CDN отдал ЧУЖУЮ схему — форма молча пишет не те поля |
| имена операторов ⊆ реестр | `missing-components`, `missing-data-sources`, `missing-fns` | ссылка на незарегистрированный компонент/источник/функцию |
| имена `$part(...)` ⊆ `parts` документа | `missing-parts` | подформа или шаблон строки ссылается на необъявленную часть |
| шаги потока ⊆ селекторы | `unknown-step-selectors` | пошаговая валидация молча не срабатывает на переименованном шаге |
| пути `$model(...)` ⊆ начальные значения | `unmaterialized-model-paths` | поля нет в модели → нет сигнала → **ошибки валидации тихо исчезают** |

Каждая ловит отказ, который иначе молчалив или называет только первый промах.

### Шаги потока против селекторов

Поток шагов записи (`flow: { steps: [{ id, rules }] }`, `FormFlowConfig` из `@reformer/core`)
адресует шаги идентификатором, равным `selector` узла шага в документе. Договорённость держится
только на совпадении строк: переименовали шаг в документе — его правила перестали бы проверяться,
молча. Preflight сверяет каждый `flow.steps[].id` с селекторами документа (включая части) и
перечисляет известные селекторы в сообщении.

### Про последнюю, самую коварную

Прогон правил разносит замечания по нодам через `getNodeForSignal(handle)?.setIssues(...)`.
Опциональная цепочка означает, что для поля, отсутствующего в начальных значениях, сигнала нет — и
замечание просто исчезает. Ни поведение, ни валидация к такому полю не привяжутся, и никто об этом
не скажет. Симптом на месте выглядит как «валидация не работает», причина — в структуре начальных
значений.

Индексы массивов (`items.0.name`) из проверки исключены: массив на старте пуст по определению, и
отсутствие элемента ошибкой не является. Шаблон строки массива (`item`) против начальных значений не
проверяется: его пути относительны элементу.

## Уровни

- `error` — форму собирать нельзя, `loadForm` бросает `FormPreflightError`;
- `warn` — соберётся, но часть поведения молча не сработает; попадает в `loaded.preflight.problems`.

Единственная проверка уровня `warn` — нематериализованные пути: форма при этом работает, просто её
валидация частично мертва.

## Проверяется СОСТАВНОЙ реестр

Preflight получает реестр уже после `composeRegistries(base, own)`. Если бы он смотрел только в
базовый, любое расширение записи давало бы ложный отказ — и, что хуже, потеря композиции прошла бы
незамеченной.

## Проверяется документ ПОСЛЕ перевода

Запись единого контракта получает документ формата 2: загрузчик переводит прежний формат
(`migrateJsonSchema`) до проверок, поэтому preflight видит шаги визарда уже в `children`. Документ
записи прежнего контракта (с `renderBehavior`) проверяется как есть.

## Валидация схемы мета-схемой

Стратегия комбинированная:

- **до релиза** — все `inline`/`module` схемы прогоняются полным ajv в тесте; рантайм-стоимость
  нулевая;
- **в релизе** — валидируются только сетевые схемы, потому что только они могут разойтись с кодом
  после сборки.

```ts
import { validateSchemaCached, assertSchemaValid } from '@reformer/form-registry/manifest';
```

`validateFormSchema` создаёт `new Ajv()` и компилирует мета-схему на КАЖДЫЙ вызов — при слоте с
пятью формами это пять компиляций одного и того же. `validateSchemaCached` кэширует результат по
паре (схема, реестр) через `WeakMap`: схема иммутабельна, повторная проверка того же объекта не
может дать другой ответ, а `WeakMap` не удерживает схемы от сборки мусора.
