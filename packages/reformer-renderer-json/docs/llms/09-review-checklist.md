# Чек-лист ревью формы

Короткий список для проверки формы на `@reformer` за пять минут. Собран по итогам реального
переноса большой формы между UI-китами (см. рекомендации §10). Проверяет границы слоёв и типовые
молчаливые поломки.

## Границы слоёв

- [ ] в документе схемы (`form.schema.json` / `form.schema.ts`) только структура и пропы —
      **никаких функций и рантайм-сущностей** (правила, расчёты, компоненты живут в TS-файлах, не в
      схеме);
- [ ] правила валидации (`form.validation.*`) **не импортируют** React и папку моста к UI-kit
      (валидация — над ручками модели, а не над деревом рендера); правила несут коды, тексты — в
      словаре `defineIssueMessages`;
- [ ] поведение формы одно (`defineFormBehavior`): значения модели меняют операторы модели
      (`compute`/`enableWhen`/`onChange`), дерево рендера — операторы узлов
      (`hideWhen`/`patchProps`/`onComponentEvent`); бизнес-расчёты не в правилах узлов.

## Связи по строкам (ломаются молча)

- [ ] у каждого узла, который адресует поведение, есть `selector`, и он в union-типе селекторов
      страницы (опечатка → ошибка компиляции, а не тихий промах);
- [ ] `id` шагов потока (`flow.steps[].id`) совпадают с `selector` узлов шагов визарда — иначе
      визард не свяжет шаг с разметкой (dev-предупреждения сборки и визарда);
- [ ] `$model(path)` пути соответствуют форме модели — типизируй схему `defineJsonSchema<T>()`,
      чтобы опечатка ловилась компилятором;
- [ ] шаблон новой строки массива объявлен в модели (`arrayOf(blank)`); `initialValue` узла, если
      он есть, содержит **все** ключи элемента — `validateFormSchema` это проверяет;
- [ ] документ проверяется `validateFormSchema` хотя бы в dev — ловит неизвестные
      `$component`/`$dataSource`/`$part` и структурные ошибки до сборки.

## Валидация и видимость

- [ ] правила шагов — в потоке сборки (`flow: { steps: [{ id, rules }] }`), а не в узлах и не по
      индексу шага; «Далее» и отправка сами помечают проверенные поля `touched`;
- [ ] скрытие секции (`hideWhen`) идёт в паре с отключением/сбросом полей в поведении — иначе
      скрытое поле продолжает валидироваться и уезжает в значения отправки;
- [ ] предикаты `hideWhen` читают значение внутри колбэка (`model.x`), иначе они не реактивны.

## Рендер и мост

- [ ] в реестре — сами компоненты `@reformer/ui-kit` (`Input`, `InputNumber`, `SelectAsync`, …): диалект
      поля они объявляют статикой `reformerAdapter`; число — `InputNumber`, а не `Input` с
      `type: 'number'`; чужим контролам без статики — `resolveFieldAdapter`;
- [ ] у каждого контрола в реестре, который сам потребляет ноду формы, стоит `reformerNeedsControl`
      либо `passControl` в его `FieldAdapter`; остальным `control` не нужен;
- [ ] модель и форма собираются **один раз** — `createForm` внутри `useFormBundle` (ленивый
      `useState`), а не пересоздаются в `useMemo`/на каждый рендер (иначе теряется введённое);
- [ ] визард зарегистрирован как есть (`reg.component('FormWizard', FormWizard)`), без прикладного
      шима; отправка — `onComponentEvent(schema.node('wizard'), 'onSubmit', (values) => …)`,
      навигация — `flow.goTo(id)`;
- [ ] реестр уровня страницы — это нормально и должно быть дефолтом; в общий реестр моста выносится
      только то, что переиспользуется несколькими формами.
