# Инфографика по коду → Excalidraw

Генерирует схему монорепозитория `@reformer/*` в формате Excalidraw: карта пакетов
и их зависимостей сверху, ниже — «диаграмма кода»: каталоги, файлы, экспортируемые
символы и реальные вызовы между ними.

Формат вывода — markdown плагина [obsidian-excalidraw](https://github.com/zsviczian/obsidian-excalidraw-plugin)
(`excalidraw-plugin: parsed` + секции `## Text Elements` и `## Drawing`), поэтому файл
одинаково открывается и в Obsidian, и в excalidraw.com.

## Запуск

```bash
npm run diagram                              # полный прогон
npm run diagram -- путь/схема.excalidraw.md  # явный путь вывода
npm run diagram:redraw                       # перерисовать из готовой модели, без анализа кода
npm run diagram -- --no-check                # без проверки читаемости линий
npm run diagram -- --help
```

Куда пишется файл — первый подходящий вариант:

1. аргумент командной строки;
2. переменная окружения `REFORMER_DIAGRAM_OUT`;
3. `.tmp/code-viz/Reformer-all.excalidraw.md` (каталог в `.gitignore`).

Vault Obsidian у каждого свой, поэтому его пути в репозитории нет. Чтобы команда
писала прямо в vault, задайте переменную:

```bash
# PowerShell
$env:REFORMER_DIAGRAM_OUT = "D:/Work/obsidian/PARA/0.Projects/ReFormer/Reformer-all.excalidraw.md"
```

Либо пропишите её в `.claude/settings.local.json` (`env`), чтобы работало в агентских сессиях.

## Пайплайн

| Шаг | Скрипт               | Результат                                                                                                                                          |
| --- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `extract-code.mjs`   | `.tmp/code-viz/code-structure.json` — каталоги → файлы → экспортируемые символы, граф импортов. Разбор через `ts.createSourceFile`, без регулярок. |
| 2   | `extract-calls.mjs`  | `.tmp/code-viz/calls.json` — **реальные** вызовы методов классов и импортированных функций, тип получателя резолвится type checker-ом.             |
| 3   | `prepare-model.mjs`  | `.tmp/code-viz/code-model.json` — модель боксов и рёбер. Всё, что урезано, фиксируется в поле `caps`: молчаливых обрезаний нет.                    |
| 4   | `gen-excalidraw.mjs` | `.excalidraw.md` — координаты, боксы, ортогональная маршрутизация стрелок.                                                                         |
| 5   | `check-lines.mjs`    | отчёт о читаемости: дубли точек прикрепления, наложение параллельных линий, пересечения с блоками, крюки в маршрутах.                              |

`index.mjs` связывает шаги в одну команду. Каждый скрипт запускается и отдельно —
путь вывода первым аргументом, пути по умолчанию берутся из `paths.mjs`.

## Что стоит знать при правках

- **Генерация детерминирована.** PRNG засеян константой (`_s = 987654321`), поэтому
  одинаковый вход даёт побайтово одинаковый файл — diff показывает только реальные
  изменения схемы, а не перетасованные id.
- **Верхняя часть схемы (карта пакетов) задана в коде** `gen-excalidraw.mjs` вручную:
  тексты, акценты, выводы. Она не пересобирается из анализа — при существенных
  изменениях архитектуры её надо править руками.
- **Нижняя часть (диаграмма кода) строится из модели** и обновляется сама.
- `check-lines.mjs` печатает отчёт, но не роняет сборку: единичные «крюки» в маршрутах
  допустимы, важна динамика — пункты 1–3 должны оставаться нулевыми.
