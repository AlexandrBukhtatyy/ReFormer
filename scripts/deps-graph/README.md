# Граф зависимостей (dependency-cruiser)

Схема зависимостей всего монорепозитория или одного его проекта. Импорты разбирает
[dependency-cruiser](https://github.com/sverweij/dependency-cruiser), рисует Graphviz,
собранный в WebAssembly (`@hpcc-js/wasm-graphviz`), — системный Graphviz не нужен.

Не путать с `npm run diagram` ([scripts/diagrams](../diagrams/README.md)): там
Excalidraw-инфографика по классам и вызовам, здесь — кто кого импортирует.

## Запуск

```bash
npm run deps:graph                                  # весь монорепозиторий
npm run deps:graph -- @reformer/builder             # один проект — по имени пакета,
npm run deps:graph -- projects/reformer-builder     #   по пути
npm run deps:graph -- reformer-builder              #   или по имени каталога
npm run deps:graph -- @reformer/core @reformer/cdk  # несколько проектов за раз
npm run deps:graph -- --help
```

Результат пишется в `.tmp/deps-graph/` (каталог в `.gitignore`):

| Файл                             | Что на схеме                                                                                     |
| -------------------------------- | ------------------------------------------------------------------------------------------------ |
| `monorepo/workspaces.html`       | весь монорепозиторий: узел — воркспейс, ребро — импорты из одного в другой                       |
| `<каталог проекта>/folders.html` | проект: узел — папка до заданной глубины, справа — пакеты монорепозитория, от которых он зависит |
| `<каталог проекта>/modules.html` | с `--modules`: каждый модуль отдельно, в оформлении dependency-cruiser                           |

Рядом с каждым HTML лежат `.svg` (та же картинка) и `.dot` (исходник для Graphviz).
HTML — страница dependency-cruiser: наведение подсвечивает связи узла, правый клик
закрепляет подсветку, Esc снимает; подсказка на ребре — сколько в нём импортов.

## Как читать схему

- Сплошная линия — импорт в рантайме, пунктир — только `import type`, синие точки —
  только динамический `import()` (ленивая загрузка).
- Толщина ребра растёт с числом импортов; параллельные рёбра сливаются в пучки.
- Красное — цикл по рантайм-импортам. Связь только через `import type` цикла не даёт:
  она стирается при компиляции.
- `имя/*` — файлы, лежащие прямо в папке, у которой есть и вложенные группы.

В консоль печатаются пакеты монорепозитория, от которых зависит проект, циклы между
группами и циклы между модулями.

## Опции

| Опция             | Что делает                                                                                         |
| ----------------- | -------------------------------------------------------------------------------------------------- |
| `--depth <n>`     | глубина папок-узлов от корня проекта: 3 по умолчанию, 4 у билдера (`src/plugins/<домен>/<плагин>`) |
| `--focus <regex>` | только узлы, чей путь или имя совпали, и их соседи; действует и на `--modules`                     |
| `--npm`           | показать пакеты npm и встроенные модули Node                                                       |
| `--with-tests`    | учитывать тесты: `*.test.*`, `*.spec.*`, `testing/`, каталоги `tests/` рядом с `src`               |
| `--modules`       | для проекта — ещё и граф по модулям: крупный, удобен вместе с `--focus`                            |
| `--json`          | сохранить сырой результат dependency-cruiser (`cruise.json`)                                       |
| `--out <каталог>` | куда писать вместо `.tmp/deps-graph`                                                               |

```bash
npm run deps:graph -- @reformer/builder --focus plugins/rjsf              # домен RJSF и его соседи
npm run deps:graph -- @reformer/builder --modules --focus plugins/rjsf/   # он же по файлам
npm run deps:graph -- @reformer/core --npm                                # с внешними пакетами
```

## Как устроено

| Файл             | Что делает                                                                 |
| ---------------- | -------------------------------------------------------------------------- |
| `workspaces.mjs` | воркспейсы из `workspaces` корневого package.json: корни обхода и tsconfig |
| `analyze.mjs`    | обход воркспейса dependency-cruiser'ом, классификация каждого импорта      |
| `graph.mjs`      | сведение модулей к группам, поиск циклов, печать на языке DOT              |
| `render.mjs`     | DOT → SVG (wasm-Graphviz) → HTML                                           |
| `index.mjs`      | командная строка                                                           |

Что стоит знать при правках:

- **Каждый воркспейс обходится отдельно, со своим tsconfig.** Алиасы у проектов
  разные: у плейграунда `@builder-src/…` ведёт в исходники билдера, и без его tsconfig
  эта связь потерялась бы.
- **Куда ведёт импорт, решается и по разрешённому пути, и по спецификатору.** Пакеты
  `@reformer/*` разрешаются в свой `dist`, которого на свежем клоне нет, а суффиксы Vite
  (`?raw`, `?worker`) не разрешаются никогда. Имя пакета есть в спецификаторе всегда,
  поэтому граф не зависит от того, собран ли монорепозиторий.
- **`dist` и другие выходные каталоги не исключаются шаблоном** — они просто не
  попадают в корни обхода (`src`, а без него — верх воркспейса). dependency-cruiser
  сверяет `exclude` и с целью импорта, и шаблон `dist` выбросил бы ребро к пакету,
  разрешённому в его `dist`.
- **Глубина по умолчанию для отдельных проектов** — таблица `DEPTH` в `index.mjs`.
