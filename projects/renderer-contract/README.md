# renderer-contract

Контрактный набор рендерера ReFormer: одни и те же сценарии проходят рендереры React, Vue и
Angular. Набор отвечает на вопрос «рисует ли рендерер сборку `createForm` так же, как остальные»,
а не «устроен ли он так же внутри».

Пакет приватный и не собирается: рендереры подключают его исходники тестовой зависимостью.

## Как устроен

Сценарий собирает форму `createForm`, просит адаптер рендерера её смонтировать и смотрит в DOM. О
фреймворке сценарий не знает. Всё, что у стеков разное, — в адаптере:

- **кит компонентов-зондов** — десять компонентов с одинаковой разметкой: каждый пишет полученные
  пропсы в атрибуты `data-*`, событие вызывается кликом по кнопке `data-action`;
- **монтирование** — `mount(bundle, options)` возвращает `{ root, settle(), unmount() }`.

Разметка каждого зонда и правила для атрибутов описаны в [src/adapter.ts](src/adapter.ts) — это и
есть контракт кита. Главное правило: атрибут ставится, только когда компонент получил проп, — по
отсутствию атрибута сценарий видит, что проп до компонента не дошёл.

## Что проверяется

| Файл сценариев      | О чём                                                                                |
| ------------------- | ------------------------------------------------------------------------------------ |
| `tree`              | поле, подформа, строки массива; контейнер без компонента; сборка без схемы           |
| `scopes-visibility` | `hideWhen`, области подформ и строк, `setHidden` / `resetHidden`                     |
| `props-events`      | `patchProps`, `onComponentEvent`, сигналы и описатели `msg()` в пропсах              |
| `field-binding`     | значение в обе стороны, `disabled`, `touched`, диалект контрола, нода поля, `testId` |
| `wrapper`           | обёртка поля: откуда берётся, что получает, какие пропсы не доходят до контрола      |
| `arrays`            | строки, кнопки компонента массива, шаблон нового элемента, ключи строк               |
| `text-html`         | HTML-узлы и текст, в том числе реактивный                                            |
| `self-managed`      | компонент, который ведёт детей сам: узлы и `renderNode`                              |
| `context`           | сборка в контексте рендерера                                                         |
| `refs-lifecycle`    | ref узла, `onMount` / `onUnmount`, эффекты отрисовки                                 |

Вне набора — то, что есть не у всех стеков: неуправляемая привязка поля, низкоуровневый путь
`render` + `createRenderSchema`, граница ошибок, чистка атрибутов HTML-узлов.

## Как подключить рендерер

1. Добавить пакету рендерера тестовую зависимость `"renderer-contract": "*"` и поставить
   зависимости из корня репозитория.
2. Написать тестовый файл под окружением с DOM: кит и монтирование.

```ts
// @vitest-environment happy-dom
import { describeRendererContract, type ContractKit } from 'renderer-contract';

const kit: ContractKit = { Input, InlineInput, Toggle /* … */ };

describeRendererContract({
  name: 'renderer-vue',
  kit,
  mount(bundle, options) {
    // смонтировать `FormRenderer` со сборкой: `options.fieldWrapper` — в настройки рендерера,
    // `options.locale` — локалью поддерева
    return { root, settle, unmount };
  },
});
```

Требования к монтированию:

- к возврату `mount` первая отрисовка завершена и хуки монтирования исполнены; ошибка рендера —
  исключением или отказом промиса;
- `settle()` дожидается перерисовки после записи в сигнал и после события;
- к возврату `unmount()` хуки снятия исполнены, а `root` убран из документа.

Готовые образцы — `tests/contract.dom.test.tsx` рендерера React и `tests/contract.dom.test.ts`
рендереров Vue и Angular. У Angular хост зонда — сам нативный элемент (селектор `input[probeInput]`):
атрибуты, которых зонд входами не объявил, рендерер ставит на хост-элемент.

## Как добавить сценарий

Сценарий пишется в файл своей темы в [src/scenarios](src/scenarios) и работает только через
`ScenarioContext`: `form()` собирает форму, `mount()` монтирует, помощники из
[src/dom.ts](src/dom.ts) действуют за пользователя и читают DOM. Точная разметка (`cleanHtml`)
сравнивается только у поддерева из HTML-узлов и текста: у компонента в разметку может попасть его
хост-элемент, поэтому компоненты ищутся по атрибутам.

Новый сценарий сначала должен пройти на всех подключённых рендерерах; расхождение — повод
выяснить, какой из них прав, а не подгонять сценарий.

## Проверка

```bash
npm run typecheck -w renderer-contract
npm run test -w @reformer/renderer-react
npm run test -w @reformer/renderer-vue
npm run test -w @reformer/renderer-angular
```
