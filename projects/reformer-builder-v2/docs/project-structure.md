# Структура проекта v2

> К [implementation-plan.md](implementation-plan.md) и [core-contracts.md](core-contracts.md).
>
> Главное правило: **раскладка должна делать нарушение границы механически заметным.**
> Если «Host не знает про формы» держится на дисциплине, оно продержится до первого дедлайна.

## Решение: один проект, границы проверяются, а не подразумеваются

Внешний документ предлагает раскладку из npm-пакетов (`host`, `plugin-sdk`, `plugins/*`, `app`).
Сейчас это преждевременно: v2 приватный, локальный, публикуется не отсюда, и мы уже решили
не строить версионирование API и маркетплейс до появления внешнего автора.

Поэтому **один проект с внутренними слоями**, но раскладка такая, что вынос в пакеты позже —
перемещение каталога, а не переработка. Граница держится не соглашением, а правилом импортов
в линтере. Прецедент в репозитории уже есть: у `@reformer/mcp` отсутствие node-глобалов в ядре
проверяется отдельной командой, у пакетов — изоляция ajv.

## Пять слоёв и правила импорта

| Слой        | Что это                                                    | Кому можно импортировать            |
| ----------- | ---------------------------------------------------------- | ----------------------------------- |
| `host/`     | платформа: примитивы, Workspace, Source, сервисы, оболочка | только `host/` и внешние библиотеки |
| `sdk/`      | поверхность, которую видит плагин                          | только типы из `host/`              |
| `lib/`      | чистый домен: модель схемы, каталог, киты, компилятор      | `lib/` и внешние библиотеки         |
| `plugins/*` | вся предметная логика как вклады                           | `sdk/`, `lib/`, свой каталог        |
| `app/`      | композиция: какой Host с какими плагинами                  | всё                                 |

Три запрета, ради которых всё это и делается:

1. **`host/` не импортирует `lib/` и `plugins/`.** Это буквальное выражение принципа «Host
   не знает предметных сущностей». Нарушение видно сразу.
2. **`plugins/*` не импортируют друг друга.** Связь — через сервисы, команды и события.
3. **`lib/` не импортирует `host/`.** Домен остаётся переносимым: именно поэтому его можно
   взять из v1 почти дословно и позже вынести в пакет.

## Библиотека и плагин — не одно и то же

Тонкое место, на котором легко ошибиться.

Правило «плагины не связываются друг с другом» относится к **рантайм-состоянию и сервисам**,
а не к общему чистому коду. Модель схемы, каталог и компилятор нужны сразу нескольким плагинам —
редактору, валидатору, кодогену, ассистенту. Сделать их плагинами значит либо заставить плагины
зависеть друг от друга, либо гонять чистые функции через реестр сервисов.

Поэтому: **чистое и без состояния — в `lib/`, импортируется напрямую. Состояние и жизненный цикл —
в плагине, достаётся через сервис.**

Пример на активном ките: дескрипторы и типы китов — `lib/kits/` (чистые данные, импортируются
кем угодно), а «какой кит активен сейчас» — сервис плагина `plugins/kits/`, потому что это
состояние, и редактор с превью обязаны видеть одно и то же значение.

## Устройство плагина

```text
plugins/editor-schema/
├── index.ts          definePlugin — единственный экспорт наружу
├── plugin.ts         activate: регистрация вкладов
├── locales/{ru,en}.json
├── ui/               React-компоненты панелей и канваса
├── commands.ts
└── *.test.ts
```

Наружу плагин отдаёт **только** `index.ts`. Всё остальное — его внутренности; правило проверяется
запретом импорта `plugins/*/…` глубже корня.

**Словари везёт плагин.** Иначе Host снова начнёт знать предметные строки — а это ровно то,
что мы разбираем. Пространство имён словаря — идентификатор плагина.

## Как проверяется

Без новых зависимостей: `no-restricted-imports` с шаблонами в плоском конфиге ESLint, по одному
блоку `files` на слой.

```js
// eslint.config.js — набросок
{
  files: ['src/host/**'],
  rules: { 'no-restricted-imports': ['error', { patterns: [
    { group: ['**/lib/*', '**/plugins/*'], message: 'Host не знает предметной логики' },
  ]}]},
},
{
  files: ['src/plugins/*/**'],
  rules: { 'no-restricted-imports': ['error', { patterns: [
    { group: ['**/host/*'], message: 'Плагин видит платформу только через sdk/' },
    { group: ['../*/**'],   message: 'Плагины не импортируют друг друга: сервисы, команды, события' },
  ]}]},
}
```

Если правил станет много или понадобится граф — `scripts/check-boundaries.mjs` по образцу
уже имеющихся в репозитории проверок. Начинаем с линтера: он дешевле и срабатывает в редакторе.

**Правило приёмки:** нарушение границы валит `npm run lint`, а не выясняется на код-ревью.

## Что переезжает из v1 и куда

Домен переносится почти дословно, оболочка и состояние пишутся заново.

| v1                                       | v2                                           | Как                                                                                                                |
| ---------------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `model/`                                 | `lib/form-model/`                            | дословно + стабильные ID узлов                                                                                     |
| `catalog/`                               | `lib/catalog/`                               | дословно                                                                                                           |
| `kits/` (дескрипторы)                    | `lib/kits/`                                  | дословно                                                                                                           |
| `kits/` (активный кит)                   | `plugins/kits/`                              | как сервис; уходит перезагрузка страницы при переключении                                                          |
| `preview-runtime/live/`                  | `host/modules/` + `plugins/preview/`         | механика загрузки кода — платформенная, «что компилировать для формы» — предметное; реестр модулей неприкосновенен |
| `codegen/`                               | `plugins/codegen/`                           | цели генерации становятся вкладами                                                                                 |
| `templates/`, `app/*-templates.ts`       | `plugins/templates/`                         | переписывается: 900 строк накопленного объёма                                                                      |
| `canvas/`, `panels/`                     | `plugins/editor-*/`                          | переписывается против нового Workspace                                                                             |
| `agent/core/`                            | `plugins/ai/`                                | почти дословно: ядро уже без React и без состояния                                                                 |
| `io/fs-*`, `discovery`                   | `plugins/source-fs/`                         | **переписывается** против контракта Source                                                                         |
| `io/opfs`, `io/idb`, `draft-store`       | `host/workspace/storage/`                    | переписывается: working set вместо копии на вкладку                                                                |
| `app/save-actions.ts` (709)              | разносится                                   | **не переносится целиком**: это девять мест, ходивших к диску мимо рабочей копии                                   |
| `app/EditorLayout.tsx` (617)             | `host/ui/Shell.tsx` + вклады                 | переписывается; ввод уходит в редакторы, команды в реестр                                                          |
| `store/reducers.ts` (985)                | `host/workspace/` + `plugins/editor-schema/` | вкладки в Host, выделение и блочные операции в редактор                                                            |
| `pages/HomePage.tsx`, `react-router-dom` | —                                            | не переносится                                                                                                     |

Строки в третьей колонке — не украшение: `save-actions.ts`, панель файлов и шаблоны это те самые
2700 строк «накопленного объёма», и они же — самое связанное с источником. Их нельзя скопировать,
потому что копировать пришлось бы вместе с прямым доступом к диску, которого в v2 нет.

## Соглашения

- **Тесты рядом с кодом**, `*.test.ts` — как в v1, `include: ['src/**/*.test.ts']`.
- **Псевдоним `@/`** на `src/`, как в v1.
- **Один экспорт наружу у плагина** — `index.ts`.
- **Именование каталогов плагинов по роли**: `source-*`, `editor-*`, `validator-*`.
  Роль видна в дереве без открытия файлов.
- **`app/plugins.ts` — единственное место со списком плагинов.** Ответ на вопрос «из чего собрано
  это приложение» должен быть в одном файле; из него же потом вырастет конфигурация сборок.

## Решено по ходу

1. ~~Куда попадает панель файлов~~ — **решено** в [plugin-and-shell.md](plugin-and-shell.md):
   дерево ресурсов принадлежит Host (оно про источник и Workspace, а не про формы), а знание
   «этот JSON — схема формы» приходит вкладом-декорацией. Поэтому `plugins/files/` из раскладки
   уходит, а вместо него появляется `host/ui/ResourceTree.tsx` и вклад декораций
   в `plugins/editor-schema/`.
2. ~~Нужен ли отдельный `sdk/`~~ — **решено**: нужен, и вопрос снят решением о плагинах
   из каталога. `sdk/` — это буквально тот объект, который загрузчик подставляет плагину
   под именем `@builder/sdk` при линковке. Не лишний слой перенаправления, а точка подстановки.

## Каталог рядом с проектом

Конфигурация и плагины живут в `.ui_builder/` в корне открытого проекта:

```text
<проект>/.ui_builder/
├── config.json
├── component-catalog.json
├── templates/<slug>/
├── kits/<id>.json
└── plugins/<id>/          manifest.json, main.js, styles.css
```

Имя отличается от `.reformer/`, который v1 уже использует для шаблонов форм. Это осознанно:
каталог принадлежит инструменту, а не библиотеке форм, и разведение имён избавляет от вопроса,
чей это конфиг, когда рядом лежат оба.
