# Ассистент билдера: каталог сценариев e2e

Полный список того, что делает ассистент (плагин `reformer.ai`) глазами пользователя, и чем
каждый сценарий проверяется. Тест называется ID сценария в квадратных скобках: `'[M3] …'` —
по нему тест находится поиском, а сценарий — по имени упавшего теста.

Модель подменена (`shared/model-mock.ts`): ответы идут из очереди по одному на запрос, шлюз
держит запрос, пока тест не отпустит, — так проверяется всё, что случается посреди хода.

**Приоритет:** P0 — баги и фичи текущей работы, P1 — основные потоки, P2 — остальное.

**Статус:**

- `покрыт` — тест есть и проходит;
- `воспроизведение` — тест есть и падает на текущем коде: он и есть описание бага, зелёным
  станет вместе с исправлением;
- `план` — теста ещё нет;
- `unit` — в e2e не проверяется (нужен облачный канал, таймер и т. п.), покрыт тестами плагина.

Коды D1–D11 — дефекты бага «правки уходят не туда» из плана
`docs/plans/rustling-wibbling-kahn.md`.

## M — несколько форм (`multi-form.spec.ts`)

формами — между ходами и посреди хода.

| ID  | Сценарий                                                                               | P   | Статус      |
| --- | -------------------------------------------------------------------------------------- | --- | ----------- |
| M1  | Структурный: ход на A, затем на B — правки в своих формах; модели сказано о смене (D4) | P0  | покрыт      |
| M2  | Файлы: путь из прошлой формы не создаёт файл в модуле B (D3)                           | P0  | покрыт      |
