# reformer-builder-host-example

Приложение-образец со встроенным [`@reformer/builder`](../reformer-builder): билдер открывается
в рамке поверх страницы приложения, правит его исходники на диске, а форму в превью рисует
само приложение — со своим API, своими провайдерами и своими стилями. Отдаёт билдер dev-сервер
приложения; приложение его не компилирует.

Как встраивание устроено — [docs/embedding.md](../reformer-builder/docs/embedding.md) билдера.
Здесь — как запустить и что попробовать.

## Запуск

```bash
npm run dev -w reformer-builder-host-example               # http://localhost:5175
```

Перед запуском команда собирает плагины билдера на месте, в каталоге проекта-образца: билдер
берёт их оттуда живьём. Ей нужны собранные пакеты SDK и сборщика плагинов
(`npm run build -w @reformer/builder-plugin-api -w @reformer/builder-plugin-cli` и остальные
из списка в [README e2e](../reformer-builder-playground-e2e/README.md)) — те же, что билдеру
в своей вкладке. Сам билдер не собирается: dev-сервер приложения отдаёт его из исходников.

Первое открытие билдера после запуска дольше обычного: в этот момент поднимается его
dev-сервер и готовятся зависимости.

Браузер — Chromium: проект билдер открывает через File System Access.

## Что попробовать

1. Откройте `http://localhost:5175/contact` — страница приложения с формой обращения. Список
   городов в ней приходит из `GET /api/cities`.
2. Нажмите «Билдер» в углу страницы. Билдер открывается поверх приложения. Заголовок
   и умолчания у него — из `.ui_builder/config.json` этого приложения.
3. «Открыть папку…» → выберите каталог этого приложения
   (`projects/reformer-builder-host-example`). Выбор нужен один раз.
4. Откройте `src/forms/contact/schema/form.schema.json` и нажмите «Форма» в полосе вкладки (кнопка
   со значком, рядом с «Дерево» и «Схема»). В теле вкладки — форма, как её рисует приложение:
   без шапки приложения, со списком городов из API.
5. Вернитесь к «Дереву», выберите поле «Имя», откройте «Свойства» на правом рейле и поменяйте
   подпись. Снова «Форма»: приложение рисует прежнее — правка ещё не записана, и полоса над
   формой так и говорит. Сохраните (Ctrl+S или кнопкой в полосе): файл записан на диск,
   форма показана заново, уже с новой подписью.
6. Заполните и отправьте форму — уведомление показывает приложение, не билдер.
7. Откройте панель «Превью» на правом рейле — приложение целиком; по адресной строке можно
   ходить по приложению. Кнопка ↗ открывает его в отдельной вкладке, уже без билдера.
8. Оставьте в панели страницу `/contact` и откройте `src/services/cities.ts` — сервис,
   из которого форма берёт словарь. Поменяйте, чем подписана опция (`city.name` →
   `city.region`), сохраните — список городов на странице в панели изменился.
9. «Закрыть билдер» — приложение на той же странице и в том же состоянии. Откройте снова:
   проект и вкладки на месте, билдер не выгружался.
10. Палитра команд (Ctrl+Shift+P) → «Delivery Hello: привет» — команда плагина из
    `.ui_builder/plugins/delivery-hello` этого приложения. Выполните «Плагины: наблюдать
    «Delivery Hello» — режим разработки», поправьте `main.ts` плагина в своей IDE и вернитесь
    в браузер: плагин перечитан без перезагрузки страницы.

Проверка шагов 3 и 5–6 руками важна: автотест подменяет системный диалог выбора папки, и запись
через настоящий диалог он не проходит.

## Что внутри

| Путь                 | Что это                                                                                |
| -------------------- | -------------------------------------------------------------------------------------- |
| `vite.config.ts`     | `reformerBuilder()` — плагин, которым dev-сервер отдаёт билдер; API приложения         |
| `src/main.tsx`       | `<ReformerBuilder>` вокруг приложения, внутри его провайдеров                          |
| `.ui_builder/`       | конфиг билдера и плагин приложения — как у проекта, открытого билдером в своей вкладке |
| `server/`            | API приложения прямо в dev-сервере: `GET /api/cities`, `POST /api/contact-requests`    |
| `src/app/`           | провайдеры, навигация, каркас страниц                                                  |
| `src/notifications/` | уведомления приложения — свои, на обычном CSS                                          |
| `src/services/`      | сервисы приложения: словарь городов, приём обращений                                   |
| `src/forms/contact/` | модуль формы в раскладке, которую печатает кодоген билдера; `index.ts` — его экспорты  |

Первые две строки — всё встраивание. Ни псевдонимов, ни путей в `tsconfig`, ни каталога
плагинов у приложения нет.

Форма связана с приложением в двух своих файлах, которые при перегенерации не затираются:
`behavior/index.ts` берёт список городов у сервиса приложения, `api/index.ts` отправляет
обращение в его API и показывает его уведомление.

## Ограничения образца

- **Только dev и только Vite**: билдер отдаёт плагин его dev-сервера. В прод-сборке компонент
  билдера рисует одно приложение.
- **Только Chromium**: проект билдер открывает через File System Access.
- **Хранилище браузера общее**: адрес у билдера и приложения один.
