# reformer-builder-host-example

Приложение-образец со встроенным [`@reformer/builder`](../reformer-builder): билдер открывается
поверх страницы приложения, правит его исходники на диске, а форму в превью рисует само
приложение — со своим API, своими провайдерами и своими стилями.

Как встраивание устроено — [docs/embedding.md](../reformer-builder/docs/embedding.md) билдера.
Здесь — как запустить и что попробовать.

## Запуск

```bash
npm run builder:plugins -w reformer-builder-host-example   # каталог плагинов билдера → public/builder-plugins
npm run dev -w reformer-builder-host-example               # http://localhost:5175
```

Первая команда нужна один раз и после правок плагинов билдера: она собирает их для поставки
и кладёт в статику приложения. Ей нужны собранные пакеты SDK и сборщика плагинов
(`npm run build -w @reformer/builder-plugin-api -w @reformer/builder-plugin-cli` и остальные
из списка в [README e2e](../reformer-builder-playground-e2e/README.md)).

Браузер — Chromium: проект билдер открывает через File System Access.

## Что попробовать

1. Откройте `http://localhost:5175/contact` — страница приложения с формой обращения. Список
   городов в ней приходит из `GET /api/cities`.
2. Нажмите «Билдер» в углу страницы. Билдер открывается поверх приложения.
3. «Открыть папку…» → выберите каталог этого приложения
   (`projects/reformer-builder-host-example`). Выбор нужен один раз.
4. Откройте `src/forms/contact/form.schema.json` и панель «Превью» на правом рейле. В рамке —
   форма, как её рисует приложение: без шапки приложения, со списком городов из API.
5. Выберите в дереве схемы поле «Имя», откройте «Свойства», поменяйте подпись, вернитесь
   в «Превью» и сохраните (Ctrl+S). Файл записан на диск, рамка показала новую форму.
6. Откройте `src/services/cities.ts` — сервис, из которого форма берёт словарь. Форма в превью
   остаётся на экране. Поменяйте, чем подписана опция (`city.name` → `city.region`),
   сохраните — список городов в превью изменился.
7. Заполните и отправьте форму в превью — уведомление показывает приложение, не билдер.
8. Переключите превью на «Приложение» — страница целиком; по адресной строке можно ходить
   по приложению. Кнопка ↗ открывает его в отдельной вкладке, уже без билдера.
9. «Закрыть билдер» — приложение на той же странице и в том же состоянии.

Проверка шагов 3 и 5–6 руками важна: автотест подменяет системный диалог выбора папки, и запись
через настоящий диалог он не проходит.

## Что внутри

| Путь                      | Что это                                                                                   |
| ------------------------- | ----------------------------------------------------------------------------------------- |
| `src/main.tsx`            | всё встраивание: `<ReformerBuilder>` вокруг приложения, внутри его провайдеров            |
| `vite.config.ts`          | сборка: `builderHostResolve()` — псевдонимы исходников билдера; API приложения            |
| `tsconfig.app.json`       | те же псевдонимы для типов                                                                |
| `public/builder-plugins/` | каталог плагинов билдера (сборка, в git не едет)                                          |
| `server/`                 | API приложения прямо в dev-сервере: `GET /api/cities`, `POST /api/contact-requests`       |
| `src/app/`                | провайдеры, навигация, каркас страниц                                                     |
| `src/notifications/`      | уведомления приложения — свои, на обычном CSS                                             |
| `src/services/`           | сервисы приложения: словарь городов, приём обращений                                      |
| `src/forms/contact/`      | модуль формы в раскладке, которую печатает кодоген билдера; `index.tsx` — компонент формы |

Форма связана с приложением в двух своих файлах, которые при перегенерации не затираются:
`form.render.ts` берёт список городов у сервиса приложения, `api.ts` отправляет обращение в его
API и показывает его уведомление.

## Ограничения образца

- **Псевдонима `@` у приложения нет**: он принадлежит исходникам билдера. Свои модули
  приложение импортирует относительными путями.
- **React 19**: билдер исполняется на React приложения.
- **Только dev**: в прод-сборке компонент билдера рисует одно приложение.
