# reformer-builder-host-example

Приложение-образец со встроенным [`@reformer/builder`](../reformer-builder): билдер открывается
в рамке поверх страницы приложения, правит его исходники на диске, а форму в превью рисует
само приложение — со своим API, своими провайдерами и своими стилями. Отдаёт билдер dev-сервер
приложения; приложение его не компилирует.

Как встраивание устроено — [docs/embedding.md](../reformer-builder/docs/embedding.md) билдера.
Здесь — как запустить и что попробовать.

## Запуск

```bash
npm run dev -w reformer-builder-host-example               # http://localhost:5175
npm run preset:hexa-ui -w reformer-builder-host-example    # то же, активный кит — HexaUI
```

`dev` и `preset:ui-kit` — одно и то же: билдер стартует с китом `@reformer/ui-kit`.
`preset:hexa-ui` перед запуском собирает плагин кита HexaUI в `.ui_builder/plugins/kit-hexa-ui`
этого приложения (`npm run plugins:kit`, около 10 секунд; в git сборка не едет) и стартует билдер
с китом HexaUI. Подробнее — в разделе [Второй кит: HexaUI](#второй-кит-hexaui).

Перед запуском команда собирает плагины билдера на месте, в каталоге проекта-образца: билдер
берёт их оттуда живьём. Ей нужны собранные пакеты SDK и сборщика плагинов
(`npm run build -w @reformer/builder-plugin-api -w @reformer/builder-plugin-cli` и остальные
из списка в [README e2e](../reformer-builder-playground-e2e/README.md)) — те же, что билдеру
в своей вкладке. Ещё она собирает клиент билдера — `client/` пакета, то, что приложение
импортирует из `@reformer/builder`; он нужен и `typecheck`, и `build` образца
(`npm run build:client -w @reformer/builder`, если запускать их отдельно). Сам билдер
не собирается: dev-сервер приложения отдаёт его из исходников.

Первое открытие билдера после запуска дольше обычного: в этот момент поднимается его
dev-сервер и готовятся зависимости.

Браузер — Chromium: проект билдер открывает через File System Access.

## Что попробовать

1. Откройте `http://localhost:5175/contact` — страница приложения с формой обращения. Список
   городов в ней приходит из `GET /api/cities`.
2. Нажмите «Билдер» в углу страницы. Билдер открывается поверх приложения. Заголовок
   и умолчания у него — из пресета `.ui_builder/presets/ui-kit.json` этого приложения.
3. «Открыть папку…» → выберите каталог этого приложения
   (`projects/reformer-builder-host-example`). Выбор нужен один раз.
4. Откройте `src/forms/contact/schema/form.schema.json` и нажмите «Форма» в полосе вкладки (кнопка
   со значком, рядом с «Дерево» и «Схема»). В теле вкладки — форма, как её рисует приложение:
   без шапки приложения, со списком городов из API.
5. Вернитесь к «Дереву», выберите поле «Имя», откройте «Свойства» на правом рейле и поменяйте
   подпись. Снова «Форма»: приложение рисует прежнее — правка ещё не записана, и полоса над
   формой так и говорит. Сохраните (Ctrl+S или кнопкой в полосе): файл записан на диск,
   форма показана заново, уже с новой подписью.
6. Заполните и отправьте форму — уведомление показывает приложение, не билдер.
7. Откройте панель «Превью» на правом рейле — приложение целиком; по адресной строке можно
   ходить по приложению. Кнопка ↗ открывает его в отдельной вкладке, уже без билдера.
8. Оставьте в панели страницу `/contact` и откройте `src/services/cities.ts` — сервис,
   из которого форма берёт словарь. Поменяйте, чем подписана опция (`city.name` →
   `city.region`), сохраните — список городов на странице в панели изменился.
9. «Закрыть билдер» — приложение на той же странице и в том же состоянии. Откройте снова:
   проект и вкладки на месте, билдер не выгружался.
10. Палитра команд (Ctrl+Shift+P) → «Delivery Hello: привет» — команда плагина из
    `.ui_builder/plugins/delivery-hello` этого приложения. Выполните «Плагины: наблюдать
    «Delivery Hello» — режим разработки», поправьте `main.ts` плагина в своей IDE и вернитесь
    в браузер: плагин перечитан без перезагрузки страницы.

Проверка шагов 3 и 5–6 руками важна: автотест подменяет системный диалог выбора папки, и запись
через настоящий диалог он не проходит.

## Второй кит: HexaUI

Форма может быть нарисована не только `@reformer/ui-kit`: страница «Форма на HexaUI»
(`/contact-hexa`) — та же форма обращения на дизайн-системе Kaspersky HexaUI, модуль
`src/forms/contact-hexa`. Его напечатал кодоген билдера с активным китом HexaUI: реестр
импортирует компоненты из `@reformer/kit-hexa-ui`, а страница формы оборачивает её провайдером
кита `KitProvider` (у ui-kit провайдера нет — его страница прежняя). Поведение и отправка —
те же сервисы приложения, что у `contact`.

**Пресеты.** Какой кит билдер берёт активным, говорит конфиг запуска — пресет из
`.ui_builder/presets/`: `ui-kit.json` или `hexa-ui.json`. Пресет называет кит настройкой
`plugin.kits.active` в `defaults.settings`; его выбирает переменная `REFORMER_BUILDER_CONFIG`,
которую читает `vite.config.ts` (без неё — `ui-kit.json`). Выбор кита в строке состояния
билдера сильнее пресета и запоминается браузером; вернуть пресет — пункт «Как в конфиге
запуска». `.ui_builder/config.json` — конфиг проекта, в нём только заголовок: умолчания
действуют лишь на уровне запуска, и записанные там иначе, чем в пресете, билдер показывал бы
предупреждением при каждом открытии.

**Плагин кита.** Кит HexaUI приходит в билдер плагином проекта: `settings.json` включает
`kit-hexa-ui`, а сборку кладёт `npm run plugins:kit` (из исходников `@reformer/kit-hexa-ui`).
Пока сборки нет, включённый плагин билдер пропускает молча — в списке китов только ui-kit.

**Стили.** CSS HexaUI — ресет antd на `html`, `body` и теги, вне каскадных слоёв: подключённый
как есть, он перекрасил бы всё приложение на Tailwind, и навсегда — однажды загруженный CSS со
страницы не уходит. Поэтому `vite.config.ts` подключает плагин кита `hexaUiStyles()` из
`@reformer/kit-hexa-ui/vite`: селекторы без классов уходят под контейнер, который ставит
`KitProvider`, а классы дизайн-системы остаются глобальными — на них держатся всплывающие окна.
Страница грузится лениво: на остальных страницах HexaUI нет вовсе.

Что попробовать:

1. `npm run preset:hexa-ui -w reformer-builder-host-example` — в строке состояния билдера кит
   «Kaspersky HexaUI», в палитре компонентов — его поля (`WeeklySchedule`, `CheckboxGroup`).
2. Откройте `src/forms/contact-hexa/schema/form.schema.json` → «Форма»: форма на HexaUI.
3. Перейдите в приложении на «Форму на HexaUI» и обратно на «Главную»: шрифты, цвета и отступы
   остальных страниц не изменились.

**Кит — один на проект.** Палитра, превью и кодоген работают с активным китом, а модуль формы
печатается командой «Сгенерировать» — под него же. Модуль, напечатанный другим китом, команда
не перепечатывает: она отказывает и называет оба кита. Поэтому каждую форму правьте под пресетом
её кита: `contact` — под `dev`/`preset:ui-kit`, `contact-hexa` — под `preset:hexa-ui`.

## Что внутри

| Путь                      | Что это                                                                                      |
| ------------------------- | -------------------------------------------------------------------------------------------- |
| `vite.config.ts`          | `reformerBuilder()` — плагин, которым dev-сервер отдаёт билдер; API приложения; стили HexaUI |
| `src/main.tsx`            | `<ReformerBuilder>` вокруг приложения, внутри его провайдеров                                |
| `.ui_builder/`            | конфиг билдера и плагин приложения — как у проекта, открытого билдером в своей вкладке       |
| `.ui_builder/presets/`    | конфиги запуска билдера, по одному на кит: `ui-kit.json`, `hexa-ui.json`                     |
| `server/`                 | API приложения прямо в dev-сервере: `GET /api/cities`, `POST /api/contact-requests`          |
| `src/app/`                | провайдеры, навигация, каркас страниц                                                        |
| `src/notifications/`      | уведомления приложения — свои, на обычном CSS                                                |
| `src/services/`           | сервисы приложения: словарь городов, приём обращений                                         |
| `src/forms/contact/`      | модуль формы в раскладке, которую печатает кодоген билдера; `index.ts` — его экспорты        |
| `src/forms/contact-hexa/` | та же форма на ките HexaUI; страница `/contact-hexa` грузит её лениво                        |

Первые две строки — всё встраивание. Ни псевдонимов, ни путей в `tsconfig`, ни каталога
плагинов у приложения нет.

Форма связана с приложением в двух своих файлах, которые при перегенерации не затираются:
`behavior/index.ts` берёт список городов у сервиса приложения, `api/index.ts` отправляет
обращение в его API и показывает его уведомление.

Тексты замечаний под полями («Обязательное поле», «Введите корректный email») — словарь формы
`validation/messages.ts`, тоже её файл: правила в `validation/form.ts` несут только код
замечания, а страница `ContactForm.tsx` подключает словарь провайдером
`ValidationMessagesProvider`. Там же объявлен язык формы `formLocale` — русская локаль кита:
страница задаёт его форме своим `I18nProvider`, и склонения, единицы размера и подписи кита
по-русски при любой локали приложения. А в `validation/form.ts` выбрано, когда поле проверяется само,
не дожидаясь отправки, — на каждое изменение (`strategy: 'change'`): замечание уходит, как только
значение исправили.

## Ограничения образца

- **Только dev и только Vite**: билдер отдаёт плагин его dev-сервера. В прод-сборке
  (`npm run build`) плагин подменяет клиент заглушкой: в бандле приложения билдера нет.
- **Только Chromium**: проект билдер открывает через File System Access.
- **Кит — один на проект**: формы на разных китах правятся каждая под пресетом своего кита
  (см. [Второй кит: HexaUI](#второй-кит-hexaui)).
- **Хранилище браузера общее**: адрес у билдера и приложения один; своё билдер держит под
  пространством имён `reformer-builder`, и «Очистить кэш» сносит только его.
