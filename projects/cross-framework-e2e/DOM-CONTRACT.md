# DOM-контракт кросс-фреймворк проверки

Одна форма ReFormer рисуется в React, Vue и Angular — каждый раз китом своей библиотеки компонентов.
Сценарии не знают ни фреймворка, ни библиотеки: они находят элементы по `data-testid` и читают
состояние страницы из `window.__bench`. Этот документ — правила, по которым размечают страницу кит
и хост стека, чтобы общие сценарии прошли на нём без правок.

## Страница

- Адрес — `/cross/<форма>/` на сервере хоста; порты стеков — в [stacks.ts](stacks.ts).

  | Стек    | Хост                              | Кит                     | Драйвер списка                   |
  | ------- | --------------------------------- | ----------------------- | -------------------------------- |
  | React   | `react-playground`, Vite          | `@reformer/ui-kit`      | [ui-kit.ts](drivers/ui-kit.ts)   |
  | Vue     | `vue-playground`, Vite            | `@reformer/kit-vuetify` | [vuetify.ts](drivers/vuetify.ts) |
  | Angular | `angular-playground`, Angular CLI | `@reformer/kit-taiga`   | [taiga.ts](drivers/taiga.ts)     |

- **Документ формы** — `forms-benchmark/src/cross/<форма>.form.json`: документ участника бенчмарка
  на `@reformer/renderer-json` с именами каталога китов (`Input`, `InputMask`, `Select`,
  `FieldArray`, `FormWizard`, `Step`, …). Реестр хоста — компоненты кита под этими именами, как их
  связывает реестр, который печатает генератор форм, плюс компоненты приложения: `CaptchaWidget` и
  `ReadonlyValue`.
- **Оболочку страницы рисует хост**, а не документ: заголовок `<h1>`, `<form>`, у регистрации —
  кнопки `btn-submit` и `btn-reset`, у обеих форм — подтверждение `submit-result`. Кнопки шагов и
  «Отправить» кредитной заявки рисует визард кита.
- Хост Angular ставит `window.__bench` позже события `load`: страница — отдельный чанк, а приложение
  стартует асинхронно. Поэтому POM, открыв страницу, сначала ждёт появления харнесса. Пакеты
  рендерера и кита Angular хост берёт из их `dist/` — перед запуском пакеты должны быть собраны.
- `window.__bench` ставит общий харнесс (`forms-benchmark/src/cross/page.ts`, `installBench`):
  хост передаёт ему только свои `mount` и `unmount`. Готовность первого экрана, покой, вызовы API
  и отправленные данные у трёх стеков считает один и тот же код; первый шаг мастера харнесс узнаёт
  по разметке китов.
- Заголовок первого уровня на странице один: сценарии снимают фокус с поля кликом по нему.
- Анимации библиотеки выключены (`createKitVuetify({ animations: false })`,
  `provideKitTaiga({ animations: false })`): сценарий читает DOM сразу после покоя страницы.

## testid

Роли — общие у трёх китов; путь поля — через дефис (`registrationAddress-city`, `properties-0-type`).

| testid                                                 | Правило                                                                                                    |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| `field-{path}`                                         | корень поля — вместе с подписью и ошибкой                                                                  |
| `label-{path}`                                         | подпись поля                                                                                               |
| `input-{path}`                                         | **нативный элемент** там, где он у виджета есть                                                            |
| `error-{path}`                                         | элемент с текстом ошибки; пока ошибки нет, элемента нет в DOM                                              |
| `input-{path}-{value}`                                 | радиокнопка опции `value`                                                                                  |
| `option-{path}-{value}`                                | пункт открытой панели списка                                                                               |
| `step-indicator-{n}`                                   | пункт шапки мастера; у текущего `data-step-current="true"`, номер — `data-step-number`                     |
| `btn-previous`, `btn-next`                             | переходы мастера; `btn-previous` на первом шаге нет вовсе                                                  |
| `btn-submit`                                           | отправка; у мастера — только на последнем шаге                                                             |
| `array-add`, `array-item-{i}`, `array-item-{i}-remove` | кнопки и строки массива внутри его секции `[data-slot="field-array"]`; «Удалить» у единственной строки нет |
| `computed-{path}`                                      | вычисляемое значение (`ReadonlyValue` приложения), контрола нет                                            |
| `captcha-image`, `captcha-refresh`                     | картинка и кнопка обновления капчи (`CaptchaWidget` приложения)                                            |
| `btn-reset`, `submit-result`                           | очистка и подтверждение отправки — оболочка хоста                                                          |

`input-{path}` на нативном элементе — главное правило. Библиотеки оборачивают `<input>` в свою
разметку, а `data-testid`, переданный компоненту, оставляют на его корне. Кит обязан донести
атрибут до внутреннего элемента: тогда `fill`, `pressSequentially`, `check`, `toHaveValue`,
`toBeChecked` работают в сценариях одинаково на всех стеках.

Элемент с ролью вместо нативного допустим, если Playwright ведёт его так же: флажок с
`role="checkbox"` и `aria-checked` отмечается через `check()` и читается через `toBeChecked()`.
Готовность экрана харнесс определяет тем же способом: `checked` нативного элемента либо
`aria-checked`.

`error-{path}` отсутствует в DOM без ошибки — сценарии собирают показанные ошибки запросом
`[data-testid^="error-"]`. Кит, у которого библиотека держит пустой контейнер ошибки или оставляет
уходящее сообщение до конца анимации, рисует элемент под условием.

Кнопки и строки массива не названы по массиву, а массивов на шаге бывает несколько — поэтому
сценарий находит массив по заголовку его секции. Мастер и массивы размечены у китов иначе, чем у
участников бенчмарка: POM спрашивает эту разметку ([markup.ts](markup.ts)), как спрашивает драйвер
списка.

## Список

Список библиотеки компонентов — не `<select>`: на поле стоит подпись выбранного пункта, а пункты —
всплывающая панель, которой нет в DOM, пока она закрыта. `selectOption` и `toHaveValue` на таком
списке не работают, поэтому сценарий ведёт список через **драйвер стека**
([drivers](drivers/index.ts)): выбрать значение, прочитать выбранное, перечислить пункты.

- Драйвер открывает панель, выбирает пункт `option-{path}-{value}` и ждёт, пока панель уйдёт из
  DOM. Значения списка он читает из пунктов открытой панели.
- Выбранное значение кит пишет в атрибут `data-value` на `input-{path}`. Его же читает харнесс,
  когда сверяет первый экран: у элемента с `data-value` значение — атрибут, а не `value`.
- Пустое значение (`''`) в перечне пунктов стоит первым, как у нативного `<select>`: сценарии ждут
  его в списке. Киты Vuetify и Taiga UI рисуют пустой пункт сами; у панели Radix в ui-kit пустого
  пункта нет — его ставит первым драйвер.

## Значения

Значение поля — одно на всех стеках: текст — строка, флажок — `boolean`, число — `number`, пустое
числовое поле — `null`, список без выбора — `''`, дата — строка `YYYY-MM-DD` (поле `Input` с
`type: "date"`). Отправленные данные сравниваются с эталоном целиком.

`InputMask` применяет маску у всех трёх китов: цифры встают в слоты шаблона, литералы
подставляются — сценарий вводит цифры и читает отформатированное значение.

Поле «только чтение» — проп `readOnly`: его ставит поведение формы, имя одно на трёх стеках. Кит
доносит его до нативного элемента атрибутом `readonly`.

## Сценарии

Тела сценариев общие с conformance бенчмарка форм:
`forms-benchmark-e2e/scenarios/<форма>.ts` объявляет тесты для страницы, которую открывает
переданная функция. Conformance зовёт их по разу на каждую библиотеку форм с разметкой бенчмарка,
этот проект — по разу на каждый стек (проект Playwright `<форма>:<стек>`) с разметкой китов.

```bash
npx playwright test                              # все стеки
npx playwright test --project=registration:react # одна форма на одном стеке
CROSS_STACKS=react npx playwright test           # сервер поднимается только для названных стеков
```
