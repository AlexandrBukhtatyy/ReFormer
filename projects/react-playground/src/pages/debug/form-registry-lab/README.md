# Стенд реестра форм: кэш схем и метрики

Страница монтирует три существующие JSON-формы через `@reformer/form-registry`, тянет их схемы по
настоящему HTTP и показывает, что при этом делает кэш: попадания в память и в хранилище,
ревалидацию через `304`, склейку одновременных запросов, ретраи и отказы.

**Маршрут:** `/examples/registry-lab` — в боковой навигации «Реестр форм» → «Стенд: кэш и метрики».

## Запуск

```bash
npm run build -w @reformer/form-registry   # обязательно: витрина резолвит пакеты в dist/
npm run dev                                 # из корня репозитория
```

Первый шаг не косметический: `projects/react-playground` подключает `@reformer/*` симлинками npm
workspaces и импортирует **собранный** `dist/`, а не исходники. Без пересборки страница пойдёт против
старой версии API и упадёт на `cache is not a function`.

Скрипт `npm run dev` из корня — это `npm run dev --workspace react-playground`. Порт передавайте
через двойной дефис (`npm run dev --workspace react-playground -- --port 5199`); без него значение
уедет в vite позиционным аргументом, а позиционный аргумент у vite — это **корень проекта**, и весь
сайт начнёт отдавать 404.

## Что на странице

### Переключатели

| Переключатель                     | Что делает                                                              |
| --------------------------------- | ----------------------------------------------------------------------- |
| **Вкладки форм**                  | Регистрация (9,7 КБ) · Кредитная заявка (68 КБ) · Список алертов (2 КБ) |
| **Источник схемы**                | `Из бандла` · `HTTP: статика` · `HTTP: MSW`                             |
| **Хранилище L2**                  | `IndexedDB` · `OPFS` · `Только память`                                  |
| **Срок свежести**                 | 5 минут · 10 секунд · 0 (всё протухло)                                  |
| **Размонтировать / Смонтировать** | Снимает и возвращает форму — главный жест стенда                        |
| **Две копии сразу**               | Монтирует две копии одной записи одновременно                           |

Смена **источника** — это смена записи реестра: идентификатор собирается как
`<форма>--<источник>`, например `registration-form--static`. Разные `id` нужны потому, что
`FormOutlet` монтирует поддерево с ключом `id@version`: при совпадающем ключе переключение источника
не пересоздало бы ни форму, ни загрузку. Заодно расходятся ключи кэша, и варианты не делят одну
ячейку.

Смена **хранилища** или **срока свежести** пересоздаёт экземпляр кэша — иначе никак, оба параметра
замкнуты внутри `createSchemaCache`. Смонтированные формы при этом перезагружаются: это ожидаемо и
на стенде как раз наглядно.

### Панель «Кэш схем»

Счётчики разложены по **двум независимым осям**, и это не оформление, а условие того, что цифры
сходятся.

**Исход поиска** — ровно одно событие на каждое чтение схемы:

|         | Что значит                                                    |
| ------- | ------------------------------------------------------------- |
| `L1`    | Свежее значение из памяти                                     |
| `L2`    | Свежее значение из хранилища — пережило перезагрузку страницы |
| `dedup` | Присоединились к запросу, который уже в полёте                |
| `stale` | Тело было, но протухло — уходим в сеть с `If-None-Match`      |
| `miss`  | Тела не было вовсе                                            |

**Исход сети** — не больше одного на каждый заведённый запрос:

|               | Что значит                                  |
| ------------- | ------------------------------------------- |
| `fetched`     | Холодная загрузка                           |
| `refetched`   | Протухшее заменено новым телом              |
| `revalidated` | Сервер подтвердил `304`                     |
| `error`       | Отказ загрузки                              |
| `aborted`     | Запрос погашен, когда ушёл последний ждущий |

Проверяемые соотношения:

```text
L1 + L2 + dedup + stale + miss                      === числу чтений схемы
fetched + refetched + revalidated + error + aborted === stale + miss
```

Правая часть второго — именно `stale + miss`, а **не** число заведённых запросов: попадание в L2
закрывает запрос до сети и события сетевой оси не даёт вовсе. В сеть уходят ровно те чтения, которые
не нашли свежего значения.

Ниже счётчиков — **журнал событий кэша** и отдельно **журнал сетевых обращений загрузчика**. Второй
считает реальные вызовы `fetch`: страница отдаёт провайдеру считающую обёртку `fetchImpl`, поэтому
цифра не зависит ни от Service Worker, ни от кэша браузера.

### Панель «Реестр стенда»

Все девять записей (3 формы × 3 источника), вид источника схемы и **ключ кэша** каждой записи.
Ключей два, и они разные: запись адресуется как `id@version`, а кэш — как
`owner/id@version#часть`. Отсюда неочевидное следствие: смена `owner` при той же самой записи даёт
промах кэша.

Внизу — диагностика preflight и отказов L2.

### Панель «Сценарий MSW»

Активна только при источнике `HTTP: MSW`. Задержка ответа, `ETag`/`304`, смена ревизии схемы на
сервере и инъекция отказов `500` / `429` / `404`.

## Сценарии: что сделать, чтобы увидеть

**Попадание в память.** Источник `HTTP: статика`, срок свежести `5 минут` → «Размонтировать» →
«Смонтировать». Растёт `L1`, «Вызовов fetch» **не меняется**.

**Хранилище переживает F5.** Хранилище `IndexedDB`, форма загружена → перезагрузить страницу
(F5). После перезагрузки память пуста, а схема приходит из хранилища: растёт `L2`, сетевых
обращений ноль.

**Ревалидация через 304.** Срок свежести `0 (всё протухло)` → перемонтировать. Каждое чтение уходит
условным запросом: `stale` → `revalidated`, в журнале сети код `304`. Тело повторно не качается —
`refetched` остаётся нулём.

**Сервер отдал новую схему.** Источник `HTTP: MSW`, срок свежести `0` → «Изменить схему на сервере»
(меняет `ETag`) → перемонтировать. Теперь вместо `304` приезжает тело: `stale` → `refetched`.

**Склейка одновременных запросов.** «Размонтировать» → «Обнулить счётчики» → «Две копии сразу» →
«Смонтировать». Два монтажа делят один запрос: один сетевой исход и `dedup` на остальные чтения.

**Ретраи.** Источник `HTTP: MSW`, срок свежести `0`, затем «Уронить один запрос: 500» →
перемонтировать. Загрузчик повторяет запрос, форма всё равно собирается, `error` остаётся нулём.

**Отказ без ретрая.** То же самое с `404`: клиентские коды не повторяются, показывается панель
отказа с причиной и кнопкой «Повторить». Повтор проходит — отказ в кэше не залипает.

**Кэш не участвует.** Источник `Из бандла` → перемонтировать. Все счётчики нулевые, и это норма:
загрузчик отдаёт значение до кэша.

## Как читать цифры, чтобы не обмануться

- **`dedup` при первом же монтаже — не баг.** В режиме разработки React StrictMode монтирует дважды,
  и второй монтаж присоединяется к запросу первого. Для честной демонстрации склейки пользуйтесь
  кнопкой «Две копии сразу»: она даёт тот же эффект и в разработке, и в сборке.
- **Данные формы в разработке грузятся дважды — и это не про кэш схем.** В сетевой вкладке браузера
  видно по два запроса `credit-applications/1`, `dictionaries`, `cities` — их шлёт не реестр, а
  render-behavior самой формы. Причина та же, что и у `dedup`: StrictMode монтирует дважды. Разница
  показательна — **схема** при этом запрашивается один раз, потому что второй монтаж присоединяется
  к запросу первого через `SchemaCache`, а собственные запросы формы такой склейки не имеют. В
  прод-сборке (`vite preview`) и тех и других по одному. Проверяется сравнением с обычной страницей
  `/examples/form-registry`: там ровно то же удвоение, стенд к нему отношения не имеет.
- **Нули на вкладке «Из бандла» — не баг.** `kind: 'inline'` возвращает значение до обращения к кэшу.
- **Одна инъекция `500` даёт два сетевых обращения**, а не одно: отказ и успешный повтор. Всего
  загрузчик делает не больше трёх попыток. В счётчиках это по-прежнему один исход.
- **Три кнопки сброса делают три разные вещи.** «Инвалидировать схему» убирает **одну** запись из
  обоих уровней; «Очистить кэш» — всё содержимое; «Обнулить счётчики» содержимое **не трогает**.
- **«Из сети» — размер после сериализации**, а не байты по проводу: сжатие и заголовки не учтены.
- **Отказы L2 считаются отдельно от `error`.** Сорванное хранилище загрузку не срывает — она просто
  уходит в сеть, и смешивать эти цифры значит потерять смысл обеих.

## Если что-то не работает

Панель отказа называет причину: бейдж `kind`, код ответа, адрес и подсказка. Это важно, потому что
сам загрузчик оборачивает **любой** отказ в одно и то же сообщение «не загрузилось по сети (url)» —
по нему `404` неотличим от обрыва сети.

| `kind`              | Что это значит                                                                                                                            |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `http-error`        | Сервер ответил кодом ошибки. Проверьте адрес рядом с идентификатором записи                                                               |
| `not-json`          | Вместо схемы приехал не-JSON: классика — dev-сервер не нашёл файл и отдал `index.html` со статусом 200                                    |
| `not-a-form-schema` | JSON получен, но в нём нет поля `root`                                                                                                    |
| `network`           | До сервера не достучались: не поднят или перезапускается (при правке файлов Vite перезапускается — отказ временный, помогает «Повторить») |
| `aborted`           | Запрос погашен, потому что ждать его стало некому                                                                                         |

Ещё две вещи, которые выглядят как поломка, но ею не являются:

- **Источник MSW работает только в режиме разработки.** Моки поднимаются при
  `NODE_ENV === 'development'` и глушатся флагом `?mocks=off` в адресе. В StackBlitz MSW подменён
  прокси только для `/api/*`, так что MSW-источник схем там недоступен.
- **OPFS доступен не везде.** Недоступный вариант в переключателе заблокирован; для предсказуемости
  (и в e2e) используйте IndexedDB.

## Тесты

```bash
cd projects/react-playground-e2e
npx playwright test --project=form-registry-lab
```

Восемь сценариев `REG-001…REG-008`. Проект намеренно однопоточный: тесты делят одно L2-хранилище на
origin и мешали бы друг другу.

Сеть в тестах считается через `window.__labNet` — зеркало журнала обёртки `fetchImpl`. Использовать
`page.route()` или `page.on('request')` **нельзя**: запросы, обслуженные Service Worker'ом MSW, до
перехватчиков Playwright не доходят.

| Файл                                                          | Роль                                                                                      |
| ------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `FormRegistryLab.tsx`                                         | Страница: переключатели, слот формы, панель отказа. Свой вложенный `FormRegistryProvider` |
| `lab-registry.ts`                                             | Изолированный `createFormRegistry()` и девять записей                                     |
| `schema-sources.ts`                                           | Три источника схемы и адреса, по которым они едут                                         |
| `lab-cache.ts`                                                | Кэш стенда: выбор хранилища, срок свежести, журнал событий                                |
| `lab-net.ts`                                                  | Считающая обёртка `fetch` и её зеркало в `window.__labNet`                                |
| `lab-store.ts`                                                | Журнал под `useSyncExternalStore`                                                         |
| `load-error.ts`                                               | Разбор цепочки `cause` до настоящей причины отказа                                        |
| `cache-panel.tsx` · `registry-panel.tsx` · `msw-scenario.tsx` | Панели                                                                                    |

Схемы не копируются: статический источник импортирует те же файлы, что и обычные страницы витрины,
через `?url&no-inline`. Суффикс `no-inline` обязателен — схема алертов (2040 Б) меньше порога
`assetsInlineLimit` (4096) и в прод-сборке молча стала бы `data:`-URL, то есть перестала бы быть
сетевым источником вовсе.

Обработчики MSW живут в `src/mocks/form-schema-handlers.ts` — рукописный файл, подключённый в
`browser.ts` перед сгенерированными. В `_generated/` дописывать нельзя: его перезаписывает
`npm run generate:mocks` внутри сборки.

## Ограничения

- **Реестр стенда изолирован от общего намеренно.** `FormOutlet` без версии отдаёт первую запись
  после сортировки по убыванию версии, и варианты стенда угнали бы обычные страницы витрины.
- **Две копии формы регистрации делят состояние отправки.** `FormEntry.registry` — экземпляр, а не
  фабрика, поэтому её UI-сигналы живут на уровне модуля. Между монтажами состояние сбрасывается, но
  две одновременные копии видят один `pending` и один текст статуса.
- **Отмена загрузки не подключена.** `useFormResource` не прокидывает `signal` в загрузчик: на
  связке «кэш + StrictMode» второй монтаж присоединился бы к уже отменённому запросу и получил бы
  вечную ошибку. Ограничение закреплено тестом в пакете.
