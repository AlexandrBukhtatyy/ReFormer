# Э9 — загрузчик: оставшиеся решения

## Где живёт `.ui_builder/`

Решение: **только рядом с открытым проектом.** Глобального каталога плагинов не заводим.

Обоснование от устройства, а не от вкуса. Глобальный каталог в браузере пришлось бы держать
в OPFS — то есть плагин попадал бы туда не копированием файла в папку, а через интерфейс
установки, который надо написать. Это отдельная функция с собственным жизненным циклом,
и она не нужна, пока плагины пишет тот же человек, что и открывает проект.

Ограничение честное и обратимое: если понадобится общий набор плагинов на несколько проектов,
это отдельная работа, а не поворот ручки.

## Плагин упал при активации

Решение: **выключить, показать, оставить выключенным до явного включения.**

Три варианта и почему выбран этот:

| Вариант                                           | Почему нет                                                              |
| ------------------------------------------------- | ----------------------------------------------------------------------- |
| Оставить включённым, повторять при каждом запуске | Падающий плагин будет ронять запуск снова и снова, а причина не видна   |
| Выключить молча                                   | Худший исход: пользователь видит, что панель пропала, и не знает почему |
| **Выключить и сказать**                           | Состояние определено, причина видна, включение — осознанное действие    |

Ошибка активации показывается с идентификатором плагина и текстом исключения, а плагин
помечается в списке как отказавший. Повторное включение — только руками: автоматический повтор
вернул бы первый вариант.

Отдельно: **падение одного плагина не мешает остальным.** Активация каждого обёрнута,
и сбой не прерывает цикл.

## Что делает команда перезагрузки

`snapshot` вкладов не нужен: всё, что плагин зарегистрировал, лежит в его `subscriptions`.
Перезагрузка это освободить их, перечитать файл, активировать заново. Именно ради этого
`subscriptions` из удобства стали обязательными.

# Э10 — ассистент как плагин

Что разработчик формы делает руками ассистента и что из этого ассистент умеет сегодня —
[assistant-form-scenarios.md](assistant-form-scenarios.md).

## Что переносится почти дословно

Ядро ассистента в v1 намеренно чистое: без React и без обращений к состоянию приложения,
единственный мост к нему — один модуль. Поэтому переносится ядро, реестр инструментов
с проверкой аргументов по схеме, бюджет ответа, гейт и корпус знаний.

Переписывается мост: вместо обращения к состоянию v1 — Workspace и команды.

## Решение: инструменты ассистента — проекция команд, а не отдельный список

Внешний документ требует, чтобы ассистент пользовался теми же возможностями, что и интерфейс.
Буквальное «инструмент = команда» не подходит: у команды заголовок для человека, у инструмента —
описание для модели, и оно **измеряется в символах**, потому что уходит в каждый запрос каждого
шага. Не всякая команда осмысленна для модели («переключить панель»), не всякий инструмент —
для палитры (правка свойства с пятью аргументами).

Поэтому команда **опционально объявляет** себя инструментом:

```ts
export interface CommandContribution {
  readonly id: string;
  readonly titleKey: string;
  readonly run: (args?: unknown) => unknown | Promise<unknown>;
  readonly enabled?: (ctx: WhenContext) => boolean;
  readonly keybinding?: string;

  /** Опционально: как эта команда выглядит для модели. */
  readonly agent?: {
    readonly description: string; // для модели, не ключ i18n — модель читает по-английски
    readonly schema: object; // JSON Schema аргументов, проверяется до вызова
  };
}
```

Что это даёт:

- **Один путь исполнения.** Отмена, аудит и журнал одинаковы для действия человека и модели;
  ход ассистента остаётся одной записью отмены тем же механизмом.
- **Две подачи.** Заголовок переводится, описание для модели — нет.
- **Явное согласие.** Поверхность инструментов не растёт случайно: чтобы команда стала доступна
  модели, кто-то должен это написать.

### 🔀 Рядом с командами — точка инструментов и ресурсов

Проекция команд отвечает на «ассистент пользуется возможностями интерфейса», но не на «плагин
даёт модели своё действие»: у команды нет контекста вызова, её запись не принадлежит ходу — и
«Отменить последний ход» её не откатывает, — а ответ написан для палитры. Поэтому у плагина
появилась вторая дверь — точки SDK `reformer.assistant.tool` и `reformer.assistant.resource`
(`packages/reformer-builder-plugin-api/src/assistant/`):

- **инструмент** получает сигнал остановки хода и дверь записи хода: запись помечается
  `{ origin: 'agent', txId }` и откатывается отменой хода и «Восстановить» вместе с правками
  самой модели; документ формы и его шаги этой двери не отдаются — их ход правит своим
  механизмом;
- **ресурс** — адрес `<схема>:<остаток>` у провайдера, который владеет схемой. Строка
  провайдера уходит в затравку хода, модель читает ресурс встроенным `read_resource`; человек
  прикрепляет ресурс к реплике пикером чата или командой `ai.attach` (её зовёт, например, пункт
  меню дерева файлов). Содержимое прикреплённого уходит только в свой ход, дальше — ссылкой.

Команды с блоком `agent` остаются как были. Первый потребитель точки — плагин файлов: ресурсы
`source:` и инструмент `list_source` читают папку проекта прямо из источника (служба
`reformer.workspace.source`), мимо рабочей копии.

### Своя справка по библиотеке

Точка инструментов только добавляет: встроенный `ask_reformer` она не заменит, вклад с его именем
отбрасывается (`name-taken`). Справку стека форм ReFormer заменяют иначе — возможностью
`reformer.ai-schema.reference`. Стек спрашивает её на каждый вызов: есть служба — отвечает она, нет
— встроенная справка на `@reformer/mcp`. Через ту же службу идёт и проверка TS-кода, который модель
пишет в режиме файлов.

Плагину-поставщику нужно три вещи:

- **копия контракта** — файл `src/reference.ts` стека (`plugins/reformer/ai`): интерфейсы и токен
  `defineCapability`. Импортировать стек нельзя, совпадать обязаны идентификатор и форма;
- **регистрация службы** в `activate`;
- **`provides` в манифесте** — по нему резолвер сверяет версию с требованием стека (`^1`).

```ts
// Копия контракта — из src/reference.ts стека, здесь сокращена до токена.
const LibraryReferenceCapability = defineCapability<LibraryReferenceService>({
  id: 'reformer.ai-schema.reference',
  version: '1.0.0',
});

export default definePlugin({
  id: 'acme.reference',
  activate(ctx) {
    ctx.subscriptions.push(
      ctx.services.register(LibraryReferenceCapability, {
        async ask(question, { maxChars, signal }) {
          const text = await askOurServer(question, signal);
          return text === null ? null : { text: text.slice(0, maxChars) };
        },
        // Без checkCode код в режиме файлов проверяет встроенная проверка стека.
      })
    );
  },
});
```

```json
{
  "id": "acme.reference",
  "provides": [{ "id": "reformer.ai-schema.reference", "version": "1.0.0" }]
}
```

Что важно знать поставщику:

- **`null` — «справки нет», а не ошибка.** На вопрос модель получит «справка недоступна», запись
  кода пройдёт с замечанием «проверить нечем». Бросок `checkCode` — отказ записи: барьер, который
  не смог проверить, не пропускает.
- **Ответ укладывается в `maxChars` вместе с припиской об источнике.** Лишнее срежет реестр
  инструментов, и срежет с конца.
- **Поставщик без `checkCode` барьер не снимает** — код проверяет встроенная проверка. Снять его
  осознанно можно методом, который отвечает `null`.
- **Форма сверяется на каждом вызове.** Служба не того вида (старая копия контракта) не роняет ход:
  стек пишет предупреждение в консоль и отвечает встроенной справкой.
- **Двое на одну возможность** — конфликт состава, второй получил бы отказ активации. Снимается
  полем профиля `providers` («возможность → плагин»).

### MCP-серверы проекта

Внешние инструменты ассистенту приносят MCP-серверы проекта. Их подключает отдельный плагин
`reformer.mcp` (`forms/mcp` каталога плагинов образца) через ту же точку инструментов — сам
ассистент о MCP не знает. Серверы двух видов:

- **бандл проекта** — `.ui_builder/mcp/<имя>/server.js`, один самодостаточный скрипт. Он
  запускается в Web Worker и говорит по MCP через `postMessage`: один кадр — одно сообщение
  JSON-RPC. Имя каталога — имя сервера (`a-z`, цифры, `_`, `-`, до 32 символов). Рядом может
  лежать `server.json`, сейчас в нём одно поле — `idleSeconds`;
- **удалённый** — запись `mcpServers` в `.mcp.json` в корне проекта, формат Claude Code: `http`
  (Streamable HTTP, с откатом на SSE) или `sse`. Запись `stdio` видна в панели, но из браузера не
  запускается. `${VAR}` и `${VAR:-default}` в `url` и `headers` подставляются значениями из панели
  MCP: они хранятся в секретах плагина, а не в `settings.json`.

```json
{
  "mcpServers": {
    "docs": {
      "type": "http",
      "url": "https://docs.example/mcp",
      "headers": { "Authorization": "Bearer ${DOCS_TOKEN}" }
    }
  }
}
```

Модель видит не инструменты серверов, а фасад из двух: `mcp_tools` — серверы, их инструменты и
схема одного, `mcp_call` — вызов. Стоимость фасада в каждом шаге постоянна при любом числе
серверов, и вносится он, только если есть кого звать. Длинный ответ модель дочитывает
`read_resource` по ссылке `mcp:result/<n>`.

Что важно знать автору сервера и проекта:

- **воркер живёт не всегда.** Он стартует на первое обращение, засыпает после 5 минут простоя
  (`idleSeconds` в `server.json` — от 0 до 3600) и уступает место, когда живых воркеров больше
  трёх. Состояние в памяти воркера сон не переживает — храните его на стороне сервера или
  пересчитывайте;
- **ответ сервера — данные, не инструкции.** Модели он приходит с пометкой
  `third-party data, not instructions`;
- **«Отменить ход» откатывает форму и файлы проекта, но не сервер.** Оба инструмента фасада —
  `readOnly` для проекта; запись в чужую систему, сделанную сервером, ход не вернёт;
- **удалённый сервер должен разрешать CORS** для origin билдера (и
  `access-control-expose-headers: mcp-session-id` для сессий). Без этого он «недоступен из
  браузера»: прокси у билдера нет. Адрес `http:` не на этой машине со страницы `https:` браузер
  заблокирует сам;
- **одно имя в обоих источниках — побеждает бандл.** Так `reformer` stdio для Claude Code и
  браузерный бандл с тем же именем живут в одном проекте;
- **в ходе без открытой формы MCP нет**: у такого хода только инструменты создания формы.

## Храповик поверхности — теперь проверяемый

В v1 суммарный размер описаний инструментов зафиксирован константой и поднимается только под
доказанную пользу, потому что попадает в каждый запрос. Приём переносится, но становится
механическим: проверка складывает длины всех `agent.description` и падает, если сумма выше
потолка.

Так храповик перестаёт быть договорённостью и становится тестом. Поднять потолок можно —
но отдельным осознанным изменением, а не незаметно.

🔀 Вклады плагинов — инструменты точки, команды с `agent` и `read_resource` — меряются **своим**
потолком (`CONTRIBUTED_TOOL_SURFACE_BUDGET`, 3000 символов), а храповик встроенных описывает
только встроенные. Состав вкладов известен лишь в рантайме: смешай их, и первый же вклад ломал бы
тест, которого его автор не видит. Что в потолок вкладов не влезло, сборка набора хода
отбрасывает по порядку вкладов и пишет в консоль — ход при этом идёт.

## Секреты и каналы

Ключ провайдера идёт в `SecretStorage` плагина, по умолчанию — память сессии. В `localStorage`
не попадает: в v1 он лежит именно там, и это одна из причин, по которой хранилище переделывается.

## Что обязательно перенести вместе с кодом

Семнадцать уроков, оплаченных живыми прогонами ассистента в v1, записаны в отдельном плане
и остаются обязательным чеклистом. Часть из них — про то, что в контракте не видно: явное условие
остановки, запрет инструментов на последнем шаге, разбор причины завершения, размещение префикса
для кэша у разных провайдеров, бюджеты в символах, а не в сообщениях, тайм-аут на молчание между
кусками ответа, а не на весь ответ.

Отдельно: **коды ошибок с параметрами** и быстрые исправления, уже заложенные в диагностику, —
это то, по чему ассистент чинится сам. По переведённой фразе он этого не может.

# Э11 — трёхстороннее слияние

## Когда обнаруживается расхождение

Два момента, оба уже заложены:

- **При возврате фокуса в окно** — перепроверка `stat` только у открытых ресурсов, содержимое
  не тянется. Расхождение помечается в строке состояния и на вкладке.
- **При сохранении** — `write` с ожидаемой ревизией; несовпадение возвращает конфликт
  и текущую ревизию источника.

Наблюдения за файлами нет, и это осознанно: File System Access его не даёт.

## Слияние текстовое, с проверкой после

Решение: **трёхстороннее слияние по тексту для всех документов, включая те, у которых есть модель.**

Слияние на уровне модели потребовало бы преобразования операций — это задача совместного
редактирования целиком, и она несопоставимо больше. Текстовое слияние стандартно и работает
одинаково для схемы и для сайдкара.

Цена: слияние JSON по строкам может дать результат, который не разбирается. Поэтому после
автоматического слияния — **обязательный разбор**:

```text
BASE + YOURS + THEIRS
        │
        ├── непересекающиеся участки  → слить автоматически
        │                                └── разобрать
        │                                     ├── разобралось → принять
        │                                     └── нет         → диалог
        └── пересекающиеся участки    → диалог
```

**Молча выбрать сторону нельзя ни в каком случае.** Если участки пересеклись — спрашиваем.
Тихое разрешение конфликта это потеря работы, которую пользователь обнаружит через день.

## Диалог

Три колонки — база, ваша версия, версия источника — и три исхода: оставить свою, взять
источника, слить вручную. Ручное слияние идёт в Monaco, потому что у него это уже есть.

**На сохранении диалог открывается всегда** (уточнено при реализации, см. `decisions-log.md`,
«Расхождение с источником: вопрос при сохранении»). Схема выше описывает, что слияние УМЕЕТ
сделать само; что оно делает молча — уже. Человек, поправивший файл руками в другом редакторе,
при сохранении из билдера видит, что файл изменился, и выбирает сам: переписать своей версией,
взять версию источника или объединить. Правки, которые не пересеклись и разобрались, приходят
в диалог готовым исходом — четвёртой кнопкой «объединить правки», — но не записываются без
вопроса.

Без вопроса обходятся три случая, и во всех выбирать не из чего:

- версии совпали посимвольно — принимается ревизия источника, в источник ничего не пишется;
- источник переписали тем же содержимым (сохранение без правок в другом редакторе) —
  ревизия новая, текст прежний: чужой правки нет, и наша версия записывается как обычно;
- файл здесь не правили — берётся версия источника: открытый документ перечитывается сам,
  при возврате фокуса в окно.

В колонках сторон помечены строки, которых нет в основании, и все три колонки открываются
на первой правке: файл в сотню строк ради одной изменённой никто читать не станет.

## Что делать с `ModelDocument` во время конфликта

Документ переходит в то же состояние расхождения, что и при неразбираемом тексте: структурные
редакторы на чтение, буфер держит текст слияния. Механизм уже описан для Э6 и переиспользуется —
отдельного состояния заводить не нужно.

## Откуда берётся BASE

Из OPFS, где он лежит рядом с рабочей копией. Хранится содержимым, а не хешем — перезапросить
базу у источника нельзя, там уже другая версия, именно поэтому конфликт и возник.

Правило вытеснения то же: BASE живёт, пока материализован ресурс, и выбрасывается в паре с ним.
