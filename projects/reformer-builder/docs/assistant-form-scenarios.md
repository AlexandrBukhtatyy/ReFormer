# Сценарии разработки форм с ассистентом

Что разработчик формы делает в билдере руками ИИ-ассистента — от создания формы до генерации
кода — и что из этого ассистент умеет сегодня.

Список служит четырём целям:

- **дорожная карта** — пробелы П1–П8 и сценарии с ❌/⚠️ говорят, что ассистенту доделать;
- **прогон на реальной модели** — каждый сценарий становится запросом, а результат проверяется по
  получившейся форме;
- **e2e с подменой модели** — проверка, что обвязка билдера выдерживает сценарий;
- **сам по себе** — общий словарь задач, на который ссылаются задачи и тесты по номеру `7.3`.

Каталог
[`tests/assistant/SCENARIOS.md`](../../reformer-builder-playground-e2e/tests/assistant/SCENARIOS.md)
— другое: он о механике хода (смена формы посреди хода, вторая попытка, отмена, вопросы). Этот
список — о задачах разработчика формы.

## Как читать

Статус — что ассистент может **сейчас**, по коду (на 2026-10-23), без прогона на модели. Качество
результата на конкретной модели этим не сказано.

| Знак | Значит                                      |
| ---- | ------------------------------------------- |
| ✅   | инструменты есть, результат сохраняется     |
| ⚠️   | частично или с оговоркой — она в примечании |
| ❌   | нельзя                                      |
| ?    | не исследовано                              |
| —    | к режиму не относится                       |

Колонки режимов: **С** — структурный режим (правка инструментами над узлами формы), **Ф** — режим
файлов (правка файлов модуля формы). Файлы правил (`validation/*.ts`, `behavior/index.ts`) и
прочие файлы модуля в Ф есть только после генерации модуля.

Пути ниже — от `projects/reformer-builder-playground/.ui_builder/plugins/reformer/`.

## 7. Валидация

`set_form_rules` (С) принимает имена встроенных валидаторов на поле, условие `when` и правило
для каждой строки массива `each`; правила С ложатся файлом `form.rules.json` рядом с документом,
и генерация печатает из него `validation/*.ts`. В Ф — правка `validation/*.ts`,
гейт проверяет API ReFormer, но не типы.

## 8. Поведение

`set_form_rules` (С) знает десять видов связей: `compute`, `computeFrom`, `copyFrom`, `syncFields`,
`onChange`, `enableWhen`, `disableWhen`, `resetWhen`, `transformValue`, `revalidateWhen`;
`set_render_rules` — скрытие узлов, события и смену props. Правила С ложатся тем же файлом правил,
генерация печатает их в `behavior/index.ts`. В Ф —
правка `behavior/index.ts`.

| №   | Сценарий                                                                             | С   | Ф   | Примечание          |
| --- | ------------------------------------------------------------------------------------ | --- | --- | ------------------- |
| 8.1 | Вычисляемое поле: сумма, возраст из даты рождения                                    | ✅  | ✅  |                     |
| 8.2 | Копирование («проживание = регистрация» по флажку), двусторонняя синхронизация       | ✅  | ✅  |                     |

| 8.4 | Скрыть блок (в паре с выключением его полей)                                         | ✅  | ✅  |                     |
| 8.5 | Сбросить зависимое поле при смене родителя; автоформат (trim, верхний регистр)       | ✅  | ✅  |                     |
| 8.6 | Реакция на изменение с загрузкой (данные по ИНН), события компонентов, props на лету | ✅  | ✅  |                     |

## Оси вариаций

Каждый сценарий стоит прогонять по нескольким осям:

- режим: С или Ф;
- раскладка модуля: плоская, `schema/`, мастер по файлам;
- кит компонентов;
- размер формы: 5 полей или 50+;
- точность запроса: точный или расплывчатый;
