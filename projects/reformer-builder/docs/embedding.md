# Билдер внутри приложения

> Вторая оболочка билдера: он открывается поверх страницы разрабатываемого приложения и даёт
> то же, что в своей вкладке. Форму в его превью рисует само приложение.
>
> Решения, принятые при реализации, — в [decisions-log.md](decisions-log.md), запись «Билдер
> внутри приложения». Раскладка каталогов — в [project-structure.md](project-structure.md).

## Зачем

Билдер в своей вкладке рисует форму сам: своим реестром компонентов и данными-заглушками.
О приложении, для которого форма делается, он не знает ничего — ни его API, ни его провайдеров,
ни того, как выглядит страница вокруг формы.

Встроенный билдер этот разрыв закрывает без единой точки интеграции: превью — это запущенное
приложение в рамке. Словарь в поле формы пришёл из настоящего API, потому что форму нарисовало
приложение; уведомление при отправке показало оно же; правка сервиса во встроенном редакторе
кода легла на диск, и dev-сервер приложения показал её в превью.

Самостоятельный режим никуда не делся: это две оболочки над одной платформой и одним набором
плагинов.

## Как это выглядит

1. Приложение оборачивает себя компонентом `<ReformerBuilder>`.
2. Запускается dev-режим, открывается любая страница.
3. Кнопка «Билдер» в углу страницы открывает билдер поверх неё — тот же интерфейс.
4. Один раз выбирается папка проекта (File System Access); дальше она поднимается сама.
5. Форма или любой файл проекта правится и сохраняется — файл пишется прямо на диск.
6. Панель «Превью» показывает результат, который рисует приложение:
   - **Форма** — только компонент формы, без остальной страницы;
   - **Приложение** — страница целиком, с адресной строкой;
   - **↗** — то же приложение в отдельной вкладке, уже без билдера.

Рабочий образец — [`projects/reformer-builder-host-example`](../../reformer-builder-host-example/README.md).

## Подключение

```tsx
// main.tsx приложения
import { ReformerBuilder } from '@reformer/builder';

createRoot(document.getElementById('root')!).render(
  <AppProviders>
    <ReformerBuilder pluginsUrl="/builder-plugins/">
      <App />
    </ReformerBuilder>
  </AppProviders>
);
```

Компонент стоит ВНУТРИ провайдеров приложения: форму, показанную в превью отдельно от страницы,
рисует это же приложение, и провайдеры ей нужны те же.

| Проп          | Что задаёт                                                                                                     |
| ------------- | -------------------------------------------------------------------------------------------------------------- |
| `pluginsUrl`  | адрес каталога плагинов билдера — того, в котором лежит их индекс; приложение раздаёт его своей статикой       |
| `projectBase` | префикс адреса, под которым dev-сервер отдаёт открытую в билдере папку; по умолчанию открыт корень dev-сервера |
| `loadForm`    | своя загрузка модуля формы по пути от корня проекта — для сборщиков, которые не отдают исходники по адресу     |
| `enabled`     | включён ли билдер вообще; по умолчанию — везде, кроме прод-сборки                                              |
| `labels`      | подписи кнопки и оверлея                                                                                       |

Помимо компонента приложению нужны три вещи. Все три временные — до библиотечной сборки билдера,
с которой останется обычная зависимость от пакета.

- **Сборка из исходников.** Библиотечной сборки у билдера пока нет: его собирает сборщик
  приложения. Псевдонимы исходников, вход под именем пакета и список рантаймов, которым
  положена одна копия на страницу, билдер отдаёт сам —
  [`vite/source-resolve.mjs`](../vite/source-resolve.mjs), функция `builderHostResolve()`.
  Тем же модулем пользуется конфиг самого билдера, так что два списка не расходятся.
- **Типы.** `tsconfig` приложения повторяет те же псевдонимы в `paths`.
- **Каталог плагинов.** Плагины билдера — отдельная сборка. Её собирает
  `scripts/collect-application-plugins.mjs` с названным списком и каталогом назначения:
  состав встроенного билдера — [`application-plugins.embedded.json`](../application-plugins.embedded.json).
  Плагинов, которыми форму рисует сам билдер, в нём нет; есть плагин «Превью приложением».

## Что рисует компонент

Один и тот же компонент стоит и на странице, где человек работает, и в документах, которые
открывает превью, — поэтому смотрит, ГДЕ он открыт.

| Где открыт документ              | Что на экране                                                     |
| -------------------------------- | ----------------------------------------------------------------- |
| обычная страница                 | приложение и кнопка «Билдер»                                      |
| режим включён                    | оверлей с билдером; приложение скрыто, но не размонтировано       |
| рамка превью                     | только приложение — кнопки билдера внутри собственного превью нет |
| рамка превью, адрес стенда       | одна форма вместо приложения                                      |
| прод-сборка, серверная отрисовка | только приложение                                                 |

Несколько свойств, на которые можно опираться:

- **Модуль лёгкий.** Оболочка, состав плагинов и стили приезжают отдельным чанком по первому
  включению режима. Пока билдер не включён, приложение платит за него кнопкой.
- **Билдер рисуется в свой корень React.** Провайдеры, строгий режим и границы ошибок приложения
  на билдер не действуют, а его сбой не роняет приложение. Экземпляр React при этом общий.
- **Приложение под оверлеем скрыто, а не снято.** Закрыв билдер, человек возвращается на ту же
  страницу в том же состоянии — введённое в форму остаётся. Скрывает его `Activity` (React 19.2);
  в React постарше приложение на время режима размонтируется.
- **Присутствие в документе — только пока открыт оверлей.** Стили билдера и признак темы
  подключаются при включении режима и снимаются при выключении; заголовок вкладки билдер
  не трогает вовсе.
- **Режим переживает перезагрузку страницы.** Он хранится в хранилище сессии вкладки, а проект
  и открытые вкладки билдер восстанавливает так же, как в своей вкладке. Новая вкладка,
  открытая из превью, режим не наследует.
- **Сборка одна на страницу.** Оверлей открывают и закрывают сколько угодно раз: открытый
  проект, вкладки и рабочая копия — состояние собранного приложения, а не дерева React.

## Две оболочки

```text
        плагины билдера (файлы, редакторы, инспектор, кодоген…) — одни и те же
                              │
              общая платформа и сборка (файлы — File System Access)
                     ┌────────┴────────┐
              оболочка «своя вкладка»      встроенная оболочка
              src/shell/standalone/        src/shell/embedded/
              вход src/main.tsx            вход src/index.ts
```

| Что                                          | Своя вкладка       | Внутри приложения                               |
| -------------------------------------------- | ------------------ | ----------------------------------------------- |
| Проект и файлы                               | File System Access | то же самое                                     |
| Интерфейс                                    | на всю вкладку     | тот же, оверлеем на всю страницу                |
| Стили и признак темы                         | в документе всегда | только пока открыт оверлей                      |
| Заголовок документа                          | ставит             | не трогает                                      |
| Очистка хранилища, перезапуск, выбор профиля | есть               | нет: хранилище и страница — общие с приложением |
| Кто рисует форму                             | билдер             | приложение                                      |
| Плагины приложения                           | рядом со сборкой   | по адресу из пропа компонента                   |

Общая сборка (`shell/boot/boot.ts`) о вкладке браузера не знает: всё, что зависит от места,
где оболочка живёт, она получает портом окружения.

```ts
// shell/boot/environment.ts
export interface ShellEnvironment {
  /** Заголовок документа. Оболочка без своей вкладки метод не даёт. */
  applyTitle?(title: string | undefined): void;
  /** Куда ставится признак тёмной темы. */
  readonly themeRoot: ThemeRoot | null;
  /** Перезапуск приложения. Без него смена профиля недоступна. */
  readonly reload?: () => void;
  /** Очистка хранилища origin. Без неё команды «Очистить кэш» нет — и пункта меню тоже. */
  purgeStorage?(known: KnownStorage): Promise<PurgeReport>;
  /** Возможности, которые оболочка добавляет до активации плагинов. */
  registerCapabilities?(services: ServiceRegistry): void;
}
```

Порт, а не флаг «встроен ли»: чего у окружения нет, того нет и в интерфейсе — без проверок
режима по коду. Без параметра сборка берёт окружение вкладки браузера.

Оболочки импортируют сборку и платформу, но не состав приложения и не друг друга; состав
с оболочкой соединяет только вход. Границу держит линтер билдера.

## Превью приложением

Плагин [`base/app-preview`](../../reformer-builder-playground/.ui_builder/plugins/base/app-preview)
вносит панель «Превью» в правый док. Об устройстве приложения он не знает: адреса ему даёт
возможность, которую регистрирует встроенная оболочка.

```ts
// @reformer/builder-plugin-api
export interface AppPreviewService {
  /** Адрес страницы приложения, с которой включили режим билдера. */
  pageUrl(): string;
  /** Адрес, по которому приложение рисует одну форму. */
  formUrl(modulePath: string): string;
  /** Файлы проекта записаны на диск — пора показать приложение заново. */
  onDidWriteSource(cb: () => void): Disposable;
}
```

Возможности нет — нет и панели: в оболочке «своя вкладка» плагин ничего не вносит.

**Стенд формы.** Адрес стенда — адрес страницы приложения с параметром, в котором лежит путь
модуля формы от корня проекта. Приложение в рамке, увидев параметр, вместо себя рисует
компонент, экспортированный модулем по умолчанию, — внутри тех же провайдеров. Модуль формы —
`index.tsx` её каталога: так его печатает кодоген билдера. Под dev-сервером Vite модуль
грузится по адресу; остальным сборщикам — проп `loadForm`.

**Какая форма показана.** Форма открытого файла: его каталог и `index.tsx` в нём. Когда
у открытого файла своей формы нет — открыт сервис, из которого форма берёт словарь, — на экране
остаётся прежняя, той же рамкой. Какой модуль показан, панель называет.

**Рамка.** У формы в рамке настоящие стили и настоящая область просмотра, а стили билдера в неё
не попадают: это отдельный документ. Рамку приложение узнаёт по имени окна и кнопку билдера
внутри неё не показывает.

**Обновление.** Приложение хранит собранную форму в состоянии компонента, и «горячее»
обновление модулей его сохраняет — правка схемы приехала бы, а форма осталась прежней. Поэтому
после записи файлов панель перезагружает рамку сама, с небольшой задержкой: dev-сервер замечает
запись не мгновенно. В режиме «Приложение» рамка возвращается на тот адрес, куда человек в ней
дошёл.

## Сохранение и dev-сервер

Запись на диск — по Ctrl+S, как в своей вкладке. Билдер и приложение живут в одном документе,
поэтому у сохранения появляется побочное действие: dev-сервер видит правку.

- Обычно он обновляет модули «на лету» — и на странице с билдером, и в рамках превью.
- Когда обновить не получается (у изменённого модуля нет принимающей границы, либо правилась
  сама страница), сервер просит перезагрузиться ВСЕ открытые документы. Рамкам это и нужно.
  Страница с билдером не перезагружается: пока оверлей открыт, такая перезагрузка
  откладывается и выполняется при выключении режима — приложение под оверлеем скрыто,
  а свежим оно обязано стать к моменту, когда его снова покажут.
- Перезагрузка без названной причины-файла (сервер пересобрал зависимости) проходит как есть:
  прежние модули сервер уже не отдаёт. Режим, проект и вкладки билдер после неё поднимает сам,
  а несохранённое лежит в рабочей копии.

Удержание работает под Vite и только при сборке из исходников; в любой другой сборке страница
перезагружается как обычно.

## Панель во всю высоту дока

Рамке с чужим документом понадобился признак, которого у панелей не было: тело обычной панели
лежит в прокручиваемой области оболочки, где высоту задаёт содержимое, — и «растянуться» там
не на что. Вклад панели с `fill: true` получает область дока целиком и прокручивает себя сам.
Признак — часть контракта плагинов и работает в обеих оболочках.

## Чего нет

- **Знания о приложении.** Его реестр компонентов в палитре, источники данных в инспекторе,
  уведомления приложения на события билдера, выбор узла щелчком по форме в превью — будущий
  плагин сотрудничества с конкретным приложением.
- **Изоляции стилей.** Пока оверлей открыт, стили билдера действуют на весь документ,
  а глобальные стили приложения — на интерфейс билдера.
- **Библиотечной сборки и публикации**: отсюда псевдонимы в конфиге сборки приложения.
- **Прод-режима**: в прод-сборке компонент рисует только приложение и код билдера
  не загружает. Сами чанки билдера в выходной каталог при этом попадают — убрать их
  из прод-сборки дело упаковки.
- **Своего псевдонима `@` у приложения.** Он принадлежит исходникам билдера; приложение
  со своим `@` перехватит его импорты.
- **Браузеров, кроме Chromium.** File System Access есть только в нём.
- **React до 19-го.** Билдер исполняется на React приложения.

## Как проверяется

- **Сборка встроенной оболочки** — `src/shell/boot/integration/embedded-shell.test.ts`:
  заголовок не тронут, команды очистки хранилища нет, возможность превью зарегистрирована.
- **Модули оболочки** — тесты рядом с кодом в `src/shell/embedded/`: адреса превью, режим,
  удержание перезагрузок; в браузере — присутствие в документе, стенд формы, пять состояний
  компонента.
- **Плагин превью** — тесты его пакета: какая рамка открыта, что остаётся при смене файла,
  когда рамка перезагружается.
- **Вся связка** — e2e, цель `embedded` в
  [`projects/reformer-builder-playground-e2e`](../../reformer-builder-playground-e2e/README.md):
  dev-сервер приложения-образца над его копией, билдер пишет файл, приложение в рамке
  показывает новое.

Автотест подменяет системный диалог выбора папки, поэтому запись через настоящий диалог
проверяется руками — по шагам в README приложения-образца.
