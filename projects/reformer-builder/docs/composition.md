# Сборка билдера под организацию

Билдер — одно приложение, а не набор дистрибутивов. Что в нём есть, решают три вещи, и все
три — данные, а не код:

| Что                               | Где                                                 | Кто решает                    |
| --------------------------------- | --------------------------------------------------- | ----------------------------- |
| состав встроенных плагинов        | `preset` и `profiles` конфига запуска               | тот, кто разворачивает билдер |
| между чем человек переключается   | `presetChoices` конфига запуска                     | тот, кто разворачивает билдер |
| умолчания настроек (кит, тема, …) | `defaults` конфига запуска                          | тот, кто разворачивает билдер |
| внешние плагины (киты и другие)   | `.ui_builder/plugins/<id>/` проекта и его настройки | проект                        |

Конфиг запуска — `.ui_builder/config.json` в каталоге, где запущен `npx reformer-builder`
(или `--config <path>`). Схема для автодополнения в IDE — `runtime-config.schema.json` пакета.
Всё, что здесь описано, применяется только на уровне запуска: состав и умолчания фиксируются при
сборке приложения, до открытия проекта. Те же поля в конфиге проекта разбираются, но не
применяются. Записаны они там иначе, чем в конфиге запуска, — билдер говорит об этом уведомлением;
записаны так же — молчит: их уже применил запуск. Поэтому один `.ui_builder/config.json` на оба
уровня — запустили билдер в корне проекта и его же открыли — предупреждений не даёт.

## Встроенные профили

| Профиль            | Что внутри                                                                          |
| ------------------ | ----------------------------------------------------------------------------------- |
| `reformer.builder` | основа, киты и стек ReFormer: редактор схемы, превью, валидатор, ассистент, кодоген |
| `rjsf.builder`     | основа, киты и домен RJSF: редактор и превью форм react-jsonschema-form             |
| `plain.builder`    | основа и демо-стек `plain-form/1`                                                   |
| `builder.base`     | основа: файлы, Monaco, markdown, управление плагинами, хост превью, переключатель   |
| `minimal`          | файлы, Monaco и валидатор схемы ReFormer                                            |
| `ai-builder`       | `minimal` и ассистент                                                               |

Встроенные профили — тот же формат, что у своего профиля ниже: они лежат в
`src/application/profiles/builtin.config.json`, файле формата конфига запуска, вшитом в сборку.
Его `preset` называет профиль по умолчанию, так что этот файл — готовый образец для своего.

Без `preset` собирается `reformer.builder`. Неизвестное имя или состав, который не собирается
(опечатка в имени плагина, неразрешимое требование возможности), — предупреждение в консоли и
полный профиль: опечатка в конфиге не должна стоить инструмента.

## Рецепты

### RJSF с ui-kit

```json
{ "preset": "rjsf.builder" }
```

Формы `rjsf-form/1` открываются редактором RJSF, превью рисует их компонентами активного кита —
тема строится из каталога кита, поэтому любой кит подходит без строчки кода под RJSF.

### ReFormer с HexaUI

Кит HexaUI — внешний плагин (`packages/ui-kits/reformer-hexa-ui`). Сборка плагина:

```bash
npm run plugin:build -w @reformer/kit-hexa-ui   # dist/: manifest.json, main.js, styles.css
```

Содержимое `dist/` кладётся в проект как `.ui_builder/plugins/kit-hexa-ui/`. Включить плагин
можно в списке плагинов или настройкой проекта — файлом `.ui_builder/settings.json`:

```json
{ "workspace.plugins.enabled": ["kit-hexa-ui"] }
```

Кит выбирается в палитре команд («Кит: Kaspersky HexaUI») — или умолчанием организации, см. ниже.
Тот же кит рисует и формы RJSF: киты — платформа, а не часть стека ReFormer.

### Свой профиль

```json
{
  "preset": "acme",
  "profiles": [
    {
      "id": "acme",
      "name": "Формы Acme",
      "extends": "rjsf.builder",
      "plugins": ["reformer.editor-markdown"]
    }
  ]
}
```

Профиль конфига — те же данные, что у встроенного: `id`, `name`, `extends` (встроенный или другой
свой профиль), `plugins` (встроенные плагины сверх основы), `providers` (выбор провайдера
возможности, когда её дают двое). `id` не может совпадать со встроенным — такой профиль
пропускается с предупреждением. Прежние имена плагинов (`kits` вместо `reformer.kits`) работают.
Поправки `plugins.enable` / `plugins.disable` применяются поверх выбранного профиля.

### Кит организации по умолчанию

```json
{
  "preset": "rjsf.builder",
  "defaults": {
    "settings": { "plugin.kits.active": "hexa-ui" }
  }
}
```

`defaults.settings` — умолчания любых настроек: слой между выбором человека и умолчанием плагина.
Пока плагин кита не внёс кит, действует встроенный; как только внёс — реестр китов переключается
на кит организации сам. Выбор человека в палитре сильнее умолчания и переживает перезагрузку.

### Проект организации целиком

```text
<каталог запуска>/.ui_builder/config.json     preset, profiles, defaults.settings
<проект>/.ui_builder/plugins/kit-hexa-ui/     manifest.json, main.js, styles.css
<проект>/.ui_builder/settings.json            { "workspace.plugins.enabled": ["kit-hexa-ui"] }
<проект>/forms/*.rjsf.json                    формы
```

Запуск в корне проекта (`npx reformer-builder`) и открытие того же каталога сводят всё в один
`.ui_builder/`.

## Готовые конфиги: движок × кит

Четыре сочетания собраны готовыми файлами в
`projects/reformer-builder-playground/.ui_builder/presets/` — формат тот же, что у любого конфига
запуска (`preset` и кит по умолчанию), ничего сверх рецептов выше:

| Файл                    | Движок   | Кит              |
| ----------------------- | -------- | ---------------- |
| `reformer-ui-kit.json`  | ReFormer | ReFormer UI Kit  |
| `reformer-hexa-ui.json` | ReFormer | Kaspersky HexaUI |
| `rjsf-ui-kit.json`      | RJSF     | ReFormer UI Kit  |
| `rjsf-hexa-ui.json`     | RJSF     | Kaspersky HexaUI |

```bash
# в разработке; preset:<имя> есть на каждый
npm run preset:rjsf-hexa-ui -w reformer-builder-playground
# собранным билдером, из каталога пакета билдера
node bin/reformer-builder.mjs --config ../reformer-builder-playground/.ui_builder/presets/rjsf-hexa-ui.json
```

Файлы — образцы репозитория и лежат в проекте-образце, а не в пакете билдера: в npm они не едут.
Вне репозитория то же сочетание — две строки своего `.ui_builder/config.json`.

Файлы с HexaUI называют кит, но не привозят его: кит — плагин проекта. Пока проект с плагином
не открыт, формы рисует встроенный кит, а HexaUI включается сам, как только плагин его внесёт.
Проект для проверки — тот же проект-образец: плагин в нём уже включён, остаётся положить сборку:

```bash
npm run plugins:hexa-ui -w reformer-builder-playground   # .ui_builder/plugins/kit-hexa-ui/, не в git
```

В билдере — «Открыть папку…» и выбрать `projects/reformer-builder-playground`.

## Переключатель сочетаний

В строке состояния справа стоит ячейка «движок · кит» — действующее сочетание. Щелчок открывает
список: предложенные движки, умноженные на киты, доступные сейчас (сочетания с китом плагина
появляются, когда плагин включён в открытом проекте). Те же пункты есть в палитре команд —
«Сочетание: …».

- **Кит меняется на лету.** Это настройка, общая для всех движков.
- **Движок меняется перезагрузкой**, и перед ней билдер спрашивает: состав плагинов фиксируется при
  сборке приложения. Сочетания с другим движком помечены в списке.
- **Выбор человека сильнее конфига запуска** — обе оси, и он переживает перезагрузку. Поэтому
  готовый конфиг открывает «своё» сочетание только там, где человек не выбирал иного.
- **«Как в конфиге запуска»** — последний пункт списка: снимает оба выбора, и билдер снова следует
  конфигу. Выбрать движок конфига руками значит то же самое — такой выбор не хранится.

Что предлагать к выбору, решает тот, кто разворачивает билдер, — полем `presetChoices`:

```json
{
  "preset": "rjsf.builder",
  "presetChoices": ["rjsf.builder"]
}
```

Без поля предлагаются `reformer.builder` и `rjsf.builder`. Одно имя или пустой список закрепляют
состав: движков в списке нет, остаются только киты. В списке можно назвать и свой профиль из
`profiles`. Профиль, который не собирается или не содержит плагин `reformer.stack-switch`,
пропускается с предупреждением в консоли: из состава без переключателя нельзя было бы вернуться.
Убрать переключатель целиком — поправкой состава:

```json
{ "plugins": { "disable": ["reformer.stack-switch"] } }
```

Без переключателя в составе запуска выбора нет вовсе, и сохранённый раньше выбор движка
не действует: конфиг собирает ровно то, что в нём написано.

## В разработке билдера

`npm run dev` отдаёт конфиг запуска так же, как лаунчер: файл из переменной
`REFORMER_BUILDER_CONFIG`, иначе `projects/reformer-builder/.ui_builder/config.json` (каталог
в `.gitignore`). Файл читается на каждый запрос — правка видна после перезагрузки страницы.
Путь в переменной отсчитывается от каталога пакета билдера; скрипты `preset:<имя>` проекта-образца
выставляют её на готовый конфиг из его `.ui_builder/presets/`:

```bash
npm run preset:rjsf-hexa-ui -w reformer-builder-playground
```

Постоянный каталог для таких проб — [`projects/reformer-builder-playground`](../../reformer-builder-playground/README.md):
конфиг запуска, конфиг и настройки проекта, плагин в разработке и формы обоих движков.
`npm run builder -w reformer-builder-playground` поднимает dev-сервер с его конфигом запуска
(порт 5184). Его же открывают e2e-тесты билдера —
[`projects/reformer-builder-playground-e2e`](../../reformer-builder-playground-e2e/README.md).
