# @reformer/builder

Визуальный конструктор форм. Пакет несёт уже собранный офлайн-SPA
в `dist/` и zero-dependency лаунчер: `npx reformer-builder` поднимает локальный сервер
и открывает браузер. Серверной логики нет — файлы проекта билдер читает и пишет прямо
из браузера через File System Access API (нужен Chromium: Chrome/Edge/Arc/Brave).

Сам билдер — оболочка: открытие проекта и управление плагинами. Дерево файлов, редактор
кода, предпросмотр markdown, превью-хост и киты — плагины, как и всё про формы. **Движки форм — плагины.** Редактор схемы, превью формы, валидатор,
генерацию кода, шаблоны и ассистента для ReFormer, как и редактор с превью для RJSF, приносят
плагины, которые едут вместе с билдером (`dist/plugins/`) и работают в любом проекте. Проект
вправе принести и свои — в `.ui_builder/plugins/`, включив их в своих настройках. Исходники
плагинов и образец проекта — [projects/reformer-builder-playground](../reformer-builder-playground).

## Запуск

```bash
npx reformer-builder [--port 4321] [--host 127.0.0.1] [--no-open] [--config <path>] [--plugins <dir>]
```

`--plugins <dir>` — каталог плагинов приложения вместо собранного в билдер (`dist/plugins/`):
они работают до открытия проекта и в любом проекте. Каталог из флага живой: плагин, пересобранный
под работающим билдером, тот перезагружает сам, когда в его окно возвращаются. Подробнее —
[docs/composition.md](docs/composition.md).

## Внутри своего приложения

Тот же билдер открывается поверх страницы разрабатываемого приложения: кнопка «Билдер»
в dev-режиме, тот же интерфейс в рамке на всю страницу, а форму в превью рисует само
приложение — со своим API и своими провайдерами. Файлы проекта билдер правит прямо на диске,
как и в своей вкладке.

Отдаёт билдер dev-сервер приложения. Приложение его не компилирует: билдер — отдельный
документ, и ни его стили, ни его зависимости в сборку приложения не попадают.

Пока это работает внутри монорепозитория: пакет для встраивания не публикуется.
Устройство — [docs/embedding.md](docs/embedding.md), рабочий образец —
[projects/reformer-builder-host-example](../reformer-builder-host-example).

### Попробовать на образце

```bash
npm run dev -w reformer-builder-host-example               # http://localhost:5175/contact
```

Перед запуском команда собирает плагины билдера на месте — тем же шагом, что
`npm run builder -w reformer-builder-playground`.

### Подключить к своему приложению

**1. Зависимость.** `@reformer/builder` в `devDependencies` приложения.

**2. Плагин dev-сервера.** Он отдаёт билдер с того же адреса, что и приложение, — под
`/__reformer-builder/`:

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import { reformerBuilder } from '@reformer/builder/vite';

export default defineConfig({
  plugins: [react(), reformerBuilder()],
});
```

**3. Компонент.** Оборачивает приложение ВНУТРИ его провайдеров: форму в превью рисует это же
приложение, и провайдеры ей нужны те же.

```tsx
// main.tsx
import { ReformerBuilder } from '@reformer/builder';

createRoot(document.getElementById('root')!).render(
  <AppProviders>
    <ReformerBuilder>
      <App />
    </ReformerBuilder>
  </AppProviders>
);
```

Это всё. Псевдонимы исходников, Tailwind, пути в `tsconfig`, каталог плагинов в статике
приложения — ничего из этого не нужно.

### Каталог `.ui_builder/` приложения

Работает так же, как у билдера в своей вкладке (раздел ниже), только конфиг запуска читает
не лаунчер, а dev-сервер приложения:

- `.ui_builder/config.json` — заголовок, умолчания, профиль состава, поправки к нему;
- `.ui_builder/plugins/` — плагины проекта: включаются в настройках билдера, помеченный
  «в разработке» перечитывается, когда его файлы изменились;
- `.ui_builder/templates/`, `.ui_builder/codegen/` — шаблоны форм и цели кодогена.

В образце каталог есть: конфиг и плагин из одного файла.

### Работа

1. Запустите dev-сервер приложения и откройте любую его страницу в Chromium.
2. Нажмите «Билдер» в углу страницы — он откроется поверх приложения.
3. «Открыть папку…» → каталог приложения, тот, что раздаёт dev-сервер. Выбор нужен один раз.
4. Откройте файл формы. Результат рисует приложение, и смотрят на него в двух местах:
   - **«Форма»** в полосе вкладки (кнопка со значком, рядом с деревом и исходником) — только
     компонент формы: тот, что экспортирован по умолчанию из `index.tsx` её каталога (так
     модуль формы печатает кодоген билдера);
   - **панель «Превью»** на правом рейле — приложение целиком, с адресной строкой;
     **↗** рядом с адресом — то же приложение в отдельной вкладке, уже без билдера.
5. Правьте форму или любой файл проекта и сохраняйте (Ctrl+S): файл пишется на диск,
   и вид «Форма», и панель показывают результат.
6. «Закрыть билдер» — приложение на той же странице и в том же состоянии. Билдер при этом
   не выгружается: открытый проект и вкладки ждут следующего открытия.

Если файл поправили мимо билдера (в IDE), при сохранении он спросит: переписать своей
версией, взять версию с диска или объединить правки.

### Параметры

Плагин `reformerBuilder(options)`:

| Параметр  | Что задаёт                                                                                  |
| --------- | ------------------------------------------------------------------------------------------- |
| `config`  | конфиг запуска — путь от корня приложения; по умолчанию `.ui_builder/config.json`           |
| `plugins` | каталог плагинов приложения вместо набора, который едет с билдером                          |
| `ui`      | откуда интерфейс: исходники (в монорепозитории) или готовая сборка; по умолчанию — что есть |

Компонент `<ReformerBuilder>`:

| Проп          | Что задаёт                                                                        |
| ------------- | --------------------------------------------------------------------------------- |
| `projectBase` | префикс адреса, если в билдере открыта не корневая папка dev-сервера              |
| `loadForm`    | своя загрузка модуля формы — для сборщиков, которые не отдают исходники по адресу |
| `enabled`     | включён ли билдер; по умолчанию — когда подключён плагин                          |
| `labels`      | подписи кнопки и сообщений                                                        |

### Ограничения

- Только Chromium (Chrome, Edge): проект открывается через File System Access.
- Только dev-режим и только Vite: билдер отдаёт плагин его dev-сервера. В прод-сборке
  и без плагина компонент рисует одно приложение.
- Хранилище браузера у билдера и приложения общее: адрес у них один.

## Конфигурация — каталог `.ui_builder/`

Один конвенционный каталог на два момента чтения:

| Что                                                                                                                                                                                | Где                                         | Когда читается                                                                                                  |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `config.json` — брендинг, дефолты UI, состав (`preset`, `presetChoices`, `profiles`)                                                                                               | каталог запуска (`--config` переопределяет) | лаунчером при старте                                                                                            |
| `config.json`                                                                                                                                                                      | открытый проект                             | при каждом открытии проекта; перекрывает уровень запуска по полю (`defaults` и состав — только уровень запуска) |
| `plugins/<id>/` или `plugins/<домен>/<плагин>/` — плагины: `manifest.json`, `main.js` (собранный) или `main.ts` (в разработке — транспиляция на лету, авто-перезагрузка по правке) | открытый проект                             | при открытии; включение — явное действие человека                                                               |
| `templates/<slug>/` — шаблоны форм                                                                                                                                                 | открытый проект                             | службой шаблонов                                                                                                |
| `codegen/*.eta` — свои цели генерации                                                                                                                                              | открытый проект                             | плагином кодогенерации                                                                                          |

Запустили `npx reformer-builder` в корне проекта и его же открыли — вся конфигурация
в одном `.ui_builder/`, без дублей. О полях уровня запуска в конфиге проекта билдер предупреждает,
только когда они расходятся с конфигом запуска: один файл на оба уровня предупреждений не даёт.

`config.json` (все секции опциональны; `$schema` даёт автодополнение в IDE):

```json
{
  "$schema": "./node_modules/@reformer/builder/runtime-config.schema.json",
  "branding": { "title": "Формы Acme" },
  "preset": "builder",
  "defaults": {
    "locale": "ru",
    "theme": "system",
    "settings": { "plugin.kits.active": "hexa-ui" }
  }
}
```

Сторонний кит встраивается плагином из `.ui_builder/plugins/` (плагин привозит и каталог
компонентов, и код). Каталог плагинов допускает один уровень вложенности: подкаталог без
манифеста — домен, его подкаталоги с манифестом — плагины (`reformer/editor`, `rjsf/render`).
Составы, свои профили и кит организации по умолчанию — в
[docs/composition.md](docs/composition.md).

Профиль и кит человек меняет сам — ячейкой «движок · кит» в строке состояния: кит на лету,
профиль с перезагрузкой. Его выбор сильнее `preset` и кита из `defaults`; пункт «Как в конфиге запуска»
его снимает. Между какими профилями можно переключаться, задаёт `presetChoices` (без поля —
только `builder`; одно имя или пустой список закрепляют состав). Движок формы профилем
не выбирается: какой редактор откроет файл, решают плагины проекта.

## Отличия от 2.x

Версия 3 — переписанный билдер, и контракт запуска у него другой:

- **флага `--catalog` больше нет.** Сторонний ui-kit подключается плагином из
  `.ui_builder/plugins/`: плагин привозит и каталог компонентов, и их код — файлом данных
  превью нечем рисовать;
- **конфиг переехал** из `reformer-builder.config.json` рядом с запуском в
  `.ui_builder/config.json` (или `--config <path>`), и в нём остались брендинг и дефолты UI:
  палитра, набор компонентов и раскладка настраиваются плагинами;
- **битый конфиг больше не роняет билдер**: приложение открывается, а каждая проблема
  называется в уведомлении.
