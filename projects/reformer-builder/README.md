# @reformer/builder

Визуальный конструктор форм. Пакет несёт уже собранный офлайн-SPA
в `dist/` и zero-dependency лаунчер: `npx reformer-builder` поднимает локальный сервер
и открывает браузер. Серверной логики нет — файлы проекта билдер читает и пишет прямо
из браузера через File System Access API (нужен Chromium: Chrome/Edge/Arc/Brave).

Сам билдер — оболочка: открытие проекта и управление плагинами. Дерево файлов, редактор
кода, предпросмотр markdown, превью-хост и киты — плагины, как и всё про формы. **Движки форм — плагины.** Редактор схемы, превью формы, валидатор,
генерацию кода, шаблоны и ассистента для ReFormer, как и редактор с превью для RJSF, приносят
плагины, которые едут вместе с билдером (`dist/plugins/`) и работают в любом проекте. Проект
вправе принести и свои — в `.ui_builder/plugins/`, включив их в своих настройках. Исходники
плагинов и образец проекта — [projects/reformer-builder-playground](../reformer-builder-playground).

## Запуск

```bash
npx reformer-builder [--port 4321] [--host 127.0.0.1] [--no-open] [--config <path>] [--plugins <dir>]
```

`--plugins <dir>` — каталог плагинов приложения вместо собранного в билдер (`dist/plugins/`):
они работают до открытия проекта и в любом проекте. Подробнее —
[docs/composition.md](docs/composition.md).

## Внутри своего приложения

Тот же билдер открывается и поверх страницы разрабатываемого приложения: компонент
`<ReformerBuilder>` вокруг приложения, кнопка «Билдер» в dev-режиме, а форму в превью рисует
само приложение — со своим API и своими провайдерами. Пока это сборка из исходников внутри
монорепозитория, без публикации. Устройство и подключение —
[docs/embedding.md](docs/embedding.md), рабочий образец —
[projects/reformer-builder-host-example](../reformer-builder-host-example).

## Конфигурация — каталог `.ui_builder/`

Один конвенционный каталог на два момента чтения:

| Что                                                                                                                                                                                | Где                                         | Когда читается                                                                                                  |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `config.json` — брендинг, дефолты UI, состав (`preset`, `presetChoices`, `profiles`)                                                                                               | каталог запуска (`--config` переопределяет) | лаунчером при старте                                                                                            |
| `config.json`                                                                                                                                                                      | открытый проект                             | при каждом открытии проекта; перекрывает уровень запуска по полю (`defaults` и состав — только уровень запуска) |
| `plugins/<id>/` или `plugins/<домен>/<плагин>/` — плагины: `manifest.json`, `main.js` (собранный) или `main.ts` (в разработке — транспиляция на лету, авто-перезагрузка по правке) | открытый проект                             | при открытии; включение — явное действие человека                                                               |
| `templates/<slug>/` — шаблоны форм                                                                                                                                                 | открытый проект                             | службой шаблонов                                                                                                |
| `codegen/*.eta` — свои цели генерации                                                                                                                                              | открытый проект                             | плагином кодогенерации                                                                                          |

Запустили `npx reformer-builder` в корне проекта и его же открыли — вся конфигурация
в одном `.ui_builder/`, без дублей. О полях уровня запуска в конфиге проекта билдер предупреждает,
только когда они расходятся с конфигом запуска: один файл на оба уровня предупреждений не даёт.

`config.json` (все секции опциональны; `$schema` даёт автодополнение в IDE):

```json
{
  "$schema": "./node_modules/@reformer/builder/runtime-config.schema.json",
  "branding": { "title": "Формы Acme" },
  "preset": "builder",
  "defaults": {
    "locale": "ru",
    "theme": "system",
    "settings": { "plugin.kits.active": "hexa-ui" }
  }
}
```

Сторонний кит встраивается плагином из `.ui_builder/plugins/` (плагин привозит и каталог
компонентов, и код). Каталог плагинов допускает один уровень вложенности: подкаталог без
манифеста — домен, его подкаталоги с манифестом — плагины (`reformer/editor`, `rjsf/render`).
Составы, свои профили и кит организации по умолчанию — в
[docs/composition.md](docs/composition.md).

Профиль и кит человек меняет сам — ячейкой «движок · кит» в строке состояния: кит на лету,
профиль с перезагрузкой. Его выбор сильнее `preset` и кита из `defaults`; пункт «Как в конфиге запуска»
его снимает. Между какими профилями можно переключаться, задаёт `presetChoices` (без поля —
только `builder`; одно имя или пустой список закрепляют состав). Движок формы профилем
не выбирается: какой редактор откроет файл, решают плагины проекта.

## Отличия от 2.x

Версия 3 — переписанный билдер, и контракт запуска у него другой:

- **флага `--catalog` больше нет.** Сторонний ui-kit подключается плагином из
  `.ui_builder/plugins/`: плагин привозит и каталог компонентов, и их код — файлом данных
  превью нечем рисовать;
- **конфиг переехал** из `reformer-builder.config.json` рядом с запуском в
  `.ui_builder/config.json` (или `--config <path>`), и в нём остались брендинг и дефолты UI:
  палитра, набор компонентов и раскладка настраиваются плагинами;
- **битый конфиг больше не роняет билдер**: приложение открывается, а каждая проблема
  называется в уведомлении.
