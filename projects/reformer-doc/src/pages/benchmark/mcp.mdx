# Замеры: с MCP и без

Пакеты `@reformer/*` ставятся вместе с документацией — `llms.txt`, `docs/llms`, типами. Зачем
тогда MCP-сервер? Чтобы ответить цифрами, один и тот же агент — Claude Sonnet в Claude Code —
решал одни и те же задачи на формах в двух условиях:

- **Без MCP** — только файловые инструменты и установленные пакеты с их документацией;
- **С MCP** — то же плюс сервер `@reformer/mcp`, подключённый как есть, без настроек: агент
  собирает форму конструктором сервера.

Каждый прогон проверяет один и тот же верификатор: сборка и типы, затем поведение формы — значения,
правила, реакции, шаги мастера. Условия — в разделе [Как мерили](#как-мерили).

У каждого графика свои переключатели: **модель** (одна, Sonnet и Opus вместе или все) и
**плечо** (без MCP, с MCP или оба) — они меняют только этот график; карточки сценариев
переключаются над вкладками. Текст описывает замер на Claude Sonnet — у него оба плеча и все десять
сценариев. Claude Opus прошёл ту же полную матрицу, сравнить две модели можно вариантом «Sonnet и
Opus». Qwen2.5-Coder 14B (LM Studio) пока прошёл три сценария регистрации в обоих плечах, по три
повтора; Gemma 4 26B (Ollama) — только плечо с MCP на регистрации, по одному повтору. Полные
замеры обеих локальных моделей идут. Стоимость у них не считается, предел прогона — 25 минут. Когда моделей
несколько, сводки и разброс берут только ячейки «сценарий × стек», которые есть у каждой; наведите на
модель, чтобы приглушить остальные.

## Итог

<McpSummary />

- **Создание формы — главная разница.** Без сервера агент пишет модуль руками по документации
  пакетов и чаще ошибается в раскладке файлов, сборке и типах; на большой форме по спецификации
  это около четырёх минут и больше доллара на прогон. С MCP план, сборку и проверку типов делает
  сервер.
- **Правку и удаление готовой формы** проходят оба плеча почти без провалов, но с MCP это
  быстрее и дешевле.
- **Сильная модель не заменяет сервер.** Claude Opus без MCP прошёл 72 прогона из 90, с MCP — 89
  из 90. Sonnet с MCP прошёл 87 из 90 за $10,99 — почти в девять раз дешевле, чем Opus без сервера
  ($97,51). В каждом плече Opus дороже Sonnet в 2–2,5 раза.
- **Слабую локальную модель сервер вытягивает.** Qwen2.5-Coder 14B на регистрации прошёл с MCP 24
  прогона из 27, без сервера — ни одного из 25: модель пишет пару файлов не по раскладке модуля и
  останавливается.

## Подходы рядом

Как сработал каждый подход у каждой модели. Строка — модель на всех своих прогонах, столбец —
подход. В ячейке: сколько прогонов прошли все проверки, разбивка по видам задач, медиана времени
прогона и стоимость всех прогонов подхода. Сравнивайте внутри строки: у моделей разный набор задач —
у Sonnet и Opus все десять сценариев, у локальных моделей пока только регистрация.

<McpApproaches />

- **Без MCP** — правку и удаление проходит почти без провалов, но срывает создание формы: 15
  созданий из 27 у Sonnet и 11 из 27 у Opus. Это самый долгий и самый дорогой подход у обеих
  моделей; локальная модель с ним не прошла ни одного прогона.
- **С MCP** — больше пройденных прогонов у каждой модели, и это дешевле: 87 из 90 у Sonnet, 89 из
  90 у Opus, 24 из 27 у Qwen2.5-Coder 14B. Создание формы у Sonnet и Opus проходит почти всегда —
  25 и 26 из 27.

## Разброс прогонов

Медианы прячут хвосты. Здесь каждый из 180 прогонов — отдельный значок: закрашенный — прогон
прошёл все проверки, полый — нет; черта — медиана плеча. Наведите на значок, чтобы увидеть
сценарий, стек и цифры прогона.

<McpRunSpread />

Без сервера 21 прогон из 90 шёл дольше двух минут: 18 из них — создание формы, и половина из этих
восемнадцати не прошла проверки; ещё три — превращение одностраничной формы в мастер. С MCP дольше
двух минут шёл один прогон — создание мастера, 2,3 минуты, и он не прошёл проверки. Все двадцать
самых дорогих прогонов замера — без MCP.

Время и стоимость прогона растут вместе, поэтому на одной диаграмме плечи расходятся по диагонали:
прогоны с MCP — в левом нижнем углу, прогоны без MCP тянутся вправо вверх. Медианная стоимость
создания формы — $1,41 без MCP и $0,23 с ним; на правке и удалении облака ближе друг к другу.

## Как мерили

- **Агент** — Claude Code в неинтерактивном режиме, модель `sonnet`, во втором замере — `opus`.
  Инструменты — только файловые (`Read`, `Write`, `Edit`, `Glob`, `Grep`) внутри рабочего каталога,
  без оболочки. MCP-сервер подключён только в плече с MCP — в поверхности по умолчанию
  (`code-guided-dsl`); стенд проверяет это на старте каждого прогона.
- **Рабочий каталог** одинаков во всех плечах: установленные пакеты `@reformer/*` — ровно то, что
  публикуется в npm (сборка с типами, README, `llms.txt`, `docs/llms`); для сценариев по
  спецификации — `spec.md`; для правки и удаления — готовая форма.
- **Задание** одинаково во всех плечах: текст задачи, правила сдачи результата и раскладка модуля —
  какие части `createForm` в каких файлах. Без раскладки проверка поведения не нашла бы форму,
  написанную без сервера.
- **Лимиты** прогона одинаковы во всех плечах и заданы сценарием: деньги, шаги, время.
- **Локальные модели** работают в цикле стенда: файловые инструменты `read_file`, `write_file`,
  `list_files` внутри рабочего каталога, в плече с MCP — ещё инструменты сервера. Время прогона —
  предел сценария с поправкой на медленную модель, но не больше 25 минут: модель, застрявшая в
  цикле правок, шла бы до 100 минут на прогон. Модели Claude этот предел не задевают: самый долгий
  прогон Sonnet занял 5,3 минуты, Opus — 8 минут.
- **Проверка** — статическая (типы, стек, раскладка файлов) и поведенческая: пробы из контракта
  сценария заполняют форму и сверяют значения, ошибки правил, реакции и шаги мастера. Прогон
  **пройден**, когда прошли все обязательные проверки; **счёт** — доля пройденных проверок.
- **Порядок** — по одному прогону за раз, без параллели; каждая ячейка «сценарий × стек» проходит
  оба плеча подряд, поэтому колебания скорости API за часы замера ложатся на оба плеча почти
  одинаково.
- **Стоимость и токены** — из отчёта Claude Code о прогоне; это оценка по ценам API. Входные
  токены — вместе с чтением и записью кэша.

Ограничения: полная матрица — пока только у Claude Sonnet и Claude Opus; правка и удаление
начинаются с формы, собранной сервером, — это помогает плечу без MCP: раскладка у него уже перед
глазами.
