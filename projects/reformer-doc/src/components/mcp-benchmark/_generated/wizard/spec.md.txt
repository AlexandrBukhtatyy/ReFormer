# Форма: Оформление заказа

## Основная информация

**Название формы:** Оформление заказа в интернет-магазине (`OrderForm`)
**Назначение:** сценарии `order-*` и `wizard-*` стенда MCP. Каждая возможность ReFormer
встречается здесь хотя бы раз.

## Пользовательская история

**Как покупатель**, я хочу оформить заказ на одной странице: указать себя, способ получения,
товары и оплату, **чтобы** магазин принял заказ без звонка менеджера.

## Тип формы

Одна страница, поля сгруппированы по разделам. Порядок разделов и полей — как в таблице ниже.
Внизу страницы — кнопка «Оформить заказ».

### Строка товара (`items`)

Кнопка добавления — «+ Добавить товар», строку можно удалить, пока она не последняя.

| Ключ        | Подпись      | Компонент   | Начальное значение | Валидация                            |
| ----------- | ------------ | ----------- | ------------------ | ------------------------------------ |
| `title`     | Наименование | Input       | `''`               | Обязательное                         |
| `quantity`  | Количество   | InputNumber | `1`                | Обязательное, целое, от 1 до 99      |
| `price`     | Цена         | InputNumber | `null`             | Обязательное, не меньше 0            |
| `lineTotal` | Сумма        | InputNumber | `0`                | Только для чтения: количество × цена |

### Строка получателя (`recipients`)

Кнопка добавления — «+ Добавить получателя».

| Ключ      | Подпись             | Компонент | Начальное значение                    | Валидация                              |
| --------- | ------------------- | --------- | ------------------------------------- | -------------------------------------- |
| `email`   | Email получателя    | Input     | `''`                                  | Обязательное, формат email             |
| `primary` | Основной получатель | Checkbox  | `false` (в стартовой строке — `true`) | Основной — ровно один, см. «Поведение» |

## Поведение

| Что                              | Как                                                                                                                            |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Раздел «Компания»                | Виден только юрлицу (`customerType = company`)                                                                                 |
| Адрес доставки                   | При самовывозе недоступен для ввода и очищается                                                                                |
| Дата доставки                    | Видна только при доставке курьером; при смене способа получения на другой очищается                                            |
| Адрес для счёта                  | Пока `billingSame` отмечено, копирует адрес доставки поле в поле и недоступен для ввода                                        |
| Скидка                           | Доступна только юрлицу; когда становится недоступной, сбрасывается к начальному значению                                       |
| Промокод                         | Вводится в верхнем регистре: введённое приводится к заглавным буквам                                                           |
| Email для чека                   | Синхронизирован с `email` в обе стороны: правка любого из двух меняет второй                                                   |
| Смена типа покупателя на физлицо | Если выбран способ оплаты «По счёту», он меняется на «Картой онлайн»; правило способа оплаты перепроверяется                   |
| Основной получатель              | Отмечен ровно у одного: отметка в одной строке снимает её в остальных; если не отмечен ни у кого — им становится первая строка |
| Кнопка «Оформить заказ»          | Отправляет значения формы функцией `submitOrder(values)` из `./api` (тело — заглушка, сервера нет)                             |

## Расчёты

- `items[].lineTotal` = `quantity × price` (пустое — как 0).
- `subtotal` = сумма `lineTotal` всех строк.
- `total` = `subtotal × (1 − discount / 100)`, округление до копеек.

## ИНН

Своя проверка `innChecksum` — пишется отдельной функцией-правилом. Десятая цифра равна остатку от
деления на 11 суммы первых девяти цифр с весами `2, 4, 10, 3, 5, 9, 4, 6, 8`, взятому ещё раз по
модулю 10. Пример верного ИНН — `7707083893`.

## Промокод

Сервера нет: проверка — асинхронная заглушка с задержкой 300 мс. Верные коды — `SALE10` и `SALE20`,
остальные — ошибка. Пустой промокод не проверяется.
