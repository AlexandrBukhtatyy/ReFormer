# InputPassword

<ComponentDoc config={inputPasswordDocConfig}>
Поле пароля с кнопкой «показать / скрыть». Кнопка-глаз появляется, как только в поле есть
текст. В форме `InputPassword` кладётся в `component`
[узла схемы](../reference/glossary.md#форма-и-данные) как есть.

## Когда брать

- Вход, регистрация, смена пароля, подтверждение пароля.
- Любое секретное значение, которое человеку полезно проверить глазами: ключ API, кодовое слово.

Соседи:

- код фиксированной длины по ячейкам — [InputOTP](./input-otp.mdx);
- своя кнопка или иконка у поля вне формы — [InputGroup](./input-group.mdx).

`Input` с `type: 'password'` тоже скроет символы, но кнопки «показать» у него нет.

## Анатомия

| Компонент       | Значение поля    | Ключевые пропсы                                         |
| --------------- | ---------------- | ------------------------------------------------------- |
| `InputPassword` | `string \| null` | `showToggle`, `placeholder`, `autoComplete`, `readOnly` |

- `showToggle` (по умолчанию `true`) — показывать ли кнопку-глаз. Для поля «Повторите пароль» её
  обычно выключают.
- `placeholder` по умолчанию берётся из локали: «Пароль» / «Password».
- `autoComplete` — подсказка менеджеру паролей: `current-password` — вход, `new-password` —
  регистрация и смена пароля (браузер предложит сгенерировать пароль), `one-time-code` — код из
  СМС, `off`. Не задан — браузер решает сам.
- Пустой ввод даёт `null`.

Кроме своих пропсов, поле понимает общие для всех полей кита: `label`, `required`, `description`,
`labelTooltip`, `tooltip`, `testId` — см. [FormField](./form-field.mdx#общие-пропсы-полей). Иконка
`tooltip` встаёт левее кнопки-глаза, а пока глаза нет — у правого края.

```tsx
{
  model: model.$.password,
  component: InputPassword,
  componentProps: { label: 'Пароль' },
}
```

`value`, `onChange`, `onBlur` и `disabled` в `componentProps` не пишут: их подставляет обёртка
поля. Вне формы `InputPassword` тоже работает со значением, а не с событием: `onChange` получает
строку или `null`.

Проверку «пароли совпадают» делает правило над двумя полями — `cross` в схеме валидации, см.
[Свои правила](../validation/custom.md).

Видимостью можно управлять из кода. Ref компонента — `InputPasswordHandle`: кроме `focus()` и
`blur()` у него есть `setVisible(visible)` и `toggleVisibility()`.

## Доступность

- Под капотом настоящий `<input type="password">`: символы скрыты, менеджер паролей узнаёт поле.
  В режиме «показать» тип меняется на `text`.
- Кнопка-глаз — настоящая кнопка с `type="button"`: она не отправляет форму, фокусируется по Tab
  (фокус виден кольцом, как у поля) и нажимается Enter или пробелом. Её подпись для скринридера
  меняется: «Показать пароль» / «Скрыть пароль». У выключенного поля кнопка тоже выключена.
- `FormField` связывает поле с подписью (`<label for>`, `aria-labelledby`), пояснением и
  замечанием (`aria-describedby`). Пока замечание показано, у поля стоят `aria-invalid` и
  `aria-errormessage`; при `required` — `aria-required`.

## Локализация

`InputPassword` рисует три строки сам. Все берутся из локали кита; без локали — по-английски.

| Ключ                            | Русский         | Где                               |
| ------------------------------- | --------------- | --------------------------------- |
| `kit.inputPassword.placeholder` | Пароль          | подсказка в пустом поле           |
| `kit.inputPassword.show`        | Показать пароль | подпись кнопки, пока пароль скрыт |
| `kit.inputPassword.hide`        | Скрыть пароль   | подпись кнопки, пока пароль виден |
| `kit.infoHint.label`            | Подсказка       | подпись кнопки-иконки `tooltip`   |

Заменить подсказку для одного поля — проп `placeholder`. Подписи кнопки пропом не задаются: их
меняют ключом словаря для всего приложения. Как подключить локаль кита и переопределить ключ — в
[обзоре](./overview.md#локализация).
