# FileUpload

Поле выбора и загрузки файлов. Четыре компонента с разным видом — кнопка, зона перетаскивания,
строка ввода и аватар — и одним поведением: отбор файлов, список, загрузка на сервер с
прогрессом. Поведение даёт headless-слой [`@reformer/cdk/file-upload`](/docs/cdk/file-upload),
кит добавляет вид.

## Когда брать

- **`FileUploadBase`** — кнопка «Выбрать файлы» и список под ней. Подходит по умолчанию.
- **`FileUploadDropzone`** — файлов много или их удобно перетаскивать: документы к заявке.
- **`FileUploadInput`** — вложения второстепенны и места мало: имена файлов строкой, как в
  текстовом поле, без списка с превью.
- **`FileUploadAvatar`** — одно изображение с превью: фото профиля, логотип.

Соседи:

- нужна своя разметка (свой список, своя зона) — headless
  [FileUpload из CDK](/docs/cdk/file-upload): набор частей `Root`, `Trigger`, `Dropzone`,
  `ItemGroup`, `Item`, `ItemPreview`, `ItemProgress` и других или хук `useFileUpload`;
- показать уже прикреплённый файл без выбора — [Attachment](./attachment.mdx), на нём построен
  список файлов.

## Анатомия

| Компонент            | Значение поля                       | Ключевые пропсы                                                       |
| -------------------- | ----------------------------------- | --------------------------------------------------------------------- |
| `FileUploadBase`     | `File[] \| RemoteFileRef[] \| null` | `accept`, `multiple`, `maxFiles`, `maxFileSize`, `hint`, `uploader`   |
| `FileUploadDropzone` | `File[] \| RemoteFileRef[] \| null` | то же + `allowDrop`, `allowPaste`                                     |
| `FileUploadInput`    | `File[] \| RemoteFileRef[] \| null` | то же + `allowDrop`, `allowPaste`                                     |
| `FileUploadAvatar`   | `File \| RemoteFileRef \| null`     | `shape`, `accept` (по умолчанию `image/*`), `maxFileSize`, `uploader` |

Пропа `variant` нет — каждый вид отдельный компонент. В `component`
[узла схемы](../reference/glossary.md#форма-и-данные) он кладётся как есть.

**Значение поля — один массив, а не массив вложенных форм.** Пустой список приходит как `null`,
поэтому `required()` работает без доработок. Начальное значение в модели — `null`; тип поля в
интерфейсе формы — `FileUploadValue` из `@reformer/cdk/file-upload`.

**Два режима значения:**

- **отложенный** (по умолчанию) — значение `File[]`. Сети в компоненте нет: файлы отправляете
  вы при отправке формы, например через `FormData`;
- **сразу при выборе** — задан `uploader(file, { onProgress, signal })`. Файлы уходят на сервер
  при выборе: прогресс, повтор после ошибки, отмена при удалении. Значение — сериализуемые
  дескрипторы `RemoteFileRef` (`{ id, name, url?, size?, type? }`) только успешно загруженных
  файлов. Такое значение переживает черновик, JSON-форму и повторное открытие формы на
  редактирование. `autoUpload: false` ставит загрузку на паузу: файлы ждут в списке, пока проп
  снова не станет `true`.

**Отбор файлов** делает сам компонент, до записи в значение: `accept` (свой разбор — нативный
`accept` на перетаскивание не действует), `maxFiles`, `maxFileSize`, `minFileSize`,
`maxTotalFileSize`, дубликаты (`preventDuplicates`, по имени и размеру) и своя проверка
`validate`. Отклонённые файлы в значение не попадают: они приходят в `onReject` и показываются
под списком. При `multiple: false` новый выбор заменяет текущий файл.

```tsx
{
  model: model.$.documents,
  component: FileUploadDropzone,
  componentProps: {
    label: 'Документы',
    hint: 'PDF, до 10 МБ',
    accept: '.pdf',
    multiple: true,
    maxFileSize: 10 * 1024 * 1024,
  },
}
```

Общие пропсы полей (`label`, `required`, `description`, `tooltip` и другие) — в
[описании FormField](./form-field.mdx#общие-пропсы-полей). У `FileUploadAvatar` нет видимого
текста, поэтому `label` у него ещё и подпись зоны для скринридера.

Из поведения формы выбор файлов открывают программно:
`schema.node('documents').getRef<FileUploadFieldHandle>().current?.openFilePicker()`; есть и
`clear()`, и `abort()` — прервать активные загрузки.

## Доступность

Основу даёт headless-слой:

- внутри — скрытый настоящий `<input type="file">`, поэтому подпись поля и `focus()` работают
  как у обычного поля;
- зона перетаскивания (и строка ввода) — элемент с `role="button"`: Enter и пробел открывают
  выбор файлов. Перетаскивание — не единственный способ добавить файл;
- статусы («файл добавлен», «загрузка завершена», ошибки) объявляет скрытый регион
  `aria-live`;
- у кнопки удаления `aria-label` с именем файла, прогресс загрузки — `role="progressbar"`.

[FormField](./form-field.mdx) вешает подпись и замечание на кнопку или зону. При показанном
замечании зона, строка ввода и аватар подсвечивают рамку по `aria-invalid`; кнопка показывает
ошибку только текстом под полем. Вне формы рамку включает проп `invalid`.

## Локализация

Строки кита:

| Ключ                              | Где                                               | Проп          |
| --------------------------------- | ------------------------------------------------- | ------------- |
| `kit.fileUpload.choose`           | текст кнопки; подпись скрепки у `FileUploadInput` | `placeholder` |
| `kit.fileUpload.dropzone`         | текст зоны перетаскивания                         | `placeholder` |
| `kit.fileUpload.inputPlaceholder` | пустая строка ввода                               | `placeholder` |
| `kit.fileUpload.clear`            | подпись крестика очистки у `FileUploadInput`      | —             |
| `kit.fileUpload.avatarLabel`      | подпись зоны аватара для скринридера              | `label`       |
| `kit.fileUpload.error`            | метка ошибки на аватаре                           | —             |

Объявления `aria-live` и подписи кнопок удаления и повтора — строки CDK (`cdk.fileUpload.*`),
они входят в локаль кита.

Тексты отказов и ошибок загрузки — это замечания с кодами `fileType`, `maxFileSize`,
`minFileSize`, `maxFiles`, `maxTotalFileSize`, `fileExists`, `uploadFailed`, `uploadAborted`.
Текст по коду ищется так же, как у правил: [словарь сообщений](../reference/glossary.md#валидация)
формы (`ValidationMessagesProvider messages`), затем локаль, затем встроенный английский. Как
подключить русскую локаль кита — в [обзоре](./overview.md#локализация).
