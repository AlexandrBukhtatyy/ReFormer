# Table

<ComponentDoc config={tableDocConfig}>
Таблица в двух видах. Части `Table…` — стилизованные теги таблицы для разметки руками. `DataGrid`
— таблица, которая сама запрашивает страницы данных у вашей функции и показывает загрузку, ошибку
и пустой результат. Это не поле формы.

## Когда брать

- **Части Table** — данные уже на руках и их немного: итоги заказа, сравнение тарифов, состав
  заявки. Строки, ячейки и подписи вы пишете сами.
- **DataGrid** — данные на сервере и приходят страницами: реестр заявок, список пользователей.
  Нужны фильтр по колонке, переход по страницам, выбор строк.
- [List](./list.mdx) — массив [модели](../reference/glossary.md) формы нужно показать списком, без
  колонок.
- [Item](./item.mdx) — строка-карточка с иконкой, описанием и кнопками: список настроек или
  участников, а не табличные данные.
- [Pagination](./pagination.mdx) — только навигация по страницам у своей разметки. DataGrid
  ставит её сам.

## Анатомия

Оба вида импортируются только из `@reformer/ui-kit/table`: в корневом `@reformer/ui-kit` таблицы
нет.

### Части Table

```tsx
import {
  Table,
  TableBody,
  TableCaption,
  TableCell,
  TableFooter,
  TableHead,
  TableHeader,
  TableRow,
} from '@reformer/ui-kit/table';

<Table>
  <TableCaption>Последние платежи</TableCaption>
  <TableHeader>
    <TableRow>
      <TableHead>Счёт</TableHead>
      <TableHead className="text-right">Сумма</TableHead>
    </TableRow>
  </TableHeader>
  <TableBody>
    <TableRow>
      <TableCell>INV-001</TableCell>
      <TableCell className="text-right">2 500 ₽</TableCell>
    </TableRow>
  </TableBody>
</Table>;
```

| Часть          | Тег             | Что это                                                                    |
| -------------- | --------------- | -------------------------------------------------------------------------- |
| `Table`        | `div` + `table` | Таблица в контейнере с горизонтальной прокруткой. Узкий экран не ломается. |
| `TableCaption` | `caption`       | Подпись под таблицей. Скринридер называет ею таблицу.                      |
| `TableHeader`  | `thead`         | Шапка.                                                                     |
| `TableBody`    | `tbody`         | Тело. У последней строки нет нижней границы.                               |
| `TableFooter`  | `tfoot`         | Итоги на приглушённом фоне.                                                |
| `TableRow`     | `tr`            | Строка с подсветкой при наведении. `data-state="selected"` — выбранная.    |
| `TableHead`    | `th`            | Ячейка заголовка.                                                          |
| `TableCell`    | `td`            | Ячейка данных.                                                             |

Каждая часть принимает атрибуты своего тега (`colSpan`, `scope`, `data-*`) и `className`. Классы
сливаются через `tailwind-merge`: ваш класс побеждает встроенный. Логики у частей нет.

### DataGrid

`DataGrid` построен на `@tanstack/react-table`. Это необязательная зависимость кита, её ставят
отдельно:

```bash
npm install @tanstack/react-table
```

```tsx
import { DataGrid, type TableSettings } from '@reformer/ui-kit/table';

type User = { id: number; name: string; email: string };

const settings: TableSettings<User> = {
  columns: [
    {
      id: 'name',
      header: 'Имя',
      accessor: (u) => u.name,
      filterable: true,
      filterPlaceholder: 'Поиск по имени',
    },
    { id: 'email', header: 'E-mail', accessor: (u) => u.email },
  ],
  pageSize: 20,
  rowKey: (u) => u.id,
  // Получает страницу, фильтры и сортировку, возвращает строки страницы и общее число строк.
  dataProvider: async ({ pagination, filters, sorting }) => {
    const response = await fetch(buildUsersUrl(pagination, filters, sorting));
    return response.json(); // { rows: User[], total: number }
  },
};

<DataGrid settings={settings} />;
```

Всё описание таблицы — в одном объекте `settings`:

| Поле                | Что делает                                                                                          |
| ------------------- | --------------------------------------------------------------------------------------------------- |
| `columns`           | Колонки: `id`, `header`, `accessor`, `sortable`, `filterable`, `filterLabel`, `align`, `className`. |
| `dataProvider`      | `(query) => Promise<{ rows, total }>`. Сортирует, фильтрует и режет на страницы — он, а не таблица. |
| `pageSize`          | Строк на странице, по умолчанию `10`. Смена значения перезапрашивает данные с первой страницы.      |
| `rowKey`            | Стабильный ключ строки. С ним выбор строк переживает перелистывание.                                |
| `selection`         | `'none'`, `'single'` или `'multiple'` — колонка выбора строк.                                       |
| `onSelectionChange` | `({ keys, rows }) => void` — выбранные строки после каждого изменения выбора.                       |

Как работает таблица:

- `dataProvider` вызывается при монтировании и при каждой смене страницы, фильтра, сортировки
  или `pageSize`. Блок загрузки виден только до первой страницы. Дальше на время запроса таблица
  остаётся на месте и приглушается. Ответ устаревшего запроса отбрасывается.
- Колонка с `sortable` получает кнопку в заголовке: первый щелчок сортирует по возрастанию,
  второй — по убыванию, третий снимает сортировку. Направление уходит в `query.sorting`.
- Колонка с `filterable` получает текстовое поле над таблицей. Его значение уходит в
  `query.filters[id]` на каждое нажатие клавиши. Смена фильтра возвращает таблицу на первую
  страницу.
- Отказ промиса показывает блок ошибки с кнопкой «Повторить». Текст ошибки — `message` у `Error`,
  иначе общий текст «Не удалось загрузить данные».
- Пустой `rows` — строка «Нет данных» в теле таблицы. Пагинация появляется, когда страниц больше
  одной.
- Выбор строк хранится внутри таблицы. Снаружи его читает `onSelectionChange({ keys, rows })`:
  он вызывается после каждого изменения выбора, в том числе после сброса. С `rowKey` выбор
  переживает перелистывание, и в `rows` попадают строки, выбранные на других страницах. Без
  `rowKey` ключ строки — её номер на странице, поэтому выбор сбрасывается при каждой смене строк:
  страница, фильтр, сортировка, перезагрузка.

## Доступность

Части Table — нативные теги таблицы, скринридер читает строки и колонки сам.

- Назовите таблицу: `TableCaption` или `aria-label` у `Table`.
- `TableHead` не ставит `scope`. Для заголовков строк (первая ячейка — `th`) добавьте
  `scope="row"` сами.

DataGrid добавляет к этому:

- Блок загрузки объявляется вежливо (`role="status"`, `aria-live="polite"`), блок ошибки —
  сразу (`role="alert"`). Кнопка «Повторить» — обычная кнопка.
- Флажки и переключатели выбора — нативные `input` с подписями «Выбрать все» и «Выбрать строку».
  Переключатели режима `single` — одна группа с общим `name`: `Tab` заходит в неё один раз,
  стрелки переводят выбор.
- Кнопка сортировки — обычная кнопка в заголовке. Заголовок колонки, по которой отсортировано,
  получает `aria-sort` (`ascending` или `descending`).
- У поля фильтра есть подпись для скринридера: `filterLabel` колонки или «Фильтр: Имя» из
  словаря (`kit.table.filter` с заголовком колонки; если заголовок не строка — с `id`).
  `filterPlaceholder` — только подсказка внутри поля.
- Пагинация — `nav` с подписью, текущая страница помечена `aria-current="page"`, недоступные
  «Назад» и «Вперёд» — `aria-disabled`.
- При перезагрузке таблица и пагинация остаются на месте, поэтому фокус на кнопке сортировки или
  ссылке страницы не теряется. Пока идёт запрос, область таблицы помечена `aria-busy`.

## Локализация

Части Table своих строк не рисуют. DataGrid рисует строки сам и берёт их из словаря кита:

| Ключ                                | English             | Русский                        |
| ----------------------------------- | ------------------- | ------------------------------ |
| `kit.table.empty`                   | No data             | Нет данных                     |
| `kit.table.loadError`               | Failed to load data | Не удалось загрузить данные    |
| `kit.table.selectAll`               | Select all          | Выбрать все                    |
| `kit.table.selectRow`               | Select row          | Выбрать строку                 |
| `kit.table.filter`                  | Filter: \{column}   | Фильтр: \{column}              |
| `kit.asyncBoundary.loadingTitle`    | Loading data...     | Загрузка данных...             |
| `kit.asyncBoundary.loadingSubtitle` | Please wait         | Пожалуйста, подождите          |
| `kit.asyncBoundary.errorTitle`      | Failed to load      | Ошибка загрузки                |
| `kit.asyncBoundary.retry`           | Retry               | Повторить                      |
| `kit.pagination.previous` / `next`  | Previous / Next     | Назад / Вперёд                 |
| `kit.pagination.previousLabel`      | Go to previous page | Перейти на предыдущую страницу |
| `kit.pagination.nextLabel`          | Go to next page     | Перейти на следующую страницу  |
| `kit.pagination.label`              | Pagination          | Страницы                       |
| `kit.pagination.more`               | More pages          | Ещё страницы                   |

Пропсов для этих строк у `DataGrid` нет: свой текст есть только у поля фильтра — подпись
`filterLabel` и подсказка `filterPlaceholder` колонки. Без провайдера локализации строки
английские. Русский набор кита подключает `I18nProvider` из `@reformer/core/react` — готовой
локалью `ru` из `@reformer/ui-kit/locale/ru` или загрузчиком `loadKitLocale` из
`@reformer/ui-kit/locale`. Свою формулировку задаёт ключ в локали:

```tsx
import { extendLocale } from '@reformer/core/i18n';
import { I18nProvider } from '@reformer/core/react';
import { ru } from '@reformer/ui-kit/locale/ru';

// Константа модуля: новый объект локали на каждый рендер заново перерисовывал бы все подписи.
const locale = extendLocale(ru, { messages: { 'kit.table.empty': 'Заявок пока нет' } });

<I18nProvider locale={locale}>
  <DataGrid settings={settings} />
</I18nProvider>;
```
