# List

Обёртка для массива, который форма только показывает: уведомления, статусы документов, бейджи.
Элементы приходят уже нарисованными, List кладёт их в контейнер со списочной разметкой. Кнопок
«Добавить» и «Удалить» у него нет.

## Когда брать

- **List** — массив [модели](../reference/glossary.md) нужно показать, а не редактировать. Состав
  меняет код (например, [поведение](../reference/glossary.md) формы), а не пользователь.
- [FieldArray / FieldArraySection](./field-array.mdx) — пользователь сам добавляет, удаляет и
  переставляет строки. Тот же узел массива, другой `component`.
- `List` из [`@reformer/cdk/list`](../cdk/list.mdx) — компонент без оформления для React-кода
  вне схемы: строки и пустое состояние рисуете вы.
- [Item](./item.mdx) — оформление одной строки. Внутри List им удобно рисовать элементы.
- [Box](./box.mdx) — контейнер для фиксированного набора узлов, без массива.

## Анатомия

List — один компонент, без частей. В [схеме формы](../reference/glossary.md) он стоит в узле
массива: `model` — массив модели, `item` строит разметку строки, `component: List` оформляет
результат.

```tsx
import type { FormModel, FormSchemaNode } from '@reformer/core';
import { Item, List } from '@reformer/ui-kit'; // или '@reformer/ui-kit/list'

type Notice = { text: string };

const schema = (model: FormModel<{ notices: Notice[] }>): FormSchemaNode => ({
  children: [
    {
      model: model.$.notices,
      component: List,
      componentProps: { className: 'space-y-1' },
      item: (row: FormModel<Notice>) => ({
        component: Item,
        componentProps: { role: 'listitem' },
        children: [row.$.text], // сигнал поля строки — текст обновится сам
      }),
    },
  ],
});
```

| Проп        | Что делает                                                                         |
| ----------- | ---------------------------------------------------------------------------------- |
| `items`     | Готовые элементы `{ key, index, model?, children }`. В схеме их передаёт рендерер. |
| `className` | Классы контейнера поверх встроенного `space-y-2`.                                  |
| `as`        | Тег контейнера: `'div'` по умолчанию, `'ul'` или `'ol'` для маркированного списка. |
| `testId`    | Атрибут `data-testid` контейнера.                                                  |

Подписки на модель и цикла по массиву в List нет: строки строит и обновляет рендерер. Поэтому
компонент можно отрисовать и без формы — передав `items` руками, как во вкладке «Варианты» ниже.

### В документе renderer-json

В JSON тот же узел массива ссылается на компонент по имени. Пути `$model(...)` внутри `$template`
считаются от строки массива.

```json
{
  "model": "$model(notices)",
  "component": "$component(List)",
  "componentProps": { "className": "space-y-1" },
  "item": {
    "$template": {
      "component": "$component(Item)",
      "componentProps": { "role": "listitem" },
      "children": ["$model(text)"]
    }
  }
}
```

Оба компонента нужно зарегистрировать в [реестре](../reference/glossary.md):

```ts
import { Item, List } from '@reformer/ui-kit';

reg.component('List', List);
reg.component('Item', Item);
```

Без `component` узел массива тоже отрисуется, но без оформления, и рендерер предупредит об этом в
консоли.

## Доступность

- Контейнер получает `role="list"` при любом значении `as`.
- Роль `listitem` у элементов List не ставит. Список без `listitem` внутри скринридер читает
  неверно, поэтому роль задаёт шаблон строки: `componentProps: { role: 'listitem' }` у
  компонента строки или `as: 'ul'` у List и тег `li` в строке (`{ component: 'li', children: […] }`).
- Элемент со своей ролью не может одновременно быть `listitem`: у `Alert`, например, роль
  `alert`. Такой элемент оборачивайте в `li`, а List ставьте с `as: 'ul'`.
- Клавиатурой List не управляет: фокус получают только интерактивные элементы внутри строк.

## Локализация

Своих строк компонент не рисует: содержимое строк — ваш шаблон `item`.
