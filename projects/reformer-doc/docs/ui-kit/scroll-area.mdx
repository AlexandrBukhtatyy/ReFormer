# ScrollArea

<ComponentDoc config={scrollAreaDocConfig}>
Область фиксированного размера, внутри которой содержимое прокручивается. Вместо системных полос
прокрутки она рисует тонкие полосы в цветах темы, одинаковые во всех браузерах. Сама прокрутка
остаётся системной: колесо, тачпад и касание работают как обычно. Построен на Radix ScrollArea.

## Когда брать

- **ScrollArea** — длинный список или текст в блоке ограниченного размера, и системная полоса
  выглядит чужой: ряд вкладок, панель со списком, текст соглашения в форме.
- Класс `overflow-auto` — если системная полоса устраивает. Это проще и не добавляет разметки.
- [Resizable](./resizable.mdx) — пользователь сам меняет размер панелей. Прокрутку внутри панели
  при этом по-прежнему даёт ScrollArea.
- [MessageScroller](./message-scroller.mdx) — лента сообщений чата, которая держится у конца при
  новых сообщениях.
- [Tree](./tree.mdx) — у дерева своя прокрутка с виртуальными строками, оборачивать его не нужно.

## Анатомия

```tsx
import { ScrollArea, ScrollBar } from '@reformer/ui-kit'; // или '@reformer/ui-kit/scroll-area'

<ScrollArea className="h-40 w-72 rounded-md border">
  <div className="p-4">{/* длинное содержимое */}</div>
  <ScrollBar orientation="horizontal" />
</ScrollArea>;
```

| Часть        | Что это                                                                                         | Ключевые пропсы                                                 |
| ------------ | ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `ScrollArea` | Корень. Внутри — область прокрутки с вашим содержимым и вертикальная полоса.                    | `className`, `type`, `scrollHideDelay`, `size`, `viewportProps` |
| `ScrollBar`  | Дополнительная полоса. Нужна для горизонтальной прокрутки: без неё лишнее по ширине обрезается. | `orientation`, `size`                                           |

- Размер задают классы корня (`h-*`, `w-*`). Без высоты область растёт вместе с содержимым и
  вертикальной прокрутки нет.
- `type` решает, когда видны полосы: `hover` (по умолчанию) — при наведении и прокрутке, `scroll`
  — только во время прокрутки, `auto` — когда содержимое не помещается, `always` — всегда.
- `size="xs"` делает полосы тоньше: 6px вместо 10px. У ScrollArea он действует на её
  вертикальную полосу, у ScrollBar — на эту полосу.
- `className` и остальные атрибуты попадают на корень. Прокручивается же внутренний элемент с
  атрибутом `data-slot="scroll-area-viewport"`. Его пропсы — в `viewportProps`: `tabIndex`,
  `aria-label`, `ref` (чтобы прокрутить область из кода), обработчики; `className` оттуда
  дополняет классы кита.

## Доступность

- Прокрутка системная, поэтому работают колесо мыши, тачпад, касание и прокрутка к элементу, на
  который перешёл фокус по `Tab`.
- Полосы — нарисованные элементы, а не системные. Их можно тянуть мышью, но фокуса и клавиатуры у
  них нет.
- `tabIndex` области ни Radix, ни кит сами не ставят. Если внутри нет ни одного фокусируемого
  элемента, пролистать область стрелками можно не во всех браузерах. Для текста, который
  пользователь должен прочитать (соглашение), сделайте область фокусируемой и назовите её:
  `viewportProps={{ tabIndex: 0, 'aria-label': 'Текст соглашения' }}`. Кольцо фокуса у неё уже
  есть.
- При `dir="rtl"` (или внутри [DirectionProvider](./direction.mdx) с `rtl`) вертикальная полоса
  встаёт слева.

## Локализация

Своих строк компонент не рисует.
