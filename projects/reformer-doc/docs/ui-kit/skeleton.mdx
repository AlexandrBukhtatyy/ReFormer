# Skeleton

<ComponentDoc config={skeletonDocConfig}>
Серый пульсирующий блок на месте содержимого, которое ещё загружается. Форму и размер задают
классы: строка текста, круг аватара, прямоугольник картинки. Компонент входит в
[кит](../reference/glossary.md#пакеты) `@reformer/ui-kit`, это не поле формы.

## Когда брать

- **Skeleton** — заранее известно, как будет выглядеть содержимое: карточка, строка таблицы,
  профиль. Скелет повторяет раскладку, и страница не прыгает, когда данные придут.
- [Spinner](./spinner.mdx) — короткое ожидание без известной раскладки или ожидание внутри кнопки.
- [Progress](./progress.mdx) — известна доля выполненного: загрузка файла, шаг из многих.
- [AsyncBoundary](./async-boundary.mdx) — готовые состояния «загрузка / ошибка / пусто» вокруг
  блока с данными. Скелет передают ему пропом `loadingSlot` вместо спиннера.

## Анатомия

```tsx
import { Skeleton } from '@reformer/ui-kit'; // или '@reformer/ui-kit/skeleton'

<Skeleton className="h-4 w-48" />;
```

Это один `<div>` с классами `animate-pulse rounded-md bg-accent`. Своих пропсов нет — всё задаёт
`className`:

| Что нужно           | Классы                   |
| ------------------- | ------------------------ |
| Строка текста       | `h-4 w-48`, `h-4 w-full` |
| Аватар              | `h-12 w-12 rounded-full` |
| Картинка или превью | `h-40 w-full rounded-xl` |

Без высоты и ширины блок пустой и не виден. Ваш класс скругления перекрывает базовый
`rounded-md`.

## Доступность

- Сам скелет для скринридера пуст: у него нет ни текста, ни роли.
- Пометьте область загрузки `aria-busy="true"` и положите внутрь скрытую подпись
  (`<span className="sr-only">Загружаем профиль…</span>`), как в примере «Профиль». Когда данные
  придут, снимите `aria-busy` вместе со скелетом.
- Пульсация — анимация CSS (`animate-pulse`). Если пользователь просил браузер уменьшить движение,
  отключите её классом `motion-reduce:animate-none`.

## Локализация

Своих строк компонент не рисует. Подпись для скринридера — ваш текст.
