# Модель данных

[Модель](/docs/reference/glossary) хранит значения формы. Это обычный на вид объект,
под каждым полем которого стоит сигнал. Значения принадлежат модели, а не компонентам и не нодам
формы.

## Когда нужно

Модель есть у каждой формы: `createForm` создаёт её из `initial` или берёт готовую. Обращаться к
модели напрямую приходится, когда вы:

- загружаете данные с сервера в форму;
- читаете значения для отправки или автосохранения;
- добавляете и удаляете строки массивов;
- описываете схему, правила и поведение — они указывают на поля через сигналы полей.

## Минимальный пример

```typescript
import { createModel } from '@reformer/core';

type Profile = { name: string; address: { city: string } };

const model = createModel<Profile>({ name: '', address: { city: '' } });

model.name = 'Анна'; // запись присваиванием
model.$.address.city.value = 'Казань'; // запись через сигнал поля
model.get(); // { name: 'Анна', address: { city: 'Казань' } }
model.reset(); // назад к начальным значениям
```

Ниже — то же вживую. Первое поле пишет в модель через сигнал `model.$.name`, второе — присваиванием
`model.address.city`. Блок под кнопками показывает значение модели целиком.

## Модель в сборке формы

`createForm` возвращает [сборку формы](/docs/reference/glossary) (`FormBundle`) —
объект с моделью, нодами, проверкой, шагами и отправкой. Модель — её основа: ноды и проверка читают
значения из модели, а не хранят свои копии. `bundle.model` — та же модель, что вы передали в
`createForm` или что сборка создала из `initial`.

## Значение поля и сигнал поля

К полю модели обращаются двумя способами.

| Запись          | Что это                                      | Где нужно                                                |
| --------------- | -------------------------------------------- | -------------------------------------------------------- |
| `model.email`   | значение поля: читается и пишется как обычно | условия и расчёты поведения, обработчики событий         |
| `model.$.email` | сигнал поля                                  | привязка в схеме, правила валидации, операторы поведения |

```typescript
model.address.city; // прочитать значение
model.address.city = 'Казань'; // записать значение

model.$.address.city; // сигнал поля
model.$.address.city.value; // значение через сигнал: чтение и запись
model.$.address.city.peek(); // значение без подписки
```

Оба способа ведут к одному сигналу. Внутри `compute`, `effect` или условия `enableWhen` чтение
`model.address.city` подписывается на поле так же, как чтение `model.$.address.city.value`.

## Значение целиком

| Метод                  | Что делает                                                                    |
| ---------------------- | ----------------------------------------------------------------------------- |
| `model.get()`          | снимок всех значений — например, для отправки                                 |
| `model.set(value)`     | записать объект целиком, со всеми ключами типа                                |
| `model.patch(partial)` | записать только переданные ключи; группы сливаются, массив заменяется целиком |

```typescript
model.patch({ address: { city: 'Казань' } }); // имя не меняется
model.set({ name: 'Иван', address: { city: 'Москва' } }); // все поля сразу
```

Вычисляемые поля (цели `compute`) ни `set`, ни `patch` не перезаписывают: ими владеет
[поведение](/docs/behaviors/computed).

Подписаться на всю модель или на группу можно через их сигнал: `model.$` — сигнал модели целиком,
`model.$.address` — сигнал группы. Так устроен живой пример выше.

```typescript
// Вызывается сразу с текущими значениями и потом при каждом изменении модели.
const stop = model.$.subscribe((values) => saveDraft(values));
```

## Сброс и точка отсчёта

[Точка отсчёта](/docs/reference/glossary) — значения, к которым возвращает сброс и
относительно которых модель считается изменённой. Сначала это начальные значения.

| Метод                    | Что делает                                                     |
| ------------------------ | -------------------------------------------------------------- |
| `model.reset()`          | вернуть значения к точке отсчёта                               |
| `model.isDirty()`        | отличаются ли значения от точки отсчёта                        |
| `model.captureInitial()` | сделать текущие значения новой точкой отсчёта (после загрузки) |

```typescript
model.patch(await loadProfile()); // данные с сервера
model.captureInitial(); // теперь сброс возвращает к ним, а форма не считается изменённой
```

`model.reset()` меняет только значения. Сброс для пользователя — кнопка «Сбросить» — делает
`form.reset()`: та же точка отсчёта, и вдобавок снимаются замечания и касания полей. Подробнее — в
[Отправке и сбросе](/docs/patterns/submit-and-reset).

## Вложенные группы

Объект внутри модели — тоже модель: у `model.address` есть свои `$`, `get`, `patch`, `reset` и
`isDirty`.

```typescript
model.address.get(); // { city: 'Казань' }
model.address.patch({ city: 'Москва' });
model.address.$.city === model.$.address.city; // true — один и тот же сигнал
```

## Массивы

Массивы объектов принадлежат модели, и строки добавляют и удаляют на ней. Шаблон новой строки
задают в начальных значениях функцией `arrayOf(blank)` — тогда `push()` без аргумента добавит
строку по шаблону.

```typescript
import { arrayOf, createModel } from '@reformer/core';

type Item = { title: string; qty: number };

const model = createModel<{ items: Item[] }>({
  items: arrayOf((): Item => ({ title: '', qty: 1 })),
});

model.items.push(); // строка по шаблону
model.items.push({ title: 'Книга', qty: 2 });
model.items.removeAt(0);
model.items.move(0, 1);
model.items.length; // число строк
```

Остальные операции (`insertAt`, `swap`, `clear`, `at`, `map`, `toArray`) и рендер строк — в
[Массивах и динамических формах](/docs/patterns/arrays).

## Подводные камни

- **`model.get()` не подписывает.** Внутри `compute`, `effect` или условия пересчёта не будет.
  Читайте поля по отдельности: `model.price`, `model.$.price.value`.
- **Привязка — всегда через `$`.** В схеме, правилах и операторах поведения нужен сигнал поля:
  `model: model.$.email`. Запись `model: model.email` не скомпилируется.
- **`set` ждёт объект целиком.** Если в данных с сервера не хватает ключей, эти поля останутся
  прежними, а в режиме разработки появится предупреждение. Для части полей — `patch`.
- **Шаблон `arrayOf` теряется при копировании.** `structuredClone` и `JSON.parse(JSON.stringify(…))`
  отдают массив без шаблона. Держите начальные значения в функции, а не в константе, которую
  копируют.
- **Имена методов модели заняты.** Поле с именем `get`, `set`, `patch`, `reset`, `isDirty`,
  `captureInitial`, `signalAt` или `$` закроет одноимённый метод.
