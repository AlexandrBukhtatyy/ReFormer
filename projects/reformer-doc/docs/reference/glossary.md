# Глоссарий

Слова, которые документация ReFormer использует в узком смысле. Если термин в тексте непонятен —
он здесь.

## Форма и данные

| Термин                   | Что это                                                                                                                                 | В коде                                                                         |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| **Модель**               | Хранилище значений формы. Обычный на вид объект, под каждым полем которого стоит сигнал. Значения принадлежат модели, а не компонентам. | `createModel`, `bundle.model`                                                  |
| **Сигнал поля**          | Реактивное значение одного поля модели. Через него схема, правила и поведение указывают, о каком поле речь.                             | `model.$.email`, `model.$.address.city`                                        |
| **Схема формы**          | Дерево узлов: какие поля есть и каким компонентом рисуется каждое. Правил в ней нет.                                                    | `FormSchemaNode`, функция `(model) => узел`                                    |
| **Узел схемы**           | Элемент схемы. Узел поля связывает сигнал с компонентом и его пропсами, контейнер перечисляет вложенные узлы.                           | `{ model, component, componentProps }`, `{ children }`                         |
| **Нода**                 | Состояние поля в форме: значение, касание, замечания, доступность. Бывает трёх видов.                                                   | `FormControl` (поле), `FormGroup` (группа), `FormArray` (массив); `form.email` |
| **Сборка формы**         | Всё, что вернул `createForm`: модель, ноды, проверка, шаги и отправка в одном объекте.                                                  | `FormBundle`, `createForm`, `useFormBundle`                                    |
| **Точка отсчёта модели** | Значения, к которым возвращает сброс и относительно которых поле считается изменённым. Это начальные значения, пока их не перенесли.    | `model.captureInitial()`, `form.reset()`, `model.isDirty()`                    |
| **M1**                   | Название архитектуры ядра: модель, схема, правила и поведение описываются отдельно и собираются вызовом `createForm`.                   | —                                                                              |

## Валидация

| Термин                  | Что это                                                                                                                                      | В коде                                                           |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| **Схема валидации**     | Правила формы, описанные отдельно от разметки, функцией над моделью.                                                                         | `defineValidation`, `validate(...)`                              |
| **Правило** (валидатор) | Проверка одного значения. Возвращает замечание или ничего.                                                                                   | `required()`, `email()`, `minLength(2)`                          |
| **Замечание**           | Результат правила: код, параметры и важность. Текста в замечании нет — его даёт словарь сообщений.                                           | `ValidationIssue = { code, params?, severity? }`                 |
| **Важность замечания**  | `error` блокирует отправку, `warning` показывается, но не блокирует.                                                                         | `severity: 'warning'`                                            |
| **Словарь сообщений**   | Тексты замечаний по их кодам, для каждого языка свой.                                                                                        | `defineIssueMessages`, `I18nProvider`                            |
| **Стратегия валидации** | Когда проверять поле и показывать замечания: при отправке, при уходе из поля, при каждом изменении или живая проверка после первой отправки. | `strategy: 'submit' \| 'blur' \| 'change' \| 'afterFirstSubmit'` |
| **Касание**             | Отметка «поле трогали». Замечания обычно показываются только у тронутых полей.                                                               | `touched`, `markAsTouched()`                                     |

## Поведение, шаги и отправка

| Термин          | Что это                                                                                                    | В коде                                                    |
| --------------- | ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| **Поведение**   | Декларативные реакции формы: вычисляемые поля, условная доступность, копирование и синхронизация значений. | `defineFormBehavior`, `compute`, `enableWhen`, `copyFrom` |
| **Поток шагов** | Порядок и правила шагов многошаговой формы.                                                                | `flow: { steps: [{ id, rules }] }`, `useFormFlow`         |
| **Отправка**    | Проверить всю форму и, если блокирующих замечаний нет, вызвать обработчик. Результат — объект со статусом. | `bundle.submission.submit(handler)`, `SubmitResult`       |

## Рендеринг

| Термин           | Что это                                                                                                    | В коде                                                   |
| ---------------- | ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| **Адаптер поля** | Описание того, как компонент поля читает и пишет значение ноды. Позволяет подключать свои компоненты.      | `getFieldAdapter`                                        |
| **Реестр**       | Для формы из JSON: набор компонентов, источников данных и функций, на которые ссылается документ по имени. | `reg.component`, `reg.dataSource`, `'$component(Input)'` |

## Пакеты

| Термин   | Что это                                                             |
| -------- | ------------------------------------------------------------------- |
| **Ядро** | `@reformer/core` — модель, форма, валидация, поведение, хуки React. |
| **CDK**  | `@reformer/cdk` — компоненты без оформления: поле, массив, мастер.  |
| **Кит**  | Набор готовых компонентов полей. Основной — `@reformer/ui-kit`.     |

## Билдер

Визуальный редактор форм. Подробно — в разделе [Билдер](/docs/builder/overview).

| Термин             | Что это                                                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------------ |
| **Оболочка**       | Сам билдер без плагинов: окно, открытие проекта, сохранение, управление плагинами.                     |
| **Плагин**         | Пакет с `manifest.json` и кодом, который добавляет билдеру панели, команды, редакторы.                 |
| **Рабочая копия**  | Файлы проекта, какими их видит билдер, вместе с несохранёнными правками. На диск попадают по `Ctrl+S`. |
| **Модуль формы**   | Каталог с кодом формы для приложения: схема, модель, правила, поведение. Его печатает экспорт кода.    |
| **Движок формы**   | Плагины одного формата формы: редактор, превью, проверки, генерация кода.                              |
| **Ход ассистента** | Ответ ассистента на одну просьбу вместе со всеми его правками. Отменяется целиком.                     |
