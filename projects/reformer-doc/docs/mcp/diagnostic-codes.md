# Коды диагностик

У каждой находки MCP-сервера есть стабильный код. Текст находки может меняться от версии к версии,
код — нет: хост со своим языком выбирает текст по коду. Семейств три:

- `RF0xx` — коды `validate_form`. В `kind="bundle"` находка судьи заворачивается в код `RF`, а свой
  код ставит в начало сообщения (`RF014 … unknown-key: …`).
- `C1`–`C13` — кросс-проверки intent против раскладки, которую из него строит сборка.
- коды чтения и судьи (`unknown-key`, `unplaced`, …) — их `form_build` печатает первыми в строке
  находки `<код> at <место>: <что не так> → <что сделать>`, а `@reformer/mcp/intent` возвращает в
  `problems`, `notices`, `errors` и `warnings`.

Список полный: тест сверяет его с кодом сервера. Тот же реестр для модели — раздел
`reformer://docs/mcp/diagnostic-codes`.

## RF — validate_form

| Код     | Имя                       | Что значит                                                                                                            | Что делать                                                              |
| ------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `RF001` | INVALID_API_USAGE         | API вызван против сигнатуры или контекста; сюда же C1, C9, C12 и заметки печати модуля в `bundle`                     | Следовать подсказке; сигнатура — `get_symbol_docs`                      |
| `RF002` | UNKNOWN_SYMBOL            | Символа `@reformer/*` не существует                                                                                   | Взять предложенное имя или найти: `list_symbols`, `choose_api`          |
| `RF003` | WRONG_PACKAGE             | Символ импортирован не из того пакета или подпути                                                                     | Импортировать из пути, который назван в диагностике                     |
| `RF004` | VALIDATION_OUTSIDE_SCHEMA | Оператор валидации вне схемы валидации; сюда же C4 и `lost-message`                                                   | Перенести вызов в схему валидации; поправить цель правила или его текст |
| `RF005` | BEHAVIOR_OUTSIDE_SCHEMA   | Оператор поведения вне схемы поведения; сюда же C5                                                                    | Перенести вызов в схему поведения; поправить цель или источник          |
| `RF006` | BEHAVIOR_CYCLE            | Цикл в вычисляемых полях; сюда же C7                                                                                  | Разорвать цикл: поле не должно вычисляться из себя через другие         |
| `RF007` | INVALID_RENDER_SCHEMA     | Неверная раскладка или документ формы; сюда же C6, C8, C10, C11, C13, `unplaced`                                      | Поправить узел, на который указывает диагностика                        |
| `RF008` | UNKNOWN_COMPONENT         | Компонент не зарегистрирован или его нет в ките; сюда же C2, `unknown-component`, `component-props`                   | Взять компонент кита или зарегистрировать свой; пропсы — из его перечня |
| `RF009` | UNKNOWN_DATASOURCE        | Справочник не объявлен; сюда же C3                                                                                    | Объявить его в `dataSources` или поправить имя                          |
| `RF010` | DEPRECATED_API            | Устаревшее или удалённое API прежнего контракта формы                                                                 | Взять названную замену; рецепт `find_recipe unified-contract`           |
| `RF011` | LAYOUT_FILE_NAME          | Файл модуля формы назван вне канона                                                                                   | Переименовать в ожидаемое имя                                           |
| `RF012` | LAYOUT_FILE_MISSING       | Нет обязательного файла набора                                                                                        | Добавить названный файл                                                 |
| `RF013` | LAYOUT_FILE_EXTRA         | Файл сверх канонического набора                                                                                       | Перенести содержимое туда, куда говорит диагностика                     |
| `RF014` | INTENT_RECORD             | Запись intent не прочитана — код проблемы чтения ниже                                                                 | Переписать запись по образцу из диагностики                             |
| `RF015` | ENVIRONMENT               | Окружение не даёт собрать форму: нет индекса ядра или каталога кита                                                   | Установить в проект `@reformer/core` и `@reformer/ui-kit`               |
| `RF016` | NOT_ON_TARGET             | Правило, которое таргет не исполняет (`not-on-target`), или запись, которой нет места в документе (`not-in-document`) | Сменить таргет или перенести правило туда, где таргет его исполняет     |

## C — кросс-проверки

| Код   | Что значит                                                                                            |
| ----- | ----------------------------------------------------------------------------------------------------- |
| `C1`  | Привязка разметки ведёт в поле, которого нет в модели                                                 |
| `C2`  | Компонент разметки не зарегистрирован                                                                 |
| `C3`  | Справочник используется, но не объявлен                                                               |
| `C4`  | Цель правила валидации не существует                                                                  |
| `C5`  | Цель или источник поведения не существует                                                             |
| `C6`  | Селектора правила узла или видимости нет в разметке — правило ничего не сделает                       |
| `C7`  | Цикл в графе вычислений                                                                               |
| `C8`  | Узел массива собран неверно: нет шаблона строки или ключи `initialValue` не совпадают с полями строки |
| `C9`  | Мёртвое объявление — объявлено и не используется (предупреждение)                                     |
| `C10` | Два узла с одним `testId`                                                                             |
| `C11` | Ссылка раскладки ведёт в необъявленное                                                                |
| `C12` | Свой оператор не объявлен или не подключается                                                         |
| `C13` | Шаги вперемешку с другими узлами в одном контейнере                                                   |

## Проблемы чтения — запись не прочитана

| Код                 | Что значит                                                                              |
| ------------------- | --------------------------------------------------------------------------------------- |
| `intent-unreadable` | Вход — не объект intent: строка не JSON, массив, число                                  |
| `not-an-object`     | Запись списка — не объект: поле, массив, правило, поведение, видимость, шаг, узел       |
| `missing-key`       | Нет обязательного ключа: имени поля, цели правила, вида поведения, ссылки узла          |
| `unknown-key`       | Ключ, которого у записи нет; подсказка называет ближайший допустимый                    |
| `key-conflict`      | Два синонима одного ключа с разными значениями либо описание на месте против объявления |
| `prop-unsupported`  | Свойство, которого у компонента нет                                                     |
| `invalid-value`     | Значение не того вида: `required` не логическое, параметр замечания — объект            |
| `unknown-kind`      | Вид поведения, которого контракт не знает                                               |
| `duplicate`         | Второе объявление того же пути                                                          |
| `inert-behavior`    | Связь, которая собралась бы и не сработала ни разу                                      |

## Предупреждения чтения — прочитано, но не так, как записано

| Код                        | Что значит                                                                           |
| -------------------------- | ------------------------------------------------------------------------------------ |
| `consumer`                 | Свои `warnings` intent (из `plan_form`) — как есть                                   |
| `intent-string`            | Intent пришёл строкой — разобран как JSON                                            |
| `keys-renamed`             | Ключи приведены к именам контракта                                                   |
| `target-unknown`           | Неизвестный таргет — взят `core`                                                     |
| `type-default`             | У поля нет типа — взят `string`                                                      |
| `type-unknown`             | Неизвестный тип поля — взят `string`                                                 |
| `type-is-component`        | В `type` записано имя компонента — прочитано как компонент                           |
| `component-default`        | У поля нет компонента — взят компонент по умолчанию для его типа                     |
| `component-normalized`     | Компонент или его пропсы приведены к киту (регистр, синонимы, лишние пропсы)         |
| `array-as-field`           | Поле со строками — прочитано как массив                                              |
| `array-duplicate`          | Массив записан и в `fields`, и в `arrays` — взята запись из `arrays`                 |
| `layout-kind-unknown`      | `kind` узла — имя компонента: прочитано как контейнер, который он рисует             |
| `required-lifted`          | `required: true` у полей — в валидацию добавлено правило `required()`                |
| `item-interface-default`   | У массива нет `itemInterfaceName` — дано имя по умолчанию                            |
| `initial-value-default`    | У массива нет `initialValue` — взят пустой список                                    |
| `unnamed-dropped`          | Записи без имени отброшены                                                           |
| `no-fields`                | Нет ни поля, ни текста — модуль был бы пустой оболочкой                              |
| `intent-as-node`           | Intent — узел раскладки: прочитан как `layoutRoot`                                   |
| `step-as-key`              | Один шаг под `step` — прочитан как `steps` из одного шага                            |
| `steps-as-object`          | `steps` — объект: прочитан как список из одного шага                                 |
| `layout-as-list`           | Раскладка — список: прочитана как дети корневого контейнера                          |
| `rules-in-fields`          | Правила валидации внутри `fields` — перенесены в `validation`                        |
| `rules-on-fields`          | Проверки записаны на самих полях — перенесены в `validation`                         |
| `inline-fields`            | Поля описаны прямо в шагах или узлах — объявлены в `fields`                          |
| `inline-arrays`            | Массивы описаны прямо в шагах или узлах — объявлены в `arrays`                       |
| `inline-merged`            | Описания на месте дополнили объявления, которые уже были в `fields`/`arrays`         |
| `bare-refs`                | Узлы раскладки только с именем — прочитаны как ссылки на поля                        |
| `reset-as-on-change`       | `resetWhen`, который не читает ни одного поля модели, — записан сбросом по изменению |
| `computed-toggle-replaced` | Переключатель, который сделал бы вычисляемое поле редактируемым, — заменён           |
| `prop-lifted`              | Пропс компонента записан рядом с полем — перенесён в `componentProps`                |
| `value-coerced`            | Значение приведено к нужному виду: `required: "true"`, число в `params`              |
| `list-as-map`              | Список записан словарём `{ имя: запись }` — прочитан списком                         |
| `steps-ignored`            | `steps` рядом с `layoutRoot` — раскладка из `layoutRoot`, `steps` не читаются        |
| `each-lifted`              | Правило на путь поля строки — прочитано правилом каждой строки (`each`)              |
| `rule-empty-dropped`       | Правило без проверок (`"rules": []`) — отброшено                                     |
| `meta-dropped`             | Ключи без формы (`version`, `$schema`, пустой `components`, `intent`) — отброшены    |
| `wizard-as-list`           | Шаги списком в `wizard` — прочитаны как `steps`                                      |
| `json-schema-lifted`       | JSON Schema вместо полей — поля и правила прочитаны из её `properties`               |

## Судья

| Код                 | Вид            | Что значит                                                                        |
| ------------------- | -------------- | --------------------------------------------------------------------------------- |
| `unplaced`          | ошибка         | Поле или массив объявлены, но не стоят в раскладке: пользователь их не увидит     |
| `lost-message`      | ошибка         | У кода замечания нет своего текста либо их два                                    |
| `unknown-component` | ошибка         | Компонента нет в ките                                                             |
| `environment`       | ошибка         | Окружение не даёт собрать модуль: нет индекса ядра или каталога кита              |
| `not-on-target`     | ошибка         | Правило, которое выбранный таргет не исполняет: видимость и правила узлов на core |
| `not-in-document`   | ошибка         | Запись, которой нет места в документе формы: код модуля                           |
| `module-note`       | предупреждение | Заметка печати модуля — например, тексты раскладки, которые на core пишутся в JSX |
| `component-props`   | предупреждение | Пропсы, которых у компонента нет, — ушли бы в DOM                                 |
| `not-kept`          | предупреждение | Документ формы этого не сохранит: начальные значения, справочник без значений     |
