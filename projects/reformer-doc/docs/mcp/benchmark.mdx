# Замеры: с MCP и без

Пакеты `@reformer/*` ставятся вместе с документацией — `llms.txt`, `docs/llms`, типами. Зачем
тогда MCP-сервер? Чтобы ответить цифрами, один и тот же агент — Claude Sonnet в Claude Code —
решал одни и те же задачи на формах в трёх условиях:

- **Без MCP** — только файловые инструменты и установленные пакеты с их документацией;
- **MCP · инструменты** — то же плюс сервер `@reformer/mcp` с набором инструментов
  (`REFORMER_SURFACE=tools`): до 15 ноября 2026 года это было умолчание сервера;
- **MCP · code-guided-dsl** — то же плюс сервер с конструктором форм
  (`REFORMER_SURFACE=code-guided-dsl`). По итогам замера 15 ноября эта поверхность стала
  умолчанием; здесь — повторный замер на текущем коде.

Каждый прогон проверяет один и тот же верификатор: сборка и типы, затем поведение формы — значения,
правила, реакции, шаги мастера. Условия — в разделе [Как мерили](#как-мерили).

## Итог

<McpSummary />

- **Создание формы — главная разница.** Без сервера агент пишет модуль руками по документации
  пакетов и чаще ошибается в раскладке файлов, сборке и типах; на большой форме по спецификации
  это около четырёх минут и больше доллара на прогон. С MCP план, сборку и проверку типов делает
  сервер.
- **Правку и удаление готовой формы** проходят все три плеча почти без провалов, но с MCP это
  быстрее и дешевле.
- **Набор инструментов** по числу пройденных прогонов не опережает работу без сервера, хотя
  средний счёт проверок у него выше: его провалы на создании — одна известная проблема (правило
  «оплата по счёту — только юрлицу» не доходит до формы), она в работе.

## Разброс прогонов

Медианы прячут хвосты. Здесь каждый из 270 прогонов — отдельный значок: закрашенный — прогон
прошёл все проверки, полый — нет; черта — медиана плеча. Наведите на значок, чтобы увидеть
сценарий, стек и цифры прогона.

<McpRunSpread />

Без сервера 24 прогона из 90 шли дольше двух минут: 18 из них — создание формы, и 11 из этих
восемнадцати не прошли проверки; ещё шесть — превращение одностраничной формы в мастер. С MCP
дольше двух минут не шёл ни один прогон: самый долгий с набором инструментов занял 1,9 минуты, с
code-guided-dsl — 1,5. Все двадцать семь самых дорогих прогонов замера — без MCP.

Время и стоимость прогона растут вместе, поэтому на одной диаграмме плечи расходятся по диагонали:
code-guided-dsl — в левом нижнем углу, прогоны без MCP тянутся вправо вверх. Медианная стоимость
создания формы — $0,99 без MCP и $0,21 с ним; на правке и удалении облака ближе друг к другу.

## По видам задач

Создание — новая форма по описанию или спецификации; правка — изменение готовой формы (поля,
правила, шаги мастера); удаление — поля и шаги вместе со всем, что от них зависит. Под долей
пройденных — медиана времени прогона и стоимость всех прогонов задачи.

## Как мерили

- **Агент** — Claude Code в неинтерактивном режиме, модель `sonnet`. Инструменты — только файловые
  (`Read`, `Write`, `Edit`, `Glob`, `Grep`) внутри рабочего каталога, без оболочки. MCP-сервер
  подключён только в плечах с MCP; стенд проверяет это на старте каждого прогона.
- **Рабочий каталог** одинаков во всех плечах: установленные пакеты `@reformer/*` — ровно то, что
  публикуется в npm (сборка с типами, README, `llms.txt`, `docs/llms`); для сценариев по
  спецификации — `spec.md`; для правки и удаления — готовая форма.
- **Задание** одинаково во всех плечах: текст задачи, правила сдачи результата и раскладка модуля —
  какие части `createForm` в каких файлах. Без раскладки проверка поведения не нашла бы форму,
  написанную без сервера.
- **Лимиты** прогона одинаковы во всех плечах и заданы сценарием: деньги, шаги, время.
- **Проверка** — статическая (типы, стек, раскладка файлов) и поведенческая: пробы из контракта
  сценария заполняют форму и сверяют значения, ошибки правил, реакции и шаги мастера. Прогон
  **пройден**, когда прошли все обязательные проверки; **счёт** — доля пройденных проверок.
- **Порядок** — по одному прогону за раз, без параллели; плечи чередуются внутри каждой ячейки,
  поэтому колебания скорости API за часы замера ложатся на все плечи одинаково.
- **Стоимость и токены** — из отчёта Claude Code о прогоне; входные токены — вместе с чтением и
  записью кэша.

Ограничения: замер на одной модели; правка и удаление начинаются с формы, собранной сервером, —
это помогает плечу без MCP: раскладка у него уже перед глазами.

### Как повторить

```bash
npm run build -w @reformer/mcp
npm run mcp:scenarios -- --agent claude-code --model sonnet \
  --approach no-mcp,mcp-default,mcp-dsl --repeats 3 --max-usd-batch 120
npm run mcp:approaches -- <батч> --save packages/reformer-mcp/eval/runs/approaches/mcp-value-sonnet.json
node packages/reformer-mcp/eval/scenarios/mcp-value-docs.mjs \
  packages/reformer-mcp/eval/runs/approaches/mcp-value-sonnet.json \
  projects/reformer-doc/src/data/mcp-benchmark.json
```
