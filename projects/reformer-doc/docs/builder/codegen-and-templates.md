# Экспорт кода и шаблоны

**Экспорт** превращает документ формы в **модуль формы** — каталог с кодом на TypeScript и
React, который приложение подключает как обычный код. **Шаблон** — готовый модуль, с которого
начинается новая форма.

## Экспорт формы

Откройте документ формы и панель «Экспорт формы» на правом рейле. Проверьте «Имя формы» — из него
выводятся имя типа, имена файлов и маршрут, — и нажмите «Сгенерировать».

![Панель «Экспорт формы»: имя формы, кит, кнопка «Сгенерировать» и файлы модуля](/img/builder/codegen.png)

Под кнопкой — файлы модуля с пометкой, что с каждым будет при следующей генерации, итог прогона и
блок «Регистрация в приложении» со строкой подключения. Тот же экспорт запускают пункт
«Сгенерировать» → «ReFormer» → «Весь модуль» в меню файла формы и команда «Экспортировать форму в
код» палитры. В том же меню можно перепечатать один файл модуля.

<CodegenFlow />

Модуль печатается под **активный кит**: реестр компонентов импортирует их из пакета кита. Если
модуль уже напечатан другим китом, «Сгенерировать» откажет и назовёт оба кита — переключите кит в
строке состояния на кит модуля.

## Что в модуле

Для формы `feedback`:

```text
feedback/
├── FeedbackForm.tsx      страница: сборка формы → FormRenderer
├── index.ts              реэкспорты: страница по умолчанию, сборка, запись реестра форм, тип
├── README.md             как подключить и что дописать
├── application/          create.ts — сборка формы, submit.ts — отправка, entry.ts — запись реестра форм
├── api/index.ts          запросы к серверу
├── model/                initial-value.ts, model.ts
├── schema/               form.schema.json — документ формы, registry.ts — компоненты и источники
├── validation/           form.ts — правила, messages.ts — тексты замечаний, <шаг>.ts — правила шага
├── behavior/index.ts     поведение: вычисляемые поля, условная доступность
├── flow/feedback-flow.ts поток шагов — только у мастера
├── types/feedback.ts     тип значений формы
└── constants/feedback.ts значения источников данных
```

Модуль собирает форму одним вызовом `createForm` — так, как описано в разделах
[Модель](../core-concepts/model.mdx) и [renderer-json](../packages/renderer-json.mdx). Правила и
поведение — обычный код ReFormer, который можно дописывать руками.

## Какие файлы перезаписываются

Каждый файл модуля помечен маркером происхождения — строкой `// @reformer-generated` с отпечатком
содержимого. По маркеру билдер понимает, правили ли файл руками.

| Файлы                                                                                                                                    | Что делает «Сгенерировать»                                                    |
| ---------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| страница, `index.ts`, `README.md`, `application/create.ts`, `application/entry.ts`, `model/*`, `schema/registry.ts`, `types/*`, `flow/*` | перепечатывает всегда — в панели «перезаписывается». Ручная правка пропадёт   |
| `validation/form.ts`, `validation/<шаг>.ts`, `behavior/index.ts`, `application/submit.ts`                                                | перепечатывает из правил формы, пока вы файл не правили; правленый не трогает |
| `validation/messages.ts`, `api/index.ts`, `constants/<имя>.ts`                                                                           | пишет один раз — в панели «ваш». Дальше это ваш код                           |

Пропущенные файлы панель перечисляет: «Пропущено (ваши правки не тронуты)». Файл с тем же текстом
не пишется вовсе — генерация без изменений ничего не меняет на диске.

**Где окажутся файлы.** Обычно панель сразу записывает их на диск — итог «Отправлено в источник».
«Осталось в рабочей копии — сохраните проект» значит, что файлы ждут `Ctrl+Alt+S`.

## Свои шаблоны печати

Чтобы модуль печатался по-вашему — например, `schema/registry.ts` импортировал компоненты из
пакета вашей дизайн-системы, — плагин писать не нужно. Достаточно файла в
`.ui_builder/codegen/` проекта.

1. В панели «Экспорт формы» у файла модуля нажмите «Выгрузить шаблон в проект». Билдер положит
   встроенный шаблон этого файла в `.ui_builder/codegen/<имя>.eta` — с готовым заголовком.
2. Поправьте шаблон.
3. Команда «Перечитать шаблоны генерации» в палитре — и следующий прогон напечатает файл вашим
   шаблоном. Новые файлы билдер подхватывает и при открытии проекта.

Файл цели — заголовок JSON между строками `---` и шаблон [Eta](https://eta.js.org) за ним:

```text
---
{ "id": "user.registry", "overrides": "codegen.registry", "path": "schema/registry.ts",
  "cls": "derived", "order": 40, "title": "Реестр компонентов (наш)" }
---
// schema/registry.ts — …
```

| Поле             | Что задаёт                                                                                             |
| ---------------- | ------------------------------------------------------------------------------------------------------ |
| `id`             | имя цели, уникальное                                                                                   |
| `path`           | путь файла от корня модуля; токены `{Type}`, `{dir}`, `{schema}`, `{schemaDir}`, `{step}`, `{stepDir}` |
| `cls`            | `derived` — перезаписывать всегда, `user` — написать один раз                                          |
| `overrides`      | `id` встроенной цели, которую файл заменяет                                                            |
| `each`           | `"step"` — печатать по файлу на каждый шаг мастера; в `path` тогда нужен `{step}`                      |
| `applies`        | выражение JavaScript над данными шаблона `it`, например `it.layout.isWizard`                           |
| `order`, `title` | место и подпись цели в панели                                                                          |

Какие данные видит шаблон, показывает панель: «Данные шаблона (it)». Ошибки разбора и печати —
в блоке «Отказы целей» той же панели.

## Шаблоны форм

Панель «Шаблоны форм» на левом рейле собирает шаблоны из двух мест:

| Группа       | Откуда                                                    |
| ------------ | --------------------------------------------------------- |
| «Встроенные» | от движка формы; печатаются под активный кит              |
| «Проект»     | каталоги `.ui_builder/templates/<имя>/` открытого проекта |

Группа «Локальные» — шаблоны в хранилище браузера — появится, когда у плагинов будет постоянное
хранилище. Сейчас плагин шаблонов его не получает: шаблон, сохранённый в память сессии, пропал бы
при перезагрузке страницы.

Встроенных два: «Простая форма» — анкета из трёх секций с полем каждого вида, правилами,
вычисляемым полем и условной видимостью, и «Пошаговая форма» — та же анкета в три шага. Вторая
есть у кита с компонентом-мастером.

![Панель «Шаблоны форм» и окно «Создать форму по шаблону»](/img/builder/template-dialog.png)

**Создать форму.** Щелчок по шаблону открывает окно «Создать форму по шаблону»: «Имя формы»
(нужны буквы или цифры — из имени выводятся имена файлов, компонентов и импорты), «Каталог формы»
и список файлов шаблона — лишние можно снять.

**Сохранить свой шаблон.** В меню каталога формы в дереве «Проект» — «Шаблоны» → «Создать
шаблон…». Задайте «Название шаблона» — шаблон сохранится в проект, в `.ui_builder/templates/`.
Удалить проектный шаблон из панели нельзя: удалите его каталог в дереве «Проект». Имя формы в путях
и текстах заменится подстановкой `__FormName__` (а также `__formName__`, `__form-name__`,
`__form_name__`), и при создании новой формы на её место встанет новое имя. Бинарные файлы в
шаблон не попадают.

Шаблон в проекте — обычный каталог с файлами и необязательным `template.json`:

```json
{ "version": "1.0", "name": "Анкета клиента", "description": "Поля клиента и адрес" }
```

Без `template.json` имя шаблона берётся из имени каталога. Каталоги шаблонов билдер не
отслеживает — после правки нажмите «Обновить» в панели или выполните «Перечитать шаблоны форм».

## Подводные камни

- **Правка в странице или `model/model.ts` пропала.** Эти файлы перепечатываются всегда.
  Логику держите в `behavior/index.ts`, `validation/*` и `api/index.ts`, а страницу меняйте своим
  шаблоном печати.
- **Правила не обновились после генерации.** Файл правил правили руками — билдер его больше не
  перепечатывает. Перенесите правку в код или удалите файл, и он напечатается заново.
- **Рядом с новыми файлами остались старые.** Билдер не удаляет файлы, которые перестали быть
  нужны (переименованный шаг, прежняя раскладка), — он называет их в панели и в уведомлении.
  Перенесите свои правки и удалите их.
