# Первый плагин

Плагин из шаблона за пять минут: команда в палитре, подпись которой берётся из словаря. Дальше
он растёт панелями, редакторами и службами — см.
[Манифест и API плагина](./manifest-and-api.md).

**Что нужно:** Node 20 или новее, папка проекта, которую вы открываете в билдере.

## 1. Создать

```bash
npx @reformer/builder-plugin-cli create acme-forms --name "Acme Forms"
cd acme-forms && npm install
```

`create` кладёт в пустой каталог готовый плагин:

| Файл                            | Что это                                                                             |
| ------------------------------- | ----------------------------------------------------------------------------------- |
| `manifest.json`                 | манифест: `main` указывает на `src/main.ts`, словари объявлены                      |
| `src/main.ts`                   | плагин с одной командой                                                             |
| `src/main.test.ts`              | тест: `id` в коде совпадает с `id` манифеста — иначе билдер откажет                 |
| `locales/ru.json`, `en.json`    | словари «ключ → строка»                                                             |
| `package.json`, `tsconfig.json` | `@reformer/builder-plugin-api` и `@reformer/builder-plugin-cli` в `devDependencies` |

Идентификатор по умолчанию — имя каталога, другой задаёт `--id`. В непустой каталог команда не
пишет.

Код плагина:

```ts title="src/main.ts"
import { definePlugin } from '@reformer/builder-plugin-api';

export default definePlugin({
  id: 'acme-forms',
  activate(ctx) {
    ctx.subscriptions.push(
      ctx.commands.register({
        id: 'acme-forms.hello',
        // Ключ словаря плагина, а не текст: строки лежат в locales/*.json.
        titleKey: 'command.hello',
        run: () => true,
      })
    );
  },
});
```

```json title="locales/ru.json"
{ "command.hello": "Acme Forms: привет" }
```

Всё, что плагин регистрирует, он кладёт в `ctx.subscriptions`: так выключение плагина снимает
его вклады само.

`@reformer/builder-plugin-api` нужен только для типов и сборки: в рантайме плагин получает объект
контракта от оболочки, поэтому пакет стоит в `devDependencies`.

## 2. Проверить

```bash
npx reformer-plugin validate
```

`validate` разбирает манифест **тем же кодом, что и билдер**, проверяет файлы, на которые он
ссылается, и сверяет версию `package.json` с версией манифеста. Код выхода `0` — билдер плагин
примет, `1` — нет, и почему именно, напечатано построчно: `manifest-invalid`, `api-version`,
`entry-missing`, `messages-invalid`…

## 3. Подключить к проекту

Самый короткий путь — положить каталог плагина в `.ui_builder/plugins/acme-forms/` проекта как
есть: `src/main.ts` билдер транспилирует на лету.

Для плагина с зависимостями нужна сборка. `dev` собирает плагин прямо в каталог плагинов
проекта и пересобирает на каждое сохранение исходников:

```bash
npx reformer-plugin dev --project ../my-forms-project
```

Сборка ляжет в `../my-forms-project/.ui_builder/plugins/acme-forms/`.

## 4. Включить

Откройте проект в билдере. Найденный плагин появится выключенным — код из проекта сам не
запускается. Включите его: «Настройки» → «Плагины» или палитра команд → «Плагины: включить «Acme
Forms»». Если манифест просит права, билдер спросит подтверждение.

Проверьте: в палитре команд (`Ctrl+Shift+P`) есть «Acme Forms: привет».

Плагин появился в папке, когда проект уже открыт, — выполните «Плагины: перечитать каталог
проекта».

## 5. Режим разработки

Чтобы видеть правки без перезагрузки страницы, пометьте плагин «в разработке»: палитра → «Плагины:
наблюдать «Acme Forms» — режим разработки» или переключатель «Режим разработки» в карточке
плагина в настройках.

Помеченный плагин билдер перечитывает сам — когда его файл сохранён во встроенном редакторе
кода или когда вы вернулись в окно браузера после правки в IDE. Вместе с `reformer-plugin dev`
цикл такой: сохранили исходник в IDE → `dev` пересобрал → вернулись в браузер → плагин
перезагружен. Вручную — «Плагины: перезагрузить «Acme Forms»».

Упавший при включении плагин в режиме разработки поднимается сам после правки файлов.

## 6. Собрать и опубликовать

```bash
npx reformer-plugin build --minify   # сборка в dist/: manifest.json, main.js, словари, стили
npx reformer-plugin pack             # архив <имя>-<версия>.tgz для npm
```

В архиве только сборка и `package.json`: версия берётся из манифеста, ключевое слово
`reformer-builder-plugin` добавляется само. Исходников и зависимостей в архиве нет.

Опубликованный в npm плагин ставят прямо из билдера: «Плагины: установить из npm…» и имя пакета.
Пакет скачается в браузер и появится в списке выключенным. Ставятся только выпущенные версии —
без пререлизов, — и только пакеты с подписью целостности (`dist.integrity`).

Собранный каталог (`dist/`) можно и просто положить в `.ui_builder/plugins/<id>/` проекта.

## Подводные камни

- **В палитре вместо подписи — `⟦…⟧`.** Нет строки в словаре: проверьте ключ и
  `contributes.messages` в манифесте.
- **«id-mismatch».** `id` в коде, в манифесте и имя каталога плагина должны совпадать (кроме
  плагина внутри домена — там имя каталога свободное).
- **«api-version».** Манифест просит версию API, которой у билдера нет; `apiVersion` пишут
  диапазоном — `"^1"`.
- **«в каталоге … нет manifest.json».** Плагин не собран: соберите его или положите исходники с
  манифестом в корень каталога плагина.
