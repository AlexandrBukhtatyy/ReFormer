# Манифест и API плагина

Плагин видит от билдера ровно то, что описано в пакете `@reformer/builder-plugin-api`, и ничего
сверх. Эта страница — карта контракта: манифест, контекст плагина и основные точки расширения.
Полный список имён — в README пакета.

```bash
npm install --save-dev @reformer/builder-plugin-api
```

Пакет ставится в `devDependencies`: в рантайме плагин получает объект контракта от оболочки, а
сборка держит пакет внешним. Вторая копия пакета внутри плагина означала бы вклады в чужой пустой
реестр — панель просто не появилась бы.

## Манифест

```json title="manifest.json"
{
  "id": "acme-forms",
  "name": "Acme Forms",
  "version": "1.0.0",
  "apiVersion": "^1",
  "main": "main.js",
  "contributes": {
    "messages": { "ru": "locales/ru.json", "en": "locales/en.json" },
    "keybindings": [{ "command": "acme-forms.hello", "key": "mod+shift+h" }]
  },
  "styles": { "file": "styles.css", "isolation": "scoped" },
  "permissions": ["workspace.save"],
  "provides": [{ "id": "acme.forms", "version": "1.2.0" }],
  "requires": {
    "required": [{ "id": "reformer.kit.catalog", "range": "^2" }],
    "optional": [{ "id": "acme.telemetry", "range": ">=0.2.0" }]
  }
}
```

| Поле                      | Что задаёт                                                                                                                        |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `id`                      | идентификатор: буквы, цифры, `.`, `_`, `-`. Совпадает с именем каталога плагина (кроме плагина в домене)                          |
| `name`                    | подпись в списке плагинов; без неё — `id`                                                                                         |
| `version`                 | версия плагина; обязательна в исходниках — по ней публикуется пакет                                                               |
| `apiVersion`              | диапазон версий контракта, против которого написан плагин                                                                         |
| `main`                    | точка входа: `main.js`, на время разработки — `main.ts` или `src/main.ts`                                                         |
| `contributes.messages`    | словари строк: язык → файл                                                                                                        |
| `contributes.keybindings` | сочетания клавиш командам: `command`, `key` и необязательное условие `when`                                                       |
| `styles`                  | своя таблица стилей; `isolation: "scoped"` ограничивает её поддеревом плагина — см. [Сборка и стили](./build-and-styles.md#стили) |
| `permissions`             | права: `workspace.save`, `workspace.resources`, `plugins.manage` — см. [Права](./concepts.md#права)                               |
| `provides`                | возможности, которые плагин даёт: `id` и точная `version`                                                                         |
| `requires`                | возможности, которые нужны: `required` — без них не включится, `optional` — желательны; `id` и `range`                            |
| `compatibility`           | `{ "builder": "<диапазон>" }` — версии самого билдера, когда нужна сборка, где что-то исправлено                                  |

**Диапазоны версий** пишутся как в npm: `^1`, `^1.2.3`, `~1.2`, `>=1.0.0`, `1.x`, `*`, точная
версия. Составных диапазонов (`>=1 <2`) и пререлизов (`1.0.0-beta`) разбор не принимает — это
отказ манифеста, а не тихое «не совпало».

**`apiVersion` и `compatibility.builder` — разные оси.** Первая отвечает, какие имена контракта
доступны плагину: минор контракта растёт, когда имя добавили, мажор — когда убрали или сменили
смысл. Вторая — какое приложение их подаёт. Не совпала любая — плагин не грузится и объясняет
почему: `api-version` или `builder-version`.

## Контекст плагина

`activate(ctx)` получает контекст:

| Поле                | Что это                                                                  |
| ------------------- | ------------------------------------------------------------------------ |
| `ctx.id`            | идентификатор плагина                                                    |
| `ctx.commands`      | реестр команд                                                            |
| `ctx.extensions`    | точки расширения: панели, редакторы, меню, киты, инструменты ассистента… |
| `ctx.services`      | службы оболочки и других плагинов                                        |
| `ctx.capabilities`  | возможности — службы с версией                                           |
| `ctx.events`        | шина событий                                                             |
| `ctx.i18n`          | словарь плагина                                                          |
| `ctx.storage`       | хранилище производного состояния плагина                                 |
| `ctx.secrets`       | хранилище токенов и ключей                                               |
| `ctx.subscriptions` | всё, что сюда положено, снимается при выключении плагина                 |

Три правила, на которых держится всё остальное:

1. **`activate` только регистрирует.** Он синхронный. Долгую работу — загрузку, чтение файлов —
   запускают без ожидания, а результат показывают, когда он готов.
2. **Службу ищут в момент использования, а не в `activate`.** Порядок включения плагинов ничего
   не значит: поставщик вправе подняться позже или быть выключен на ходу.
3. **Всё зарегистрированное — в `ctx.subscriptions`.** Тогда выключение плагина возвращает билдер
   в исходное состояние.

Возможность спрашивают одним из трёх способов:

| Вызов                               | Когда                                                          |
| ----------------------------------- | -------------------------------------------------------------- |
| `ctx.capabilities.get(cap)`         | «возьму, если есть»: `undefined` — работаем без неё            |
| `ctx.capabilities.require(cap)`     | «без этого операции нет»: бросает, называя версию и поставщика |
| `ctx.capabilities.observe(cap, cb)` | «скажи, когда появится»: зовёт сразу и на каждую смену         |

Свою возможность объявляют `defineCapability({ id, version })`, регистрируют
`ctx.services.register(cap, impl)` в `activate` и называют в `provides` манифеста.

## Команды

```ts
ctx.subscriptions.push(
  ctx.commands.register({
    id: 'acme-forms.hello',
    titleKey: 'command.hello',
    keybinding: 'mod+shift+h',
    run: () => true,
  })
);
```

Заголовок команды — ключ словаря плагина: билдер переведёт его словарём того плагина, который
команду зарегистрировал. `enabled(ctx)` решает, доступна ли команда сейчас, `allowInEditable` —
срабатывает ли сочетание, когда фокус в поле ввода. Команда попадает в палитру; блок `agent` —
описание для модели и JSON Schema аргументов — делает её доступной ещё и ассистенту.

## Панели

```tsx
import { definePlugin, PanelPoint, useTranslate } from '@reformer/builder-plugin-api';

export default definePlugin({
  id: 'acme-forms',
  activate(ctx) {
    function Body() {
      // Хук подписывает панель на смену языка интерфейса.
      const t = useTranslate(ctx.i18n);
      return <p className="p-3 text-sm">{t('panel.hello')}</p>;
    }

    ctx.subscriptions.push(
      ctx.extensions.contribute(PanelPoint, {
        id: 'acme-forms.panel',
        slot: 'panel.right',
        titleKey: 'panel.title',
        Body,
      })
    );
  },
});
```

| Поле               | Что задаёт                                                      |
| ------------------ | --------------------------------------------------------------- |
| `slot`             | `panel.left`, `panel.right` или `panel.bottom`                  |
| `titleKey`         | заголовок — ключ словаря плагина; он же подпись кнопки на рейле |
| `icon`             | значок на рейле; без него — первые буквы заголовка              |
| `railPlacement`    | `top` или `bottom` — у какого края рейла стоит кнопка           |
| `when`             | условие видимости, например «открыта форма ReFormer»            |
| `order`            | порядок среди панелей слота                                     |
| `Actions`          | кнопки в шапке панели                                           |
| `fill`, `headless` | панель на всю высоту дока; без шапки                            |

Регистрируйте панель один раз, а видимость меняйте `when`: регистрация на время активности
редактора заставила бы рейл мигать при каждом переключении вкладки.

## Словарь

Словари плагина объявляют в манифесте (`contributes.messages`) или вносят из кода:
`ctx.i18n.contribute(locale, messages)`. Пространство имён у каждого плагина своё: ключ
`panel.title` двух плагинов — две разные строки. В React строки берут хуком
`useTranslate(ctx.i18n)`. Ключ, которого нет в словаре, в разработке видно маркером `⟦…⟧`, в
сборке — английской строкой.

## Данные плагина: хранилище, секреты, настройки

| Что               | Где                                                            | Для чего                                                       |
| ----------------- | -------------------------------------------------------------- | -------------------------------------------------------------- |
| **Настройки**     | форма в «Настройки» → «Плагины», значения в настройках проекта | то, что человек правит руками                                  |
| **`ctx.storage`** | хранилище плагина                                              | производное состояние: кэши, черновики                         |
| **`ctx.secrets`** | секреты плагина; по умолчанию — память сессии                  | токены и ключи; `set(key, value, { persist: true })` сохраняет |

Настройки плагин объявляет **формой ReFormer** — вкладом в `CatalogPluginSettingsPoint`. Форму
рисует раздел «Плагины» окна настроек, и ей сразу доступно всё, что умеет форма ReFormer:
видимость, зависимости, валидация. Компонентов девять: `Box`, `Checkbox`, `FormField`, `Input`,
`RadioGroup`, `Section`, `Select`, `Switch`, `Textarea`.

```ts
import {
  CatalogPluginSettingsPoint,
  definePlugin,
  pluginSettingsKey,
  SettingsServiceToken,
} from '@reformer/builder-plugin-api';

const SCHEMA = {
  version: '1.0',
  root: {
    /* $component(Input), $model(endpoint) … */
  },
};
const DEFAULTS = { endpoint: 'https://api.example.com' };

export default definePlugin({
  id: 'acme',
  activate(ctx) {
    const settings = ctx.services.get(SettingsServiceToken);
    if (settings) {
      ctx.subscriptions.push(settings.registerDefault(pluginSettingsKey(ctx.id), DEFAULTS));
    }
    ctx.subscriptions.push(
      ctx.extensions.contribute(CatalogPluginSettingsPoint, { pluginId: ctx.id, schema: SCHEMA })
    );
  },
});
```

Значения плагин читает сам — `settings.get(pluginSettingsKey(ctx.id))` — и подписывается на
`onDidChange`. Настройки есть только у плагинов проекта: у встроенных нет строки в списке.

## Журнал

Запись в «Журнал», вид «События», остаётся до перезагрузки страницы — в отличие от уведомления:

```ts
import { errorDetail, LogServiceToken, pluginMessageKey } from '@reformer/builder-plugin-api';

ctx.services.get(LogServiceToken)?.append({
  level: 'error',
  source: ctx.id,
  messageKey: pluginMessageKey(ctx.id, 'kit.load.failed'),
  params: { name },
  detail: errorDetail(error),
});
```

Текст — ключом словаря плагина, `detail` показывается как есть и свёрнутым.

## Точки расширения

| Точка                                          | Что вносит плагин                                                           |
| ---------------------------------------------- | --------------------------------------------------------------------------- |
| `PanelPoint`                                   | панель                                                                      |
| `EditorPoint`                                  | редактор файлов своего формата                                              |
| `MenuPoint`                                    | пункты меню «Файл», «Справка», меню файла в дереве и «Ещё действия» вкладки |
| `PaletteItemsPoint`                            | динамические пункты палитры — например, список форм                         |
| `ResourceDecorationPoint`                      | пометки на файлах дерева и вкладках                                         |
| `DocumentModelPoint`, `ValidatorPoint`         | разбор документа в модель и проверки                                        |
| `PreviewSurfacePoint`                          | поверхность превью — чем нарисовать документ                                |
| `KitSourcePoint`                               | кит компонентов — см. ниже                                                  |
| `CodegenStackPoint`, `CodegenTargetPoint`      | свой формат формы в генерации кода и цели генерации                         |
| `TemplateStackPoint`, `TemplateStorePoint`     | свой формат в шаблонах и хранилища шаблонов                                 |
| `AssistantToolPoint`, `AssistantResourcePoint` | инструменты и ресурсы ассистента — см. ниже                                 |
| `FormAssistantStackPoint`                      | свой формат формы в ассистенте                                              |
| `CatalogPluginSettingsPoint`                   | форма настроек плагина                                                      |

Редактор отвечает за три вещи, без которых он ломает соседей: пишет в реестр фокуса
(`TextEditorFocusToken`), пока человек печатает; просит рабочую область догнать буфер
(`documents.flush(id)`) после снятия фокуса; отдаёт одну и ту же ссылку `Body` на всё время жизни
вклада. Подробности — раздел «Контракт редактора» README пакета.

## Киты

Кит вносит себя в `KitSourcePoint`: шапку (`id`, `label`, `package`) — значением, каталог и
пространство имён компонентов — загрузчиками, чтобы тяжёлое грузилось, только когда кит выбран.
Плагин кита требует возможность `reformer.kit.catalog` `^2` — её даёт плагин «Киты», и через неё
же движки получают активный кит.

- **Каталог** — `catalog.json` по контракту `3.0`: записи компонентов со схемой пропсов и блок
  `kit`. Генерирует его `reformer-plugin catalog` — см.
  [Сборка и стили](./build-and-styles.md#каталог-кита).
- **Корень каждого компонента принимает `className`** — по нему билдер находит узел щелчком в
  превью и подсвечивает выделенный.
- **Мастер** (`kit.adapters.wizard`) работает по протоколу каталога `3.0`: шаги приходят данными,
  форма и поток шагов — из контекста сборки формы.
- **Провайдер** (`kit.adapters.provider`) — тема, контейнер всплывающих окон, граница стилей.
- **Импорт в напечатанном коде** — `kit.codegen.importSpecifier`, по умолчанию `kit.package`.

Отказы реестра китов — уведомлением: кит без `id`, занятый `id` (встроенный побеждает), каталог не
по контракту.

## Инструменты ассистента

Плагин даёт модели своё действие вкладом в `AssistantToolPoint`, а данные для чтения — в
`AssistantResourcePoint`.

- **Инструмент** — имя (до 30 символов, `snake_case`), описание для модели (до 500 символов,
  по-английски), JSON Schema аргументов, `readOnly` и `run(params, ctx)`. Запись через
  `ctx.write` принадлежит ходу и откатывается «Отменить последний ход» вместе с правками самой
  модели. Исключение из `run` ход не роняет — модель получает ошибку.
- **Ресурс** — адрес `<схема>:<остаток>`. Модель читает его встроенным `read_resource`, а человек
  прикрепляет к реплике пикером чата или командой `ai.attach`.
- **Описания платятся каждым шагом**: они уходят модели в каждом запросе. У вкладов плагинов общий
  потолок; не влезшее отбрасывается с сообщением в консоли.
