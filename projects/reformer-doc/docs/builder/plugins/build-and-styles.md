# Сборка и стили плагина

`reformer-plugin build` собирает каталог, который билдер грузит как есть, и проверяет его **теми
же правилами, что и билдер**. Если сборка прошла, билдер плагин примет.

## Конвейер

<PluginBuildPipeline />

| Команда                                                         | Что делает                                                           |
| --------------------------------------------------------------- | -------------------------------------------------------------------- |
| `reformer-plugin validate [каталог]`                            | проверяет манифест и файлы, ничего не собирая                        |
| `reformer-plugin build [каталог] [--out <каталог>]`             | собирает, по умолчанию в `dist/`                                     |
| `reformer-plugin dev [каталог] --project <проект>`              | собирает в `<проект>/.ui_builder/plugins/<id>/` на каждое сохранение |
| `reformer-plugin dev [каталог] --out <каталог>`                 | то же, каталог вывода назван прямо                                   |
| `reformer-plugin pack [каталог] [--out <каталог>]`              | собирает и упаковывает в `<имя>-<версия>.tgz`                        |
| `reformer-plugin catalog [каталог] [--config <файл>] [--check]` | собирает каталог кита из TypeScript-типов — см. ниже                 |

Параметры сборки `--minify` (сжать код, воркеры и стили) и `--bundle-css` (см. «Стили»)
принимают `build`, `dev` и `pack` — плагин обязан собираться одинаково, чем бы его ни собирали.
`--minify` — для поставки: в сборке на месте сжатый стек ошибки не прочитать.

## Что получается

```text
dist/
├── manifest.json    с main: "main.js" и секцией build — графом файлов
├── main.js          точка входа, CommonJS
├── chunks/*.js      отложенные модули и общий код
├── locales/*.json   словари — по тем же путям
└── styles.css       если стили объявлены
```

- **Код — CommonJS.** Билдер связывает модули плагина сам и подставляет свои пакеты.
- **Пакеты, которые даёт оболочка, остаются внешними:** React, `@reformer/*` из списка оболочки и
  сам контракт. Импорт другого `@reformer/*` — отказ `module-unavailable`: вложенная копия была
  бы вторым экземпляром пакета.
- **`await import('./engine')` уезжает в `chunks/`** вместе со всем, что нужно только ему.
  Билдер прочтёт такой файл при первом обращении, а не при включении плагина. Так везут тяжёлый
  движок, который нужен не каждому запуску. Модуль, общий для `main.js` и отложенного файла,
  попадает в общий чанк и живёт в одном экземпляре.
- **`await import('./corpus.json')`** — большие данные отдельным модулем в `chunks/`, по
  требованию. Статический `import data from './a.json'` вкладывается в `main.js`.
- **`import EchoWorker from './echo.worker?worker'`** — конструктор воркера, как у Vite. Воркер
  собирается отдельным самостоятельным файлом и запускается из Blob-URL.
- **`import text from './form.eta?raw'`** — текст файла строкой: так держат шаблоны файлами.
- **Текст в `main.js` — UTF-8** без экранирования: кириллица не раздувает файл.

После сборки печатается, сколько кода читается сразу и сколько — по требованию.

## Проверки сборки

Собранный каталог проходит то же, что пройдёт у билдера:

- разбор манифеста;
- потолок числа файлов кода;
- **пробная активация** — `main.js` исполняется под Node с настоящим контрактом и заглушками
  остального. Так ловятся `not-a-plugin`, `id-mismatch` и `provides-unregistered`. Если код
  падает на заглушке — например, `activate` трогает DOM, — это не отказ, а заметка
  `! … не проверено`;
- у кита — проверка каталога тем же правилом, что у реестра китов билдера.

Не прошедшая проверки сборка прошлую не затирает. В каталоге вывода сборка удаляет только свои
прошлые файлы; непустой каталог без её сборки — отказ `output-not-ours`.

### Сборка на месте

Пакет плагина может лежать прямо в каталоге плагинов проекта и собираться в собственный корень:

```text
.ui_builder/plugins/<id>/
├── package.json
├── src/                 исходники: manifest.json, код, стили, словари
├── manifest.json        ┐
├── main.js              ├ сборка `reformer-plugin build src --out .` — её грузит билдер
└── locales/…            ┘
```

Собранное держат вне git. Так устроены плагины проекта-образца ReFormer.

## Стили

### Основной путь — без своего CSS

Панели плагина — React-компоненты внутри оболочки. Им доступны служебные классы Tailwind и
токены кита `@reformer/ui-kit`, поэтому плагин без своего CSS выглядит родным и меняется вместе с
темой. В манифесте это выражается отсутствием поля `styles`.

Оговорка: доступны только те классы, правила для которых билдер уже собрал. Класс, которого нет в
CSS билдера, молчит — вёрстка не падает, а теряет отступ или цвет. Гарантированы классы кита;
всё сверх них плагин везёт сам.

### Изолированная таблица

```json title="manifest.json"
{ "styles": { "file": "styles.css", "isolation": "scoped" } }
```

Билдер ограничивает таблицу поддеревом плагина: каждый вклад рисуется внутри контейнера с
атрибутом `data-rb-plugin="<id>"`, и селекторы переписываются под него. Заодно таблица
обезвреживается: `@property` вырезается, `@keyframes` и `@font-face` переименовываются в
пространство имён плагина, а `html`, `body` и `:root` заменяются контейнером — ресет плагина
работает, но только внутри него.

Что из этого следует:

- **порталы** — диалоги, меню — уходят в `document.body`, вне контейнера. Их корень помечают
  сами: `{...pluginScopeAttributes('<id>')}` из `@reformer/builder-plugin-api`;
- **правила для самого контейнера** ничего не рисуют: размеры корня портала задают стилем, а не
  классом;
- **ссылки на цвета** — через токены кита: они объявлены всегда. Переменные темы Tailwind
  (`--color-…`) билдер объявляет, только пока пользуется ими сам.

Таблицу объявляют только в манифесте: импорт CSS из кода — отказ `css-from-code`. Параметр
`--bundle-css` снимает отказ: CSS, который импортирует код и его зависимости, сборка дописывает в
объявленную таблицу. Так плагин везёт стороннюю библиотеку, чьи модули сами подключают свои
стили. Шрифты и картинки из `url(…)` вкладываются в таблицу data-URL-ом.

Shadow DOM билдер не использует: классы оболочки внутрь теневого дерева не проходят, и плагин без
своего CSS перестал бы выглядеть родным.

## Каталог кита

Плагину кита нужен каталог компонентов `catalog.json`. Руками его не пишут:
`reformer-plugin catalog` собирает его из TypeScript-типов **входа пакета кита**, поэтому с кодом
каталог разойтись не может. Конфиг говорит только то, чего в типах нет.

```js title="catalog.config.mjs"
// @ts-check
import { defineKitCatalog, optionsProp } from '@reformer/builder-plugin-cli/catalog-config';

export default defineKitCatalog({
  entry: './src/index.ts',
  kit: { id: 'acme', label: 'Acme DS', package: '@acme/ds', infra: { fieldWrapper: 'FormField' } },
  ownership: { packages: ['@acme/ds'] },
  fields: {
    Input: { value: 'string | null' },
    DatePicker: { exportName: 'DateField', value: 'Date | null' },
  },
  categories: { 'Поля ввода': ['Input', 'DatePicker'], Контейнеры: ['Tabs'] },
  limited: { Modal: 'оверлей — нужен триггер' },
  service: ['FormField', 'KitProvider'],
  props: { override: { Select: { options: optionsProp() } } },
});
```

| Ключ                 | Что задаёт                                                            |
| -------------------- | --------------------------------------------------------------------- |
| `entry`, `kit`       | вход пакета и шапку кита                                              |
| `fields`             | поля — компоненты со статикой `reformerAdapter`; тип значения каждого |
| `categories`         | разделы палитры                                                       |
| `limited`            | компоненты, которые превью рисует заглушкой, — с причиной             |
| `service`, `exclude` | служебные компоненты вне палитры и вне каталога                       |
| `statics`, `parts`   | статики (`Textbox.Password`) и части составных компонентов            |
| `props`              | убрать (`omit`) или уточнить (`override`) выведенные пропсы           |

```json title="package.json"
{
  "scripts": {
    "catalog": "reformer-plugin catalog .",
    "catalog:check": "reformer-plugin catalog . --check"
  }
}
```

`--check` ничего не пишет: сверяет файл с типами и при расхождении печатает дифф с кодом выхода
`1`. Поставьте его в CI — обновлённая дизайн-система тогда потребует перегенерации каталога, а не
сломает билдер молча. Тот же контроль из теста — `checkKitCatalog` из
`@reformer/builder-plugin-cli/catalog`. Для `catalog` нужен `typescript` — из каталога кита или
рядом с CLI.

## Программный вход

```ts
import { buildPlugin } from '@reformer/builder-plugin-cli';

const result = await buildPlugin({ dir: './acme-forms', outDir: './out' });
if (!result.ok) console.log(result.findings);
```

## Подводные камни

- **`module-unavailable`** — импорт `@reformer/*`, которого оболочка не даёт. Такой пакет нужно
  убрать из зависимостей плагина или получить его возможностью другого плагина.
- **`css-from-code`** — стили импортируются из кода. Объявите таблицу в `styles` манифеста или
  соберите с `--bundle-css`.
- **Класс Tailwind «не работает».** Его нет в CSS билдера — добавьте правило в свою таблицу.
- **Диалог плагина без стилей.** Он ушёл порталом в `document.body`: пометьте его корень
  `pluginScopeAttributes`.
