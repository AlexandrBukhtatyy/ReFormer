# Киты и движки

Две независимые вещи решают, что вы видите в билдере:

- **кит** — набор компонентов полей, которыми форма рисуется в превью и которые импортирует
  напечатанный код;
- **движок формы** — плагины одного формата формы: редактор, превью, проверки, генерация кода.

Кит выбирает человек, движок — формат открытого файла. Один и тот же кит рисует формы любого
движка.

## Кит

| Кит                  | Пакет                      | Как появляется в билдере       |
| -------------------- | -------------------------- | ------------------------------ |
| **ReFormer UI Kit**  | `@reformer/ui-kit`         | встроенный, есть всегда        |
| **Kaspersky HexaUI** | `@reformer/kit-hexa-ui`    | плагином проекта `kit-hexa-ui` |
| свой кит             | пакет вашей дизайн-системы | плагином проекта — см. ниже    |

**Выбор кита.** Ячейка кита в правом углу строки состояния: щелчок открывает список доступных
китов, кит меняется сразу, без перезагрузки. То же — в палитре команд: «Кит: …». Пункт «Как в
конфиге запуска» снимает ваш выбор, и билдер снова берёт кит из конфига. Кит один — ячейка просто
подпись.

![Форма в виде «Форма», нарисованная китом Kaspersky HexaUI, и открытый список китов](/img/builder/kit-hexa.png)

**Кит — настройка проекта, а не формы.** Палитра, превью и экспорт работают с активным китом.
Модуль, напечатанный другим китом, «Сгенерировать» перепечатывать откажется и назовёт оба кита.
Формы на разных китах правят каждую под своим китом.

**Кит по умолчанию для всех** задаёт конфиг запуска — см.
[Конфигурация](./configuration.md#кит-по-умолчанию).

### ReFormer UI Kit

Встроенный кит — компоненты [`@reformer/ui-kit`](../ui-kit/overview.md): поля ввода, выбор и
переключатели, контейнеры, типографика, мастер. По нему построены встроенные шаблоны «Простая
форма» и «Пошаговая форма».

### Kaspersky HexaUI

Кит на дизайн-системе Kaspersky HexaUI. Пакет `@reformer/kit-hexa-ui` живёт в репозитории ReFormer,
в каталоге плагинов проекта-образца `projects/reformer-builder-playground`, и в npm не
публикуется. Он одновременно кит для приложения и плагин, который вносит кит в билдер.

- **Полный каталог** — около полутора сотен записей. Оверлеи, навигация, вкладки, таблицы и
  тяжёлые компоненты есть в палитре, но превью рисует их подписанной заглушкой; код импорт
  печатает.
- **29 полей.** Имена — как у `@reformer/ui-kit` (`Input`, `Select`, `DatePicker`, `FileUpload`…),
  поэтому одна схема формы рисуется обоими китами. Восьми полей у ui-kit нет: `CheckboxGroup`,
  `CodeEditor`, `InputSearch`, `RichTextEditor`, `TimeInput`, `TimeRange`, `ToggleButtonGroup`,
  `WeeklySchedule`.
- **Мастер** есть, поэтому есть и шаблон «Пошаговая форма».

Подключение к билдеру — собрать плагин и положить сборку в `.ui_builder/plugins/kit-hexa-ui/`
проекта, затем включить его (см. [Конфигурация](./configuration.md)). В приложении форму на
HexaUI оборачивают провайдером кита `KitProvider`, а глобальный CSS HexaUI ограничивают
плагином Vite `hexaUiStyles()` из `@reformer/kit-hexa-ui/vite`.

Известные ограничения: HexaUI объявляет React 16–18, а билдер работает на React 19 — формы
рисуются, но в консоли бывают предупреждения antd и styled-components; повторное включение
плагина в той же вкладке даёт предупреждение о втором экземпляре styled-components до
перезагрузки.

### Свой кит

Кит дизайн-системы организации вносится тем же путём, что HexaUI, — плагином. Ни билдер, ни
движки о ките заранее не знают: кит описывает себя **каталогом компонентов**.

1. **Поля** — обёртки над контролами дизайн-системы со статикой `reformerAdapter`
   (`FieldAdapter` из `@reformer/core/react`): адаптер сводит значение, `onChange` и `onBlur` формы
   к контракту контрола. Корень каждого компонента обязан принимать `className` — по нему билдер
   находит узел щелчком в превью.
2. **Каталог** не пишется руками. Его собирает `reformer-plugin catalog` из TypeScript-типов
   входа пакета кита, а конфиг `catalog.config.mjs` добавляет то, чего в типах нет: тип значения
   каждого поля, разделы палитры, ограниченные и служебные компоненты.
3. **Плагин кита** вносит кит в точку `KitSourcePoint` и требует возможность
   `reformer.kit.catalog` `^2`.
4. По желанию — **мастер** (`kit.adapters.wizard`) и **провайдер** (`kit.adapters.provider`):
   первым включается шаблон «Пошаговая форма», вторым превью и страница модуля оборачивают форму.

Проверить, что каталог не разошёлся с типами, — `reformer-plugin catalog --check`: файл не
пишется, расхождение печатается диффом с кодом выхода `1`. Подробности команды — на странице
[Сборка и стили плагина](./plugins/build-and-styles.md#каталог-кита), контракт кита — в
[Манифест и API плагина](./plugins/manifest-and-api.md#киты).

## Движки форм

Встроенных движков у билдера нет — их приносят плагины. Билдер везёт два.

| Движок       | Документ формы                                                                                    | Плагины                                                                                                                  |
| ------------ | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **ReFormer** | `form.schema.json` — формат `@reformer/renderer-json`                                             | «Редактор формы», «Предпросмотр формы ReFormer», «Проверка схемы», генерация кода, шаблоны и ассистент для форм ReFormer |
| **RJSF**     | `*.rjsf.json` — JSON Schema и uiSchema [RJSF](https://rjsf-team.github.io/react-jsonschema-form/) | «RJSF: редактор формы», «RJSF: превью формы в ките»                                                                      |

Какой редактор откроет файл, решает разбор его содержимого, а не расширение: `.json` бывает и
формой, и конфигом. Без плагинов движка форма открывается текстом.

### Формы RJSF

Документ RJSF — JSON с полями `$schema: "rjsf-form/1"`, `schema` (JSON Schema) и `uiSchema`:

```json
{
  "$schema": "rjsf-form/1",
  "schema": {
    "type": "object",
    "title": "Контакт",
    "required": ["name"],
    "properties": {
      "name": { "type": "string", "title": "Имя" },
      "agree": { "type": "boolean", "title": "Согласен на обработку данных" }
    }
  },
  "uiSchema": { "name": { "ui:placeholder": "Как к вам обращаться" } }
}
```

Новую форму создаёт команда «Новая форма RJSF». У редактора три вида — «Структура», «Форма» и
«Исходник». В «Структуре» поля переставляются и удаляются, «+ Добавить поле» добавляет новое; в
«Свойствах» у поля — «Имя в данных», «Подпись», «Тип значения», «Обязательное», у формы —
«Заголовок формы». Кнопка «Экспорт Form.tsx» печатает компонент формы для приложения.

![Форма RJSF в виде «Структура» и панель «Свойства»](/img/builder/rjsf.png)

Форму RJSF рисует активный кит. Если подходящего поля в ките нет, берётся стандартный виджет
RJSF, и билдер говорит об этом находкой в «Журнале».
