# Редактирование формы

Документ формы ReFormer — файл `form.schema.json` в формате
[renderer-json](../packages/renderer-json.mdx). Билдер открывает его редактором формы: дерево
узлов, раскладка, живая форма и текст — четыре вида одного документа. Правка в любом виде сразу
видна в остальных.

Этот раздел — о формах ReFormer. Формы RJSF редактируются проще, о них — на странице
[Киты и движки](./kits-and-engines.md#формы-rjsf).

## Четыре вида

Кнопки видов — справа на полосе вкладок.

| Вид              | Что показывает                                                                  | Для чего                                 |
| ---------------- | ------------------------------------------------------------------------------- | ---------------------------------------- |
| **Дерево**       | узлы формы списком: подпись, путь в модели, компонент                           | быстро найти узел и поменять порядок     |
| **Схема**        | раскладку блоками: ряды и столбцы, вложенные контейнеры                         | собирать раскладку перетаскиванием       |
| **Форма**        | живую форму, нарисованную активным китом                                        | проверить, как форма выглядит и работает |
| **Исходный код** | текст файла в редакторе кода — с подсказками и подчёркнутыми находками проверок | правка, для которой нет кнопки           |

![Вид «Схема»: блоки полей, ряд из двух полей вверху; слева палитра «Компоненты»](/img/builder/editor-schematic.png)

**В виде «Форма»** обычный щелчок принадлежит форме: флажок переключается, поле получает
фокус, мастер листает шаги. Узел выбирают `Alt`+щелчком, а тащат за ручку у выделенного узла.
Значения, введённые в форму, не пропадают, когда переключаете вид или правите схему.

![Вид «Форма» и нижняя панель «Модель» со значениями полей](/img/builder/editor-form.png)

**В виде «Исходный код»** можно править что угодно. Пока текст не разбирается как форма,
остальные виды только показывают документ: правка в них вернётся, когда текст починят.

## Добавить компонент

- **Палитра «Компоненты»** на левом рейле — компоненты активного кита по разделам, с поиском.
  Щелчок добавляет компонент в выделенный контейнер; компонент можно и перетащить в вид «Схема»
  или «Форма».
- **Быстрое добавление** — `Enter` на выделенном узле открывает окно «Добавить компонент»:
  наберите имя компонента или тег, стрелками выберите, `Enter` — добавить.

![Окно «Добавить компонент» с поиском по слову date](/img/builder/quick-add.png)

Состав палитры зависит от кита: у Kaspersky HexaUI есть поля, которых нет у `@reformer/ui-kit`.
Подробнее — [Киты и движки](./kits-and-engines.md).

## Панель «Свойства»

Выберите узел — панель «Свойства» на правом рейле покажет его компонент и свойства по разделам:
«Основные», «Значения», «Текст», «Поведение», «Состояние». Описание свойства — по значку ⓘ
рядом с его именем.

- **«Привязка к модели»** — путь значения в модели формы, без обёртки `$model()`. Выберите
  объявленный путь из списка или введите новый.
- **«Включено»** — логические свойства компонента, например `required` и `readOnly` у `Input`.
- Свойство, у которого нет удобного поля ввода, помечено «Правится в JSON» — его правят в виде
  «Исходный код».

Выбрано несколько узлов — свойства правятся по одному. Компонента нет в каталоге активного
кита — панель так и скажет: «Компонента … нет в каталоге активного кита».

## Клавиши редактора

Работают, когда фокус в дереве или схеме. На macOS вместо `Ctrl` — `Cmd`.

| Клавиши                  | Действие                                          |
| ------------------------ | ------------------------------------------------- |
| `Enter`                  | добавить компонент в выделенный узел              |
| `Delete`, `Backspace`    | удалить узел                                      |
| `Ctrl+D`                 | дублировать узел                                  |
| `Alt+Shift+стрелка`      | дублировать в сторону стрелки                     |
| `Ctrl+стрелка`           | переместить узел                                  |
| `Ctrl+G`                 | сгруппировать выделенное в контейнер              |
| `Ctrl+Shift+G`           | разгруппировать                                   |
| `Ctrl+Shift+L`           | перевернуть направление контейнера: ряд ↔ столбец |
| `Ctrl+Z`, `Ctrl+Shift+Z` | отменить, повторить                               |
| `Esc`                    | снять выделение                                   |

Остальные действия — в палитре команд: «Заменить компонент», «Заменить путь модели»,
«Переименовать свойство», «Показать формой», «Показать схемой».

## Пошаговые формы

Мастер — форма, разбитая на шаги. Шаги можно держать в одном документе или каждый в своём
файле `schema/steps/<шаг>/form.schema.json`. Переключают раскладку команды «Разбить визард по
файлам шагов» и «Собрать форму в один файл». Разбитую форму билдер открывает целиком, как один
документ, а правки раскладывает по файлам шагов сам.

Мастер есть не у каждого кита: у `@reformer/ui-kit` и Kaspersky HexaUI он есть, и для них есть
встроенный шаблон «Пошаговая форма».

## Панель «Модель»

Нижняя панель «Модель» показывает значения живой формы: путь, значение, отметку `touched`. Здесь
же можно:

- поменять значение поля руками;
- «сбросить» поле или «выключить» его;
- с галочкой «Сырая запись» значение пишется без события изменения и без отметки `touched`, как
  данные с сервера: так проверяют, как форма принимает загруженные данные;
- «Копировать модель» — забрать значения в буфер обмена.

## Проблемы и быстрые исправления

Проверки формы идут на каждую правку. Найденное видно в трёх местах: счётчиком на строке файла
в дереве «Проект», контуром на узле в виде «Форма» и списком в «Журнале», вид «Проблемы». Щелчок
по находке открывает её место.

У частых находок есть быстрые исправления: «Подставить ближайшее имя из каталога» — для
опечатки в имени компонента, «Подставить ближайший объявленный путь» — для пути модели,
«Исправить имя свойства», «Убрать осиротевшее правило».

## Сохранение и чужие правки

`Ctrl+S` пишет активный документ на диск, `Ctrl+Alt+S` — все изменённые. Пока файл не сохранён,
на его вкладке стоит точка.

Файл могли поменять мимо билдера — в IDE или командой `git`. Билдер замечает это, когда вы
возвращаетесь в его окно, и пишет в строке состояния «… изменены снаружи». Что дальше:

- **файл здесь не правили** — билдер просто перечитает его;
- **правили и здесь, и там** — при сохранении откроется окно «Файл … изменился в источнике».
  Варианты: «Переписать своей версией», «Взять версию источника» и, если правки не пересеклись,
  «Объединить правки». Вкладка «Слить вручную» даёт три колонки — общее основание, наша версия,
  версия источника — и текст слияния.

Молча билдер не выбирает ни одну сторону.

## Подводные камни

- **Правка в виде «Дерево» или «Схема» не применяется.** Текст документа не разбирается —
  откройте «Исходный код» и найдите ошибку: она подчёркнута и есть в «Журнале».
- **Поле в виде «Форма» пустое после правки схемы.** Значение переносится по пути модели: если
  путь поменяли, старое значение остаётся у старого пути.
- **Компонент рисуется заглушкой.** Его нет в ките или кит рисует его ограниченно — так бывает у
  оверлеев и таблиц HexaUI.
