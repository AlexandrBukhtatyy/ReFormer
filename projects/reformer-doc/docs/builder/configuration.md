# Конфигурация `.ui_builder/`

Всё, что билдер читает из проекта, лежит в одном каталоге `.ui_builder/` в корне проекта.
Каталог не обязателен: без него билдер работает, а настройки проекта хранит в браузере. Как
только каталог появится, настройки переедут в его `settings.json`.

## Что где лежит

```text
<проект>/
├── .ui_builder/
│   ├── config.json        заголовок, умолчания, состав билдера
│   ├── settings.json      включённые плагины и выданные им права — пишет билдер
│   ├── plugins/           плагины проекта
│   ├── templates/         шаблоны форм
│   ├── codegen/           свои шаблоны печати кода (*.eta)
│   └── mcp/<имя>/         MCP-серверы ассистента: server.js и server.json
└── .mcp.json              удалённые MCP-серверы ассистента
```

| Что                 | Подробнее                                                             |
| ------------------- | --------------------------------------------------------------------- |
| `plugins/`          | [Плагины: понятия](./plugins/concepts.md#где-лежат-плагины)           |
| `templates/`        | [Шаблоны форм](./codegen-and-templates.md#шаблоны-форм)               |
| `codegen/`          | [Свои шаблоны печати](./codegen-and-templates.md#свои-шаблоны-печати) |
| `mcp/`, `.mcp.json` | [MCP-серверы](./assistant.md#справка-по-reformer-и-mcp-серверы)       |

## `config.json`

Все секции необязательны. `$schema` даёт автодополнение в IDE.

```json
{
  "$schema": "./node_modules/@reformer/builder/runtime-config.schema.json",
  "branding": { "title": "Формы Acme" },
  "defaults": {
    "locale": "ru",
    "theme": "system",
    "settings": { "plugin.kits.active": "hexa-ui" }
  }
}
```

| Поле                                | Что задаёт                                                      |
| ----------------------------------- | --------------------------------------------------------------- |
| `branding.title`                    | заголовок окна билдера                                          |
| `defaults.locale`                   | язык интерфейса до первого выбора: `ru` или `en`                |
| `defaults.theme`                    | тема до первого выбора: `light`, `dark` или `system`            |
| `defaults.settings`                 | умолчания любых настроек: ключ настройки → значение             |
| `preset`                            | профиль состава — из каких встроенных плагинов собрать билдер   |
| `presetChoices`                     | между какими профилями человек переключается в строке состояния |
| `profiles`                          | свои профили состава                                            |
| `plugins.enable`, `plugins.disable` | поправки к составу профиля; `disable` сильнее                   |
| `marketplace.registry`              | адрес JSON-каталога плагинов для вкладки «Каталог» в настройках |

Выбор человека — в настройках или в строке состояния — сильнее `defaults` и переживает
перезагрузку.

### Два уровня: запуск и проект

`config.json` читается дважды:

1. **При запуске** — его читает лаунчер `npx @reformer/builder` из каталога, где он запущен, или
   dev-сервер приложения со [встроенным билдером](./embedding.mdx). Это **конфиг запуска**.
2. **При открытии проекта** — билдер читает `config.json` открытой папки. Это **конфиг проекта**.

Состав и умолчания — `defaults`, `preset`, `presetChoices`, `profiles`, `plugins` — действуют
только из конфига запуска: к открытию проекта билдер уже собран. В конфиге проекта они
разбираются, но не применяются; если они там записаны иначе, чем в конфиге запуска, билдер
предупредит уведомлением. Запустили билдер в корне проекта и его же открыли — файл один на оба
уровня, и предупреждений нет.

Битый конфиг билдер не роняет: он открывается, а каждую проблему называет в уведомлении.

## `settings.json`

Этот файл пишет билдер — при каждом открытии проекта и при каждом изменении настроек проекта.
Руками его обычно не правят, но знать, что в нём, полезно:

```json
{
  "workspace.plugins.enabled": ["kit-hexa-ui", "acme-forms"],
  "workspace.plugins.permissions": {
    "acme-forms": ["workspace.save"]
  }
}
```

- `workspace.plugins.enabled` — какие плагины проекта включены;
- `workspace.plugins.permissions` — какие права им уже выданы. Записанное право билдер не
  спрашивает повторно.

Значение, заданное здесь, перекрывает глобальное, и окно настроек об этом говорит.

## Запуск билдера локально

Пакет `@reformer/builder` несёт собранный билдер и маленький лаунчер без зависимостей: он
поднимает локальный сервер и открывает браузер.

```bash
npx @reformer/builder@beta [--port 4321] [--host 127.0.0.1] [--no-open] [--config <path>] [--plugins <dir>]
```

| Флаг              | Что делает                                                               |
| ----------------- | ------------------------------------------------------------------------ |
| `--port`, `-p`    | порт, по умолчанию `4321`; занят — берётся следующий свободный           |
| `--host`          | адрес, по умолчанию `127.0.0.1`                                          |
| `--no-open`       | не открывать браузер                                                     |
| `--config <path>` | конфиг запуска; без флага — `.ui_builder/config.json` в текущем каталоге |
| `--plugins <dir>` | каталог плагинов приложения вместо набора, собранного в пакет            |

Поставленный в проект пакет (`npm i -D @reformer/builder@beta`) запускается короче:
`npx reformer-builder`.

**Каталог `--plugins` живой.** Пересобрали плагин под работающим билдером — билдер перезагрузит его
сам, когда вы вернётесь в его окно.

## Профили состава

Профиль — список **встроенных** плагинов оболочки: открытие проекта, управление плагинами,
переключатель профиля. Движки форм и киты в профиль не входят — это плагины.

| Профиль        | Подпись               | Что внутри                                  |
| -------------- | --------------------- | ------------------------------------------- |
| `builder`      | «Конструктор»         | профиль по умолчанию                        |
| `builder.base` | «Основа конструктора» | проект, управление плагинами, выбор профиля |

Свой профиль:

```json
{
  "preset": "acme",
  "presetChoices": ["builder", "acme"],
  "profiles": [
    {
      "id": "acme",
      "name": "Формы Acme",
      "plugins": ["reformer.project", "reformer.profile-switch"]
    }
  ]
}
```

Поля профиля: `id` (не может совпадать со встроенным), `name`, `extends` — встроенный или другой
свой профиль, `plugins`, `providers` — какой плагин даёт возможность, когда её дают двое.

Профиль меняется ячейкой профиля в строке состояния или командой «Профиль: …» — с перезагрузкой,
и билдер спросит перед ней. Без `presetChoices` выбора нет: предлагается только `builder`.
Неизвестное имя профиля или состав, который не собирается, — предупреждение в консоли и
профиль по умолчанию.

## Кит по умолчанию

Кит организации — умолчание настройки `plugin.kits.active` в конфиге запуска:

```json
{
  "defaults": {
    "settings": { "plugin.kits.active": "hexa-ui" }
  }
}
```

Пока плагин кита не внёс кит, работает встроенный ReFormer UI Kit; как только внёс, билдер
переключится на кит организации сам. Выбор человека в ячейке кита сильнее умолчания, а пункт
«Как в конфиге запуска» его снимает.

## Подводные камни

- **Поле в конфиге проекта «не работает».** `defaults`, `preset` и состав действуют только из
  конфига запуска — билдер об этом предупреждает.
- **Плагин проекта не виден.** Плагин проекта включает человек: «Настройки» → «Плагины» или
  `workspace.plugins.enabled` в `settings.json`.
- **`settings.json` меняется после каждого открытия.** Так и задумано: его пишет билдер.
  Исключите файл из форматтера, иначе открытие проекта будет давать diff.
