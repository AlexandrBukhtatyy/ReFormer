# Встраивание в Vite-приложение

Билдер можно открыть поверх страницы приложения, которое вы разрабатываете. Это тот же
интерфейс, только форму в превью рисует **само приложение** — со своими провайдерами, своим API
и своими стилями. Файлы проекта билдер правит прямо на диске.

## Когда нужно

Билдер в своей вкладке рисует форму сам: своими компонентами и данными-заглушками. О приложении
он ничего не знает — ни его API, ни провайдеров, ни того, как выглядит страница вокруг формы.
Встроенный билдер этот разрыв закрывает: список в поле формы приходит из настоящего API,
уведомление после отправки показывает приложение, а правка сервиса в редакторе кода сразу видна
в превью.

## Подключение

**1. Зависимость** — в `devDependencies`: в прод-сборку приложения билдер не попадает.

```bash
npm i -D @reformer/builder@beta
```

Peer-зависимости — `react` 18 или 19 и `vite` 6 или 7.

**2. Плагин dev-сервера.** Он отдаёт билдер с того же адреса, что и приложение, под путём
`/__reformer-builder/`.

```ts title="vite.config.ts"
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import { reformerBuilder } from '@reformer/builder/vite';

export default defineConfig({
  plugins: [react(), reformerBuilder()],
});
```

**3. Компонент.** Оберните приложение **внутри** его провайдеров: форму в превью рисует это же
приложение, и провайдеры ей нужны те же.

```tsx title="main.tsx"
import { createRoot } from 'react-dom/client';
import { ReformerBuilder } from '@reformer/builder';

createRoot(document.getElementById('root')!).render(
  <AppProviders>
    <ReformerBuilder>
      <App />
    </ReformerBuilder>
  </AppProviders>
);
```

Больше ничего не нужно: ни псевдонимов исходников, ни Tailwind, ни путей в `tsconfig`. Билдер —
отдельный документ, его стили и зависимости в сборку приложения не попадают.

## Как работать

1. Запустите dev-сервер приложения и откройте любую его страницу в Chromium.
2. Нажмите «Билдер» в углу страницы — билдер откроется поверх приложения.
3. «Открыть папку…» — выберите каталог приложения, тот, что раздаёт dev-сервер. Выбор нужен один
   раз.
4. Откройте документ формы. Результат смотрят в двух местах:
   - **вид «Форма»** в полосе вкладки — только компонент формы: тот, что экспортирован по
     умолчанию из `index.tsx` или `index.ts` её модуля;
   - **панель «Превью»** на правом рейле — приложение целиком, с адресной строкой; **↗** рядом с
     адресом открывает его в отдельной вкладке, уже без билдера.
5. Правьте форму или любой файл проекта и сохраняйте (`Ctrl+S`): файл пишется на диск, и вид
   «Форма», и панель показывают результат.
6. «Закрыть билдер» — приложение на той же странице и в том же состоянии. Открытый проект и
   вкладки ждут следующего открытия.

<BuilderEmbeddingFrames />

**Приложение рисует то, что записано на диск.** Пока в рабочей копии есть несохранённые правки,
над формой стоит полоса: «Есть несохранённые правки. Приложение рисует то, что записано на диск,
— сохраните, и форма обновится». Сохранить можно там же.

**Модуля формы ещё нет** — вместо формы будет сказано, какого файла не хватает. Напечатайте модуль
кнопкой «Сгенерировать» в «Экспорте формы», и форма покажется сама.

## Параметры

Плагин `reformerBuilder(options)`:

| Параметр  | Что задаёт                                                                                    |
| --------- | --------------------------------------------------------------------------------------------- |
| `config`  | конфиг запуска — путь от корня приложения; по умолчанию `.ui_builder/config.json`             |
| `plugins` | каталог плагинов приложения вместо набора, который едет с билдером                            |
| `ui`      | откуда интерфейс: `auto` (по умолчанию), `source` — из исходников, `dist` — из готовой сборки |

Компонент `<ReformerBuilder>`:

| Проп          | Что задаёт                                                                                                 |
| ------------- | ---------------------------------------------------------------------------------------------------------- |
| `projectBase` | префикс адреса, если в билдере открыта не корневая папка dev-сервера                                       |
| `loadForm`    | своя загрузка модуля формы по пути от корня проекта — для сборщиков, которые не отдают исходники по адресу |
| `enabled`     | включён ли билдер; по умолчанию — когда к dev-серверу подключён плагин                                     |
| `labels`      | подписи кнопки и сообщений                                                                                 |

Переменные окружения плагин не читает — путь к конфигу называет `vite.config.ts`. Так, например,
выбирают пресет кита при старте:

```ts title="vite.config.ts"
// По умолчанию — ui-kit; REFORMER_BUILDER_CONFIG=.ui_builder/presets/hexa-ui.json — HexaUI.
const config = process.env.REFORMER_BUILDER_CONFIG || '.ui_builder/presets/ui-kit.json';

export default defineConfig({ plugins: [react(), reformerBuilder({ config })] });
```

Каталог `.ui_builder/` приложения устроен так же, как у любого проекта, — см.
[Конфигурация](./configuration.md). Конфиг запуска плагин перечитывает на каждый запрос:
правка видна после перезагрузки страницы.

## Прод-сборка

В `vite build` тот же плагин подменяет `@reformer/builder` заглушкой с тем же API, которая просто
рисует детей. В бандл приложения не попадают ни кнопка, ни рамка, ни чтение хранилища сессии.
Сам билдер приложение не собирает никогда — его отдаёт только dev-сервер.

## Что полезно знать

- **Режим переживает перезагрузку страницы**: он хранится в хранилище сессии вкладки. Новая
  вкладка, открытая из превью, режим не наследует.
- **Хранилище браузера у билдера и приложения общее** — адрес у них один. Своё билдер держит под
  пространством имён `reformer-builder`, и «Очистить кэш» сносит только его; данные приложения
  не трогает.
- **Перезагрузку страницы dev-сервер откладывает**, пока билдер открыт: вместе со страницей ушла
  бы и рамка с билдером. Перезагрузка выполнится, когда билдер закроют.
- **Внутри превью кнопки «Билдер» нет**: приложение узнаёт рамку превью по имени окна.

## Ограничения

- **Только Vite и только режим разработки.** Билдер отдаёт плагин dev-сервера Vite; другим
  сборщикам остаётся проп `loadForm` для загрузки модуля формы.
- **Только Chromium** — проект открывается через File System Access.
- **Несохранённых правок в форме нет**: вид «Форма» показывает записанное на диск.
- **Билдер не знает о приложении**: палитра — компоненты кита, а не реестр приложения;
  выбрать узел щелчком по форме, которую рисует приложение, нельзя.

## Попробовать на образце

В репозитории ReFormer есть приложение-образец со встроенным билдером —
`projects/reformer-builder-host-example`:

```bash
npm run dev -w reformer-builder-host-example   # http://localhost:5175/contact
```

Откройте страницу, нажмите «Билдер», выберите каталог образца и откройте
`src/forms/contact/schema/form.schema.json` — форма обращения со списком городов из API
приложения.
