# Тексты замечаний

[Замечание](../reference/glossary.md#валидация) валидации несёт код и параметры, но не текст:
`{ code: 'minLength', params: { minLength: 8 } }`. Текст под полем подбирает резолвер сообщений.
`ValidationMessagesProvider` задаёт, откуда он берёт тексты для части формы, а
`useIssueMessageResolver` отдаёт итоговый резолвер вашему компоненту.

## Когда использовать

- Общий текст локали не подходит полю: вместо «Обязательное поле» нужно «Укажите телефон для связи».
- У правила свой код (`required({ code: 'phone.required' })`), и тексту нужен этот код.
- Тексты уже живут в i18n-библиотеке приложения, и замечания должны брать их оттуда.
- Вы рисуете замечания своим компонентом и хотите тот же текст, что у `FormField`.

Если нужно только перевести стандартные тексты на другой язык — достаточно локали и
`I18nProvider`: см. [Локализация](/docs/guides/localization).

## Анатомия

Откуда резолвер берёт текст, по порядку:

1. **Словарь формы** — `messages` ближайших `ValidationMessagesProvider`. Вложенный провайдер
   накладывает свои записи поверх внешнего.
2. **Свой резолвер** — `resolver` ближайшего провайдера, если он задан. Тогда локаль и внешние
   провайдеры для этого поддерева не участвуют.
3. **Локаль** — словарь активного языка по коду (`validation.<code>`), затем встроенный
   английский, затем сам код.

| Что                          | Импорт                | Что делает                                                                    |
| ---------------------------- | --------------------- | ----------------------------------------------------------------------------- |
| `ValidationMessagesProvider` | `@reformer/cdk`       | Пропсы `messages` (словарь формы) и `resolver` (свой источник) для поддерева. |
| `useIssueMessageResolver()`  | `@reformer/cdk`       | Итоговый резолвер в точке вызова: `(issue) => string`.                        |
| `defineIssueMessages({ … })` | `@reformer/core/i18n` | Словарь формы: код → шаблон с параметрами `{name}` или функция.               |

Отдельного входа у провайдера нет — импорт из корня `@reformer/cdk`.

```tsx
import { defineIssueMessages } from '@reformer/core/i18n';
import { ValidationMessagesProvider } from '@reformer/cdk';

// Константа модуля: новый объект на каждый рендер пересчитывал бы тексты.
const messages = defineIssueMessages({
  'phone.required': 'Укажите телефон для связи',
  minLength: 'Пароль — не короче {minLength} символов',
});

<ValidationMessagesProvider messages={messages}>
  <SignUpForm />
</ValidationMessagesProvider>;
```

Код, которого нет в словаре формы, получает текст из локали. Шаблон форматирует локаль, поэтому
параметры замечания (`{minLength}`) подставляются по правилам активного языка.

Провайдер читают `FormField.Error` и `FieldArray.Error` из cdk и `FormField` из ui-kit — а значит,
и формы, которые рендерер рисует с обёрткой поля ui-kit.
Смена языка в `I18nProvider` переводит уже показанные замечания без повторной проверки.

## Подводные камни

- **`messages` того же провайдера важнее `resolver`.** Если задать оба, коды из словаря возьмутся
  из словаря, остальные — из `resolver`.
- **Резолвер — функция рендера.** Его идентичность меняется вместе с языком и словарём: вызывайте
  его при рендере, а не сохраняйте текст заранее.
- **Не показывайте `issues[0]` руками.** Замечания идут в порядке правил, и предупреждение может
  стоять раньше ошибки. Главное замечание поля уже выбрано в `error` у `useFormFieldContext()`.

## Доступность

Провайдер ничего не рендерит. Объявление текста скринридеру — забота компонента, который его
показывает: `FormField.Error` и `FieldArray.Error` рендерят элемент с `role="alert"`.

## Локализация

Встроенные тексты замечаний — в словарях ядра (`validation.<code>`), язык задаёт `I18nProvider` из
`@reformer/core/react`. Как подключить словари ядра, cdk и кита — в руководстве
[Локализация](/docs/guides/localization), строки самого cdk — на странице [Локализация cdk](./locale.md).
