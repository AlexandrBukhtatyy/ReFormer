# AsyncBoundary

<ComponentDoc config={cdkAsyncBoundaryDocConfig}>
`AsyncBoundary` показывает одно из четырёх состояний загрузки данных: загрузка не нужна (`idle`),
идёт (`loading`), готово (`ready`), ошибка (`error`). Он не добавляет разметки — каждое состояние
вы описываете своим слотом.

## Когда использовать

- Форма редактирования ждёт данные с сервера, а форма создания не ждёт ничего.
- Справочники для полей грузятся отдельно, и пока их нет, форму показывать рано.
- Нужен повтор после сбоя и отмена запроса, когда пользователь ушёл со страницы.

Готовый вид с индикатором, текстом ошибки и кнопкой повтора — [`AsyncBoundary` из
ui-kit](../ui-kit/async-boundary.mdx). cdk-версию берите, когда эти состояния нужно нарисовать
по-своему.

Это не Suspense-граница: компонент ничего не перехватывает. Состояние он ведёт сам или получает
от вашего кода.

## Анатомия

Режим выбирается при монтировании по пропу `load`:

| Режим            | Включается        | Кто ведёт состояние                                                                                     |
| ---------------- | ----------------- | ------------------------------------------------------------------------------------------------------- |
| **self-managed** | передан `load`    | Компонент: грузит, отменяет прежний запрос при смене `loadKey` и при размонтировании, даёт повтор.      |
| **controlled**   | `load` не передан | Ваш код через `status`, `error`, `onRetry`. Например, правило поведения формы, которую рисует рендерер. |

В self-managed режиме пропсы `status`, `error`, `refreshing` и `onRetry` не действуют: источник
состояния должен быть один. Повторная загрузка поверх уже полученных данных идёт в фоне — контент
остаётся на экране.

| Часть                   | Что делает                                                                                                                  |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `AsyncBoundary.Root`    | Провайдер состояния. Разметки не рендерит. Принимает `ref` с `reload()` и `abort()` для кнопок вне границы.                 |
| `AsyncBoundary.Idle`    | Содержимое, когда грузить нечего: форма создания, не выбран `id`.                                                           |
| `AsyncBoundary.Loading` | Содержимое во время загрузки. С `delayMs` при быстром ответе не показывается вовсе.                                         |
| `AsyncBoundary.Error`   | Содержимое при ошибке. Принимает функцию `({ error, retry, canRetry })` — текст сбоя и повтор не нужно передавать отдельно. |
| `AsyncBoundary.Content` | Содержимое при `ready`. В self-managed режиме принимает функцию от загруженных данных.                                      |
| `AsyncBoundary.Empty`   | Внутри `Content`: данные пришли, но пусты. Условие — проп `when`, а не отдельный статус.                                    |
| `AsyncBoundary.Retry`   | Кнопка повтора. Не рендерится без `onRetry`: кнопка, которая ничего не делает, хуже отсутствующей.                          |

Без compound-дерева то же дают хуки: `useAsyncBoundary` — расчёт состояния и наборы a11y-пропсов,
`useAsyncResource` — загрузка с отменой и повтором без разметки.

```tsx
import { AsyncBoundary } from '@reformer/cdk/async-boundary';

function ApplicationPage({ applicationId, bundle }: Props) {
  return (
    <AsyncBoundary.Root
      load={(signal) => loadApplication(applicationId, signal)}
      loadKey={applicationId}
      enabled={applicationId !== null}
      onSuccess={(data) => bundle.model.patch(data)} // ответ — в модель формы
      delayMs={200}
    >
      <AsyncBoundary.Idle>
        <h1>Новая заявка</h1>
      </AsyncBoundary.Idle>
      <AsyncBoundary.Loading>
        <p role="status">Загрузка заявки…</p>
      </AsyncBoundary.Loading>
      <AsyncBoundary.Error>
        {({ error, retry }) => (
          <div role="alert">
            <p>{String(error)}</p>
            <button onClick={retry}>Повторить</button>
          </div>
        )}
      </AsyncBoundary.Error>
      <AsyncBoundary.Content>
        <CreditForm form={bundle.form} />
      </AsyncBoundary.Content>
    </AsyncBoundary.Root>
  );
}
```

`load` получает `AbortSignal` — передайте его в `fetch`, иначе отменённый запрос продолжит висеть в
сети. `loadKey` сравнивается через `Object.is`: передавайте примитив, а не новый объект, иначе
загрузка будет перезапускаться на каждом рендере.

## Доступность

Компонент сам расставляет атрибуты на наборах пропсов `useAsyncBoundary`:

| Набор          | Атрибуты                                                     | Зачем                                                                        |
| -------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| `rootProps`    | `aria-busy` при загрузке и фоновом обновлении, `data-status` | Скринридер знает, что содержимое обновляется; `data-status` — для CSS и e2e. |
| `loadingProps` | `role="status"`, `aria-live="polite"`                        | Появление индикатора не прерывает чтение.                                    |
| `errorProps`   | `role="alert"`, `aria-live="assertive"`                      | Сбой прерывает чтение — иначе пользователь продолжит работать вслепую.       |

Слоты compound-дерева разметки не добавляют. Роли индикатора и ошибки ставьте сами — как в
примерах выше — или используйте готовый `AsyncBoundary` из ui-kit. Фокус после загрузки или ошибки
компонент не переносит.

## Локализация

Видимый текст пишете вы. Сам компонент произносит одну строку: текст ошибки, когда отказ не несёт
своего (`reject({ status: 500 })`). Это ключ `cdk.asyncBoundary.unknownError` — «Неизвестная
ошибка» в русской локали, «Unknown error» без провайдера. Язык задаёт `I18nProvider`; как подключить
строки cdk — на странице [Локализация](./locale.md). Фраза берётся в момент отказа: смена языка уже
показанную ошибку не переводит. Свой тип ошибки задаёт `toError`.
