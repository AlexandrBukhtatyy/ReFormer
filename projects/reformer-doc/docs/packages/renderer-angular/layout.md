# Вёрстка: контейнеры, HTML и текст

Кроме полей, схема описывает вёрстку: секции, колонки, заголовки, поясняющий текст и живую сводку
значений. Для этого есть узел-контейнер. Его `component` — standalone-компонент Angular или
HTML-тег строкой, а `children` — вложенные узлы и текст вперемешку.

## Когда это нужно

- Поля нужно разложить по секциям и колонкам.
- В форме есть заголовки, плашки с пояснением, разделители — заводить под них компоненты не хочется.
- Нужна сводка, которая пересчитывается на лету: «Платёж в месяц: 12 500 ₽».

## Пример

```ts
import type { FormModel, FormSchemaNode } from '@reformer/core';
import { computed } from '@reformer/core/signals';
import { InputNumber, Section } from '@reformer/kit-taiga';

type Installment = { amount: number; months: number };

export const installmentSchema = (model: FormModel<Installment>): FormSchemaNode => {
  // Вычисляемый текст — обычный computed над моделью.
  const monthly = computed(() => Math.round((model.amount ?? 0) / (model.months || 1)));

  return {
    component: 'div',
    componentProps: { className: 'space-y-6' },
    children: [
      {
        component: 'h2',
        componentProps: { className: 'text-xl font-bold' },
        children: ['Рассрочка'],
      },
      {
        component: Section,
        componentProps: { title: 'Условия' },
        children: [
          { model: model.$.amount, component: InputNumber, componentProps: { label: 'Сумма, ₽' } },
          {
            model: model.$.months,
            component: InputNumber,
            componentProps: { label: 'Срок, мес.' },
          },
        ],
      },
      { component: 'hr' },
      // Текст и сигналы в children: перерисовывается только сам текст.
      { component: 'p', children: ['Платёж в месяц: ', monthly, ' ₽'] },
    ],
  };
};
```

## Контейнер

| Ключ             | Что задаёт                                                                       |
| ---------------- | -------------------------------------------------------------------------------- |
| `component`      | компонент Angular (`Section`, `Box`) или тег строкой (`'div'`, `'p'`)            |
| `componentProps` | пропсы компонента — по трём каналам; у тега — атрибуты, классы, стили, слушатели |
| `children`       | вложенные узлы и текстовые части                                                 |
| `selector`       | имя узла для поведения и шагов потока                                            |

- `children` — ключ самого узла. Внутри `componentProps` вложенные узлы не рисуются.
- Контейнер без `component` рисует только своих детей — прямо на своём месте, без лишней разметки.
- Пропсы компонента раскладываются по объявленным входам, выходам и хосту — см.
  [Как пропсы узла доходят до компонента](./fields.md#как-пропсы-узла-доходят-до-компонента).
- `selector` узла компонент получает, только если объявил такой вход. На хост атрибутом он не
  уходит.

### Дети — содержимым

Компонент-контейнер получает детей проекцией: в его шаблоне нужен `<ng-content />`.

```ts
import { ChangeDetectionStrategy, Component, input } from '@angular/core';

@Component({
  selector: 'section[appSection]',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    @if (title(); as text) {
      <h3>{{ text }}</h3>
    }
    <ng-content />
  `,
})
export class AppSection {
  readonly title = input<string>();
}
```

- **`<ng-content />` — вне `@if`.** Содержимое должно оказаться на месте, когда компонент создан.
  Компонент без `<ng-content />` или с ним под условием детей не получит, а в dev-режиме будет
  предупреждение `Компонент "…" не вывел содержимое при создании`. Прятать детей по условию —
  атрибутом `[hidden]` или классом, см. [Свой контейнер](./node-control.md#свой-контейнер).
- Дети создаются после компонента и с его инжектором: провайдеры контейнера им видны.
- Компонент, которому дети нужны данными — визард, вкладки, — объявляет статику
  `__selfManagedChildren = true`. См.
  [Управление узлами](./node-control.md#компонент-сам-рисует-детей).

## HTML-теги

Тег строкой рисуется как есть: `{ component: 'h3', children: ['Итого'] }` даёт `<h3>Итого</h3>`.
Элемент тега — сам хост служебного компонента, лишней обёртки вокруг него нет: сетка и flex
родителя не ломаются. Отдельный компонент нужен, только когда у блока есть своя логика или
состояние.

Пропсы тега пишутся в диалекте React — так же, как их читают рендереры на React и Vue:

```ts
const hintNode = {
  component: 'label',
  componentProps: {
    htmlFor: 'email', // атрибут for
    className: 'hint', // класс
    style: { marginTop: 8 }, // style="margin-top: 8px"
    onClick: () => console.log('подсказка'), // слушатель click
  },
  children: ['Подсказка'],
};
```

- Правила для атрибутов, классов, стилей и слушателей те же, что у хоста компонента — см. таблицу
  на странице [Поля](./fields.md#как-пропсы-узла-доходят-до-компонента).
- `selector` в DOM не попадает: он адресует узел схемы, а не элемент. `hideWhen` по нему работает.
- Пустые теги (`hr`, `br`, `img`) детей не получают — их `children` пропускаются.
- Ref узла-тега — сам DOM-элемент.
- Теги и компоненты вкладываются друг в друга в любом порядке.

## Текст

Ребёнок контейнера — узел либо текстовая часть:

| Текстовая часть | Пример                              | Обновляется                     |
| --------------- | ----------------------------------- | ------------------------------- |
| строка, число   | `'Итого: '`, `42`                   | нет                             |
| сигнал поля     | `model.$.monthlyPayment`            | при изменении значения          |
| `computed(…)`   | `computed(() => model.a + model.b)` | при изменении прочитанных полей |

- Соседние части склеиваются без разделителя. Пробелы ставьте в строках сами.
- Порядок в `children` сохраняется: `['Важно: ', { component: 'b', children: ['срок'] }, ' истёк']`.
- `null` и `undefined` в сигнале дают пустую строку.
- Текст — отдельная текстовая нода: за сигналами следит эффект ядра, и при смене значения
  обновляется только она.
- Текст у компонента-контейнера приходит ему содержимым, как и узлы:
  `{ component: Button, children: ['Отправить'] }` — в `<ng-content />` кнопки.

## Узлы по условию

Условие, которое известно при сборке, решается обычным кодом: `...(withPhone ? [phoneNode] : [])`.
Пустые места (`null`, `undefined`, `false`) в `children` компилятор схемы пропускает.

Условие, которое меняется во время работы формы, — правило `hideWhen` в поведении формы. Скрытый
узел снимается вместе с компонентами внутри, показ создаёт их заново. См.
[Управление узлами](./node-control.md).

## Подводные камни

- **Текст не обновляется** — значение подставлено строкой при построении схемы:
  `` `Платёж: ${model.monthlyPayment}` `` читает его один раз. Передавайте сам сигнал:
  `['Платёж: ', model.$.monthlyPayment]`.
- **Контейнер пустой** — `children` положили в `componentProps`, в шаблоне компонента нет
  `<ng-content />` или он стоит под `@if`.
- **Класс узла не появился на элементе** — компонент объявил вход `className`, но сам его не
  применил. Без такого входа класс ложится на хост сам.
- **Компонент, который ведёт детей сам** (визард, вкладки), получает узлы, а не текст: текстовые
  части ему не передаются, в dev — предупреждение. См.
  [Управление узлами](./node-control.md#компонент-сам-рисует-детей).
