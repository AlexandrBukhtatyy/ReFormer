# Сеть и кэш

Схема формы может приходить с сервера: `schema: { kind: 'http', url }`. Схемы бывают объёмными —
многошаговая заявка весит десятки килобайт, — поэтому реестр форм кэширует их в памяти и в
хранилище браузера и не скачивает заново при каждом открытии страницы.

## Когда это нужно

- Схему формы выкладывают отдельно от кода — на CDN или в CMS.
- Одна и та же сетевая схема показывается в нескольких местах страницы.
- Схема должна открываться быстро и после перезагрузки страницы.

## Пример

```tsx
import { createSchemaCache } from '@reformer/form-registry';
import { pickStorage } from '@reformer/form-registry/storage';

// Кэш создаётся один раз: новый объект кэша перезагружает показанные формы.
export const schemaCache = createSchemaCache({ storage: await pickStorage() });

<FormRegistryProvider
  registry={getFormRegistry()}
  baseRegistry={appComponents}
  context={context}
  cache={schemaCache}
>
  <App />
</FormRegistryProvider>;
```

```ts
// В записи формы:
schema: { kind: 'http', url: '/forms/checkout.json' },
```

Кэш нужен только сетевым источникам. Части `inline` и `module` загрузчик отдаёт до кэша, поэтому на
таких записях счётчики кэша остаются нулевыми — это нормально.

## Загрузка по сети

Загрузчик (`fetchJson`) делает больше, чем `fetch`:

- **Повторяет запрос при ответах 5xx, 408, 425, 429** — с растущей задержкой и случайным разбросом,
  чтобы клиенты не повторяли запрос одновременно. Заголовок `Retry-After` учитывается.
- **Не повторяет 4xx**: сервер ответил «так нельзя», повтор ничего не изменит.
- **Проверяет `content-type`.** Если вместо JSON пришла HTML-страница (частый ответ SPA на
  неизвестный путь), ошибка называет причину, а не падает на разборе.
- **Проверяет, что пришла схема формы**, до записи в кэш: чужой JSON в кэше закрепил бы ошибку.
  Документ с `format`, отличным от `2`, тоже отвергается.

Отказ — исключение `FormFetchError` с полем `kind`:

| `kind`              | Что случилось                                           |
| ------------------- | ------------------------------------------------------- |
| `not-json`          | пришёл не JSON — обычно HTML-страница вместо файла      |
| `not-a-form-schema` | JSON без `root` либо документ неподдерживаемого формата |
| `http-error`        | 4xx или 5xx, на которые кончились повторы               |
| `network`           | сеть недоступна                                         |
| `aborted`           | запрос отменён: ушло последнее место, которое его ждало |

На месте формы такой отказ показывает `loadErrorFallback` с кнопкой повтора — см.
[Монтирование](./mounting.md#состояния-загрузки).

## Как работает кэш

Уровней два: в памяти — разобранные схемы и запросы «в полёте», в хранилище браузера —
сериализованные тела. Чтение идёт память → хранилище → сеть, запись — в обратном порядке.

- **Свежесть** — `maxAgeMs`, по умолчанию 5 минут. Устаревшую запись кэш перепроверяет условным
  запросом с `ETag`; ответ 304 продлевает ей жизнь.
- **Один запрос на всех.** Два места, которые ждут одну схему, делят один запрос. Ушло одно место —
  запрос продолжается для второго; отменяется он, только когда ушли все.
- **Отказ кэша не ломает загрузку.** Ошибка хранилища, битая запись, очистка данных сайта — кэш
  сообщает об этом и идёт в сеть.
- **Кэш можно выбросить в любой момент**: `clear()` безопасен, всё просто скачается заново.

Ключ записи кэша — `owner/id@version#schema`: хранилище общее для всего сайта, и `owner` разводит
одноимённые формы разных микрофронтендов.

```ts
await schemaCache.invalidate('mfe-orders/checkout@1.0.0#schema'); // сбросить одну схему
await schemaCache.clear(); // сбросить всё
```

Документ прежнего формата кэш хранит как есть: загрузчик переводит его в формат 2 после чтения,
поэтому кэш переживает выкладку новой версии библиотеки.

## Метрики

```ts
const schemaCache = createSchemaCache({ storage, onEvent: (event) => telemetry.push(event) });

schemaCache.stats(); // { l1Hit, l2Hit, dedup, stale, miss, fetched, ... } — копия счётчиков
schemaCache.resetStats(); // обнулить счётчики; содержимое кэша не трогает
```

Каждый вызов кэша даёт ровно одно событие поиска и не больше одного сетевого:

| Ось   | События                                                   |
| ----- | --------------------------------------------------------- |
| поиск | `l1-hit`, `l2-hit`, `dedup`, `stale`, `miss`              |
| сеть  | `fetched`, `refetched`, `revalidated`, `error`, `aborted` |

`stale` — запись была, но устарела: дальше обычно `revalidated`. `miss` — записи не было: дальше
полная загрузка. Ошибки хранилища считаются отдельно от сетевых `error`.

## Хранилища

```ts
import {
  createIndexedDbStorage,
  createMemoryStorage,
  createOpfsStorage,
  DEFAULT_STORAGE_ORDER, // ['opfs', 'indexeddb', 'memory']
  pickStorage,
} from '@reformer/form-registry/storage';
```

`pickStorage(order?)` возвращает первое работающее хранилище из списка. Работоспособность проверяется
пробной операцией: в приватном режиме части браузеров IndexedDB объявлен, но не открывается. Память
доступна всегда — ею выбор и заканчивается.

| Хранилище | Где живёт               | Особенности                                             |
| --------- | ----------------------- | ------------------------------------------------------- |
| OPFS      | файловая система origin | запись атомарна; общая для всего сайта                  |
| IndexedDB | база браузера           | одно соединение; при переполнении — вытеснение и повтор |
| память    | вкладка                 | живёт до перезагрузки                                   |

Старые записи вытесняются по давности использования, потолок по умолчанию — 32 МБ.

## Подводные камни

- **`not-json` на рабочем стенде** — путь к схеме неверен, и сервер отдал `index.html`.
- **Схема не обновилась после выкладки** — запись ещё свежая (`maxAgeMs`). Сбросьте её
  `invalidate(...)` или уменьшите `maxAgeMs`.
- **Формы перезагружаются по кругу** — кэш создаётся на каждом рендере.
