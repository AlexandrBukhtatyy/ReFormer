# Measurements: with MCP and without

The `@reformer/*` packages ship with their documentation — `llms.txt`, `docs/llms`, types. Why an
MCP server then? To answer with numbers, the same agent — Claude Sonnet in Claude Code — solved the
same form tasks under three conditions:

- **No MCP** — file tools only and the installed packages with their documentation;
- **MCP · tool set** — the same plus the `@reformer/mcp` server with its tool set
  (`REFORMER_SURFACE=tools`), the server default until November 15, 2026;
- **MCP · code-guided-dsl** — the same plus the server with the form builder
  (`REFORMER_SURFACE=code-guided-dsl`). After the November 15 measurement this surface became the
  default; this page shows a repeat measurement on the current code.

The same verifier checks every run: the build and types first, then the behavior of the form —
values, rules, reactions, wizard steps. The conditions are in [How it was measured](#how-it-was-measured).

## Summary

<McpSummary />

- **Creating a form is the main difference.** Without the server the agent writes the module by
  hand from the package docs and more often goes wrong in the file layout, the build and the types;
  on a large form from a spec that is about four minutes and over a dollar per run. With MCP the
  server does the plan, the build and the type check.
- **Editing and removing** in a ready form pass in all three arms almost without failures, but
  with MCP it is faster and cheaper.
- **The tool set** does not beat working without the server by the number of passed runs, though
  its mean check score is higher: its failures on creation are one known issue (the rule “pay by
  invoice — companies only” does not reach the form), and it is being fixed.

## Spread of runs

Medians hide the tails. Here every one of the 270 runs is a separate mark: a filled one passed every
check, a hollow one did not; the bar is the median of the arm. Hover a mark to see the scenario, the
stack and the numbers of the run.

<McpRunSpread />

Without the server 24 runs of 90 took longer than two minutes: 18 of them create a form, and 11 of
those eighteen failed the checks; six more turn a one-page form into a wizard. With MCP no run took
longer than two minutes: the longest took 1.9 minutes with the tool set and 1.5 with
code-guided-dsl. All twenty-seven most expensive runs of the measurement are without MCP.

Run time and cost grow together, so on one chart the arms spread along the diagonal: code-guided-dsl
sits in the lower left corner, runs without MCP stretch up and to the right. The median cost of
creating a form is $0.99 without MCP and $0.21 with it; on edits and removals the clouds are closer.

## How it was measured

- **Agent** — Claude Code in non-interactive mode, model `sonnet`. Tools — file tools only (`Read`,
  `Write`, `Edit`, `Glob`, `Grep`) inside the working directory, no shell. The MCP server is
  connected only in the MCP arms; the harness checks this at the start of every run.
- **The working directory** is the same in every arm: the installed `@reformer/*` packages — exactly
  what is published to npm (the build with types, README, `llms.txt`, `docs/llms`); `spec.md` for
  the spec scenarios; a ready form for edits and removals.
- **The task** is the same in every arm: the task text, the delivery rules and the module layout —
  which parts of `createForm` go into which files. Without the layout the behavior check would not
  find a form written without the server.
- **Limits** per run are the same in every arm and set by the scenario: money, steps, time.
- **The check** — static (types, stack, file layout) and behavioral: probes from the scenario
  contract fill the form and compare values, rule errors, reactions and wizard steps. A run
  **passes** when every required check passes; the **score** is the share of passed checks.
- **Order** — one run at a time, no parallelism; every “scenario × stack” cell goes through all
  three arms back to back, so API speed changes over the hours of the measurement fall on all arms
  almost alike.
- **Cost and tokens** — from the Claude Code report of the run; input tokens include cache reads
  and writes.

Limitations: one model; edits and removals start from a form the server built — this helps the arm
without MCP, as the layout is already in front of it.

### How to reproduce

```bash
npm run build -w @reformer/mcp
npm run mcp:scenarios -- --agent claude-code --model sonnet \
  --approach no-mcp,mcp-default,mcp-dsl --repeats 3 --max-usd-batch 120
npm run mcp:approaches -- <batch> --save packages/reformer-mcp/eval/runs/approaches/mcp-value-sonnet.json
node packages/reformer-mcp/eval/scenarios/mcp-value-docs.mjs \
  packages/reformer-mcp/eval/runs/approaches/mcp-value-sonnet.json \
  projects/reformer-doc/src/data/mcp-benchmark.json
```
